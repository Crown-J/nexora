## 0424-A｜開工 blocker 診斷（08:56 ~ 09:30）

### Blocker 1：分支基底
原指令寫「從 develop 拉」，但 repo 根本沒有 `develop` 分支（本地+remote 皆無）。
→ Crown 確認昨天 Alex 誤判，改從 `main` 拉。

### Blocker 2：useSessionMe.ts 顯示 modified
`git status` 顯示 `apps/nx-ui/src/features/auth/hooks/useSessionMe.ts` 被修改，但所有 diff 指令（含 `--stat`、`-w`、`--ignore-cr-at-eol`）皆空輸出。

**診斷**：
| 檢查項 | 結果 |
|---|---|
| Index 換行 | LF |
| Working tree 換行 | LF |
| Byte 數（HEAD vs WT）| 8504 vs 8504 |
| `.gitattributes` | 無 |
| `core.autocrlf` | `true`（repo 層級）|
| 檔案 mtime | 2026-04-24 08:56:51 |

**結論**：純粹是 `core.autocrlf=true` + 無 `.gitattributes` 造成的誤報。檔案被今早某工具（IDE formatOnSave / 背景 lint）touch 過但 byte 完全沒變，git 比對規範化後卻誤判 modified。

**處理**：Crown 核准 `git restore`，working tree 立刻乾淨。

### 順手修復：`.gitattributes`
為避免同樣誤報反覆發生，Crown 授權順手加根目錄 `.gitattributes`：

```
* text=auto eol=lf
```

**理由**：repo 基礎設定、純 chore、風險極低、早進 main 所有分支受惠、符合三條件自清規則。

**Commit**：`3e95fb8` — `[CHORE] add .gitattributes to normalize line endings to LF`（進 main）

### 分支建立
