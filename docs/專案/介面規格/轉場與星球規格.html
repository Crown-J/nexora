轉場動畫 & 星球 完整規格

這份文件把目前 NEXORA 系統.html 裡的所有轉場動畫與星球(planet)實作逐一拆解，附上實際數值、easing、觸發條件與檔案位置。直接交給 Claude Code 當實作依據，比讓它從截圖推測準得多 —— 因為動畫與飛行軌跡在靜態畫面裡是看不見的。

A

登入 → 儀表板 主轉場

系統的招牌轉場。由 <body> 的 state class 驅動：login → state-leaving → state-app。觸發點：登入表單 submit（enter() @ system-engine.js）。星球在這裡實際飛行，是整個轉場的主角。

狀態機時間軸 JS 驅動

system-engine.js · enter() ／ globals.css 段 .state-machine
  1. 送出表單 → 加上 body.state-leaving。登入卡與品牌同時退場：.lg-right 往右滑出 translateX(64px) scale(.98)（.65s cubic-bezier(.5,0,.2,1)）；.lg-brand 下沉淡出 translateY(8px)（.5s）；welcome／title／subtitle／ver 淡出。
  2. 星球第一步 — 滑向畫面中心並微放大。placePlanet(中心, 0.44×高, scale 1.12, 'transform .8s cubic-bezier(.45,0,.25,1)')。
  3. 800ms 後 — 加上 body.state-app，星球收縮並停泊進 TopBar logo 槽。placeDock('transform .95s cubic-bezier(.6,0,.2,1)')，停泊縮放 = logo寬 / 440 × 2。
  4. 同時：#app-layer opacity 0→1（.6s）；#login-layer 淡出（.5s）並於 620ms 後 display:none。
  5. 1500ms — forceShow() 保險。就算分頁被切到背景動畫沒跑完，也強制把內容設為可見（避免卡在 opacity:0）。

關鍵不可省：星球不是「登入畫面一顆、TopBar 另一顆」。它是同一個 DOM 元件在兩個位置之間飛 —— 詳見下方「星球完整拆解」。少了這個架構，這段主轉場根本做不出來。

B

登出 反向轉場

觸發：使用者選單「登出」→ window.nxLogout()。是 A 的鏡像。

反向時間軸 JS 驅動

system-engine.js · logout()
  1. 儀表板整體淡出：#app-layer opacity→0（.55s）。移除 state-app、加回 state-leaving，並還原 #login-layer 為 display:flex（此時表單仍被 state-leaving 壓著隱藏）。
  2. 星球從 TopBar 脫離 → 飛回中心並微放大（.8s cubic-bezier(.45,0,.25,1)）。
  3. 星球滑回登入大圖位置（.95s cubic-bezier(.6,0,.2,1)）；移除 state-leaving → 表單／品牌淡入；清掉殘留 inline style；重置 submit 按鈕。
C

視圖切換 · 散開／合攏

首頁 ↔ 核心主檔 ↔ 進貨 之間切換時的轉場。觸發：nxNavigate() → showView()。TopBar 全程不動，只有主內容區的「框框」動。

散開 → 合攏 JS 驅動

system-integrate.js · showView() / setScatter()
  1. 舊視圖散開：每個框（.card / .nx-frame / .nx-page-head）以視圖中心為原點，沿自身方向向外推 120px 並 scale(.9) 淡出。transform .44s cubic-bezier(.34,.05,.2,1)，opacity .4s。
  2. 300ms 後切換：舊視圖 hidden、render() 填入新內容、新視圖先設為「已散開」狀態（instant），強制 reflow（offsetWidth），再合攏回原位淡入。
  3. 560ms 後 finalize() 清掉 inline transform／opacity。

易漏點：散開方向是逐框計算的徑向向量（每張卡朝離開中心的方向飛），不是整塊一起淡入淡出。少了這個就失去「爆開／聚攏」的手感。

星球(Planet) 完整拆解

這是落差最大的部分。星球不是一張 PNG、也不是單一 SVG icon，而是一個多層 DOM＋inline SVG 組裝、由 requestAnimationFrame 物理驅動、會在兩個位置間實際飛行的元件。要長得一樣，下面每一層與每個子動畫都得在。

核心架構：一顆星球，兩個位置 最關鍵

DOM: #planet-stage > #planetWrap（固定定位，z-index 60）· system-engine.js: placePlanet/placeLogin/placeDock
  • 只有一顆星球。 #planetWrap 是 position:fixed、自然尺寸 440×440（常數 BASE=440）的單一元件，永遠浮在最上層。
  • 登入大圖與 TopBar 小 logo 是同一顆。 JS 用 getBoundingClientRect() 量出登入區占位 #lg-slot 與 TopBar 的 .logo 兩個矩形，再用 transform: translate()+scale() 把同一顆星球擺到對應位置／縮放。登入時 placeLogin()、進系統後 placeDock()。
  • TopBar 裡那個 .logo SVG 是隱形佔位。 CSS .logo{opacity:0} —— 它只負責「卡」出版面空間，讓飛過來的真星球有地方停泊。真正看到的金色星球永遠是 #planetWrap。
  • resize 會重新定位。 視窗縮放時依當前狀態重算 placeLogin/placeDock，星球不會跑位。

若把它做成兩個獨立元素（登入一個大星球、TopBar 一個小 logo）—— 飛行／停泊轉場（A、B 段）就完全無法成立，這通常就是「星球差很多」的根因。

能量漣漪是手刻生成的：以球心為原點鋪一張六邊網格，每個 cell 的 animation-delay 正比於離心距離，視覺上就是一圈圈能量往外推。這一段很容易被當成「裝飾」整段砍掉。

三顆守護衛星（只在登入時出現）rAF 物理

system-engine.js · sats[] / updateSats()
  • 橢圓軌道。 三顆各有自己的起始角 a、角速度 sp（含正負＝順逆時針）、半徑 rx .66 / ry .30、與不同傾角 tilt（18° / 78° / 132°），所以軌道面交錯成 3D 感。
  • 深度感。 依 sin(角度) 算 depth → 動態調整 scale（0.8–1.12）、opacity（.55–1）、z-index（衛星會繞到球前 / 球後）。
  • 滑鼠互動 (guarding)。 游標靠近星球（距離 < 0.62×球寬）時，三顆衛星會聚集到游標那一側、放大到 1.16、加速跟手（lerp k 0.085→0.16）。
  • 只在登入態存在。 appState !== 'login' 時 opacity 設 0 —— 停泊進 TopBar 後衛星就收起來。

星空背景 Canvas（星球的舞台）Canvas rAF

system-engine.js · #stars canvas · frame()
  • 三層視差星空（depth 5 / 14 / 30，共 300 + 140 + 42 顆），各自 twinkle 閃爍、緩慢漂移，並隨滑鼠視差位移（最遠層最敏感）。最亮層帶 glow。
  • 18 顆發光微粒（青／藍／金三色）緩緩上升，globalCompositeOperation='lighter' 疊加發光。
  • 流星：每隔約 7–17 秒從左/右上方畫過，帶漸層拖尾。
  • 淺色主題會切換成不同的極光式渲染（柔光 + 微粒）。
★

為什麼你的星球會「差很多」

對照常見的重做結果與正確架構，落差幾乎都落在這幾點：

常見錯誤重做

  • 做成一張靜態 PNG / 單一 SVG icon → 沒金屬漸層層次、沒呼吸、沒漣漪，看起來扁平
  • 登入星球與 TopBar logo 做成兩個獨立元素 → 沒有飛行＋停泊轉場
  • 漏掉 buildHexWave() 能量漣漪、環紋自轉 → 星球靜止「死掉」
  • 沒有 rAF 衛星，或衛星只是固定繞圈、無傾角／無滑鼠互動
  • 漏掉 #stars 星空 canvas → 星球失去舞台、孤立懸空
  • 用近似色硬填，沒照 metalG / coreG 的漸層停點 → 顏色與質感不對

正確架構（照這個給指令）

  • 一顆 #planetWrap（440px、fixed、z-60），多層 DOM + inline SVG 組裝
  • JS 量 #lg-slot / .logo 兩矩形，用 transform 在兩處間飛行＋縮放；TopBar .logo 設 opacity:0 當佔位
  • 常駐動畫全到：breathe 5.6s／breatheCore 3.8s／環紋 140s／hexwave 6.8s(距離延遲)
  • 三顆衛星 rAF：各自角速度＋傾角(18/78/132°)＋深度 scale/opacity/z＋滑鼠 guarding，僅登入態
  • 保留 #stars 三層視差星空 + 發光微粒 + 流星
  • 顏色一律照 SVG 漸層停點，不自創色

給 Claude Code 的一句話總結：「星球是單一多層 DOM+SVG 元件，用 JS transform 在登入大圖位置與 TopBar logo 佔位之間飛行；本體含 breathe/breatheCore/旋轉環紋/距離延遲的 hexwave 漣漪四組常駐動畫，外加三顆 rAF 橢圓軌道（含傾角與滑鼠互動）衛星，背景是三層視差星空 canvas。請逐項實作，勿簡化成靜態圖。」
