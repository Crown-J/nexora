# NEXORA GRID v3.0.0 介面架構

## 0. 這份文件是什麼

v3.0.0 是**介面的全新設計**，不是既有畫面的微調。本文是介面層的最高依據，
所有頁面、元件、快捷鍵的設計爭議都以本文為判準。

- 上位依據：`docs/專案/規格書/核心/NEXORA-策略骨架.md`
- 舊介面資產（太空風 / 頂部選單列 workbench）**封存不刪**，但不再是設計基準

---

## 1. 設計約束（為什麼是這樣設計）

這幾條是所有設計決定的源頭，改設計前先確認沒有違反：

| 約束 | 來源 | 影響 |
|---|---|---|
| **使用者年紀偏大、3C 學習慢** | 通路業現場真相 | 字要大、位置永遠固定、不要動畫、不要藏起來的操作 |
| **熟手只記快捷鍵，不看選單** | 恆迎用偉盟 30 年的實證 | 選單是備援不是導覽，不該常駐佔畫面 |
| **ERP 表格橫向寬、縱向短** | 單身十幾欄 | 水平像素比垂直像素值錢，不做左側常駐選單 |
| **雙螢幕，一邊系統一邊 LINE／PARTSLINK** | 業務日常 | 切走再切回要能立刻定位、表單狀態不能掉、照 1366 寬設計 |
| **核心引擎行業無關，汽配是可抽換的皮** | 策略骨架 | 九宮格第二層不得出現汽配專屬功能，汽配的東西放第三層或套件 |

## 2. 畫面骨架

```
┌──────────────────────────────────────────────────┐
│ ☰ │ 🏠工作檯 │                                   │
├──────────────────────────────────────────────────┤
│                                                  │
│                     工作區                        │
│                                                  │
└──────────────────────────────────────────────────┘
```

**常駐畫面上的只剩一條，而且只有兩顆按鈕**：☰ 開九宮格 · 🏠 回工作檯。

⛔ 左邊那兩顆刻意留著、⛔ 不再減：☰ 是滑鼠使用者唯一的入口，
🏠 是一鍵回家。§6 明訂「滑過才出現的按鈕一律要有常駐替代」，全部藏起來會違規。

⛔ **沒有常駐選單列。** 這是 v3.0.0 跟 v2.x 最大的差異。

情境工具列（頁面自帶的操作列）沿用既有的插槽做法：有就顯示、沒有自動收合。

### 2.1 ⛔ 一頁式呈現，不用彈跳視窗

**所有功能都開在分頁裡，內容在頁面上直接流動。⛔ 不做蓋在畫面上的彈跳視窗。**

多步驟流程（例如開單精靈）在頁面上依序走完，不是彈窗裡切步驟。

理由：

| 問題 | 彈窗 | 一頁式 |
|---|---|---|
| 層次感 | **長輩搞不清楚自己在第幾層**，Esc 一按不知道關掉什麼 | 永遠只有一層 |
| 空間 | 被邊框和遮罩吃掉 | 吃滿工作區 |
| 疊加 | 彈窗開彈窗，焦點與返回邏輯複雜 | 不會發生 |
| 手機 | 手機沒有彈窗的概念 | 桌機手機同一套 |

**「不離開當前情境」由分頁接手** —— 查貨開一個分頁、報價開另一個，切回去內容還在。
這是分頁工作區存在的理由。

例外（僅此三種可用浮層）：
1. 確認對話（刪除／作廢／離開未存資料）—— 單一問句、兩個按鈕
2. 挑選器（選客戶、選料號）—— 選完即關、不承載流程
3. 系統級提示（Toast）

⚠️ 既有的 `FocusLockedDialog` 浮層工作站範式在 v3.0.0 **不再延用**，改為分頁承載。

## 3. 三個入口

| 入口 | 觸發 | 給誰 | 內容 |
|---|---|---|---|
| **工作檯** | 登入落點 · 🏠 分頁 | 所有人 | 今天要做的事，不用找 |
| **九宮格** | `F2` | 所有導覽 | 角色 → 功能 → 子功能 |

⭐ **Dock 與 F2 合併為單一入口**（執行長 2026-08-01 拍板）。原本分兩個是因為
「F2 只顯示我的角色、Dock 顯示全部」，但兩者結構完全相同，合併後使用者少學一套。

**合併的做法：第一層永遠顯示九個角色的固定位置，沒權限的格子變灰、不可進入。**

- ⛔ 不因為「這個人只有兩個角色」就把九格重排成兩格 —— 位置固定是肌肉記憶的前提
- 灰掉比消失好：使用者看得到「這裡有東西，我沒權限」，知道要去找誰開
- 這是恆迎 F2 圓盤驗證過的做法（格位固定、不可見的標為停用、不隨身分改變格位）

⚠️ **F2 舊的用途（即時工作檯，2026-07-14 拍板的五個站）由九宮格接管。**
舊的鍵位登記與站台設定全部重新設計，不受既有拍板約束（執行長 2026-08-01）。

### 3.1 F2 九宮格

**三層結構：**

```
第一層  角色層    ← 九個角色的固定位置，沒權限的變灰；只掛一個角色時自動跳過
第二層  功能層    ← 該角色的九格功能
第三層  子功能層  ← 該功能底下的細項（非每格都有）
```

⚠️ 取捨說明：「單一角色跳過第一層」讓多數人每天少按一下，代價是這個人日後被加上
第二個角色時動線會多一層。判斷是**多數人一輩子只有一個角色**，且加角色本來就是職務變動、
需要重新熟悉，所以省下的那一下更值得。

**按鍵：**

| 鍵 | 行為 |
|---|---|
| `1`–`9` | 選格 |
| `0` | **第一層＝回首頁（離開選單、回工作檯）；其餘層＝回上一層** |
| `Enter` | 確認游標所在的格 |
| `↑↓←→` | 移動游標（無游標時從正中央 `5` 起步） |
| `Esc` | 關閉整個選單 |

<!-- 2026-08-02 原文：`0` ＝ 回上一層（單一行為）。2026-08-03 執行長改為「回首頁＋回上一層」
     合一：一路退到底就是回家，只要記「退一步」一件事。歷史寫法保留於此註解（G.4）。 -->

**排列＝整個數字鍵盤（執行長 2026-08-03 拍板擴充）：**

```
Num  /   *   −      ← / ＝全域搜尋 · * ＝留白 · − ＝設定 · Num ＝不攔
 7   8   9   ＋     ← ＋ ＝任務／通知
 4   5   6
 1   2   3   ⏎      ← ⏎ ＝確認
 0（寬）     .      ← 0 ＝回首頁／上一層 · . ＝資訊
```

⭐ **原本只有 3×3，改成把整個數字鍵盤搬上螢幕。** 原因是常駐橫列右上角那三顆
（待辦／使用者／設定）要收起來讓畫面乾淨，而 `1`–`9` 已被九個角色佔滿且終身凍結（§5），
只能落在數字鍵盤剩下的實體鍵上。位置照實體鍵盤排，⛔ 不得為了美觀重排。

手指位置與螢幕位置一致，中間不需要轉換。**手機版用手指點同樣的九個格子**，
位置完全一致 —— 學一次，桌機手機通用。

⚠️ 「資訊」（`.`）底下＝個人資訊／行事曆／佈告欄，走同一套九宮格結構
（等於第十個入口），⛔ 不另發明一種選單。**登出的唯一入口是 `F2` → `.` → `1`。**

### 3.2 Dock（`Alt+X`）

- 分組**照九個角色**，與 F2 同一套結構（一套結構走到底，不另立分類）
- **延遲 200 毫秒才浮出**：熟手連按看不到它，生手停頓才看得到
  （比照 Windows Alt 選單機制）
- 選完即消失，不常駐

⚠️ 待確認：Dock 與 F2 結構相同，差別僅在「只顯示我的角色」vs「顯示全部角色」。
是否合併為單一入口（F2 加一個「顯示全部」切換）待執行長裁示。

### 3.3 工作檯（＝首頁）

登入直接落在這裡，內容**依角色組成**。基本結構：

```
┌──────────────────────────────────────────────────┐
│  🔍 [ 料號／品名／車型                        ]   │ ← 游標預設就在這
├────────────────┬────────────────┬────────────────┤
│  今天要處理     │  要追蹤的       │  我的待辦       │
│                │                │                │
│ · 待出貨   12  │ · 報價過期  3  │ · 待簽核   2   │
│ · 待收款    5  │ · 久未下單  8  │ · 異常回報 1   │
│ · 缺貨卡住  3  │ · 生日回訪  2  │                │
└────────────────┴────────────────┴────────────────┘
```

三條規則：

1. **搜尋框永遠聚焦** —— 客戶隨時來詢價是常態，進系統就能直接打料號
2. **只有三塊、數字要大** —— 不放圖表，長輩看數字比看圓餅圖快
3. **點數字直接進清單** —— 不必先選日期或條件

### 3.4 待辦的兩個位置

| 位置 | 角色 |
|---|---|
| 頂欄 🔔 紅點 | 隨時看得到「有幾件」，不管在哪一頁 |
| 工作檯清單 | 展開看是哪幾件、點了直接處理 |

⛔ 簽核不放進九宮格。簽核是**狀態**不是功能，放選單裡的下場是沒人記得去點。

## 4. 九個角色

### 4.1 角色與部門對照

| 部門 | 角色 |
|---|---|
| 業務部 | 銷售作業 |
| 採購部 | 採購作業 |
| 產品部 | 產品作業 |
| 倉管部 | 倉庫作業 · 物流作業 |
| 財務部 | 出納作業 · 會計作業 |
| 管理部 | 行政作業 |
| 總經理／董事長 | 經營作業 |

**一人可掛多個角色**（小公司常態：外務＝業務兼送貨、會計兼出納）。
掛兩個以上時第一層出現角色選擇；只掛一個時第一層自動跳過。

⚠️ 財務部拆出納／會計是**內控要求，不是選項**：管錢的不管帳、管帳的不管錢。
同一人若同時收款又能改帳，可收錢不入帳再做假沖銷。這是 COSO 必考題。

## 5. ⛔ 號碼凍結鐵則

> **數字一旦配給某個功能，終身不改。**
>
> - 新功能只能撿沒用過的空號排在後面
> - 功能停用，號碼跟著留白，**不回收**
> - 顯示順序可以調整，但**號碼跟著功能走，不跟著位置走**

**會出事的情境**：有人覺得「調撥比盤點常用，往上移」，於是調撥從 5 變成 4 ——
那一天起全公司打錯單。恆迎的人記了偉盟三十年的字母，靠的就是它從沒變過。

**保護做法**：第二層只放「作業類別」（不會增加），不放單據（會增加）。
新增一種入庫方式只加第三層，九宮格一格都不用動。

## 6. 視覺規範

| 項目 | 規範 |
|---|---|
| 內文字級 | **15–16px**（一般 ERP 是 12–13px） |
| 表格 | 內文 15px、表頭 14px |
| 顏色 | 高對比，⛔ **不用灰字**（老花看灰字最吃力） |
| 欄位密度 | 預設 **6–8 欄**，其餘收進「顯示更多欄位」 |
| 版面基準 | **1366 寬**（不是 1920） |
| 位置一致性 | 同一顆按鈕在每一頁都在同一個地方，**一致性優先於美觀** |
| 動畫 | ⛔ 全部關掉或縮到最短。動畫對年輕人是回饋，對長輩是「畫面剛剛怎麼了？」 |
| 隱藏式設計 | ⛔ 滑過才出現的按鈕一律要有常駐替代；hover 飛出只能是輔助，主要操作走鍵盤 |

**字大與資訊密度衝突時的解法**：拿掉不需要的欄位，⛔ 不是把字縮小塞更多。

## 7. 鍵盤操作規範

### 7.1 四條硬規則

1. **每個能點的東西都要能用 Tab 到**，順序照視覺由左到右、由上到下
2. **表格**：`↑↓` 移動 · `Enter` 進編輯 · `Esc` 取消 · `Tab` 跳下一欄 ·
   最後一欄按 `Tab` 自動新增一列
3. **下拉選單一律可打字篩選**，⛔ 不得只能用滑鼠選
4. ⛔ **禁止「只有滑鼠才做得到」的操作** —— 拖拉排序、滑過才出現的按鈕，
   一律要有鍵盤替代

### 7.2 驗收條件

> **每一頁都要能拔掉滑鼠，從頭做到尾。**

這條不寫成驗收條件，開發時一定會漏。每頁交付前實測。

### 7.3 全域鍵位

**真正的全域鍵只有一個：**

| 鍵 | 功能 |
|---|---|
| `F2` | 九宮格選單（開／關） |
| `Esc` | 關閉九宮格／取消當前操作 |

**其餘都是「面板內鍵位」——九宮格開著才有效，面板一關全部還給頁面：**

| 鍵 | 功能 |
|---|---|
| `1`–`9` | 選格（角色／功能／子功能） |
| `0` | 第一層＝回首頁；其餘層＝回上一層 |
| `.` | 資訊（個人資訊／行事曆／佈告欄）⭐ 登出在這裡 |
| `+` | 任務／通知 |
| `-` | 設定 |
| `/` | 全域搜尋 |
| `Enter` | 確認游標所在的格 |
| `↑↓←→` | 移動游標 |
| `*` · `NumLock` | ⛔ 留白／不攔 |

## 8. 手機分工

### 8.1 原則

> **手機負責「捕捉」，電腦負責「整理」。**
> 在現場的工作上手機，在座位的工作上電腦。

⛔ 手機版**不是把電腦畫面縮小**，是為現場重新設計的流程。
例：倉管的撿貨是「掃碼 → 顯示位置與數量 → 確認 → 下一筆」，單手大按鈕，
不是把撿貨清單縮小塞進手機（戴手套點不到）。

### 8.2 各角色手機範圍

| 角色 | 手機 | 內容 |
|---|---|---|
| **倉庫作業** | ⭐ 主力 | 驗收 · 撿貨 · 包貨 · 出貨 · 查庫位 · 查數量 · 盤點 |
| **物流作業** | ⭐ 唯一 | 今日配送 · 送貨 · 簽收 · 代收貨款 · 異常回報 |
| **銷售作業** | 部分 | 查價查貨 · 現場報價 · 現場下單 · 查客戶欠款 · 拜訪紀錄 |
| **採購作業** | 部分 | 查零件成本 · 現場詢價紀錄 · 特價品判斷 · 缺貨簿 · 交期追蹤 |
| **產品作業** | 部分 | 速記新品 · 拍照 · 掃車身號碼 · 市調紀錄（**速記不是建檔**） |
| **出納作業** | 極少 | **只有外出收款**：查該收多少 · 開立收據 · 記錄收現／收票 |
| **經營作業** | 部分 | 儀表板 · 簽核 |
| **會計作業** | ⛔ 不給 | |
| **行政作業** | ⛔ 不給 | 公告與簽核除外 |

### 8.3 幾個關鍵設計點

- **業務現場下單要直接接到倉庫撿貨** —— 業務在保養廠按確認，倉庫立刻收到單子。
  這條鏈通了才是賣點，否則只是「手機能開單」
- **採購的特價品判斷要給決策資料**：現在庫存 · 過去三個月銷量 · 上次進價
- **產品部是速記不是建檔**：手機填三個欄位＋一張照片，存成「待建檔」，回公司補完
- **出納外出收款證明了控制顆粒度要到「功能」級**，不是整片財務區關掉

### 8.4 開發順序

| 順序 | 對象 | 理由 |
|---|---|---|
| 1 | 倉庫 ＋ 物流 | **不做手機等於不能用**，是必要不是加分 |
| 2 | 業務查價查貨 | 推銷時要講的賣點 |
| 3 | 經營儀表板＋簽核 | 決策者體驗，成交關鍵 |
| ⛔ | 會計 · 行政 · 產品建檔 | 沒人會在手機上做，做了也沒人用 |

## 9. 分階段建制

**總方針：外殼重寫，頁面漸進改造。** 既有頁面內容多數可用，全部重寫是浪費；
外殼是全新架構，值得重來一次。

| 階段 | 內容 | 動到 |
|---|---|---|
| **0** | 本規格書定稿 | `docs/專案/介面規格/` |
| **1** | 外殼骨架：新 Shell（拿掉選單列）· Dock · F2 九宮格三層 | `apps/nx-ui/` |
| **2** | 角色接線：九角色出廠預設 · 角色→功能可維護 · 選單依權限動態產生 | ⚠️ schema · seed |
| **3** | 工作檯：九個角色的首頁 · 待辦鈴鐺 · 搜尋框聚焦 | `apps/nx-ui/` ＋ API |
| **4** | 視覺與鍵盤：字級對比全站統一 · 表格鍵盤操作 · 逐頁拔滑鼠驗收 | 全站兩百多頁 |
| **5** | 手機版：倉庫物流 → 業務查詢 → 經營儀表板 | `apps/nx-ui/` |
| **6** | 安全控制：裝置綁定 · 功能級政策 · 匯出管制與浮水印 | 全端 |

**階段 4 是最大的一塊** —— 現有兩百多個頁面逐頁套規範，這才是真正的工程量。
