# NEXORA GRID v3.0.0 介面架構

## 0. 這份文件是什麼

v3.0.0 是**介面的全新設計**，不是既有畫面的微調。本文是介面層的最高依據，
所有頁面、元件、快捷鍵的設計爭議都以本文為判準。

- 上位依據：`docs/專案/規格書/核心/NEXORA-策略骨架.md`
- 舊介面資產（太空風 / 頂部選單列 workbench）**封存不刪**，但不再是設計基準

---

## 1. 設計約束（為什麼是這樣設計）

這幾條是所有設計決定的源頭，改設計前先確認沒有違反：

| 約束 | 來源 | 影響 |
|---|---|---|
| **使用者年紀偏大、3C 學習慢** | 通路業現場真相 | 字要大、位置永遠固定、不要動畫、不要藏起來的操作 |
| **熟手只記快捷鍵，不看選單** | 恆迎用偉盟 30 年的實證 | 選單是備援不是導覽，不該常駐佔畫面 |
| **ERP 表格橫向寬、縱向短** | 單身十幾欄 | 水平像素比垂直像素值錢，不做左側常駐選單 |
| **雙螢幕，一邊系統一邊 LINE／PARTSLINK** | 業務日常 | 切走再切回要能立刻定位、表單狀態不能掉、照 1366 寬設計 |
| **核心引擎行業無關，汽配是可抽換的皮** | 策略骨架 | 九宮格第二層不得出現汽配專屬功能，汽配的東西放第三層或套件 |

## 2. 畫面骨架

```
┌──────────────────────────────────────────────────┐
│ ☰ │ 🏠工作檯 │ 銷貨單#1234 × │ 零件查詢 × │ 🔔3 👤 ⚙ │
├──────────────────────────────────────────────────┤
│                                                  │
│                     工作區                        │
│                                                  │
└──────────────────────────────────────────────────┘
```

**常駐畫面上的只有兩條**：

1. 分頁列（最左為固定的「工作檯」分頁，關不掉）＋ 左端 ☰ Dock 鈕
2. 右上角：🔔 待辦紅點 · 👤 使用者 · ⚙ 設定

⛔ **沒有常駐選單列。** 這是 v3.0.0 跟 v2.x 最大的差異。

情境工具列（頁面自帶的操作列）沿用既有的插槽做法：有就顯示、沒有自動收合。

## 3. 三個入口

| 入口 | 觸發 | 給誰 | 內容 |
|---|---|---|---|
| **工作檯** | 登入落點 · 🏠 分頁 | 所有人 | 今天要做的事，不用找 |
| **F2 九宮格** | `F2` | 熟手日常 90% | 我的角色 → 功能 → 子功能 |
| **Dock** | `Alt+X` | 找冷門功能 | 全部九個角色的完整清單 |

### 3.1 F2 九宮格

**三層結構：**

```
第一層  角色層    ← 這個人擔任的職務；只有一個角色時自動跳過
第二層  功能層    ← 該角色的九格功能
第三層  子功能層  ← 該功能底下的細項（非每格都有）
```

**按鍵：**

| 鍵 | 行為 |
|---|---|
| `1`–`9` | 選格 |
| `0` | 回上一層 |
| `Esc` | 關閉整個選單 |

**排列＝數字鍵盤：**

```
7 8 9
4 5 6      ← 螢幕上的位置＝數字鍵盤上的位置
1 2 3
```

手指位置與螢幕位置一致，中間不需要轉換。**手機版用手指點同樣的九個格子**，
位置完全一致 —— 學一次，桌機手機通用。

### 3.2 Dock（`Alt+X`）

- 分組**照九個角色**，與 F2 同一套結構（一套結構走到底，不另立分類）
- **延遲 200 毫秒才浮出**：熟手連按看不到它，生手停頓才看得到
  （比照 Windows Alt 選單機制）
- 選完即消失，不常駐

⚠️ 待確認：Dock 與 F2 結構相同，差別僅在「只顯示我的角色」vs「顯示全部角色」。
是否合併為單一入口（F2 加一個「顯示全部」切換）待執行長裁示。

### 3.3 工作檯（＝首頁）

登入直接落在這裡，內容**依角色組成**。基本結構：

```
┌──────────────────────────────────────────────────┐
│  🔍 [ 料號／品名／車型                        ]   │ ← 游標預設就在這
├────────────────┬────────────────┬────────────────┤
│  今天要處理     │  要追蹤的       │  我的待辦       │
│                │                │                │
│ · 待出貨   12  │ · 報價過期  3  │ · 待簽核   2   │
│ · 待收款    5  │ · 久未下單  8  │ · 異常回報 1   │
│ · 缺貨卡住  3  │ · 生日回訪  2  │                │
└────────────────┴────────────────┴────────────────┘
```

三條規則：

1. **搜尋框永遠聚焦** —— 客戶隨時來詢價是常態，進系統就能直接打料號
2. **只有三塊、數字要大** —— 不放圖表，長輩看數字比看圓餅圖快
3. **點數字直接進清單** —— 不必先選日期或條件

### 3.4 待辦的兩個位置

| 位置 | 角色 |
|---|---|
| 頂欄 🔔 紅點 | 隨時看得到「有幾件」，不管在哪一頁 |
| 工作檯清單 | 展開看是哪幾件、點了直接處理 |

⛔ 簽核不放進九宮格。簽核是**狀態**不是功能，放選單裡的下場是沒人記得去點。

## 4. 九個角色

### 4.1 角色與部門對照

| 部門 | 角色 |
|---|---|
| 業務部 | 銷售作業 |
| 採購部 | 採購作業 |
| 產品部 | 產品作業 |
| 倉管部 | 倉庫作業 · 物流作業 |
| 財務部 | 出納作業 · 會計作業 |
| 管理部 | 行政作業 |
| 總經理／董事長 | 經營作業 |

**一人可掛多個角色**（小公司常態：外務＝業務兼送貨、會計兼出納）。
掛兩個以上時第一層出現角色選擇；只掛一個時第一層自動跳過。

⚠️ 財務部拆出納／會計是**內控要求，不是選項**：管錢的不管帳、管帳的不管錢。
同一人若同時收款又能改帳，可收錢不入帳再做假沖銷。這是 COSO 必考題。

## 5. ⛔ 號碼凍結鐵則

> **數字一旦配給某個功能，終身不改。**
>
> - 新功能只能撿沒用過的空號排在後面
> - 功能停用，號碼跟著留白，**不回收**
> - 顯示順序可以調整，但**號碼跟著功能走，不跟著位置走**

**會出事的情境**：有人覺得「調撥比盤點常用，往上移」，於是調撥從 5 變成 4 ——
那一天起全公司打錯單。恆迎的人記了偉盟三十年的字母，靠的就是它從沒變過。

**保護做法**：第二層只放「作業類別」（不會增加），不放單據（會增加）。
新增一種入庫方式只加第三層，九宮格一格都不用動。

## 6. 視覺規範

| 項目 | 規範 |
|---|---|
| 內文字級 | **15–16px**（一般 ERP 是 12–13px） |
| 表格 | 內文 15px、表頭 14px |
| 顏色 | 高對比，⛔ **不用灰字**（老花看灰字最吃力） |
| 欄位密度 | 預設 **6–8 欄**，其餘收進「顯示更多欄位」 |
| 版面基準 | **1366 寬**（不是 1920） |
| 位置一致性 | 同一顆按鈕在每一頁都在同一個地方，**一致性優先於美觀** |
| 動畫 | ⛔ 全部關掉或縮到最短。動畫對年輕人是回饋，對長輩是「畫面剛剛怎麼了？」 |
| 隱藏式設計 | ⛔ 滑過才出現的按鈕一律要有常駐替代；hover 飛出只能是輔助，主要操作走鍵盤 |

**字大與資訊密度衝突時的解法**：拿掉不需要的欄位，⛔ 不是把字縮小塞更多。

## 7. 鍵盤操作規範

### 7.1 四條硬規則

1. **每個能點的東西都要能用 Tab 到**，順序照視覺由左到右、由上到下
2. **表格**：`↑↓` 移動 · `Enter` 進編輯 · `Esc` 取消 · `Tab` 跳下一欄 ·
   最後一欄按 `Tab` 自動新增一列
3. **下拉選單一律可打字篩選**，⛔ 不得只能用滑鼠選
4. ⛔ **禁止「只有滑鼠才做得到」的操作** —— 拖拉排序、滑過才出現的按鈕，
   一律要有鍵盤替代

### 7.2 驗收條件

> **每一頁都要能拔掉滑鼠，從頭做到尾。**

這條不寫成驗收條件，開發時一定會漏。每頁交付前實測。

### 7.3 全域鍵位

| 鍵 | 功能 |
|---|---|
| `F1` | 查價查貨（最高頻，獨立鍵不佔九宮格） |
| `F2` | 九宮格選單 |
| `Alt+X` | Dock（全功能清單） |
| `Esc` | 關閉當前浮層 |
| `0` | 九宮格內回上一層 |

⚠️ 第二層以後**用數字不用字母**，三個理由：
1. 有順序感，長輩好記
2. **不會被中文輸入法吃掉** —— 偉盟是桌面程式不受影響，網頁在注音狀態下按字母會變組字
3. 好教 —— 電話裡講「Alt+U 再按 5」講得完

## 8. 手機分工

### 8.1 原則

> **手機負責「捕捉」，電腦負責「整理」。**
> 在現場的工作上手機，在座位的工作上電腦。

⛔ 手機版**不是把電腦畫面縮小**，是為現場重新設計的流程。
例：倉管的撿貨是「掃碼 → 顯示位置與數量 → 確認 → 下一筆」，單手大按鈕，
不是把撿貨清單縮小塞進手機（戴手套點不到）。

### 8.2 各角色手機範圍

| 角色 | 手機 | 內容 |
|---|---|---|
| **倉庫作業** | ⭐ 主力 | 驗收 · 撿貨 · 包貨 · 出貨 · 查庫位 · 查數量 · 盤點 |
| **物流作業** | ⭐ 唯一 | 今日配送 · 送貨 · 簽收 · 代收貨款 · 異常回報 |
| **銷售作業** | 部分 | 查價查貨 · 現場報價 · 現場下單 · 查客戶欠款 · 拜訪紀錄 |
| **採購作業** | 部分 | 查零件成本 · 現場詢價紀錄 · 特價品判斷 · 缺貨簿 · 交期追蹤 |
| **產品作業** | 部分 | 速記新品 · 拍照 · 掃車身號碼 · 市調紀錄（**速記不是建檔**） |
| **出納作業** | 極少 | **只有外出收款**：查該收多少 · 開立收據 · 記錄收現／收票 |
| **經營作業** | 部分 | 儀表板 · 簽核 |
| **會計作業** | ⛔ 不給 | |
| **行政作業** | ⛔ 不給 | 公告與簽核除外 |

### 8.3 幾個關鍵設計點

- **業務現場下單要直接接到倉庫撿貨** —— 業務在保養廠按確認，倉庫立刻收到單子。
  這條鏈通了才是賣點，否則只是「手機能開單」
- **採購的特價品判斷要給決策資料**：現在庫存 · 過去三個月銷量 · 上次進價
- **產品部是速記不是建檔**：手機填三個欄位＋一張照片，存成「待建檔」，回公司補完
- **出納外出收款證明了控制顆粒度要到「功能」級**，不是整片財務區關掉

### 8.4 開發順序

| 順序 | 對象 | 理由 |
|---|---|---|
| 1 | 倉庫 ＋ 物流 | **不做手機等於不能用**，是必要不是加分 |
| 2 | 業務查價查貨 | 推銷時要講的賣點 |
| 3 | 經營儀表板＋簽核 | 決策者體驗，成交關鍵 |
| ⛔ | 會計 · 行政 · 產品建檔 | 沒人會在手機上做，做了也沒人用 |

## 9. 分階段建制

**總方針：外殼重寫，頁面漸進改造。** 既有頁面內容多數可用，全部重寫是浪費；
外殼是全新架構，值得重來一次。

| 階段 | 內容 | 動到 |
|---|---|---|
| **0** | 本規格書定稿 | `docs/專案/介面規格/` |
