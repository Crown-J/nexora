需求規格 00 — 登入與首頁

檔案位置：docs/專案/規格書/核心/需求規格-00-登入與首頁.html　|　版本：v1.2　|　維護：CTO（Alex）　|　NX 碼：NX00（核心 / LITE）
說明：系統外殼層「該做成怎樣」的施工級需求——登入畫面、首頁儀表板，以及橫跨全頁面的 top bar 與全域導覽（小星球）。這些是全系統共通的「框」，內容不隨模組改變。各模組畫面細節見其需求規格。

NX00 是系統外殼：使用者一進系統就看到、且橫跨所有頁面、不隨模組改變的部分。涵蓋四塊——全域導覽（小星球）、top bar、登入畫面、首頁儀表板。標記說明：本次 此版實作；伏筆 預留位置、另立任務；唯讀 使用者僅瀏覽不可改。

每個畫面的寫法：固定兩段——「一、畫面欄位」說明這張畫面有哪些欄位（靜態）；「二、操作與結果」說明按了什麼、系統做什麼、出現什麼結果（動態）。

一、全域導覽（小星球）

全系統唯一的導覽元件，桌面與手機統一使用，不再有其他 dock、浮鈕或底欄。位於 top bar 最左側。提供「去任一模組／頁面」的單一入口。

一、畫面欄位（選單結構）

喚醒後為兩層結構，橫移切換層級。

層級內容
主選單八個固定項，順序：首頁 / 個人 / 主檔 / 採購 / 銷貨 / 庫存 / 財務 / 報表
子選單頂部一個「返回」，下方為該模組的子項目清單。「主檔」項較特殊，其子選單再分一層（見下方「主檔的三層結構」）

每一個主選單項二擇一：無子選單→ 直接進入該頁；有子選單→ 進入下一層（橫移動畫）。多數模組為兩層（主選單 → 子選單頁）。

主檔的三層結構：「主檔」項因主檔數量多，採三層導覽——
第一層 主選單「主檔」 → 第二層 六大分區 → 第三層 各分區的主檔頁。
六大分區為：組織架構 / 權限管理 / 據點倉庫 / 往來對象 / 產品與廠牌 / 字典主檔（與 NX01 核心主檔規格的分區一致）。點分區橫移進入第三層、列該分區的主檔；各分區主檔清單見 NX01。

動作結果

#項目性質本次
1深淺主題（淺／深／跟隨系統）個人可調本次
2雙重驗證（2FA 開／關）個人可調本次

定位：齒輪只放「個人環境偏好」與「系統資訊瀏覽」——只影響「我自己用起來的樣子」，不含任何會動到全公司的設定（稅率、單據編號規則、簽核流程等仍歸核心主檔與各模組，不進此選單，亦不對一般員工開放）。

通知按鈕

定位：待辦驅動——只推「該你動手做的事」，做完才消，不是訊息流。

動作結果
點鈴鐺展開通知列表，依來源分類、最新在上，每則顯示來源單據
點一則直接跳到該單據詳細頁
全部已讀清紅點
badge 規則：顯示「未處理」件數（非「未讀」）。已讀 ≠ 已處理——待簽核的單，點開看了不等於簽了，badge 須等真的處理完才消，避免漏簽。

觸發來源（四類原則，具體單據隨各模組規格定稿填入）：

類別說明是否進鈴
一、待我簽核／審批不處理會擋住流程（採購單待核、折讓待審…）是
二、已指派給我的作業系統派工（驗收／撿貨／盤點／案件指派…）是
三、與我相關的狀態變化我發起的被退件、被核准等回饋保留討論
四、系統預警庫存低、帳款逾期、效期將到等保留討論
通知 vs 任務清單分工：通知鈴＝即時「叮你一下」（剛發生、要注意）；首頁任務清單＝常駐「攤開待辦」（目前所有待我處理）。兩者來源可共用、職責不同。通知後端（事件來源、已讀狀態）另立任務。

三、登入畫面

系統唯一入口。使用者進入系統的第一個畫面，驗證身分後進入首頁。

一、畫面欄位

#欄位說明必填記住我
1公司帳號對應租戶代碼是記憶
2員工編號對應帳號是記憶
3密碼含顯示／隱藏切換是不記憶

其他畫面元素：「記住我」勾選框（記公司帳號＋員編，不記密碼）、「忘記密碼」連結、星球＋星空視覺背景、版本號 footer、展示模式提示條（demo 模式時顯示）。

二、操作與結果

登入

動作結果
填三欄送出（成功）進入系統。若為首次登入→ 強制導向改密頁、改完才進首頁；否則直接進首頁
送出（密碼錯）顯示錯誤，累計失敗次數
連續錯 5 次鎖定該帳號（以「公司帳號＋員編」為單位），提示「帳號已鎖定，請 5 分鐘後再試」
鎖定中再送出擋下，提示仍在鎖定
滿 5 分鐘自動解鎖（無管理者手動解）
帳號已停用擋下，提示「帳號已停用，請聯絡管理者」
已開 2FA 者（帳密正確）多一步輸入 TOTP 驗證碼，通過才進系統；未開 2FA 者無此步

記住我

動作結果
勾選後登入下次開啟登入頁自動帶入公司帳號＋員編，密碼仍須輸入

忘記密碼

情況結果
有留 email／手機可選擇收驗證碼 → 驗證 → 設新密碼
沒留顯示「請聯絡系統管理者重設」
重設成功新密碼即生效；下次登入視同首登 → 強制改密

改密碼（首登 / 管理者重設後）

項目內容
觸發時機① 首次登入　② 管理者重設密碼後
規則新密碼至少 6 碼
完成改畢才能進入系統

三、機制定義（資安政策）

機制政策
失敗鎖定連錯 5 次 → 鎖 5 分鐘 → 純自動解（無手動解鎖）
計數單位公司帳號 ＋ 員編
密碼強度至少 6 碼（寬鬆，貼合現場）
首登強制改密首次登入 + 管理者重設後皆觸發
忘記密碼雙軌：有留 email／手機者自助重設，未留者引導找管理者
雙重驗證 2FA個人自選開／關，技術用 TOTP 驗證器；在「設定齒輪 → 環境設定」開關
停用攔截已停用帳號禁止登入

四、首頁儀表板

登入後的落地頁。聚焦「我近期要處理的事」——不是模組樞紐（導覽靠小星球）、也不是個人檔案（那是個人儀表板，另立）。

一、畫面欄位

#區塊內容
1Top bar全域元件（每頁皆有，見第二節）
2行事曆可選取日期，與事件簿連動。呈現方式（七卡輪轉）見下方備註
3事件簿顯示「選取日期」的個人行程
4全體出勤顯示全體員工當下狀態（在勤總覽）
5任務清單顯示「跟我有關的未完成單據」

二、操作與結果

行事曆 ⇄ 事件簿（連動）

動作結果
點選某一天事件簿切換成顯示「那天」的個人行程（選哪天、事件簿就顯示哪天）
選擇年月份跳轉至指定年／月
今天一鍵回到今天

事件簿事件類型（四類）：排假、假日（用戶自訂、系統不預設國定假日）、會議、活動。實際顯示內容由實作調整。

行事曆呈現方式歸設計（Hana）：本檔規格僅定「行事曆放個人行程、可選日期、選定日於事件簿顯示明細」之功能與資料；視覺呈現（現為七卡輪轉：中間今天放大、滾輪輪轉、點日輪轉到中間、滿版不捲動）屬設計範疇，規格不框死，改版不需回頭改本檔。按鈕：年月選擇 ＋ 今天（不設左右箭頭，單日切換由輪轉取代）。
行事曆＝個人行程備忘：純記錄、無統計、無報表、無核准、無協作（不邀請、不公告全公司）。正式請假流程（計特休、核准）歸人資套件 NX06。

全體出勤

動作結果
顯示全體員工當下狀態：上班／外出／出差／休假／病假等，含「在勤 X／全部 Y」總計
LITE 只看狀態、不算數據：核心版僅呈現「誰在不在」的即時狀態總覽，不統計出勤工時、不計特休剩餘天數。工時統計、特休天數、考勤報表等深度人資功能歸加購 NX06 人資；員工排休本身歸事件簿（個人行程·排假）。
可見範圍：現狀全體員工可見彼此在勤狀態（中小企業常態）。伏筆未來可加「是否顯示全體出勤」開關，本次不做。

任務清單

動作結果
顯示「跟我有關」的未完成單據＝我發起的 ＋ 指派給我的（不顯示全公司單據）；可依類別篩（報價／銷貨／出貨／收款／採購…），顯示單號、對象、金額、到期／逾期
點一筆跳到該單據詳細頁
無待辦時顯示空狀態（不放摘要數據格）
首頁不含數據格：「自訂營運數據格（營業額／毛利等 BI 數據）」與「待辦計數摘要格」皆不放首頁——前者歸加購套件，後者已移除。任務清單空時直接顯示空狀態。

五、補做與連帶事項

本檔定案連帶產生的施工與跨模組事項，彙整於此供 Hank 依序處理。

類事項

清死碼HomeTopBar 公告區、中央槽兩段死分支移除；寫死的 mock 通知（固定「3」）移除
補 token原 MasterTopBar 硬編碼暗色 → 補 design token，使其跟隨深淺主題（系統支援淺色、非 dark-only）
補 API修改密碼、忘記密碼接真實後端（現為 mock／擺設按鈕）
跨模組 🔴NX01 核心主檔員工須新增 email、手機欄位（非必填）——忘記密碼自助重設依賴此
後端失敗鎖定計數、首登標記、驗證碼重設流程、2FA（TOTP）綁定與驗證
另立任務個人儀表板（遊戲化）、通知後端、環境設定其餘伏筆項（語言／字級密度／快捷鍵）
套件連帶首頁「全體出勤」之深度功能（工時統計／特休天數／考勤報表）歸NX06 人資套件——做 NX06 規格時納入「首頁出勤看板的深度版」
