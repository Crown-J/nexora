# 往來帳戶閘門 設計規格

## 一、背景與拍板紀錄（2026-07-21 執行長）

**問題**：交易資格綁在往來對象「類型」上（銷貨只給保養廠／同行、採購只給供應商），站點要逐一挑類型、每開放一種對象就要改一輪程式（同日已連修兩處：報價開同行、銷售開同行）。

**執行長拍板的新原則**：
1. **出貨（銷售）閘門＝對方有「收款帳戶」**——我開得了應收、收得到他付的錢，就能賣他，不論他是什麼類型。
2. **進貨（採購）閘門＝對方有「付款帳戶」**——我知道錢要付給誰，就能跟他買。
3. **散客統一走現金帳戶**：不記名、免開戶（系統內建現金戶語意）。
4. **銷售環節建新客戶＝同步開收款帳戶**，對方必須提供**名稱＋統編**。
5. **開單就擋**（不是出貨時才擋），擋下時給「一鍵開戶」不打斷動線。

## 二、核心概念

| 問題 | 舊制 | 新制 |
|---|---|---|
| 能不能跟他交易？ | 看類型（C/O 可賣、S 可買） | 看帳戶（R 收款帳戶=可賣、P 付款帳戶=可買） |
| 他是什麼？ | 類型兼閘門 | 類型只做分類：代號前綴、報表分群、頁面預設過濾 |
| 雙向往來（同行） | canTransferStock ＋散落例外 | R＋P 雙帳戶＝天然雙向（未來同行軋帳的載體） |

**類型不消失**：六分類（C 保養廠／O 同行／S 供應商／T 外包物流／B 銀行／V 一般廠商）與代號前綴制全部保留，僅卸下「交易閘門」職責。

**同行調貨（TI）＝買賣**（✅ 執行長 2026-07-21 訂正 v1.0）：調貨本質是向同行**買貨**，所以**必須有付款帳戶才能調貨**；O＋canTransferStock 身分判斷維持（標記哪些同行跟我們有調貨往來），帳戶是疊加的必要條件。倉庫間**調撥（ST）**是自家庫存移動、不進閘門。

## 三、資料設計（新表）

`nx01_partner_account`（一對象最多兩戶：R 收款＋P 付款）

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | VARCHAR(15) | NX01PACT+7 碼流水 |
| tenantId | FK | 多租戶 |
| partnerId | FK nx01_partner | 對象 |
| direction | VARCHAR(1) | R=收款帳戶（他付我）／P=**進貨**付款帳戶（我付他、採購域）／T=**調貨**付款帳戶（同行調貨、業務域、v1.3） |
| status | VARCHAR(1) | A=啟用／S=停用 |
| bankName / bankCode / bankAccountNo / accountHolder | VARCHAR | P 戶必填組（匯款對象）；R／T 戶不需要（T 戶金流走同行軋帳/現結、v1.3） |
| needsTaxIdBackfill | BOOLEAN | 遷移產生的舊戶、統編未補標記（見六） |
| openedAt / openedBy / 標準審計欄 | | |

- 唯一鍵：`(tenantId, partnerId, direction)` 各方向一戶。
- **統編不放帳戶表**：沿用 `nx01_partner.taxId`（開收款帳戶時強制必填、見五）。
- 發票抬頭、結帳日、付款條件等既有欄位留在 partner 主檔不搬（避免大遷移）；帳戶表只承載「開通狀態＋金流路徑」。
- **散客（L）不開戶**：現金交易、閘門直接放行（散客不記名、拍板 #3）。
- **現金客戶旗標**（v1.2）：`nx01_partner.isCashCustomer BOOLEAN DEFAULT false`——無統編的具名客戶標記後可銷售、不開 R 戶不掛應收。

## 四、閘門規則

| 單據 | 需求帳戶 | 現行類型閘門（將取代） |
|---|---|---|
| 報價 QT | R 收款 | C/O |
| 銷貨 SO | R 收款（L 散客免） | C/O/L |
| 銷退 SR | 同原銷貨（跟單、不重驗） | — |
| 進貨詢價 RFQ／採購 PO／進貨 RR | P 付款 | （現況鬆散、多數未驗） |
| 進退 PR／向廠商保固 | P 進貨付款 | S |
| 同行調貨 TI | **T 調貨付款**（買賣、v1.1 訂正＋v1.3 拆種）＋維持 O/canTransferStock 身分 | O+canTransferStock |
| 倉庫調撥 ST | 不進閘門（自家庫存移動） | — |

**貨源與成本隔離（v1.3、✅ 執行長 2026-07-21 指出）**：業務端所有站點只查 R／T 戶；`hasAccount=P` 查詢（＝供應商名單）綁採購權限、業務打不到。單一付款戶會讓業務經由調貨資格查詢反推貨源、故拆兩種。成本價欄位權限另由明細層權限控管（既有機制）。

- 時點：**開單（建立草稿→確認）即擋**、報錯訊息附「一鍵開戶」。
- 客戶等級（毛利率）掛載對象：由「類型 C/O」改「持有 R 帳戶者」。
- 銀行（B）不買不賣、不開交易帳戶（金流母檔另屬財務模組）。

## 五、開戶規則

1. **銷售環節新客戶**（站5 快速建檔／主檔新增／一鍵開戶）：建立對象時**同步開 R 收款帳戶**，**名稱＋統編必填**（拍板 #4）。
2. **採購環節新廠商**：開 P 進貨付款帳戶，銀行帳號組必填（採購/財務權限才可開）。
3. **調貨環節**（v1.3）：業務遇未開戶同行 → 一鍵開 **T 調貨付款帳戶**（輕量、免銀行資訊）；業務無權開 P 戶。
4. 一鍵開戶 dialog：帶入既有名稱、補統編（R）或銀行帳號（P）、確認即開，回原單續作。
5. ✅ 拍板（2026-07-21）：**無統編客戶＝標記「現金客戶」**（`nx01_partner.isCashCustomer`）。有名有姓可留往來紀錄、但不開收款帳戶、不掛應收、交易走現金；閘門放行條件因此為三擇一：持有 R 帳戶／散客 L／現金客戶標記。開戶精靈遇無統編 → 引導改標現金客戶。
6. ✅ 拍板（2026-07-21）：統編做台灣 8 碼格式＋檢查碼驗證，開戶表單留「外籍／特殊統編」勾選跳過檢核。

## 六、遷移計畫（一次 migration、上線日行為不變）

| 既有類型 | 自動開戶 | 說明 |
|---|---|---|
| C 保養廠 | R | 今天能賣的明天照賣 |
| O 同行 | R＋**T**（v1.3） | 雙向戶；同行若同時是正規進貨來源、由採購另開 P 戶 |
| S 供應商／V 一般廠商／T 外包物流 | P | 今天能買的明天照買；銀行帳號空值待補 |
| B 銀行 | 不開 | 不進交易 |
| L 散客 | 不開 | 現金戶語意 |

- 既有戶統編／銀行帳號空值：**照開＋`needsTaxIdBackfill` 標記**（祖父條款），主檔列表出「待補件」徽章；新開戶才強制必填。✅ 執行長 2026-07-21 確認。

## 八、分期實作（漸進、每步一 commit）

1. **Step 1 資料層**：新表＋migration＋既有戶自動開戶腳本（行為零變化、可先上）。
2. **Step 2 後端閘門**：7 處改帳戶判斷＋`hasAccount` 查詢參數＋友善錯誤碼（含「未開戶」專屬 code 供前端辨識）。
3. **Step 3 前端**：站點選擇器改 `hasAccount` 過濾、開單擋＋一鍵開戶 dialog、主檔對象頁加「帳戶」分區（兩張卡：收款／付款、開通/停用/銀行資訊）。
4. **Step 4 驗證**：迴歸腳本（開戶→開單通過／未開戶擋下／散客免戶／同行雙向／一鍵開戶動線）＋操作手冊更新。
