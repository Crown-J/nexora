本份是工程慣例的唯一真相——所有模組共用的命名、ID、單據編號、過帳、權限、錯誤碼等底層約定。各模組的功能需求見其《需求規格》；本份只管「全系統共通的工程規則」。內容由 Hank 對 schema/service/dashboard 逐項驗證。

1. 命名規範

1.1 三層命名範式（全表一致）

層格式範例
DB 表名nx{NN}_{snake_case}nx04_so、nx05_ar_ledger
Prisma modelNx{NN}{PascalCase}Nx04So、Nx05ArLedger
DB 欄位snake_casecreated_at、customer_id
Prisma 欄位camelCase via @mapcreatedAt @map("created_at")

1.2 業務代碼欄

主檔有人讀的 code 欄（VARCHAR、tenant 內唯一 @@unique([tenantId, code])），與系統 id（15 字）分開。

1.3 平台層特例

平台層表無 nx 前綴（如 platform_admin），但 ID generator 仍循同範式（gen_platform_admin_id()）。

2. 模組 NX 碼 + ID 規則

2.1 ID 格式總則

全表 id = VARCHAR(15)，由 DB function 自動產生。格式 NX{NN}{XXXX}{7碼流水}＝NX＋2 碼模組＋4 碼表代碼＋7 碼流水。例：NX01USER0000001、NX04PRMO0000001。

2.2 ID generator 機制

CREATE SEQUENCE seq_nx04_promotion_id START 1;
CREATE FUNCTION gen_nx04_promotion_id() RETURNS VARCHAR AS $$
  SELECT 'NX04PRMO' || LPAD(nextval('seq_nx04_promotion_id')::text, 7, '0');
$$ LANGUAGE sql;
-- Prisma: id String @id @default(dbgenerated("gen_nx04_promotion_id()")) @db.VarChar(15)

4. 通用資料慣例

4.1 必填四件套 + 多租戶

每張業務表（NX01~NX10）必有：

tenantId   @map("tenant_id")  VarChar(15)
createdAt  @default(now())    createdBy  VarChar(15)
updatedAt  @updatedAt         updatedBy  VarChar(15)

4.2 多租戶強制

每個 service query 必 where: { tenantId, … }（helper requireTenantId）；缺 tenantId → 400。跨租戶查詢僅 SYSADMIN / platform_admin 可。

4.3 軟刪除範式

類型範式例
主檔isActive: Boolean + setActive(false)，UI 標「停用」（非刪除）Nx01Part、Nx01Partner
業務單據voidedAt / voidedBy / voidReason（作廢、留歷史）Nx04Quote
出貨/銷貨cancelledAt / cancelledBy / cancelReasonNx04So
軟刪除絕對主義：沒有任何業務表允許硬 DELETE。所有「刪除」UI 動作後端皆為 setActive=false 或 cancelledAt/voidedAt 寫入。

4.4 建立後鎖定

code（業務代碼）、docNo（單據編號）、id、tenantId 建立後永不可改。

5. 過帳邏輯

5.1 @FUNCTION_CODE 規範

業務關鍵函式標 @FUNCTION_CODE NX{NN}-{ENT}-{LAYER}-{NNN}-F{NN}（約 340 處），供業務規格追溯。與錯誤碼 XX-NNN（對使用者）三層共存。

5.3 冪等鎖統一範式

每個自動建單 helper 先查 dup 再建：AR by (tenantId, soId)、AP by (tenantId, poId)、Allowance by SR:{docNo}、DN by sourceSoId。重觸發回傳既有 id。

5.4 期間鎖

月關帳 Nx05Closing.status='CLOSED' → 該月 NX02~NX06 寫入由 assertFinancePeriodMutable 守（27 處）；401 期 markFiled → 該期兩月全鎖、不可解。

⚠️ 特價售出未分流（補做候選）：特價 SO 流入正常 AR、未帶分流旗標——與《需求規格-03/04/05》同一待補項：應加 sourceTag 落實「特價不污染毛利報表」。

6. Seed / 系統內建

6.1 兩層 seed

層範圍環境
system/SYSTEM 租戶 + SYSADMIN + 9 plans + view/currency/country/warehouse_type所有環境
template/各模組共用 template（建租戶時套用）建立新 tenant
test/3 測試租戶（LITE/PLUS/PRO）development/test

6.2 系統內建主檔

9 plans（席次制 LITE 15/PLUS 50/PRO 100）、country（TW+ISO-2）、currency（TWD/USD/EUR/JPY/CNY）、warehouse_type（H總部/M主倉/W分倉/S衛星倉）、view 字典（配 Nx01RoleView）。

6.3 系統內建角色（bypass）

Role範圍bypass
SYSADMINNEXORA 跨租戶系統管理（伊諾瓦 IT）兩 Guard 全 bypass
OWNER客戶租戶內最高權限兩 Guard 全 bypass

SUPER_ROLES = {'SYSADMIN','OWNER'}（PermissionsGuard / RolesGuard）。這兩個角色不出現在職務下拉（本就全權限）。

6.4 預設密碼 + 負責人

DEFAULT_EMPLOYEE_PASSWORD = 'changeme'（shared/nx01/employee-defaults.ts）+ mustChangePassword=true 首登強制改。客戶開戶時系統自動建 1 個 OWNER user（同預設密碼）。

6.5 平台層 platform_admin

表 platform_admin（跨租戶、無 nx 前綴），供伊諾瓦 IT 開戶/客服/運維，走 PlatformAdminGuard + 獨立 JWT scope，與租戶 SYSADMIN 分開。

已退役：舊 INNOVA 內部租戶範式已於 2026-06-02 退役（isActive=false），營運身分遷至 platform_admin。

7. 錯誤碼體系

7.1 格式

對使用者的錯誤碼為 6 字 XX-NNN（正則 /^[A-Z]{2}-\d{3}$/），實作於 shared/errors/nexora-error.ts。

7.2 序號分區

001–099 一般 / 100–199 狀態 / 300–399 驗證 / 400–499 限流鎖定（後續軌）/ 500–999 系統。

7.3 模組縮寫（13 模組、Crown 拍板）

AU（認證，已落地 12 碼）、NW（網路，1 碼前端）；MS/PO/IN/SO/FN/DN/HR/RP/KM/GM/SY 為 NX01~10＋系統（schema 預留）。不可用：AR/PR/RR（已被 NX 模組業務代碼占用）。

7.4 既有錯誤碼（code-truth）

碼意義

AU-101 / 102公司停用 / 帳號停用

AU-401 / 402鎖定 / IP 限流（後續軌、未落地）

8. 路由慣例

8.1 後端 API（帶 NX、內部）

/nx01/…、/nx02/po/…、/nx04/so/…、/nx05/ar/…、/nx06/delivery/…——工程內部用、客戶看不到。

8.2 前端 dashboard（不露 NX）

URL 用業務中文意、絕不出現 nx 代碼：/dashboard/base/{users,partners,parts,warehouses}（主檔）、/purchase、/inventory、/sale/{qt,so,return,promotion,bundle}、/finance。

/dashboard/base/partners 統一入口（不分客戶/廠商，由 partnerType 控制）。partnerType：C 保養廠 / O 同行 / S 供應商 / T 外包物流 / B 銀行 / V 一般廠商 / L 散客。「同行」用代號 O + canTransferStock 旗標。

9. 設計紅線（產品鐵則）

#紅線
9.1三版「只」差人數上限（LITE 15 / PLUS 50 / PRO 100）。席次制＝唯一版本機制（席次數＝啟用員工帳號數）；超出 → SE-001 擋啟用、不擋停用。
9.2功能全模組化、不綁版本。絕不做「版本功能閘門」（舊 Plan Guard 已廢、不可復活）。所有模組＋套件任何版本皆可加購；「免費送哪些」是銷售包配、非技術閘門。
9.3客戶端介面不露技術代碼。URL 不出現 nx 代碼；主檔/單據用業務中文名。
9.4平台層 vs 租戶層嚴格隔離。platform_admin + PlatformAdminGuard + 獨立 JWT；租戶走 Nx01User + JwtAuthGuard + tenant-scoped JWT。絕不混用。
9.5多租戶嚴格隔離。每業務表必有 tenantId、每 query 必 filter；跨租戶僅 SYSADMIN/platform_admin。
9.6軟刪除絕對主義。任何刪除皆 setActive=false 或 voidedAt/cancelledAt；已過帳資料加期間鎖 + POSTED 雙重防護。
9.7工程紀律。改 schema/跨表/過帳前必 grep 確認現狀；migration 一律 additive（不刪欄不改型不重命名）+ 必備份；Railway production 0 動（dev 操作、prod 等明確指示）。
