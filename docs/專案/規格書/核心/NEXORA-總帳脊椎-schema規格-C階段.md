# NEXORA 總帳脊椎 schema 規格（C 階段）

> **一句話**：B 階段的總帳自己站得住，但**沒有東西流進去**。
> C 階段把進貨、庫存、退貨接上，補上期初開帳，
> 讓對帳表的「總帳存貨 ＝ 庫存餘額表」在恆迎 **2.32 億真實資料上收斂到 0**。

**版本** v1.0 ｜ **撰寫** Hank ｜ **日期** 2026-08-01 ｜ ✅ **C 階段結案**（C1~C9、GL 13 支測試全過）

## 0. 開工第一件事：推翻了這一軌原本的理由

B 階段 §14 把「接進貨與庫存」排第一，理由是「`C3` 那 2.32 億就是這一條的缺口」。

**開工前 grep 實測，發現這個理由是錯的：**

```
租戶 TW-100001（恆迎）
  庫存餘額表金額     231,959,972.65
  庫存流水筆數                    1   ← 就是一筆
  庫存流水淨額               -189.50
```

那 2.32 億是偉盟匯入時直接寫進餘額表的**快照**，背後**沒有任何營運事件**。
接再多過帳點也生不出那筆分錄——因為沒有單據可以觸發它。

⭐ **結論：`C3` 只能靠期初開帳收斂，不是靠接過帳點。**
→ 執行長拍板把期初開帳併進本軌當收尾（否則這一軌驗收不了，儀表永遠是紅的）。

📌 **這一段的方法論值得記住**：動工前先驗證「這一軌的理由本身成不成立」，
而不是照著上一份文件的結論做。理由錯了，做得再對也解決不了問題。

## 1. 四題拍板（2026-08-01 執行長）

| # | 題目 | 拍板 |
|---|---|---|
| 1 | 成本中心用「店」還是業務員的部門？ | ⭐ **用店**（B 階段 §14 待決第 1 題結案）|
| 2 | 進貨退出的應收，要不要跟客戶應收分開？ | **分開**，用 `1113 其他應收款` |
| 3 | 銷貨退回「退現金」記在哪？ | ⭐ **甲案**：新增 `2142 其他應付款`（連帶新增 `3103 期初承接權益`）|
| 4 | 現金流量表採直接法還是間接法？ | ⭐ **間接法**（B 階段 §14 待決第 2 題結案）|

### ⭐ 第 1 題不是偏好題，是前置阻塞

所有跟存貨有關的分錄行，存貨科目那一行**都要求填成本中心**。而：

- 倉庫 → 據點：有關聯、而且必填
- 據點 → 部門：**沒有這條關聯**
- 部門本身：恆迎的五個部門全是職能部門，沒有一個代表「店」

銷貨之所以繞得過去，是因為銷貨單有業務員。
但**進貨驗收、調撥、盤點、報廢單上根本沒有業務員，只有倉庫**。
→ 不補這條關聯，本軌第一張單就會卡在「需要成本中心，呼叫端未提供」。

### ⭐ 第 3 題的判準：一個數字只講一件事

`2141 預收貨款` 講的是「客戶先付的訂金」；「我們該退還沒退的錢」是另一件事。
混在一格平常沒事，等到有人問「這筆錢到底是什麼」才要拆——而那通常是最不方便拆的時候。

⛔ 也不可以記成沖減 `1111 應收帳款`：那會讓帳面顯示兩不相欠，
但真實方向**相反**（我們欠客戶），退款義務就此從報表上消失。

同一個判準套在期初：⛔ 不把 2.32 億塞進 `3201 累積盈餘`——
那個數字的意思是「過去營運賺了多少」，塞進去等於讓它說謊。

## 4. 🔴 沿途發現並修掉的兩個缺陷

### 4.1 16 條稅額分錄行會炸掉整張單（已修）

`postByRule` 的守門規則是「非條件性分錄行金額為 0 就報錯」。
但**稅額為 0 在本系統是合法狀態**——免稅商品、零稅率、免用統一發票的小規模對象。

而過帳是掛在營運交易裡跑的。所以只要有人開一張免稅的進貨單或銷貨單，
過帳丟出例外 → **整張單被一起 rollback，單就開不出來**。

⚠ 當時還沒引爆，是因為沒有任何租戶設了會計期間。**總帳一啟用，第一張免稅單就會踩到。**
🔴 這條在 B 階段的銷貨那邊也埋著，只是還沒有人踩。

**已把 16 條全部改成條件性**（migration `20260801030000`）。
⭐ 改成條件性不會掩蓋「呼叫端忘了傳稅額」——**借貸平衡的檢查還在**，真的忘了傳會因為不平被擋下來。
判準與 B 階段那 15 條結轉成本行相同：本質上就是條件性的，只是沒標。

### 4.2 短交時單據金額與實際入庫金額不一致（不修，改成擋下來）

- 進貨單的金額是用**訂購量**算的（`lineAmount = qty × unitCost`）
- 但庫存是按**實收量**入帳的（`effectiveQty = actualQty ?? qty`）

短交時兩者不一致。這對總帳是個死結：
存貨照單記則庫存對不起來、照庫存記則應付對不起來——**兩邊都會壞，怎麼記都不對**。

⭐ **處理方式：不記。** 金額對不起來的單直接 skip、回報理由，由對帳表列成「該修的單」。
帳只報告，不替營運端的資料矛盾圓場——把它做平給人看，等於把問題藏起來。

⚠ 短交了要不要自動調單價金額、還是走折讓，**是營運端的決定，不是總帳能拍的**。

## 5. ⛔ 明確不接的路（附理由，不是遺漏）

| 路 | 為什麼不接 |
|---|---|
| **國外進貨** | 進口費用已攤進存貨成本，但應付給廠商的只有貨款 → 借貸兜不起來。正解是拆兩張傳票（先歸集 `1122` 再分攤），但**進口費用目前沒有自己的單據、也不知道付給誰** |
| **其他入庫／其他出庫** | 66 個代號裡沒有對得上的，而且**單上沒有原因欄**（領用／樣品／送修的費用科目完全不同）→ 硬接等於讓系統自己猜科目 |
| **組合／分解** | ⭐ 依設計不產生分錄：借貸都是存貨、金額相等（比照資產移轉）|
| **走保固的進貨退出** | 系統不建應收（由保固索賠另外處理）→ 過帳自動 skip，不憑空多一筆 |

### 6.1 拆細與新增

| 代號 | 內容 | C 階段做了什麼 |
|---|---|---|
| `C1` | 總帳 `1111` ＝ **客戶**應收子帳 | 🔴 拆——原本混著廠商退款一起比 |
| `C1b` | 總帳 `1113` ＝ 廠商退款應收 | 🆕 |
| `C2` | 總帳 `2101` ＝ 應付子帳 | 提示會自己算出**「已確認未到貨」**的金額（時間差不是錯）|
| `C3` | 總帳 `1121` ＝ 庫存餘額表 | 提示改成指路：先看覆蓋清單、再看 `C3b` |
| `C3b` | 庫存餘額表 ＝ 庫存流水累計 | 🆕 **庫存子帳的自我一致性** |
| `D2` | 已過帳進貨單都有傳票 | 🆕（國外進貨依設計不接、已從應有張數扣掉）|
| `D3` | 已過帳進貨退出都有傳票 | 🆕（走保固的已扣掉）|

### 6.2 ⭐ 為什麼 `C3b` 非有不可

庫存餘額是「數量 × 平均單價」重算出來的，而**平均單價只存到小數第四位**；
庫存流水則是每一筆金額直接累加。兩者數學上等價，但**捨入不等價**。

→ 有了 `C3b`，`C3` 的差額才分得出是「有單沒過帳」（真問題）
還是「捨入累積／快照沒有流水撐腰」（可解釋）。

🔴 **若 `C3b` 有差額，`C3` 就不可能剛好是 0**——先解釋 `C3b`，再解釋 `C3`。

### 6.3 ⭐ 覆蓋清單：「帳接到哪了」

12 條會動到庫存的路各一列，直說接上了沒有、本期金額多少。
**沒接上不是錯，是還沒做——但必須看得見**，否則存貨的差額永遠是沒人解釋得了的數字。

📌 清單上還有一個設計：**資料裡出現、但清單上沒有的來源會被標紅**——
那代表有人新增了會動庫存的路徑，卻沒有回頭決定它怎麼過帳。

### 6.4 恆迎真實資料的驗收快照

三種期初都做完之後：

```
A1✅ A2✅ B1✅ C1⚠  C1b✅ C2✅ C3✅ C3b⚠  C4✅ C5✅ D1✅ D2✅ D3✅
```

- ⭐⭐ **`C3` 存貨收斂到 0**——這一軌的驗收點，在 2.32 億真實資料上達成
- `C1` 的差額**剛好**等於「開帳後尚未接進總帳的收款」（實測驗的就是不多不少）
- `C3b` 的差額 ＝ 庫存餘額是匯入快照、背後沒有流水（開帳前的常態）

## 7. ⭐ 期初開帳範式（行為與其他過帳點**刻意相反**）

| | 營運鉤子（C2~C4）| 期初開帳（C6~C7）|
|---|---|---|
| 觸發 | 掛在營運交易裡，單據過帳時自動跑 | **人明確按下去**的一次性動作 |
| 出問題 | **skip ＋ 回報理由**，⛔ 絕不擋營運流程 | **大聲報錯**，把缺什麼講清楚 |
| 為什麼 | 帳還沒設好不該擋住生意 | 開帳悄悄跳過一半才是災難，而且**過帳後不可逆** |

### 金額算法（存貨／應收／應付通用）

> **開帳日當天的餘額 ＝ 現在的餘額 −（開帳日之後發生的異動）**

⭐ 這個式子對任何開帳日都成立：設在今天就等於現在的餘額；
設在過去就會把之後的異動扣回去——**而那些異動自己會有各自的傳票，不能重複算一次**。

### 傳票的顆粒度

| 開帳 | 一張傳票對應 | 為什麼 |
|---|---|---|
| 存貨 | 每個**成本中心** | 哪一家店帶進來多少貨，帳上要分得開 |
| 應收／應付 | 每個**往來對象** | 應收應付本來就是掛在對象身上的——壓成一張總數，開帳第一天就失去「誰欠誰多少」，而那正是要記帳的原因 |

### 四道守門（實測都驗過）

沒有開帳中的會計期間 ／ 倉庫的據點沒設成本中心（**會點名是哪幾個倉**）／
算出負數（開帳日設太早）／ 重複開帳。

## 8. ⭐ 間接法現金流量表的算法

### 骨架只有一句話

> **借貸恆等 ⟹ 現金的變動 ＝ 所有非現金科目變動的反號。**

把非現金科目按 `cash_flow_type` 分成三堆，三堆合計**必然**等於現金淨變動。
這不是湊出來的，是複式簿記本來就保證的。

📌 帶來一個很有用的性質：**核對不符只有一種可能——有科目的分類標錯或漏標。**

### 報表結構

```
營業活動
  本期損益
  減：屬投資／籌資的損益項目（利息費用、處分資產損益）
  加：非現金項目（累計折舊）
  加：營運資產負債變動
投資活動 / 籌資活動（各自逐科目列出）
⭐ 期初開帳（獨立一段、⛔ 不進三大活動）
期初現金 ＋ 淨變動 ＝ 期末現金
```

### 🔴 期初開帳為什麼必須獨立成一段

承接進來的餘額**不是本期的交易**。
不切出來的話，2.32 億的期初存貨會被算成「營業活動現金流出 2.32 億」——整張表徹底失真。

⭐ 實測第 ⑤ 項驗的就是這件事：**開帳 2.32 億之後，營業活動仍然是 400，沒有被污染。**

### 報表自己帶著它的限制（`notes`）

- ⚠ **折舊尚未接進總帳** → 在固定資產那一軌接上之前，營業活動的現金流量會偏高
- ⚠ **必須在年度結帳之前跑** → 結帳會把損益結轉進權益、本期損益變成 0

## 9. 🔴 收付款為什麼接不上（缺口在營運端，不在總帳）

盤點六個交易代號（收現／收票／票據到期收／付款／開票／票據到期付）後的結論：

1. **收付款單沒有記「錢從哪個帳戶進出」**（`nx05_paylog` 無銀行帳戶欄位），
   但過帳規則要求要有——因為**全系統銀行存款只有一個科目**、每個帳戶是主檔的一列。
   少了這個維度，帳上只會看到「銀行存款增加」，**看不出是哪一家銀行**。
   📌 科目備註記著恆迎的反面教材：24 個銀行子科目有 18 個三年沒動，「外匯活存（馬克）」躺了 24 年。
2. **銀行帳戶主檔是空的（0 筆）**——真實公司資料。
3. **支票那條路營運端還沒接**：票據 0 筆、收付款單從不寫票據關聯、
   程式裡**沒有任何一處依付款方式分流**（付款方式目前只是自由文字標籤）。
   → 硬接會長出應收／應付票據餘額但底下沒有票撐著，對帳表反而多兩項紅的。

⭐ **判斷：接上去也不會讓對帳表變綠**（每一筆都會被安全閘跳過），所以先擱著，

## 11. 工具與環境教訓（本軌新增）

- ⚠ **`nx05_posting_rule_line` 沒有 `tenant_id` 欄位**（掛在 rule 上）——寫 migration 時踩到
- ⚠ Prisma 7 `migrate diff` 參數是 `--from-config-datasource` ＋ `--to-schema`（不是 `--to-schema-datamodel`）
- ⚠ Prisma 的 create 只要漏掉**任何一個必填欄位**，錯誤訊息會變成「缺少關聯物件」而不是「缺少那個欄位」——
  看到 `Argument 'tenant' is missing` 要先回頭找是不是漏了別的必填純量欄位
- ⚠ HTTP 整合測試會在庫存留下流水殘留（自清有還原餘額、流水留著），
  但兩邊自洽（`stockValue − ledgerNet` 恆定），不影響期初金額
- ⚠ 同倉庫測試「同成本中心不開傳票」時，要挑**據點底下只有一個倉**的倉，
  否則同據點的大倉會把效果蓋掉
