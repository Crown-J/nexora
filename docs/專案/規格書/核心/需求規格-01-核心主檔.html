需求規格 01 — 核心主檔

檔案位置：docs/專案/規格書/核心/需求規格-01-核心主檔.html　|　版本：v2.0　|　維護：CTO（Alex）
說明：核心主檔「該做成怎樣」的施工級需求——逐主檔列欄位、性質、規則、來源、關聯。操作步驟見《操作手冊-02 Ver 2.7》；工程慣例見《核心系統規格》。

核心主檔是所有單據的資料底座，進貨/庫存/銷貨/財務/報表全引用它。本模組含七大分區：帳號與權限、產品與料號、組織架構、交易對象、系統設定、內建主檔，外加所有主檔共通的通用需求。

通用需求（所有主檔共通）

無刪除、只停用：系統沒有實體刪除、只有「停用」。停用資料不消失、只是不再出現在日常清單與下拉，需要時可再「啟用」。權限矩陣對應欄位即名為「停用」（軟刪除）。停用方向永遠放行。
欄位性質定義（本文件用語）：
· 必填＝不填不能存　· 建立後不可改＝存檔後鎖定（多為代碼/主鍵類）　· 純顯示＝系統自動記錄、唯讀　· 進階＝列表預設隱藏、需要才展開　· 未標示＝選填。
  • 每個主檔提供單筆新增 / 編輯 / 停用 / 啟用。客戶端不提供批次匯入（大量資料轉移由 Innova 內部代建工具處理，沿用既有 importer 邏輯）。
  • 提供注音快搜：輸入注音聲母快速定位；查詢自動忽略空格、星號、點、大小寫差異。
  • 多數代碼類欄位自動轉大寫、建立後鎖定。
  • 客戶端介面/URL 只用業務中文名，不外露內部代碼或表名。
【說明】 本手冊每個主檔開頭都會標「選單位置」，照著點就能找到該畫面。
【重點】 NEXORA 沒有「刪除」、只有「停用」。停用的資料不會消失、只是不再出現在日常清單與下拉裡，需要時可再「啟用」。所以權限矩陣裡那一欄也叫「停用」不是「刪除」。

帳號與權限

這一區管理「人」與「能做什麼」：建立員工帳號、定義職務、設定每個職務能用哪些畫面。共五個主檔。

使用者基本資料 一般表格 LITE

選單位置 主檔 → 帳號與權限 → 使用者基本資料

建立與維護每位員工的資料、帳號與權限。畫面分四個分頁：基本資料、帳號權限、帳號安全、人力資源。

基本資料分頁
欄位性質規則／來源／說明
員工編號必填 / 建立後不可改格式 Y＋4 碼（例如 Y0001），新增時系統自動給號、可手動覆寫。這也是登入帳號。建立後鎖定。
姓名必填員工本名。
大頭貼選填員工大頭照，可開鏡頭拍或選檔上傳，顯示在員工列表與相關畫面，方便辨識。
Email選填電子郵件，供通知與聯絡。
電話選填聯絡電話。
性別選填下拉：男／女／其他。
生日選填出生日期，點欄位選日曆。
身分證字號選填供報稅、勞健保等人事作業參考。
國籍選填下拉（來源：國家主檔），預設台灣。
部門選填從員工的「主組」自動帶出（主組屬於哪個部門就是哪個部門），唯讀；沒有掛組的員工（少數行政人員）才可在此手動選部門。
戶籍地址選填結構化填寫：選縣市→選鄉鎮市區（自動帶郵遞區號）→填詳細地址（路巷弄號樓）。
通訊地址選填實際通訊地址，填法同戶籍地址，可與戶籍不同。
到職日選填到職日期，點欄位選日曆。供年資計算。
離職日期選填員工離職日期，點欄位選日曆。留空表示在職；填了即標示已離職（仍保留資料、不刪除）。
緊急聯絡人／緊急聯絡電話選填緊急狀況的聯絡對象與電話。
最高學歷選填例如 高中／專科／大學／碩士。
畢業學校選填畢業學校名稱。
兵役狀況選填例如 已服／未服／免役／替代役。
體檢日期選填最近一次健檢日期，點欄位選日曆。
體檢結果選填合格／不合格／複檢／未體檢。只記結果文字、不存報告檔。
舊系統員工編號進階對應舊系統的舊員工編號，方便資料轉移對照。列表預設不顯示。
帳號權限分頁
欄位性質規則／來源／說明
職務選填勾選一個或多個職務（可複選），員工因此取得對應權限。
隸屬組選填選擇員工所屬的組（可選一或多個，其中一個為主組）。主組決定員工的部門（例如主組是台北一組、屬銷售部，員工部門即銷售部）。可標記是否為組長。
是否為公司負責人選填開關。標記是否為公司負責人。負責人也占一席。
隸屬據點選填下拉（來源：據點／倉庫主檔），這名員工隸屬哪個據點。也可在「使用者據點設定」批次工具一次設定多人。
是否啟用選填開關。啟用後員工才能登入；啟用人數（含負責人）受席次上限管控，停用永遠放行。
【重點】 工具列下方一直顯示席次徽章，例如「席次 3 / 10 席（已啟用含負責人）」——綠數字是已用、灰數字是上限。要再啟用員工時若已達上限會擋下並提示。
帳號安全分頁
欄位性質規則／來源／說明
強制下次登入改密碼選填開關。打開後員工下次登入須先改密碼（例如重設密碼後）。
連續失敗登入次數建立後不可改系統自動記錄，純顯示。
鎖定到期時間建立後不可改帳號因多次登入失敗被鎖定時，顯示何時解除。純顯示。
最近登入時間建立後不可改最後一次成功登入的時間。純顯示。
【說明】 「人力資源分頁」屬人資套件（加購）範圍，提供 HR 員工編號、預設職務、工作組等進階人事欄位。基本的員工資料、帳號、權限在前三個分頁就能完成；人資套件的詳細操作見人資套件手冊。

職務基本資料 一般表格 LITE

選單位置 主檔 → 帳號與權限 → 職務基本資料

職務是一組畫面權限的集合（例如採購員、業務員、倉管、會計）。員工掛上職務就取得該職務的權限。

職務欄位
欄位性質規則／來源／說明
職務代碼必填 / 建立後不可改自動轉大寫（例如 SALES、FINANCE），建立後鎖定。
職務名稱必填員工看到的中文職務名。
說明進階備註用。
層級選填職務階層（例如 G1／G2／G3），供組織呈現與 KPI 參考。各版本皆可用。
隸屬部門選填下拉（來源：部門主檔），這個職務屬於哪個部門。
排序進階顯示順序，預設 0。
【重點】 三步驟才完整：建職務 → 設權限（職務權限設定）→ 員工掛職務。只建職務、沒設權限，員工掛上去也沒有任何畫面可用。

部門基本資料 一般表格 LITE

選單位置 主檔 → 帳號與權限 → 部門基本資料

部門是組織的最上層分類（例如銷售部、採購部、倉儲部）。建好部門後，「組」會掛在部門底下，員工再透過組歸屬到部門。員工主檔、職務主檔的部門下拉都來自這裡。

部門欄位
欄位性質規則／來源／說明
部門代碼必填 / 建立後不可改自動轉大寫，建立後鎖定。
部門名稱必填部門名稱（例如 銷售部）。
排序進階顯示順序。

組基本資料 一般表格 LITE

選單位置 主檔 → 帳號與權限 → 組基本資料

組是部門底下的單位（例如銷售部的「台北一組」）。組織層級是「部門 → 組 → 員工」：員工掛在組上，組屬於哪個部門、員工的部門就跟著是哪個。

組欄位
欄位性質規則／來源／說明
組代碼必填 / 建立後不可改自動轉大寫（例如 TPE1），建立後鎖定。
組名稱必填組名稱（例如 台北一組）。
隸屬部門必填下拉（來源：部門主檔），這個組屬於哪個部門。員工的部門由此決定。
上層組選填下拉（來源：組主檔本身）。要做更細的層級時，可把這個組掛在另一個組底下（支援子組）；一般兩層就夠、可留空。
排序進階顯示順序。
【重點】 員工是不是「組長」，在員工的帳號權限分頁、隸屬組那裡標記。組長之後可用在公告對象（對全體組長發公告）等場景。

使用者職務設定 group 批次 LITE

選單位置 主檔 → 帳號與權限 → 使用者職務設定

批次工具：以「職務」為單位，一次把多名員工指派到同一個職務（一般主檔是一人一筆，這裡是一個職務配多人）。畫面左右兩欄：左欄列職務、右欄列「該職務目前的成員」。

畫面區塊
欄位性質規則／來源／說明
左欄選填全部職務清單，每列顯示職務名稱與代碼。上下鍵移動、右鍵進右欄。
右欄選填選定職務目前的成員清單，每列顯示員工姓名與帳號，附「× 撤銷」鈕；右上有筆數與「指派成員」鈕。
指派成員視窗選填搜尋帳號／姓名後多選加入；已是成員者不可重複選。
【說明】 這是批次工具、各版本皆可用。也可在「使用者基本資料」的帳號權限分頁逐一替員工勾選職務（一次一人）；批次工具則適合一次處理多人。

使用者據點設定 group 批次 LITE

選單位置 主檔 → 帳號與權限 → 使用者據點設定

與「使用者職務設定」同一種批次畫面，只是軸換成「倉庫／據點」：以倉庫為單位，一次指派多名員工隸屬該倉。

【說明】 批次工具、各版本皆可用。也可在「使用者基本資料」的隸屬據點欄位逐一設定（一次一人）。

職務權限設定 權限矩陣 LITE

選單位置 主檔 → 帳號與權限 → 職務權限設定

決定「某個職務能對某個畫面做哪些事」。畫面是一張大矩陣：上方選一個職務，縱軸是各畫面（依模組分群），橫軸是六種權限，用打勾設定。

六種權限（橫軸，由左到右）
欄位性質規則／來源／說明
瀏覽選填能不能看這個畫面。
新增選填能不能在這畫面新增資料。
修改選填能不能更正資料。
停用選填能不能停用資料（NEXORA 無實體刪除，對應軟刪除）。
匯出選填能不能把資料匯出。
核准選填能不能核准需要審核的單據。只對有審核流程的畫面有意義（例如採購單的核准／退件、保固申請、盤點），其餘畫面此格不適用。把採購單的「核准」只開放給主管職務，就能做到「採購員送審、主管才能核准」。
三層批次勾選
欄位性質規則／來源／說明
單格選填點方塊或按空白鍵，切換單一畫面的單一權限。
整列（整個畫面）選填點該畫面的「全選／清除」鈕（或鍵盤 A），一次設好這畫面的六種權限。
整模組選填點模組標題的「整模組全選／整模組清除」，一次設好整個模組所有畫面。
【注意】 權限矩陣採「暫存後一次存檔」：所有勾選都是本地累積，一定要按「存檔」才送出。若沒存就要離開頁面，系統會跳「有未存檔的權限變更，確定離開？」提醒。
【重點】 「系統管理員」與「公司負責人」這兩個職務不會出現在職務下拉裡——它們本來就擁有全部權限，不需要在這裡逐項勾選。

產品與料號

這一區管理零件本身與料號相關設定。核心是零件基本資料，搭配品牌、零件群組、通用件群組。

零件編碼設計（四層）— 目標設計與現況對照
層名稱對應現有欄位需求
① 內碼系統綁定錨點系統主鍵（不對外）系統自動產生、永不變。所有單據（進貨/銷貨/庫存）底層綁此，使對外主碼變動時歷史單據不斷。
② 編號對外主碼候選 A零件料號對外主要料號。買「汽車資料庫套件」時由編碼規則引擎自動產生統一格式；否則人工填。建立後鎖定。
③ 舊碼對外主碼候選 B舊料號客戶舊系統料號（如「06L 911 021 !」），自由填。
④ 副碼對照碼廠牌料號該廠牌對此料件的料號（原廠或副廠），供對照查詢。
主碼動態判定（現已實作）：新增零件時「零件料號」② 留空，系統自動帶「舊料號」③ 當主料號 → 即「② 有值用 ②、② 空退 ③」。
套件邊界：編碼規則引擎、品牌料號規則、車型適配、TecDoc 對照＝汽車資料庫套件（加購）；基本記錄能力（填料號/廠牌/品名/廠牌料號）留 LITE。
⚠️ 待 Hank 對 schema 驗證：(1) 是否存在獨立於「零件料號」的系統內碼 ① 作永久錨點，或「零件料號」本身即不可改錨點；(2) 若料號建立後鎖定，主碼由 ③ 切 ② 的情境是否存在、歷史單據如何處理（見待釐清）。

零件基本資料 一般表格 LITE

選單位置 主檔 → 產品與料號 → 零件基本資料

建立每顆零件的料號、品名、售價、庫存設定與照片。畫面分四個分頁：基本資料、銷貨、採購、庫存。

【注意】 權限屏障：「售價」只在銷貨分頁、「進貨成本」只在採購分頁，兩個分頁可開放給不同角色看（例如業務看得到售價、看不到進貨成本）。
基本資料分頁
欄位性質規則／來源／說明
零件料號必填 / 建立後不可改對外顯示的主要料號。新增可留空，系統自動帶「舊料號」當料號；建立後鎖定。
品名必填零件名稱。
正廠件選填開關：正廠件／副廠件。
廠牌料號選填該廠牌對這顆料件使用的料號（可能是原廠或副廠的料號），供對照查詢。
舊料號選填客戶舊系統的料號；新增時料號留空會帶這個值當主料號。
零件品牌選填下拉（來源：品牌主檔中標為零件品牌者）。品牌一律下拉、不手打，避免同品牌不同寫法。
零件族群選填下拉（來源：零件群組主檔），例如機油濾、煞車片。
零件類型選填下拉：專用件／通用件／組合件／拆解件。
產地選填下拉（來源：國家主檔）。這顆零件實際生產國，與品牌國別不同。
規格／備註選填規格說明或備註，多行文字。
單位必填計量單位（LITE 固定 pcs）。
正廠料號對應選填可建多筆「品牌＋正廠料號」對應，供副廠件對照原廠料號查詢。
改號關聯選填記錄料號改號前後的關聯。
照片管理選填進入照片管理，最多 5 張，見下方「零件照片」。
銷貨分頁
欄位性質規則／來源／說明
A／B／C／D 級售價選填四個客戶分級各自的售價，客戶下單依其分級自動帶價。
售價更新時間建立後不可改系統自動記錄售價最後更新時間。
售價更新人建立後不可改系統自動記錄更新人。
最後銷售時間建立後不可改系統自動記錄這顆零件最後一次賣出的時間，搭配最後進貨時間可抓出呆滯料。純顯示。
【重點】 編輯銷貨分頁時有「依成本重算」按鈕：按下去用「進貨成本 × 各分級加成率」自動算好四級售價，仍可手動微調。
採購分頁
欄位性質規則／來源／說明
進貨成本選填進貨成本，由採購填，是「依成本重算」售價的計算基準。
最後進貨時間建立後不可改系統自動記錄這顆零件最後一次進貨的時間，可一眼看出久未進貨的零件。純顯示。

內建主檔
欄位性質規則／來源／說明
倉別選填系統內建、唯讀的倉庫分類（描述庫存流向模式，例如良品倉、不良品倉、在途倉）。由「倉庫」的所屬倉別下拉間接使用，不開放新增或修改——因為每種倉別都綁系統的庫存流向邏輯。
畫面字典選填被「職務權限設定」當縱軸（各畫面清單）使用，系統內建、不開放單獨維護。

待釐清 / 待驗證

  • ① 零件主碼錨點：是否有獨立於「零件料號」的系統內碼作永久錨點，或料號本身即不可改錨點（影響改號與歷史單據處理）。
  • ② 主碼由舊碼切到編號：料號建立後鎖定，若要從 ③ 舊碼切到 ② 編號，歷史單據是否凍結當時編號、或重新對應。
  • ③ 沒套件時舊碼當主碼：是否需擋重複、保唯一性。
  • ④ 汽車資料庫套件加購後，LITE 既有零件編碼如何銜接到編碼規則引擎產生的統一格式。
  • ⑤ 員工編號格式：手冊載「系統自動給 Y＋4 碼、可手動覆寫、建立後鎖定、即登入帳號」；產品方向為「員編自由文字、租戶內唯一、不強制格式」。兩者以「自動給號為預設、可覆寫成任意唯一文字」對齊，請 Hank 確認現況一致。
