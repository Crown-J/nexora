需求規格 05 — 財務

檔案位置：docs/專案/規格書/核心/需求規格-05-財務.html　|　版本：v1.0　|　維護：CTO（Alex）　|　NX 碼：NX05（核心 / LITE）
說明：財務模組需求＝財務手冊（設計意圖）＋ Hank 程式碼盤點（commit 311165db）。狀態標記：✅已建 🟡部分 ❌未開放 ⚠️補做候選 🔵設計如此。操作見《操作手冊-06》。

財務模組管「錢的進出」：客戶欠多少（應收 AR）、欠廠商多少（應付 AP）、每筆收付款怎麼沖帳、折讓怎麼核可、月關帳與 401。核心觀念：應收應付不手動建立，一律由單據自動產生（AR 來自銷貨開票、AP 來自採購廠商確認與銷退退款）。

1. 應收 AR ✅已建

來源（自動產生、無新增鈕）：銷貨單開立發票 → 自動產生 AR；亦接收庫存「特價售出」產生之特價銷貨單 AR。

項目需求
工作台頂部三張即時統計卡：未收餘額、今日到期、逾期未收（紅）。搜尋＋狀態篩選（全部/未到期/逾期/部分收款/已收）。列表：單號、來源、客戶、應收日/到期日、未收餘額、狀態。
每筆四操作沖銷（開收款視窗、登記收款沖掉，可一次沖多張）／折讓（開銷貨折讓、待主管核可）／歷史（哪天用哪張票沖了多少）／催款（純內部記錄、不自動寄 email/簡訊）。
狀態自動判定未到期 → 逾期／部分收款 → 已收。依到期日與餘額自動判定；逾期門檻採租戶設定（creditOverdueDaysThreshold）。
列表「來源」標示 PR ＝廠商退費衍生的應收（如廠商超收退回），非採購需求單，勿混淆。

2. 應付 AP ✅已建（含採購應付）

來源需求狀態
⭐ 採購單廠商確認 → 應付採購單狀態轉「廠商確認（CONFIRMED）」時自動產生應付：apDate＝採購日、到期日＝採購日＋供應商付款條件（預設 NET30）、金額＝採購單總額；採購單改價會同步更新應付。冪等：同一採購單只產一筆。✅
驗收（RR）→ 應付進貨驗收亦可產生應付。✅
銷退退款客戶退貨要退的錢，由銷退單自動帶來（唯讀彙整，實際核可在折讓核可工作台）。✅

工作台：四張統計卡（未付總額、採購應付、銷退退款、逾期未付）；三分頁（全部、採購應付、銷退退款）。操作：沖銷、折讓、歷史。無手動新建應付（全由上游單據自動產生）。

⚠️ 更正手冊：財務手冊 v1.1 寫「採購應付＝建置中、目前不通」已過時——此鏈已完整串通。請 Hank 更新手冊狀態。

3. 收付款 / 票據 🟡部分

記錄每筆收款/付款（現金/匯款/支票/信用卡），同時沖掉一張或多張應收/應付。

3.1 一票沖多筆（核心）

一筆收/付款可同時沖多張帳、各自指定金額（例：客戶付 10,000 → 沖 A單5,000＋B單3,000＋C單2,000）。操作：新增收/付款 → 選對象（系統自動載入該對象所有未結清帳）→ 填日期/金額/付款方式 → 勾選要沖的帳填金額 → 「自動分配剩餘」→ 確認（沖銷總額須＝票額，容差 0.01）。送出後自動扣對應 AR/AP 餘額、更新狀態。

收付方向過濾（防掛錯帳）：收款只能選客戶/同行；付款只能選供應商/廠商/物流/銀行。選不到對象多半是方向不符。
⚠️ 補做候選（Hank 標為唯一明顯坑）：後端目前信任前端傳的沖帳明細、未校驗「沖帳總和＝票額」、未自動補餘到最後一筆。需補：後端加總和校驗，或 UI 自動算。高優先、工小。

4. 折讓核可 ✅已建

折讓＝少收或少付的補償；設計成「先開單、主管核可後才真正沖帳」，防隨意打折短收。

項目需求
兩方向銷貨折讓（少收客戶，如退貨/瑕疵補償）／進貨折讓（少付廠商，如來貨瑕疵抵下次採購）。
誰開誰核可業務/財務開立（草稿）；主管/負責人核可。誰能開、誰能核可由角色權限控制（不寫死），於職務權限設定配置。
核可跳雙重確認 → 自動建立沖銷紀錄、直接扣 AR/AP 餘額。核可不可復原（須反向開單修正）。
駁回須填駁回原因（永久保存供稽核）。
銷退自動折讓客戶退貨選「退錢」→ 系統自動建折讓草稿，與人工折讓一起進「待核可」，核可後一樣自動沖銷；可追溯回原應收/銷退單。
期間鎖修改/核可前一律檢查所屬期間是否已關帳（不可改已關帳期間）。

5. 月關帳與 401 ✅已建

5.1 月關帳

建立當月關帳單（開立）→ 確認單據齊全後「執行關帳」（已關帳，鎖住當月銷貨/進貨/收付款不能再改）→ 必要時「解除關帳」（須填原因永久保存；限「已關帳」且該期 401「未上報」）。每月只能一張。關帳檢查被 AR/AP/折讓/票據/收付款等 27 處寫入前一律調用。

5.2 401 雙月一期

項目需求
期碼雙月一期、一年六期：1–2月＝當年-01、3–4月＝-02、5–6月＝-03、7–8月＝-04、9–10月＝-05、11–12月＝-06。
彙整預覽輸入期碼預覽：銷售/進貨總額、銷項/進項淨額、應納稅額統計卡（銷項/進項拆 5% 稅計算）。
下載 TXT一次下載兩檔（進銷項資料檔＋主表檔，檔名＝公司統編），格式對齊財政部媒體申報要點。
標記上報限「已關帳」且同期兩月都關帳才允許。
⚠️ 標記上報不可逆：一旦標記，該期整整兩個月所有銷貨/進貨/收付款永久鎖死、無法再改、不能取消上報、解除關帳鈕消失。須實際送交國稅局並收回執後才標記；錯誤需聯繫 Innova。

6. 未開放 / 待拍

項目狀態說明
手動新建 AR/AP🔵設計如此帳一律由單據自動產生、不開放手動新建（折讓可人工開）。維持設計。
催款自動通知客戶🔵設計如此催款僅內部記錄、不寄 email/簡訊。維持設計。
401 特殊明細🟡待拍進口/零稅率/免稅/不得扣抵未細分（基礎版只算銷項減進項，由會計師調整）。⚠️ 待 CEO 確認是否要納入系統。
自有銀行帳戶管理⚠️補做候選目前僅票據上有銀行文字欄、無獨立銀行帳戶主檔/CRUD。低優先。

7. 跨模組接點

接點狀態說明
進貨：採購廠商確認 → 應付✅完整串通冪等（同採購單只一筆）、採購改價同步應付。對應《需求規格-02 進貨》。
庫存：特價售出 → 應收⚠️補做候選特價銷貨單會自動產 AR ✅；但 AR 帳未分流正常/特價（可由 so 旗標反查）。違反產品鐵則「特價與正常分流、不污染毛利報表」——應補 sourceTag 或讓 AR 列表帶特價旗標。對應《需求規格-03 庫存》《04 銷貨》。
銷貨：開票 → 應收 / 銷退退款 → 應付✅對應《需求規格-04 銷貨》。

待釐清 / 補做候選彙整

  • ⚠️ 收付款後端校驗：沖帳總和＝票額、自動補餘（高優先、工小）。
  • ⚠️ 特價售出 AR 分流：加 sourceTag='SPECIAL' 或 AR 列表帶特價旗標，落實毛利報表不被特價污染。
  • 🟡 401 特殊明細：是否納入進口/零稅率/免稅/不得扣抵（待 CEO 拍）。
  • ⚠️ 銀行帳戶主檔：是否建獨立主檔（低優先）。
