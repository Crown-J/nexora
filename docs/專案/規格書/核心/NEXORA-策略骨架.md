# NEXORA 策略骨架

> **一句話**：NEXORA 不是汽配 ERP，是**給「技術一流、經營二流」的台灣傳產老闆，外掛一套他缺的管理能力**——並讓他長出拿得出去的財務成績單，換到國際訂單、真正做大。

## 0. 這份文件怎麼用

這是 NEXORA 的**最高層戰略總綱**，位階在所有規格書之上。任何功能取捨、模組定義、實作邊界爭議，都用它當上位依據。判一個功能該不該做，用兩把尺量：

1. **這讓 NEXORA 更像「學經營的方式」嗎？**
2. **這屬「核心引擎」還是「行業皮」？**（見 §4）

## 1. 定位：NEXORA 是什麼

**本質＝給傳產老闆外掛經營能力。**

INNOVA 的使命是助台灣傳產數位轉型、增國際競爭力。市場真相是：**九成傳產老闆專業一流、經營二流**——這正是台灣中小企業多、卻永遠做不大的病根。NEXORA 補的就是這塊：老闆照著系統跑，他就在做一件自己不會、也沒錢請 CFO/COO 來做的事——**正規地經營一家公司**。

所以 NEXORA 賣的不是「記帳快」，是**管理紀律本身**。SOP、單據狀態機、過帳——換個角度看，全是「把專業經理人的管理習慣，寫成軟體的預設路徑」。

## 2. 品牌北極星

> **做到外面的人說：「想學經營，就得先學會用 NEXORA。」**

這是品類之王最高的一種——產品即方法論（Bloomberg 之於交易、SAP 之於大企業運營）。這個位置**只能賺到、不能喊到**：靠「第一家傳產被看得見地救活」，由市場替你喊出來。

它逼出一個與多數 ERP 相反的產品性格：**NEXORA 必須是「有主張、會教學」的產品，不是中性工具。** 中性工具讓不會經營的老闆照樣搞爛；老師有立場、會堅持對的做法、而且會解釋為什麼。

## 3. 可信架構 ＝ 國際通行證

老外/銀行下單前先看可稽核的財報。所以產品真正的產出不是「漂亮報表」，是**讓一家傳產變得 auditable（查得下去）＋ financeable（貸得到、開得了 L/C）**——這才是國際貿易的通貨。

- **內部骨架**：用**九大（交易）循環**當結構——每一塊錢、每一筆貨，都流經一個有名字的循環，最後匯進總帳。
- **對外接口**：輸出接 **IFRS/TIFRS** 格式的財報，內控設計要能過 **COSO** 檢視。
- 老外信的不是「循環」這個中文詞，是**可稽核的帳 ＋ 認得的報表格式 ＋ 拿得出的內控**。

⚠️ **產出成績單 ≠ 改善成績**。第一階段＝先蓋「可信可稽核的帳」（基礎建設）；「給建議的腦」（管理智慧層：毛利掉了為什麼、該怎麼辦）疊在其上、後做。別把兩件事混在同一階段。

## 4. 架構鐵律：核心 vs 行業皮

NEXORA 真正在蓋的，是**「通路業 ERP 的核心引擎」，汽配只是套在上面的第一層皮**。

| | 核心引擎（行業無關、可搬） | 行業皮（汽配專用、可抽換） |
|---|---|---|
| 內容 | 交易循環、單據狀態機、原子過帳進總帳、外鍵一致性、應收應付、庫存、總帳/財報、多租戶 | 料號/OEM 對照、車型引擎相容、TecDoc、VIN、維修 SOP |
| 性質 | 中性、可搬到五金/機車料/工業耗材/醫材通路 | 插件，**不得織進核心** |

**擴張 ＝ 換一層皮、留住核心。** 這也是產品鐵則「功能全模組化」的最深意義——在「定價不閘功能」之外，加上第二條軸：**領域模組化**（垂直功能是套在中性核心上的皮）。

⚠️ **「範圍砍掉」≠「架構焊死」**：生產/研發循環從 v1 砍掉，但核心引擎裡不能焊進「這世界沒有生產」的假設——要留接縫，將來擴張是「加模組」不是「重造引擎」。每一個焊進核心的「恆迎專用」假設，都是未來擴張的地雷。

## 5. 模組新定義原則（本份的可執行結論）

現有模組是**「以畫面(Top Bar)展開」**組織的（首頁/個人/主檔/進貨/銷貨/庫存/財務/報表）。新定義改成**兩軸**：

- **橫軸（通用骨架）＝ 循環當模組**：銷售循環、採購循環、庫存循環、應收、應付、**總帳/財報**、稅務……每個循環一個模組。跟著國際公認框架走，天生可信、天生可搬。
- **縱軸（行業皮）＝ 領域包插件**：汽配包、五金包、機車料包……插在對應循環模組上。

**模組 = 循環；行業 = 插件。** 這條線同時解掉「可信」（結構跟著公認框架）與「可擴」（換包即換行業）。

## 6. beachhead 與 roadmap 排序

- **灘頭堡**：汽配（恆迎／亞羅）。站穩再向外擴到其他傳產/通路業。**製造業＝後期**（比零售複雜太多）。恆迎不需生產/研發循環，先從核心通用循環做起——這幾個循環也正好是整個框架裡最國際標準的一段。
- **roadmap 硬事實**：命脈是可信財報 → **總帳/財報脊椎，優先於銷售 UI 精修**。銷售流程再精緻，帳接不進總帳、生不出財報，vision 就一步沒往前。資源要從「銷售 UI 無限精修」搬到「把 報價→銷貨→應收→總帳→財報 這條脊椎接通」。

## 7. 執行紀律（貫穿全案）

- **SOP-first**：先凍結主幹道 SOP，新需求用它當尺量——屬主幹道？屬逃生門？兩者皆非 → 進 backlog。
- **主幹道 vs 逃生門**：80% 日常單三步內結束；例外（同行調貨、現場填價、保固退貨）是「被系統記錄的逃生門」，不擋主幹道。**恆迎的例外消失在人腦，NEXORA 的例外要沉澱進資料庫。**
- **狀態即 SOP 寫進資料庫**：單據狀態機＋原子過帳＋外鍵一致性＝把「正確」寄託在**資料庫結構**上，不寄託在「程式每次都不出錯」上（偉盟的病＝沒狀態、沒外鍵、對帳靠重算，故常當機/算錯）。
- **對帳是「驗證」不是「計算」**：餘額在過帳時就一路維護好，對帳只確認「存的＝該有的」。
- **野心住架構、焦點住 roadmap**：架構要寬（核心保持通用可擴），路線要窄（先讓第一家汽配商看得見地贏）。別太早擴張。

## 8. 現況落差摘要（2026-07-21 grep 盤點）

- ⚠️ **總帳/財報脊椎是空的**：財務(Nx05)有會計科目表(Nx05AccountCode，I/E/A/L 分類)、應收/應付/存貨明細帳、收付款、票據、折讓、月關帳——但**無複式簿記總帳(日記帳/傳票/分錄)、無財務報表結構**。vision 最吃重的引擎尚未存在，是第一優先缺口。
- **模組現況＝畫面驅動**，非循環驅動；汽配資產（料號/車型/相容/注音字典/VIN/維修SOP）目前織進主檔(Nx01)與 Nx09，未隔離成可抽換行業包。
- 詳細「現況模組 → 循環模組」對照與缺口，見模組重定義分析（另件）。
