## 二、版本模型：只差人數

```
版本「只」差一個東西 = 人數上限
   LITE 15 人 / PLUS 50 人 / PRO 100 人（100以上走客製）
升級唯一硬理由 = 人數超上限

所有功能皆「模組」、任何版本都能自由加購、不綁版本
版本越高 → 免費送越多模組當誘因：
   LITE = 基本內含
   PLUS = 再免費送「多據點模組」+ 人數到 50
   PRO  = 再免費送「人資系統」等更多

升級哲學：不靠鎖功能逼升級，靠人數天花板。客戶成長(擴編)自然升級。
席次制 = 人數閘門的硬牆（一人一帳號、滿擋）。
```

## 六、零件編碼設計（汽車資料庫套件核心）

### 四層編碼（正常件）

```
1. 零件內碼  系統真正的「綁定錨點」、永不變 ← 給系統
2. 零件編號  系統自動產生的統一主碼 ← 給人看（進階、買套件才有值）
3. 零件舊碼  客戶舊系統碼、自由填（如恆迎 06L 911 021 !）← 給人看（基本）
4. 零件副碼  廠牌料號（如 442520）、TecDoc 對照 ← 給人查
```

### 主碼動態判定

```
2號有值 → 用 2號當主碼（統一乾淨）
2號為空 → 自動退回用 3號當主碼

三情境：
  ① 沒買套件 → 2號空 → 用 3號（自由填）
  ② 買套件但沒設編碼規則 → 2號空 → 仍用 3號
  ③ 買套件且設了編碼規則 → 2號有值 → 用 2號
```

### 內碼 = 定海神針

```
所有單據(進貨/銷貨/庫存)底層綁的都是「內碼」、不綁對外主碼。
→ 主碼在 2號↔3號切換時，歷史單據一條都不會斷、客戶改碼也找得到。
這是業界「穩定識別碼(對外可變、對內恆定)」的正確架構。
```

### 廠牌 = 獨立下拉字典（不再人工打字）

根治恆迎「同一 VW 有人打 VW-X、有人打 VW-瑕疵」的亂象。

### 瑕疵/中古件 = 不編碼、走異常處置機制

```
原因：每顆狀況都不同(缺角/少配件/沒包裝)、無法歸類、每顆當「個案」。
走系統現有「異常回報 → 處置」：
  現有三處置：重組 / 分解成新零件 / 報廢
  總經理要新增第四個：特價售出
⚠️ 特價售出會連動銷貨+財務：售價脫離客戶分級毛利率、瑕疵特價低於成本屬正常、
   系統需「認得是瑕疵特價、不跳毛利警示」、且與正常銷貨分流避免污染毛利報表。
「分解成新零件」拆出的好零件 → 回到正常件四層編碼體系。
```

### 汽車資料庫套件 vs LITE 基本的切分

```
✅ LITE 零件主檔基本內含：能記零件、自由填編號(像恆迎)、填廠牌品名料號
                        =「能用但不聰明」、尊重客戶粗暴記法習慣
✅ 汽車資料庫套件(加購)：系統自動產生統一編號、廠牌變下拉字典、
                        車型字典、引擎字典、VAG品牌軸、TecDoc對照、編碼規則引擎
                        =「想要乾淨統一/車型對照」才買
銷售故事：客戶先自由打用起(零負擔)、用久痛點浮現自然想加購(讓客戶體會痛再賣解藥)
```
