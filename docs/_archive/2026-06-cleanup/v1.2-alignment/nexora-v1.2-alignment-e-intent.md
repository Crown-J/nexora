## §1. 核心概念（v1.2 §11 範式）

```
同一份主檔資料、在不同地方看到不同欄位：

主檔中心（/master/*）   → 看完整全部分區
各模組頁面（銷貨/採購/財務）→ 只看「該模組角度」的欄位

例：客戶「和興汽車」這一筆——
  在「銷貨 → 客戶管理」  只看到：等級 / 信用 / 交貨方式（銷貨區）
  在「財務 → 帳戶管理」  只看到：帳單地址 / 收付款 / 銀行帳號（財務區）
  在「主檔中心 → 客戶」   看到：基本 + 銷貨 + 配送 + 財務 全部 4 區
```

⭐ 關鍵原則：各模組編輯時只動自己看到的欄位、存檔不覆蓋其他區欄位。
   （例：業務在銷貨頁改了等級，不會動到財務區的銀行帳號。）

## §2. 四張主檔的分區地圖

依 Hank 盤點，4 張表分區如下。本節是 E 階段的「顯示什麼欄位」真相來源。

### 2.1 往來對象 partner（4 區）

```
基本資料區：公司代碼 / 名稱 / 簡稱 / 英文名 / 聯絡人 / 電話 / 手機 / 傳真
            / Email / 網站 / 地址 / 身分類別 / 備註 / 服務區域
銷貨區    ：客戶等級 / 信用額度 / 信用狀態 / 預設取貨倉 / 可否同行調貨 / 業務歸屬
配送區    ：送貨地址（可多筆）
財務區    ：統編 / 國內付款條件 / 國外付款條件 / 貿易條件 / 預設幣別
            / 供應商等級 / 帳單地址
```

### 2.2 倉庫 warehouse（中性、無銷貨/財務區）

```
基本資料區：倉庫代碼 / 名稱 / 所屬據點 / 是否主倉 / 倉管主管 / 地址 / 備註
庫存區    ：庫位管理（子層 CRUD，對齊 §7.3）
配送區    ：地址（複用基本資料的地址，給司機送貨看）
```

### 2.3 員工 user（基本 + 權限/安全/HR）

```
基本資料區：登入帳號 / 姓名 / Email / 電話
權限區    ：角色掛載 / 是否負責人
安全區（負責人 admin 看）：強制改密旗標 / 登入失敗次數 / 鎖定狀態 / 最後登入時間
HR 區（PRO）：員工主檔關聯 / 部門 / 團隊
```

### 2.4 產品 part（基本 + 銷貨 + 採購 + 庫存）

```
基本資料區：料號 / 品名 / 料號 5 段 / 零件品牌 / 族群 / 正廠料號 / 舊料號
            / 副廠料號 / 正副廠別 / 改號關聯 / 車型適配 / 版本
銷貨區    ：售價 ABCD 四級 / 價格更新時間 / 價格更新人
採購區    ：進貨成本
庫存區    ：退貨政策 / 保固月數 / 安全量 / 最高量 / 建議補貨量（per 倉）
```

## §3. 三個拍板決策（總經理 2026-05-30 拍板）

### 3.1 決策一：partner 編輯頁「按身分動態顯示分區」

```
規則：partner 編輯頁依「身分類別」決定顯示哪些區，不是固定全顯示。

─ 客戶（partnerType=C 保養廠、O 同行）：基本 + 銷貨 + 配送 + 財務（4 區全顯示）
─ 供應商（S）  ：基本 + 配送 + 財務（不顯示銷貨區的客戶等級/信用等）
                 ＋財務區顯示「供應商等級」
─ 銀行（B）    ：基本 + 財務（不顯示銷貨、配送）
─ 物流（T）    ：基本 + 配送（不顯示銷貨、財務）
─ 一般廠商（V）：基本 + 財務

⭐ 主檔中心（/master）仍可顯示該筆「實際有值的全部區」、不受身分限制
   （讓有主檔中心權限者能看到完整資料）。
   各模組頁面才按身分過濾。
```

⚠️ partnerType 對照（Alex 2026-05-30 認可）：
   O 同行歸客戶 4 區、其採購屬性已在財務區涵蓋（不額外加區）。

### 3.2 決策二（v1.1 修正版）：成本保密靠「兩道天然屏障」、不做欄位級隔離

```
v1.1 修正：成本保密「不」做 service 層欄位過濾、「不」做欄位級 RBAC。
改靠兩道天然屏障：

⭐ 屏障 1：模組權限
─ 進貨成本 / 公司定價（自動算）→ 只放「進貨模組」的產品頁
─ 售價 ABCD / 售價更新人時間 → 只放「銷售模組」的產品頁
─ 使用者有哪個模組權限、就只進得去那頁、自然只看到該頁數字

⭐ 屏障 2：主檔中心存取權限
─ 「能不能進主檔中心」本身是一個可自訂的權限項目
─ 客戶自己決定哪個角色能進
─ 可細分到：能進哪些主檔（客戶/供應商/產品/倉庫/員工...逐項）、瀏覽 or 編輯
```

⚠️ 安全要求（v1.1）：成本保密靠「進不去那一頁」達成、不是靠「頁面藏欄位」。
   重點是各模組頁 + 主檔中心的「頁面進入權限」要在後端確實把關
   （沒權限的請求後端直接擋、不回傳該頁資料）、不是只在前端隱藏選單。

⚠️ Q1 解除（v1.1）：既有 NX02 比價 / NX04 毛利 / NX03 移動平均成本 service
   全部不用動、保持 full projection。後端 service 層不按角色過濾欄位。

⚠️ P3 開工前 Hank 需 grep 回報 Alex：
   階段 A+B 既有的「主檔權限」顆粒度，是否已細到「逐主檔 × 瀏覽/編輯」？
   ─ 若已夠細 → 階段 E 直接沿用、不加新權限項目
   ─ 若只有粗的「主檔.檢視/編輯」總開關 → 階段 E 要把權限項目拆細到
     「逐主檔（客戶/供應商/產品/倉庫/員工...）× 瀏覽/編輯」

### 3.3 決策三：多送貨地址「預設 + 展開」顯示

```
規則：partner 配送區有多筆送貨地址時——

─ 預設只顯示「預設地址」那一筆
─ 旁邊一個「展開看全部 (N)」按鈕，N = 總地址筆數
─ 點展開列出全部送貨地址
─ 每筆可編輯 / 設為預設 / 停用

⭐ part 的多個關聯子表（改號 / 車型 / 版本 / 庫存設定）同理：
   主檔中心編輯頁用「分頁籤 or 可收合區塊」呈現、不要全部攤平塞滿一頁。
```

## §4. 各模組頁面的分區視角（E 階段要落地的頁面）

對齊 v1.2 規格，以下頁面要「只顯示該模組角度欄位」：

```
1. 銷貨 → 客戶管理（§6.2 對應）
   只顯示 partner 的：基本資料 + 銷貨區
   （等級 / 信用 / 交貨方式 / 業務歸屬）

2. 採購 → 供應商管理（§5.6）
   只顯示 partner 的：基本資料 + 財務區（付款條件 / 供應商等級）

3. 採購 → 產品管理（進貨角度，§5.7）
   只顯示 part 的：基本資料 + 採購區（成本）+ 庫存區（安全量）
   ⚠️ 套決策二：採購頁不放售價 ABCD、屬天然分流

4. 財務 → 帳戶管理（§8.6）
   只顯示 partner 的：基本資料 + 財務區（帳單地址 / 收付款 / 銀行帳號）

5. 庫存 → 產品維護（§7.4）
   只顯示 part 的：基本資料 + 庫存區（安全量 / 最高量 / 預設庫位）

6. 主檔中心 → 各主檔（§11）
   顯示完整全部區（依 §3.1 身分動態過濾、主檔權限把關）
```
