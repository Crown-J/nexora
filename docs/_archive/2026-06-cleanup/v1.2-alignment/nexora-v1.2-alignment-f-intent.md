## §1. 財務模組五塊

```
財務
├─ 應收帳款（別人欠我的錢）
├─ 應付帳款（我欠別人的錢）
├─ 票據管理（所有收付款行為）
├─ 關帳作業（月關帳 + 雙月報 401）
└─ 帳戶管理（從財務角度看往來對象）
```

## §2. 應收帳款（總經理拍板）

### 2.1 來源（兩種）

```
1. 銷貨單 → 出貨/開發票後自動產生應收（客戶欠我貨款）
2. 廠商退費單 → 我向廠商進貨後退貨、廠商要退錢給我 → 也是「別人欠我錢」→ 進應收
```

⚠️ 給 Hank：第 2 種「廠商退費」是總經理明確指定的應收來源，
   跟一般「客戶銷貨」不同來源。請確認既有退貨/退費單據結構，
   兩種來源都要能歸進應收。

### 2.2 沖銷（三種，總經理拍板「折讓人工」）

```
1. 現金收款 → 開收款票據 → 自動沖銷
2. 銷退 → 自動沖銷（產生負應收）
3. 折讓 → 人工沖銷部分金額（負責人/財務手動輸入折讓金額）⭐ 人工、非自動
```

### 2.3 列表顯示（對齊 v1.2 §8.2）

```
總應收 / 今日到期 / 逾期未收
篩選：客戶 / 狀態 / 到期日
每筆：客戶、來源單號、金額、到期日、狀態（未收/到期/逾期）
動作：催款通知 / 沖銷 / 看詳情
```

## §3. 應付帳款（總經理拍板）

### 3.1 來源（兩種）

```
1. 採購單 → ⚠️ 到「廠商確認」狀態才產生應付（非下單即產生）
2. 銷退單 → 客戶向我退貨、我要退錢給客戶 → 「我欠別人錢」→ 進應付
```

### 3.2 採購單狀態流（總經理拍板，這是應付認列的關鍵）

```
草稿 → 主管審核 → 向廠商提出 → 廠商確認
                                  ↑
                          到這個狀態才產生應付帳款

實務理由：廠商確認後即開始備貨、備完要求先付款才出貨（先款後貨）。
從「廠商確認」這刻起客戶就有付款義務、故此時認列應付。
```

⚠️ 給 Hank：請確認既有採購單（nx02）是否已有這 4 段狀態。
   ─ 若已有對應狀態 → 在「廠商確認」狀態觸發應付產生
   ─ 若狀態不齊 → 回報 Alex，可能需補狀態（屬採購模組改動、要揭露）
   這是「跨模組接點」（NX02 採購 → NX05 財務）、實作前確認既有 NX02→NX05 helper。

### 3.3 沖銷

```
1. 付款 → 開付款票據 → 自動沖銷
2. 保固理賠成功 → 自動沖應付
3. 折讓 → 人工沖銷
```

記錄所有收付款行為：

## §5. 關帳作業 ⭐（總經理拍板，最關鍵）

### 5.1 關帳節奏：月關帳 + 雙月報 401

```
⚠️ 重要法規事實（已查證）：
營業稅依法「每兩個月為一期」申報、報期為單數月（1/3/5/7/9/11）15 號前、
申報前一期兩個月資料。例：1-2 月一期、3-4 月一期、5-6 月一期。

NEXORA 設計（總經理拍板 A 案）：
─ 關帳 = 「月」關一次（鎖定當月單據、內部控管用）
─ 401 報表 = 「雙月一期」產出（系統自動把單數+雙數月合併成一期）
```

⚠️⚠️ 給 Hank：規格書 §8.5 原文寫「每月關帳」+「當前未關帳月份：2026 年 5 月」、
   這是【事實錯誤】（跟營業稅法規衝突）。
   總經理已授權修正規格書 §8.5：改為「月關帳 + 401 雙月一期產出」。
   請在本軌一併修正 docs/_team/nexora-lite-blueprint-v1.2.md §8.5 文字。
   （此為授權例外：一般不動規格書、但此處是修正法規事實錯誤、總經理已拍板。）

### 5.2 401 報表

```
─ 階段目標：產出「可上報格式」檔案、客戶自己拿去報、不做自動串接財政部
─ 格式：媒體申報 TXT 檔（檔名 = 公司統編.TXT）、含進項+銷項明細
─ 雙月一期彙整：把該期兩個月的銷項（銷貨）+ 進項（採購）彙總
```

⚠️ 給 Hank：401 媒體申報 TXT 的「精確欄位規範」（每欄位置/長度/格式）
   依財政部「營業稅電子資料申報繳稅作業要點」。
   做到此功能前、停下回報 Alex、由 Alex 深查精確欄位規範後給你格式表。
   本軌可先做「關帳 + 進銷項彙整 + 401 預覽」、TXT 精確輸出格式待 Alex 補規範。

### 5.3 關帳後鎖定 + 上報旗標（總經理拍板 C 案）⭐

```
核心：系統要記錄每個「401 申報期」的上報狀態。

每個 401 期（雙月一期）一個狀態旗標：
─ 未上報：這期的關帳可被負責人「解鎖」回頭改單據（保留彈性）
─ 已上報：這期鎖死、解鎖按鈕消失、只能開折讓單/紅字單沖正（守合規）

負責人動作：「標記為已上報 401」→ 該期從此鎖死。

⭐ 鎖的粒度 = 蓋在「期」上、會同時鎖該期的兩個月。
   例：標記「5-6 月期已上報」→ 5 月 + 6 月一起鎖死。
   （因為關帳是「月」、報 401 是「雙月期」、鎖以期為單位。）
```

⚠️ 給 Hank：注意「月關帳」與「期上報旗標」兩層粒度的對應——
   月可以各自關帳、但「能不能解鎖」看的是該月所屬「期」的上報旗標。
   實作前把「月 ↔ 期」對應關係想清楚、有疑義回報 Alex。

### 5.4 關帳預覽（對齊 v1.2 §8.5）

```
關帳作業頁顯示：
─ 當前未關帳月份
─ 該月概況：銷售總額 / 銷售退回 / 進貨總額 / 進貨退回
─ 401 報表預覽（雙月期到齊時可預覽該期 401）
─ 動作：產出 401 報表 / 執行關帳 / 標記已上報
─ 關帳後該月單據鎖定（依 §5.3 旗標決定能否解鎖）
```

## §6. 帳戶管理（總經理拍板「統一建帳戶」）

### 6.1 統一建財務帳戶

```
總經理構想：不管客戶/供應商/廠商、系統都幫對方建一個「財務帳戶」、
所有金錢往來歸戶、利於財務分析與對帳。

好處：
─ 一個對象的應收/應付/收付款記錄全部歸戶
─ 同行（既買又調貨）淨額一眼看到
─ 對帳、催款、財務分析從帳戶層級看
```

### 6.2 兩類帳戶要分清楚

```
⚠️ 往來帳戶（客戶/供應商/廠商）：記「應收應付」、性質是「欠來欠去」
   自有銀行帳戶（B 銀行）：記「我的錢放哪」、性質是「資金存放」
   → 兩類不可混在同一視圖、帳戶管理要分開呈現。
```

⚠️ 給 Hank：這是 Alex 補的設計分類（非總經理逐字拍、但對齊其「財務分析」意圖）。
   實作時往來帳戶 vs 自有銀行帳戶分開、若既有結構難分、回報 Alex。

### 6.3 帳戶管理頁（對齊 v1.2 §8.6 + 階段 E 帳戶分區）

```
Tab：客戶 / 供應商 / 廠商 / 銀行
顯示（財務角度）：帳單地址 / 帳單寄送方式 / 收款方式 / 銀行帳號
⭐ 同一對象在銷貨頁看「等級+信用+交貨」、在這裡看「帳單+收付款+銀行帳號」、
   兩處編輯互不干擾（延續階段 E §3.1 分區原則、財務區）。
```
