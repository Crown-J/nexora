## 三、流程區塊

### 節點結構

```
主線（上層，實線）：
需求 ●━━━ 詢價 ●━━━ 採購單 ●━━━ [審核 ●] ━━━ 驗收 ●━━━ 入帳 ●━━━ 完成 ●

支線（下層，虛線）：
                                              ╎
                                           退貨 ●
```

### 節點說明

| 節點 | 說明 | 版本 |
|------|------|------|
| 需求 | 採購需求單列表（系統自動+業務提交+廠商特價）| ALL |
| 詢價 | 向廠商發出詢價單 | ALL |
| 採購單 | 建立並寄出採購單給廠商 | ALL |
| 審核 | 採購組長審核採購單 | PLUS+，LITE 隱藏 |
| 驗收 | 貨物到達執行驗收 | ALL |
| 退貨 | 驗收異常退供應商（虛線節點）| ALL |
| 入帳 | 確認入帳，庫存增加 | ALL |
| 完成 | 已完成採購記錄 | ALL |

### Badge 數字邏輯

```
需求：   待處理需求單數（未轉詢價）
詢價：   待廠商回覆的詢價單數
採購單： 待寄出/待廠商確認的採購單數
審核：   【採購人員】已審核通過，待建下一步的單據數
         【採購組長】待審核的採購單數
驗收：   待驗收的進貨單數（已到貨）
退貨：   進行中的退供應商單數
入帳：   驗收完成待入帳的進貨單數
完成：   本月已完成採購數（成績，非待辦）
```

> 採購人員的目標：讓需求→詢價→採購單→驗收→入帳的數字消失

### 審核節點特殊設計

```
LITE 版：審核節點完全隱藏，流程圖為：
  需求 ─ 詢價 ─ 採購單 ─ 驗收 ─ 入帳 ─ 完成

PLUS+ 版：審核節點顯示，採購人員視角：
  badge 數字 = 「已審核，我需要繼續處理」的單據數

PLUS+ 版：採購組長視角：
  badge 數字 = 「待我審核」的單據數
  → 角色判斷：nx01_user_role.role_code = PURCHASE + 是否為主管
```

## 四、作業區塊

---

### 4-1 需求（被動接收，無單據）

> 與銷貨「查詢」不同，採購需求是被動接收
> 不需要三欄步驟，直接是需求列表 + 右側彙總

**版型：需求列表 + 右側決策彙總**

```
┌──────────────────────────────────────┬────────────────────┐
│ 採購需求清單                          │ 決策彙總           │
│                                      │                    │
│ [全部] [系統自動] [業務提交] [廠商特價]│ X 個項目已勾選     │
│                                      │                    │
│ □ 料號 A  品名  需求量  來源  緊急度  │ 料號 A  50個  廠商1│
│ □ 料號 B  品名  需求量  來源  緊急度  │ 料號 B  100個 廠商1│
│ ☑ 料號 C  品名  需求量  來源  緊急度  │ 料號 C  30個  廠商2│
│ ☑ 料號 D  品名  需求量  來源  緊急度  │ 料號 D  20個  廠商2│
│                                      │                    │
│                                      │ 共 2 家廠商        │
│                                      │ 共 4 個料號        │
│                                      │                    │
│                                      │ [加入詢價]          │
└──────────────────────────────────────┴────────────────────┘
```

**需求清單欄位：**
- 勾選框
- 料號 / 品名
- 需求數量
- 來源（系統自動 / 業務提交 / 廠商特價）
- 緊急度（高/中/低，依來源和安全量計算）
- 建立時間
- 建議廠商（上次採購廠商）

**來源 Badge 顏色：**
- 系統自動：藍色（庫存低於安全量）
- 業務提交：橘色（客戶訂單需求）
- 廠商特價：金色（廠商主動提供）

**右側決策彙總：**
- 顯示已勾選的項目
- 自動依建議廠商分組
- 採購人員可調整數量
- `[加入詢價]` → 詢價節點依廠商分組產生詢價單

**加入詢價後：**
- 詢價節點 badge 數字更新
- 該需求項目標記「已轉詢價」
- 畫面**停留在需求節點**（可繼續處理其他需求）

---

### 4-2 詢價（有單據）

**進入節點後：**
```
左側：詢價單列表
  單據號 / 廠商 / 料號數 / 建立時間 / 狀態（待回覆/已回覆/逾期）
  [+ 新增詢價單]
```

**點選詢價單 → 進入步驟區：**

```
┌──────────┬────────────────┬──────────────┬────────────────────┐
│ ① 詢價   │ ② 確認詢價     │ ③ 填入廠商   │ 決策彙總           │
│    廠商  │    項目        │    回覆報價  │                    │
│（已帶入）│                │              │ [生成採購單]        │
└──────────┴────────────────┴──────────────┴────────────────────┘
```

**步驟一：詢價廠商**
- 由需求節點帶入建議廠商
- `Enter` 直接進入步驟二
- 可修改廠商（若要換廠商詢價）

**步驟二：確認詢價項目**
- 顯示本張詢價單的料號清單
- 確認數量（可調整）

**步驟三：填入廠商回覆報價**
- 每個料號填入廠商報價單價
- 自動計算總金額
- 填入預計到貨日期

**右側決策彙總：**
```
決策彙總
─────────────────
料號 A  廠商報價 $8.50  → 採購  [建採購單]
料號 B  廠商無法供應    → 放棄  填寫原因 / 換廠商
─────────────────
共 2 個項目
  → 建採購單：1 個
  → 放棄/換廠：1 個

[生成採購單]
```

**生成採購單後：**
- 確認採購的項目 → 採購單節點產生採購單
- 放棄的項目 → 需求節點標記，可重新詢價
- 畫面**停留在詢價節點**

---

### 4-3 採購單（有單據）

**進入節點後：**
```
左側：採購單列表
  單據號 / 廠商 / 料號數 / 金額 / 狀態
  （待寄出 / 待廠商確認 / 廠商已確認）
  [+ 新增採購單]
```

**點選採購單 → 進入步驟區：**

```
┌──────────┬────────────────┬──────────┬────────────────────┐
│ ① 採購   │ ② 確認採購     │ ③ 寄出   │ 狀態追蹤           │
│    廠商  │    明細        │    採購單 │                    │
│（已帶入）│                │           │                    │
└──────────┴────────────────┴──────────┴────────────────────┘
```

**步驟一：採購廠商**
- 由詢價節點帶入廠商資訊
- `Enter` 直接進入步驟二

**步驟二：確認採購明細**
- 料號 / 數量 / 單價 / 小計
- 付款條件（PREPAY / NET30 / NET60 / NET90）
- 預計到貨日期
- 備註

**步驟三：寄出採購單**
- 確認後系統產生採購單 PDF
- 選擇寄送方式（Email / 列印）
- 廠商確認後手動更新狀態

**右側狀態追蹤：**
```
狀態追蹤
─────────────────
PO-202604-00021
廠商：德國汽車配件
狀態：待廠商確認
寄出時間：04-12 14:30
─────────────────
[廠商已確認] 按鈕
（廠商回覆後手動點擊）
```

**廠商確認後：**
- LITE：直接進入驗收節點等待到貨
- PLUS+：進入審核節點等待組長審核

### 4-4 審核（PLUS+ 限定）

> LITE 隱藏此節點
> 採購人員視角 vs 採購組長視角不同

**採購組長進入節點後：**
```
左側：待審核採購單列表
  單據號 / 廠商 / 金額 / 採購人員 / 建立時間
  [⚠️ 待審核 badge]
```

**點選採購單 → 審核畫面：**

```
┌──────────────────────────────────────┬────────────────────┐
│ 採購單明細（唯讀）                    │ 審核決定           │
│                                      │                    │
│ 廠商：德國汽車配件                    │ [✓ 核准]           │
│ 料號 A  100個  $8.50  $850           │ [✗ 退件]           │
│ 料號 B  50個   $12.00 $600           │                    │
│ 總計：$1,450                         │ 退件原因（必填）    │
│ 付款條件：NET30                       │                    │
│ 預計到貨：2026-04-20                  │                    │
└──────────────────────────────────────┴────────────────────┘
```

**核准後：**
- 採購單進入驗收節點等待到貨
- 採購人員收到通知（badge 更新）

**退件後：**
- 採購單退回採購人員
- 採購人員收到通知，需修改後重送審核

**採購人員視角（同一節點）：**
```
左側：已審核通過，待我處理的採購單列表
  （等廠商確認 / 等到貨）
  badge 數字 = 我需要追蹤的單據數
```

---

### 4-5 驗收（有單據）

**進入節點後：**
```
左側：進貨驗收單列表
  單據號 / 廠商 / 預計到貨日 / 狀態
  （待到貨 / 已到貨待驗收 / 驗收中 / 驗收完成）
  [+ 新增進貨單]
```

**點選進貨單 → 進入步驟區：**

```
┌──────────┬────────────────┬──────────────┬────────────────────┐
│ ① 確認   │ ② 執行驗收     │ ③ 驗收結果   │ 決策彙總           │
│    廠商  │    逐筆核對    │    異常處理  │                    │
│（已帶入）│                │              │ [確認驗收]          │
└──────────┴────────────────┴──────────────┴────────────────────┘
```

**步驟一：確認廠商**
- 由採購單帶入廠商資訊
- `Enter` 直接進入步驟二

**步驟二：執行驗收**
每個料號逐筆：
```
料號 A  預期 100個
  實收數量：[____] 個
  外觀狀態：[正常 ▼]（正常/數量異常/瑕疵品）
  備註：
```

**步驟三：驗收結果與異常處理**

```
全數正常 → 直接進入入帳

有異常項目（採購組長決定）：
  ○ 全數退回廠商   → 退貨節點
  ○ 正常品入帳，異常品退回 → 分開處理
  ○ 全數接受（要求折讓）→ 入帳 + 財務折讓
```

**右側決策彙總：**
```
決策彙總
─────────────────
料號 A  100個  正常    → 入帳
料號 B  45個   數量不符 → 退貨 45個
料號 C  50個   瑕疵品  → 全退
─────────────────
  → 入帳：1 個料號
  → 退貨：2 個料號

[確認驗收]
```

**確認驗收後：**
- 正常品 → 入帳節點
- 異常品 → 退貨節點
- 畫面**停留在驗收節點**

### 4-6 退貨（虛線節點，有單據）

> 驗收異常才會觸發，從驗收節點延伸

**進入節點後：**
```
左側：退供應商單列表
  單據號 / 廠商 / 料號數 / 退貨原因 / 狀態
  （待退貨 / 已退出 / 廠商已收）
```

**點選退供應商單 → 進入步驟區：**

```
┌──────────┬────────────────┬────────────────────┐
│ ① 確認   │ ② 確認退貨     │ 狀態追蹤           │
│    廠商  │    項目與原因  │                    │
│（已帶入）│                │                    │
└──────────┴────────────────┴────────────────────┘
```

**步驟二：確認退貨項目**
- 顯示異常項目清單
- 退貨原因（數量不符 / 瑕疵品 / 錯誤料號）
- 退貨方式（廠商派車取回 / 我方寄回）

**狀態追蹤：**
```
廠商已收貨 → 系統更新 AP（未付款自動沖銷 / 已付款產生應收）
```

### 4-7 入帳（有單據）

> 驗收正常後，倉管組長確認入帳
> 入帳後庫存由 NX03 處理，採購工作台只顯示狀態

**進入節點後：**
```
左側：待入帳進貨單列表
  單據號 / 廠商 / 料號數 / 驗收時間 / 金額
```

**點選進貨單 → 確認入帳畫面：**

```
┌──────────────────────────────────────┬────────────────────┐
│ 入帳確認                              │ 入帳後觸發         │
│                                      │                    │
│ 廠商：德國汽車配件                    │ ✓ 庫存增加         │
│ 料號 A  100個  均價 $8.50            │   → NX03 分貨入庫  │
│ 料號 C  50個   均價 $12.00           │                    │
│ 總入帳金額：NT$1,450                  │ ✓ AP 應付帳款產生  │
│                                      │   → NX05 財務      │
│ [確認入帳]（橘金色大按鈕）             │                    │
└──────────────────────────────────────┴────────────────────┘
```

**確認入帳後：**
- 庫存增加（NX03 自動處理分貨）

## 八、與銷貨工作台的連動

```
銷貨工作台（NX04）← → 採購工作台（NX02）

連動點 1：業務提交客訂需求
  業務在銷貨工作台建銷貨單（狀態：待到貨）
  → 自動在採購需求節點產生需求單（來源：業務提交）
  → 採購處理完入帳後，銷貨單狀態自動更新為待撿貨

連動點 2：銷貨查詢無庫存時的同行詢價
  業務在查詢節點選「向同行詢價」
  → 產生詢價單（NX02_RFQ）進入詢價節點
  → 但此詢價是向同行（partner_type=C）非廠商
  → 採購工作台不顯示，由業務在銷貨工作台詢價節點處理
```
