## §1 NX02 業務本質

### 1.1 NX02 是什麼

**NX02 採購管理 = 亞羅產品部門的工作台**。

業務本質回答 4 個核心問題：

1. **要採購什麼？**（接 AR 缺貨建議 + 銷貨客訂、客訂優先）
2. **找誰買？**（多家詢價、比價分析、新品 / 特價）
3. **怎麼買？**（國內 / 國外 / 掃貨 3 種模式）
4. **買到了嗎？**（國外 6 階段追蹤、驗收、退貨、入帳）

### 1.2 NX02 在 NEXORA 全棧的角色

```
上游：AR 自動補貨建議單（demandType=S）
      NX04 銷貨客訂建議單（demandType=O）
        ↓
NX02 採購完整鏈：
   採購建議單 → RFQ 詢價 → Qt 報價 → 比價 → Po 採購單 →
   廠商確認 → Rr 進貨 → 驗收 → Pr 退貨（如需要）→ 通知 NX05 入帳
        ↓
下游：NX03 入庫（stock_balance + ledger source=P）
      NX05 應付帳款（ApLedger）
      NX06 物流（國外採購到貨配送）
```

**核心定位**：NEXORA 跨模組樞紐、上接需求、下接庫存 + 財務 + 物流。

### 1.3 NEXORA 戰略意義

⭐⭐ NX02 落地 3 個業界改革候選：
1. **比價分析含新品 / 特價 / 量大彈性折扣**（業界資深採購工具）
2. **國外採購 6 階段追蹤**（業界中小 ERP 少見系統化）
3. **partner ↔ part 混合範式**（主檔 + 歷史推算 fallback、跟 AR 哲學一致）

## §2 主使用者與權限

### 2.1 主使用者 = PURCHASING 產品部門

對齊亞羅 6 部門組織架構：

| 部門 | NEXORA 角色 | 跟 NX02 關係 |
|---|---|---|
| 產品部門 | **PURCHASING** | **NX02 主寫入者、所有業務動作執行** |
| 銷售部門 | SALES | 客訂建議單來源、查採購進度 |
| 倉管部門 | WAREHOUSE | 驗收執行者、跟 NX03 接點 |
| 財務部門 | FINANCE | NX05 應付帳款入帳、付款執行 |
| 管理部門 | OWNER | 跨角色 read、採購單審核（PLUS+）|
| 人資部門 | HR_ADMIN | 不涉 NX02 |

⭐ **同行調貨歸銷售（NX04）、不歸採購**（Crown Q2 揭露）：
- Qt / Ti schema 雖在 NX02、業務操作者是 SALES
- role_view 設定：QT / TI 相關 endpoint → SALES role 開放

### 2.2 權限機制 = 彈性 role_view

對齊 Crown Q1 拍板：
- 預設 PURCHASING 操作
- 用 role_view 彈性權限
- 不設「採購組長 / 採購員」雙層角色
- 主管審核走 status enum（不靠 role 分層）

### 2.3 寫入 vs 查詢分工

- **寫入**：PURCHASING 採購員主操作 + OWNER 主管審核
- **查詢**：跨角色（SALES 看客訂進度、WAREHOUSE 看待驗收、FINANCE 看待付款）

## §3 業務功能架構

### 3.1 採購 8 步 SOP（Crown 揭露核心流程）

```
1. 看採購需求單（AR 缺貨 + 銷貨客訂、客訂優先）
   ↓
2. 多家廠商詢價（RFQ、email 來往）
   ↓
3. 多家比價（含新品 + 特價 + 量大彈性折扣分析）⭐
   ↓
4. 建採購單給主管審核（主管可改量/單價、不可換廠商）⭐
   ↓
5. 寄廠商確認（email、廠商不登入 NEXORA）
   ↓
6. 廠商確認 → 產生進貨單
   ↓
7. 國內：等到貨驗收
   國外：6 階段追蹤（備貨 → 付款 → 待出貨 → 上船 → 到港 → 驗收）
   ↓
8. 驗收 → 退貨處理（如需要）→ 通知 NX05 入帳
```

### 3.2 採購 3 種模式

對齊 audit § 6.1 + Crown Q2 拍板：

| 模式 | 業務情境 | 流程 |
|---|---|---|
| **國內一般採購**（D）| 主要業務 | RFQ → Qt → Po → Rr 完整 8 步 |
| **國外採購**（I）| 進口貨、含 6 階段追蹤 | RFQ → Qt → Po → 6 階段 → Rr + RrImport |
| **掃貨採購**（B）| 緊急 / 小額 | 跳過 RFQ、直接 Po → Rr |

⭐ Crown 揭露：**同行調貨不歸採購**（業務歸銷售 NX04）。

### 3.3 採購需求單來源（步驟 1）

對齊 Crown Q11 + Q17 拍板：

| 來源 | demandType | 優先級 |
|---|---|---|
| **客戶訂單**（銷貨建）| O | **客訂優先**（純標記、UI 高亮、採購員自己判斷）⭐ |
| **AR 自動建**（庫存戰略）| S | 一般優先級 |

採購需求單 UI 範式（Crown Q20 揭露）：
- **列表式**（對齊 NX03 撿貨單範式、不是業務單據）
- **按廠商過濾顯示對應零件**（廠商只賣特定料件時、列表只顯示對應）
- **採購員勾選 N 個 row → 一次建一張 RFQ**（合併詢價）

### 3.4 比價分析範圍（步驟 3、Crown Q12 拍板）

⭐⭐ NEXORA 業界改革候選：

| 維度 | 業界 muscle memory |
|---|---|
| **歷史單價趨勢** | 多廠商同料件單價歷史折線圖 |
| **廠商主動推案** | 新品（廠商新一代產品）+ 特價（季末沖貨 / 限時促銷）|
| **採購量彈性折扣** | 量大優惠分析（如 100 顆單價 X、500 顆單價 Y）|

→ 業界資深採購工具、5 個 placeholder UI 候選承接。

### 3.5 採購單審核機制（步驟 4、Crown Q13 + Q16 拍板）

對齊 audit § 1.2 既有 schema `approvedBy / approvedAt`：

| 動作 | 權限 | 範圍 |
|---|---|---|
| 採購員建單 | PURCHASING | 一直可改到主管確認前 |
| **主管審核**（可改）| OWNER / 主管 | ✅ 量、單價 |
| | | ❌ 不可換廠商 |
| 換廠商 | 重建一單 | 取消舊單 + 建新單（PO 鎖定廠商 = 契約） |

### 3.6 詢價 / 廠商溝通範式（步驟 5、Crown Q18 揭露）

⭐ 業界中小企業真實：
- 廠商**不會用客戶 ERP**
- 採購員手動 email 來往
- 廠商不登入 NEXORA

**系統範式**：
- 系統產生 RFQ PDF / 文字 → 採購員 copy 出去寄 email
- 採購員手動 key 廠商回價（既有 Qt schema 對齊 ✓）
- 不需要廠商登入功能

### 3.7 國外採購 6 階段追蹤（步驟 7、Crown Q14 揭露）

⭐⭐ 業界改革候選：

```
PO 發出後狀態流（國外採購專屬）：
1. 廠商備貨中
2. 要求付款
3. 待廠商出貨（付款完成）
4. 出貨上船
5. 已到港 ⭐ 報關行主動通知
6. 到貨驗收
```

**業界 muscle memory**：
- 報關行**主動通知**「已到港」（採購員不去 query）
- 不強迫追蹤每階段（電話 / email 得知後手動標）
- 業界中小企業真實：靠關係 + 電話追貨

**業務員 muscle memory query**：
- 「這批貨到哪了？」→ 看狀態
- 「付款了沒？」→ 看 paidAt
- 「報關卡多久？」→ 看到港時間

### 3.8 退貨業務範式（步驟 8、Crown Q19 拍板）

對齊 audit § 1.2 既有 schema `Nx02Pr`：

| 退貨類型 | 業務情境 | 流程 |
|---|---|---|
| **全部退** | 整單退換新（如品項錯誤）| Pr 開新單、廠商換新 |
| **部分退** | 瑕疵率高、其餘收 | Pr 部分明細 |
| **折讓不退** | 保留貨、廠商折讓現金 | Pr + NX05 ApLedger 沖帳 |

⭐ **多種並存**（Q19=d）= 業界常態。

### 3.9 入帳跨模組協作（步驟 8、Crown Q15 拍板）

對齊 audit § 1.4 NX02 → NX05 reverse 5 條 FK：

```
NX02 採購確認（Po CONFIRMED）→ 通知 NX05 建 ApLedger
   ↓
NX02 進貨驗收（Rr POSTED）→ 通知 NX05 更新 ApLedger（實際金額）
   ↓
NX02 退貨折讓（Pr POSTED）→ 通知 NX05 沖帳
   ↓
NX05 應付帳款執行付款（FINANCE 主操作）
```

⭐ **NX02 通知、NX05 入帳**（同 NX03 驗收跨模組範式）。

## §4 partner ↔ part 混合範式（Crown Q-PP-1=C）

### 4.1 戰略意義

⭐⭐ 對齊 AR「系統建議為主、手動為輔」哲學：

```
主檔層（手動定義）：
   採購員可定義「A 廠商供應料件 X / Y / Z」
   → 業界戰略合作、長期合約料件
   
歷史推算（系統 fallback）：
   未在主檔定義時、系統從 Po + PoItem 歷史推算
   → 「A 廠商過去 90 天供應過 W」
```

### 4.2 應用場景

對齊 Crown Q20 揭露採購建議單 UI：

```
採購員開「採購建議單」列表
   ↓
篩選廠商 = A 廠商
   ↓
系統先查主檔層（A 廠商已定義供應料件）
   ↓
找不到則 fallback 歷史推算（A 廠商過去買過的料件）
   ↓
列表只顯示 A 廠商可供應料件
```

### 4.3 廠商料號（Crown Q-PP-3=b 選填）

業界 muscle memory：同一料件、不同廠商有自己編號（如 Bosch 自有編號 vs 廠商編號）。

→ 採購員視情況輸入、不強制。

### 4.4 partnerType 不細分（Crown Q-PP-2=a）

audit § 1.4 揭露 partner_type=S 既是「零件供應商」也是「同行」：
- 不拆 S 成兩 enum（不破壞既有）
- 用 application 層區分（context 決定 S 是供應商還是同行）

## §5 業務範例（Crown 揭露的 Golf 7 三角架延伸）

### 5.1 國內採購完整鏈

```
場景：AR 偵測 Golf 7 三角架正廠 缺 1 顆 → demandType=S

步驟 1：採購員開建議單列表、看到此 row
步驟 2：篩選廠商 = 正廠專營「A 廠商」+ 副廠「B 廠商」、發 2 張 RFQ
步驟 3：A 廠商回價 1500、B 廠商回價 1200（鳥牌副廠等效）
        比價分析：A 廠商歷史均價 1480 / B 廠商有特價 1200
        採購員選 B 廠商（價格優勢）
步驟 4：建 Po、主管審核改量為 2 顆（庫存戰略）
步驟 5：寄 B 廠商 email 確認
步驟 6：B 廠商確認 → 產生 Rr 待驗收
步驟 7：到貨 → WAREHOUSE 驗收 → 1 顆瑕疵
步驟 8：建 Pr 部分退（1 瑕疵退）→ NX05 沖帳 1200
        NX03 入庫 1 顆 source=P
```

### 5.2 國外採購完整鏈

```
場景：AR 偵測 VAG Golf 8 機油濾芯 大量缺貨 → demandType=S

步驟 1~4：同上、Po 含 purchaseType=I 國外

步驟 7 國外 6 階段：
   1. 廠商備貨中（廠商 email 通知）
   2. 要求付款（廠商 email 通知）
   3. 待廠商出貨（付款完成、匯款單號入系統）
   4. 出貨上船（船號 + 提單號入系統）
   5. 已到港 ⭐ 報關行 email 通知
   6. 到貨驗收（含 RrImport 攤分運費關稅）

步驟 8：驗收 → 入帳 NX05（含進口費用）→ NX03 入庫 source=P
```
