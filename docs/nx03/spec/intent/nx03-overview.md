## §1 NX03 業務本質

### 1.1 NX03 是什麼

**NX03 庫存管理 = 亞羅倉管部門的工作台**。

業務本質回答 4 個核心問題：

1. **什麼料、在哪倉、有幾顆、值多少錢**（即時量查詢）
2. **這些料從哪來、誰拿走、為什麼動**（異動全程溯源）
3. **快沒料了該補多少貨**（自動補貨建議、NEXORA 戰略特色）
4. **帳上跟實際對得起來嗎**（盤點 + 動態追蹤）

### 1.2 NX03 在 NEXORA 全棧的角色

- **上游**：採購（NX02 RR）進貨進來、銷貨退回（NX04 SR）退回入庫
- **下游**：銷貨（NX04 SO）出貨出去、退供應商（NX02 PR）退貨出庫
- **平行**：物流（NX06 DN）配送、報表（NX08）庫存價值快取
- **核心定位**：實體流通的物理樞紐、所有業務動作的真實對應

### 1.3 NEXORA 戰略意義

對齊 Crown 戰略揭露：NX03 是「**業務員 muscle memory → 系統 query**」範式的核心落地點之一：

- 業界傳統：「庫存量靠老師傅腦記、Excel 月底校正」
- NEXORA：「即時量查詢 + 異動帳冊 + 自動補貨建議」全系統化

## §3 業務功能架構

### 3.1 NX03 = 12 業務情境、4 大分類

```
NX03 庫存管理（倉管工作台）
   │
   ├─ 入庫
   │   ├─ 1. 進貨入庫（採購到、上架）
   │   ├─ 2. 銷售退回入庫
   │   ├─ 3. 調撥入庫（內部各倉間）
   │   └─ 4. 調貨入庫（同行 partner_type=C）
   │
   ├─ 出庫
   │   ├─ 5. 銷售出庫（撿→包→自取/寄貨/配送）
   │   ├─ 6. 調撥出庫（撿→包→配送他倉）
   │   ├─ 7. 退貨出庫（退供應商 / 退調貨來源）
   │   └─ 8. 報廢出庫
   │
   ├─ 轉換
   │   ├─ 9. 重組（A + B → C）
   │   └─ 10. 分解（X → A + B + C）
   │
   ├─ 盤點
   │   └─ 11. 動態盤點（snapshot + delta 追蹤）
   │
   └─ 自動補貨（NEXORA 戰略特色）
       └─ 12. 安全量 / 最高量 → 採購建議單
```

### 3.2 強制資料溯源（設計哲學 #13）

所有庫存異動必含 **source 分類字母**（共 10 種）：

| 字母 | 業務情境 | 來源模組 |
|---|---|---|
| P | 進貨 | NX02 RR |
| S | 銷貨 | NX04 SO |
| R | 退貨（退供 / 退銷）| NX02 PR / NX04 SR |
| T | 盤點調整 | NX03 |
| I | 開帳 | NX03 |
| X | 調撥（內部跨倉）| NX03 |
| **G** | **同行調貨**（partner_type=C 反向）| NX03（新增）|
| **W** | **報廢** | NX03（新增）|
| **M** | **重組**（merge）| NX03（新增）|
| **D** | **分解**（disassemble）| NX03（新增）|

業界價值：「這顆料從哪來、為什麼動」**永遠查得到**、業界第一個能做的中小企業 ERP。

### 3.3 12 情境業務語意明細

#### 入庫 4 種

**1. 進貨入庫**
- 觸發：NX02 採購單到貨（NX02 驗收完成、異常已分派）
- 動作：倉管上架（系統指引儲位）
- 上架時若該料未設儲位、系統主動提示倉管設定
- source = P

**2. 銷售退回入庫**
- 觸發：NX04 銷售退回單成立
- 動作：客戶退回物理收貨 + 上架
- 異常處理：對齊 NX04 退回流程
- source = R

**3. 調撥入庫**
- 觸發：他倉調撥出庫送達
- 動作：物理收貨 + 上架
- source = X

**4. 調貨入庫**
- 觸發：缺貨向同行調貨、配送員去同行取回
- 對象：同行（NEXORA partner_type=C 客戶反向、平時是賣他、缺貨時跟他調）
- 業務本質：**即時性**、不走採購繁瑣流程
- source = G

#### 出庫 4 種

**5. 銷售出庫**
- 觸發：NX04 銷貨單成立
- SOP：撿貨 → 包貨 → 三選一（自取 / 寄貨 / 配送）
- 配送才產生送貨單（NX06 DN 接管）
- source = S

**6. 調撥出庫**
- 觸發：他倉缺貨、跨倉支援
- SOP：撿貨 → 包貨 → 配送他倉
- source = X

**7. 退貨出庫**
- 觸發：退給供應商（NX02 PR）/ 退調貨來源（同行）
- 動作：撿貨 + 包貨 + 退送
- source = R

**8. 報廢出庫**
- 觸發：料件損壞 / 過期 / 無價值
- 動作：直接出庫沖銷
- source = W

#### 轉換 2 種

**9. 重組（A + B → C）**
- 業界場景：油封 A + 環圈 B → 修包組 C
- 成本算法：C unitCost = avgCost_A + avgCost_B（工資不納入庫存成本、走 NX05 製造費）
- source = M

**10. 分解（X → A + B + C）**
- 業界場景：總成 X → 油封 A + 環圈 B + 卡夾 C
- 成本算法：預設按 A/B/C 市價比例分攤 X 成本、例外允許人工指定比例
- source = D

#### 盤點 1 種

**11. 動態盤點**（NEXORA 戰略特色）
- 業界傳統：盤點凍結業務、卡營運節奏
- NEXORA 範式：**不凍結、snapshot + delta 追蹤**
- 流程：
  1. 盤點啟動 → 鎖定基準量 snapshot
  2. 期間照常進出貨（不影響業務）
  3. 盤點完成 → 公式回推：實際清點 + 期間 delta = 應有量
  4. 真實誤差才寫 source=T 帳
- source = T

#### 自動補貨 1 種（戰略獨立）

**12. 自動補貨建議單**（NEXORA 核心戰略特色）
- 觸發：系統依「進貨數據 + 銷貨數據」算
- 產出：安全量 + 最高量 → 採購建議單
- 決策：產品部門（PURCHASING）最終決定
- 可見性：倉管 + 產品雙看（倉管知道方便回應、決定權在產品）
- 業界價值：倉管不用鑽研補貨量、跟著數據走

## §4 倉庫拓樸

### 4.1 3 Tier 演進模型（Crown 揭露）

| Tier | 拓樸 | 業務階段 |
|---|---|---|
| **LITE** | H × 1 | 亞羅初期、單倉 |
| **PLUS** | H × 1 + W × N | 成長期、主倉 + 分倉 |
| **PRO** | **H × N** + S × N + W × N | 規模化、多區營運（多港進貨）|

### 4.2 倉型業務語意（Crown 揭露：H = 主倉 = 進貨倉 = 總倉）

| 倉型 | 業界角色 | flowMode |
|---|---|---|
| **H 總倉**（= 主倉 = 進貨倉）| 進貨集中、跨區擴展時可多 H | C 集中管理 |
| **W 分倉** | PLUS 階段分倉、跟主倉分流 | D 分倉管理 |
| **S 衛星倉** | PRO 階段分區出貨倉 / 營業處 | D 分倉管理 |

### 4.3 多 H 跨區擴展真相（Crown 業界揭露）

亞羅未來規模擴大、進口貨從哪邊到港從哪邊進貨：
- 北部進口走基隆港 → 台北總倉（H1）
- 南部進口走高雄港 → 高雄總倉（H2）

→ PRO Tier 允許 H × N、不是硬性 H × 1。

### 4.4 儲位機制（Nx01Location 4 欄 3D 完備）

對齊 Hank AUDIT-04 真相揭露：
- 儲位 = 倉內 3D 位置（zone / rack / levelNo / binNo）
- 業界語意：「A 區 3 排 2 層 01 格」
- 上架時系統指引、未設定時主動提示倉管設定

## §5 跨流程子模組（撿包出貨 SOP）

### 5.1 撿貨 → 包貨 → 出貨 統一流程

對齊 Crown 揭露：所有出貨類型（銷貨 / 調撥 / 退貨）走**同一 SOP**、最後一步才分流。

```
觸發單據（銷貨 / 調撥 / 退貨）
   ↓
撿貨單（業務動作集中表）
   ├─ 倉管手機查看：要撿的品項 + 儲位
   ├─ 撿貨完成（按鈕 → 待包貨狀態）
   ↓
包貨單（包裹編號管理）
   ├─ 包裹 = BX 編號
   ├─ 1 銷貨 / 調撥單可拆 N 包裹（體積彈性合包）
   ├─ 體積小可合包、體積大獨包
   ↓ 三選一分流
   ├─ 寄貨：依銷貨單拿包裹給物流（partner_type=T 外包）
   ├─ 自取：依銷貨單拿包裹給客戶（客戶來倉拿）
   └─ 配送：產生送貨單 → NX06 物流接管
```

### 5.2 撿貨單 = 業務動作集中表

對齊設計哲學 §I.2.1 #4「追蹤清單只追蹤需要動作的單」：
- 撿貨單**不是業務單據**、是「待辦工作清單」
- 倉管手機操作主介面
- 顯示要撿品項 + 儲位位置
- 撿完按確認 → 自動進待包貨狀態

### 5.3 包貨單 = 1 對 N 包裹拆分

業界 muscle memory：
- 體積差異大、不可能一個包裹打包全部
- 包貨單記錄「哪些品項放哪個包裹」
- BX 編號是包裹唯一識別、配送 / 自取依 BX 取貨

### 5.4 最後一哩分流（自取 / 寄貨 / 配送）

| 分流 | 對象 | 物流參與 | NX06 牽涉 |
|---|---|---|---|
| **自取** | 客戶來倉拿 | 無 | 不涉 NX06 |
| **寄貨** | 走宅配 / 物流公司 | 外部物流商（partner_type=T）| 不涉 NX06 送貨單 |
| **配送** | 公司配送員送 | 公司內部配送 | **產生 NX06 送貨單** |
