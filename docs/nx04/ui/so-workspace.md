## 三、流程區塊（桌面版）

> 高度固定約 160px，寬度隨視窗滿版
> 呈現方式參考台灣捷運圖

### 節點結構

```
主線（上層）：
查詢 ●━━━━ 報價 ●━━━━ 銷貨 ●━━━━ 出貨 ●━━━━ 完成 ●
      ╎          ╎                        ╎
支線（下層，虛線）：
    詢價 ●    調貨 ●              銷退 ●  保固 ●
```

**連線說明：**
- 主線：實線（━）
- 支線：虛線（╎），表示可選路徑
- 查詢 → 詢價：查詢時有無庫存項目需詢價
- 報價 → 調貨：報價後客戶確認，需向同行調貨
- 完成 → 銷退：已完成訂單發起銷退
- 完成 → 保固：已完成訂單申請保固

### 每個節點顯示

```
     ●
  5（badge）
   報價
```

- 節點圓圈：金色外框
- 當前選中：金色填滿 + 放大
- 有待處理：顯示未完成**單據數**（非品項數）
- 無待處理：badge 不顯示
- 已完成節點：綠色圓圈

### 節點 badge 說明

```
顯示規則：未完成單據數
  詢價：有詢價單尚未決策（待報價 or 放棄）
  報價：有報價單尚在有效期且未轉銷貨
  調貨：有調貨項目尚未取貨入庫
  銷貨：有銷貨單尚未完成出貨
  出貨：有出貨任務進行中
  完成：本月已完成單據數（顯示成績，非待辦）

業務的目標：讓所有 badge 數字消失（完成除外）
```

## 四、作業區塊

> 各節點的操作介面
> 共用版型：左側步驟區 + 右側決策彙總區
> 有單據的節點：進入後先顯示單據列表，點選單據後進入步驟區

---

### 4-1 查詢（無單據）

**版型：三欄步驟 + 右側決策彙總**

```
┌──────────┬──────────┬────────────┬────────────────────┐
│ ① 選客戶 │ ② 查庫存 │ ③ 選處置   │ 決策彙總           │
│          │          │            │ X 個項目           │
│          │          │            │                    │
│          │          │            │ [生成單據]          │
└──────────┴──────────┴────────────┴────────────────────┘
```

**步驟一：選擇客戶**
- 搜尋框：輸入客戶名稱 / 電話 / 代碼
- 選定後顯示：
  - 客戶等級 badge（A/B/C/D）
  - 信用狀態（正常綠色 / 警示橘色 / 凍結紅色）
  - 未收款金額
- ⚠️ 凍結客戶：顯示紅色警告框，無法繼續操作

**步驟二：查詢庫存**
- 搜尋框：輸入料號或品名
- `Enter`：進入下方搜尋結果列表
- 列表欄位：料號 / 品名 / 本倉庫存 / 他倉庫存 / 客戶等級對應售價
- 本倉庫存為 0 顯示紅色
- 他倉庫存為 0 顯示橘色
- 勾選料號後出現在步驟三

**步驟三：選擇處置方式**
- 每個勾選的料號逐筆顯示
- 每筆提供三個選項（依庫存狀況啟用/停用）：
  ```
  ○ 直接報價（本倉有庫存時啟用）
  ○ 他倉調撥後報價（他倉有庫存時啟用）
  ○ 向同行詢價（全公司無庫存時啟用）
  ```
- 選定後進入右側決策彙總

**右側決策彙總區**
```
決策彙總
─────────────────
料號 A  直接報價    A 價 $11.50
料號 B  他倉調撥    A 價 $2.50
料號 C  向同行詢價  待詢價
─────────────────
共 3 個項目
  → 詢價：1 個
  → 報價：2 個

[生成單據]（橘金色大按鈕）
```

**生成單據後：**
- 詢價項目 → 詢價節點產生 1 張詢價單（含所有需詢價項目）
- 報價項目 → 報價節點產生 1 張報價單（含所有可直接報價項目）
- 流程圖 badge 數字更新
- 畫面**停留在查詢階段**（業務可繼續處理其他客戶詢問）

---

### 4-2 詢價（有單據）

**進入節點後：**
```
左側：詢價單列表
  單據號 / 建立時間 / 項目數 / 狀態
  [+ 新增詢價單]
```

**點選詢價單 → 進入步驟區：**

```
┌──────────┬────────────────┬──────────┬────────────────────┐
│ ① 詢價   │ ② 選擇詢價項目 │ ③ 填入   │ 決策彙總           │
│    對象  │                │    報價  │                    │
│          │                │          │ [生成單據]          │
└──────────┴────────────────┴──────────┴────────────────────┘
```

**步驟一：選擇詢價對象（同行廠商）**
- 搜尋框：輸入同行名稱
- 選定後：客戶資訊已由前階段帶入，`Enter` 直接進入步驟二

**步驟二：選擇詢價項目**
- 顯示本張詢價單的所有項目（從查詢階段帶入）
- 勾選本次要向此同行詢問的項目

**步驟三：填入對方報價**
- 每個勾選項目填入同行報價金額
- 自動計算加上毛利後的客戶售價（可調整）

**右側決策彙總區**
```
決策彙總
─────────────────
料號 C  同行報價 $0.90  → 客戶售價 $1.20  [報價]
料號 D  同行無貨                           [放棄] 填寫原因
─────────────────
共 2 個項目
  → 轉報價：1 個
  → 放棄：1 個

[生成單據]
```

**生成單據後：**
- 要報價的項目 → 報價節點的報價單新增對應項目（狀態：待報價）
- 放棄的項目 → 詢價單該項目標記放棄（填寫原因）
- 畫面**停留在詢價階段**

---

### 4-3 報價（有單據）

**進入節點後：**
```
左側：報價單列表
  單據號 / 客戶 / 建立時間 / 項目數 / 有效期 / 狀態（有效/失效）
  [+ 新增報價單]
```

> 報價單有效期：預設 7 天，可由使用者在系統設定修改
> 同一張有效報價單可多次引用建立銷貨單

**點選報價單 → 進入步驟區：**

```
┌──────────┬────────────────┬──────────┬────────────────────┐
│ ① 報價   │ ② 選擇報價項目 │ ③ 填入  │ 決策彙總           │
│    對象  │                │    報價  │                    │
│（已帶入）│                │          │ [生成單據]          │
└──────────┴────────────────┴──────────┴────────────────────┘
```

**步驟一：報價對象**
- 由前階段（查詢/詢價）自動帶入客戶資訊
- `Enter` 直接進入步驟二

**步驟二：選擇報價項目**
- 顯示本張報價單的所有項目
- 勾選本次要報價的項目

**步驟三：填入報價**
- 每個項目顯示：建議售價（依客戶等級）/ 最低售價
- 可調整售價，低於最低售價顯示警告（需填原因）

**右側決策彙總區**
```
決策彙總
─────────────────
料號 A  $11.50  客戶確認  [轉銷貨單]
料號 B  $2.50   待客戶回應
料號 C  $1.20   客戶確認  [轉銷貨單]
─────────────────
共 3 個項目
  → 轉銷貨：2 個（含調撥/調貨來源）
  → 待回應：1 個（留在報價單，等客戶確認）

[生成單據]
```

**生成單據後：**
- 客戶確認的項目 → 銷貨節點產生銷貨單
- 待回應的項目 → 留在報價單（狀態：待回應），報價單 badge 不消失
- 畫面**停留在報價階段**

---

### 4-4 調貨（有單據）

> 向同行調貨（同行出貨，我方外務去取貨）

**進入節點後：**
```
左側：調貨單列表
  單據號 / 同行廠商 / 項目數 / 狀態
  [+ 新增調貨單]
```

**點選調貨單 → 進入步驟區：**

```
┌──────────┬────────────────┬────────────────────┐
│ ① 調貨   │ ② 選擇調貨項目 │ 決策彙總           │
│    對象  │                │                    │
│（已帶入）│                │ [生成單據]          │
└──────────┴────────────────┴────────────────────┘
```

**步驟一：調貨對象**
- 由詢價階段自動帶入同行廠商
- `Enter` 直接進入步驟二

**步驟二：選擇調貨項目**
- 顯示待調貨的項目，確認數量與取貨時間

**右側決策彙總區**
```
決策彙總
─────────────────
料號 C  同行A  5,000個  預計取貨 明天
─────────────────
[生成取貨單]
```

**生成單據後：**
- 產生取貨任務 → 物流節點通知外務安排取貨
- 取貨完成入庫 → 銷貨節點的對應項目狀態更新為可出貨
- 畫面**停留在調貨階段**

### 4-5 銷貨（有單據）

**進入節點後：**
```
左側：銷貨單列表
  單據號 / 客戶 / 建立時間 / 項目數 / 出貨方式 / 狀態
  [+ 新增銷貨單]
```

**點選銷貨單 → 進入步驟區：**

```
┌──────────┬────────────────┬────────────────┬────────────────────┐
│ ① 銷貨   │ ② 選擇銷貨項目 │ ③ 填入出貨     │ 決策彙總           │
│    對象  │                │    資訊        │                    │
│（已帶入）│                │                │ [確認建單]          │
└──────────┴────────────────┴────────────────┴────────────────────┘
```

**步驟一：銷貨對象**
- 由報價階段自動帶入客戶資訊
- `Enter` 直接進入步驟二

**步驟二：選擇銷貨項目**
- 顯示已確認的報價項目
- 顯示出貨來源（本倉 / 他倉調撥 / 同行調貨）

**步驟三：填入出貨資訊**
- 出貨方式：配送（D）/ 自取（P）/ 寄貨（C）
- 出貨倉庫：依庫存自動建議，可調整
  - 本倉有庫存 → 直接出貨
  - 本倉不足他倉有 → 調撥後出貨（在此決定）
- 取貨方式（若選配送）：填入地址

**右側決策彙總區**
```
決策彙總
─────────────────
料號 A  本倉出貨  配送  台北市信義區...
料號 C  調撥後出  自取

總金額：NT$1,270
─────────────────
[確認建單]
```

**確認建單後：**
- 系統預留庫存（`reserved_qty`）
- 需調撥的項目 → 自動建立調撥申請
- 出貨任務進入出貨節點
- 畫面**停留在銷貨階段**

│ SH001  IC-7805  台北電子  100  [撿貨中] │ 已出貨：1        │
│        [+ 追加] [✗ 取消]               │                  │

**狀態顏色：**

**可執行操作：**

- 取消：取消該筆出貨（需填原因）

### 4-8 銷退（有單據）

**進入節點後：**
```
左側：銷退單列表
  [+ 新增銷退單]
```

**點選或新增銷退單 → 進入步驟區：**

```
┌──────────┬────────────────┬────────────────────┐
│ ① 銷退   │ ② 選擇銷退項目 │ 決策彙總           │
│    對象  │  （從完成單    │                    │
│（已帶入）│   選取）       │ [產生銷退單]        │
└──────────┴────────────────┴────────────────────┘
```

**步驟一：銷退對象**
- 由完成節點帶入客戶資訊
- `Enter` 直接進入步驟二

**步驟二：選擇銷退項目**
- 顯示該客戶的已完成銷貨項目
- 勾選要銷退的項目
- 填入銷退原因（必填）
- 填入銷退數量

**右側決策彙總區**
```
決策彙總
─────────────────
料號 A  100 個  品質問題
─────────────────
[產生銷退單]
```

**產生銷退單後：**
- 狀態：待客戶退貨
- 客戶退貨並簽收後 → 狀態：已完成
- AR 處理由財務模組負責，本工作台不顯示

### 4-9 保固（有單據）

**進入節點後：**
```
左側：保固申請單列表
  [+ 新增保固申請]
```

**點選或新增 → 進入步驟區：**

```
┌──────────┬────────────────┬──────────────┬────────────────────┐
│ ① 銷貨   │ ② 選擇保固項目 │ ③ 填入保固   │ 決策彙總           │
│    對象  │  （從完成單    │    申請資訊  │                    │
│（已帶入）│   選取）       │              │ [產生保固申請單]    │
└──────────┴────────────────┴──────────────┴────────────────────┘
```

**步驟三：填入保固資訊**
- 問題描述（必填）
- 故障狀況說明
- 客戶提供的相關照片/文件

**產生保固申請單後：**
- 通知採購部門向廠商申請保固
- 採購流程接手，本工作台顯示申請狀態
