## 二、KPI BAR（PRO 限定）

> 庫存模組專屬，統計週期：本月
> 依使用者角色自動顯示對應層級
> 若同時兼任多個層級才顯示 Tab 切換

### 個人層級（倉管人員）

```
撿貨效率    ████████████  95%  時間達成率 × 正確率
包貨效率    █████████░░░  88%  時間達成率 × 正確率
```

**個人業績量（Exp 加分，非 KPI）：**
```
本月驗收上架：42 筆  +840 Exp
本月盤點庫位：28 格  +560 Exp
（鼓勵承接驗收/盤點工作，避免只搶撿貨包貨）
```

### 團隊/公司層級（倉管組長 / 負責人）

```
驗收上架效率  ████████░░░░  82%  當日到貨當日上架完成率  ⚠️
庫存錯誤率    ██░░░░░░░░░░   4%  盤點差異 / 總料號（越低越好）⚠️
出入庫效率    █████████░░░  91%  當日完成 / 當日應完成
```

**KPI 計算說明：**

```
撿貨效率 = 時間達成率 × 正確率
  時間達成率 = MIN（標準時間/實際時間, 1）
  正確率 = 交包貨掃描確認無異常的筆數 / 總撿貨筆數
  若撿錯（交接時發現不符）→ 該筆正確率 = 0，並記錄錯誤
  例：標準 5分/筆，實際 4分，正確 100% → 效率 100%（最高 100%）
      標準 5分/筆，實際 7分，正確  95% → 效率 68%

包貨效率 = 時間達成率 × 正確率
  正確率 = 客戶簽收後無品項客訴 / 總包貨筆數
  若包錯（客戶回報）→ 記錄在包貨員名下

驗收上架效率 = 當日到貨當日上架完成率
  當日 18:00 前完成上架 = 達標
  隔日才完成 = 未達標，計入效率下降

庫存錯誤率 = 盤點發現差異筆數 / 盤點總料號筆數
  反映整體上架品質（無法歸責個人，團隊指標）
  目標 < 2%

出入庫效率 = 當日完成出入庫 / 當日應完成出入庫
  綜合反映整體倉管運作
  目標 > 95%

標準時間設定：
  由倉管組長在 NX03 系統設定 > 標準作業時間
  例：驗收 8分/筆 / 撿貨 5分/筆 / 包貨 6分/筆
```

## 四、入庫 Tab — 作業節點

---

### 4-1 待到貨（查看為主）

**版型：全寬列表 + 右側統計**

```
┌────────────────────────────────────────┬──────────────────┐
│ 待到貨清單   [今日] [明日] [本週] 篩選  │ 今日到貨統計      │
│                                        │ 預計今日：3 批    │
│ PO-001  德國汽配  3料號  今日 14:00    │ 預計明日：1 批    │
│         [⚠️ 請準備驗收空間]            │                  │
│ PO-002  台北馬勒  2料號  今日 16:00    │ 待準備倉位：2 批  │
│ PO-003  進口貨   5料號  明日 ETA       │                  │
└────────────────────────────────────────┴──────────────────┘
```

**欄位：**
- 採購單號 / 廠商 / 料號數 / 預計到貨時間 / 付款條件 / 狀態

---

### 4-2 驗收（有單據）

**進入節點後：**
```
左側：待驗收進貨單列表
  單據號 / 廠商 / 料號數 / 到貨時間
  [+ 建立進貨單]
```

**點選進貨單 → 進入步驟區：**

```
┌──────────┬────────────────┬──────────────┬────────────────────┐
│ ① 確認   │ ② 逐筆驗收     │ ③ 異常處置   │ 決策彙總           │
│    廠商  │    核對料號    │              │                    │
│（已帶入）│    數量外觀    │              │ [確認驗收] Alt+S   │
└──────────┴────────────────┴──────────────┴────────────────────┘
```

**步驟二：逐筆驗收**

每個料號一列：
```
料號 A  IC-7805 稳壓器  預期 100個
  實收數量：[____] 個
  外觀狀態：[正常 ▼]（正常 / 數量異常 / 瑕疵品）
  [📷 拍照]（異常時必填）
  備註：[____________]
```

> 手機版：一次顯示一個料號卡片，上下滑動切換
> 大字顯示料號+預期數量，倉庫環境易讀

**步驟三：異常處置（有異常時才顯示）**

```
通知採購組長決定：
  ○ 全數退回廠商
  ○ 正常品入帳，異常品退回
  ○ 全數接受，要求折讓

選定後 → [確認驗收] Alt+S
```

**右側決策彙總：**
```
決策彙總
─────────────────
料號 A  100個  正常    → 入帳
料號 B  45/50  數量不符 → 退貨 5個
料號 C  50個   瑕疵品  → 全退

→ 入帳：2 個料號
→ 退貨：1 個料號（全退）
→ 短缺：1 個料號（5個）

[確認驗收] Alt+S
```

**確認後：**
- 正常品 → 入帳節點
- 異常品 → 退貨節點（支線）
- 系統記錄驗收員/驗收時間（效率計算用）

```
│ 料號 C   50個  均價 $12.00           │ ✓ 系統分貨建議     │
│ 總入帳金額：NT$1,450                  │                    │
│                                      │                    │

```

### 4-5 分貨上架（有單據）

> 入帳後系統依各倉安全量建議分貨

**進入節點後：**
```
左側：待分貨進貨單列表
  單據號 / 廠商 / 料號數 / 入帳時間
```

**點選進貨單 → 進入步驟區：**

```
┌──────────┬────────────────┬──────────────┬────────────────────┐
│ ① 查看   │ ② 確認/調整    │ ③ 執行上架   │ 分貨結果預覽       │
│  分貨建議│    分貨數量    │    確認庫位  │                    │
│          │                │              │ [確認執行] Alt+S   │
└──────────┴────────────────┴──────────────┴────────────────────┘
```

**步驟一：查看系統分貨建議**

```
料號 A  共 100個：
  有待出貨 SO [橘色標示] → 先出貨  60個
  BW1 分倉補貨（低於安全量）→      30個
  本倉上架                →        10個

料號 B  共 50個：
  MW1 主倉（低於安全量）→          50個
```

**步驟二：確認/調整分貨數量**
- 可手動調整各倉分配數量
- 總數不可超過入帳數量
- 有待出貨 SO 的部分橘色標示優先

**步驟三：執行上架（本倉部分）**

```
本倉上架逐筆確認：
  料號 A  10個
  指定庫位：[A-01-1 ▼]（下拉選擇或掃描庫位 QR Code）
  [確認上架]

料號 B  50個
  指定庫位：[B-03-2 ▼]
  [確認上架]
```

> ⚠️ 上架不計入個人 KPI 正確率（原因：多人上架責任難以歸屬）
> 但完成上架筆數計入個人 Exp 業績，鼓勵執行

**確認執行後：**
- 本倉上架 → 庫存更新至指定庫位
- 他倉補貨 → 自動建立調撥單
- 有待出貨 SO → 自動進入出庫 Tab 待撿貨節點
- 系統記錄：分貨時間（驗收上架效率計算用）

## 五、出庫 Tab — 作業節點

---

### 5-1 待撿貨（有單據）

**進入節點後：**
```
左側：撿貨任務列表（依急迫性排序）

[⚠️ 今日截止] PK-001  台北電子  3料號  配送  截止 14:00  [領取任務]
[一般]         PK-002  新竹科技  1料號  自取  截止今日    [領取任務]
[一般]         PK-003  台中汽修  2料號  寄貨  截止明日    [領取任務]
```

> 倉管人員需「領取任務」才算接受，系統記錄開始時間（計算效率）

**點選撿貨單 → 進入步驟區：**

```
┌──────────┬────────────────┬────────────────────┐
│ ① 確認   │ ② 依庫位順序   │ 交接確認           │
│  出貨資訊│    逐筆撿貨    │                    │
│（已帶入）│                │ [完成撿貨] Alt+S   │
└──────────┴────────────────┴────────────────────┘
```

**步驟一：確認出貨資訊**
- 客戶 / 出貨方式 / 截止時間
- `Enter` 直接進入步驟二

**步驟二：依庫位順序逐筆撿貨**

```
系統依庫位位置排序，減少走動距離：

1/3  庫位 A-01-1  IC-7805 稳壓器  100個
     [✓ 已撿到]  [✗ 找不到]

2/3  庫位 B-02-3  電容 100uF/25V  50個
     [✓ 已撿到]  [✗ 找不到]

3/3  庫位 C-01-2  電阻 10K 1/4W  5,000個
     [✓ 已撿到]  [✗ 找不到]
```

> 手機版：一次顯示一個庫位任務
> 大字顯示庫位代碼 + 料號 + 數量
> 非常適合邊走邊操作

**找不到貨的處理：**
```
點擊 [✗ 找不到] → 選擇：
  ○ 繼續找（先跳過此筆，完成其他再回來）
  ○ 確認找不到 → 進入異常節點
    系統通知業務人員（業務決定改走調撥/調貨）
    通知倉管組長
```

**交接確認（撿貨→包貨的關鍵步驟）：**
```
撿貨完成後，交給包貨前的核對：

系統顯示應撿 vs 實際撿：
  ✅ IC-7805    應撿 100個  實撿 100個  正確
  ✅ 電容100uF  應撿  50個  實撿  50個  正確
  ⚠️ 電阻 10K  應撿 5000個 實撿 4980個 差 20個 → 需說明

確認無誤 → [完成撿貨，交包貨] Alt+S
  → 系統記錄：撿貨員 / 完成時間 / 正確率
  → 計入個人撿貨效率 KPI
  → 進入包貨節點
```

### 5-3 包貨（有單據）

**進入節點後：**
```
左側：待包貨清單
  PK 單號 / 客戶 / 料號數 / 出貨方式 / 撿貨完成時間
```

> 倉管人員點擊「接受包貨任務」→ 系統記錄開始時間

**點選 → 進入步驟區：**

```
┌──────────┬────────────────┬────────────────────┐
│ ① 確認   │ ② 依出貨方式   │ 交接確認           │
│  撿貨清單│    執行包貨    │（掃描核對）        │
│（核對）  │                │ [完成包貨] Alt+S   │
└──────────┴────────────────┴────────────────────┘
```

**步驟一：確認撿貨清單（交接掃描）**
```
核對收到的料號與數量是否與系統記錄相符
若不符 → 標記異常，退回撿貨員重撿
```

**步驟二：依出貨方式包貨**

```
配送 / 寄貨：
  完整封箱 + 出貨標籤貼紙
  BOX 編號自動產生：BOX-202604-MW1-00123
  系統通知物流組長（產生 DN 送貨單）

自取：
  裝袋/箱但不封箱
  BOX 編號通知業務轉告客戶
  客戶現場核對後才封箱

國際出口：
  填入每箱毛重/淨重/長×寬×高（cm）
  系統自動產生裝箱單（Packing List）
```

**完成包貨：**
```
[完成包貨] Alt+S
  → 系統記錄：包貨員 / 完成時間
  → 計入個人包貨效率 KPI
  → 進入出貨節點
```

```
  盤點單號 / 盤點類型 / 範圍 / 排程日期 / 指派人員
```

### 6-2 盤點中（有單據）

**進入節點後：**
```
左側：進行中盤點清單
  盤點單號 / 範圍 / 進度（已盤X/總Y庫位）/ 負責人
```

**點選盤點單 → 進入步驟區：**

```
┌──────────┬────────────────┬────────────────────┐
│ ① 確認   │ ② 依庫位順序   │ 盤點進度           │
│  盤點範圍│    逐庫位清點  │ 已完成 X / Y 庫位  │
│（已帶入）│                │ [提交盤點] Alt+S   │
└──────────┴────────────────┴────────────────────┘
```

**步驟二：逐庫位清點**

```
庫位 A-01-1（系統庫存：IC-7805 × 50個）
  實際數量：[____] 個
  [正常 / 有差異]

庫位 A-01-2（系統庫存：電容 × 200個）
  實際數量：[____] 個
  [正常 / 有差異]
```

> 手機版：一次顯示一個庫位，大字顯示
> 適合倉管人員在倉庫邊走邊清點

**雙人盤點（全倉盤點時）：**
```
同一庫位需兩位倉管人員各自獨立填入數量
兩次結果不同 → 系統自動提示第三次確認
```

**提交盤點：**
```
[提交盤點] Alt+S
  → 進入差異確認節點
  → 系統計算實際 vs 系統差異清單
  → 系統記錄：盤點員 / 完成庫位數（計入 Exp 業績）
```

### 6-3 差異確認（倉管組長操作）

**版型：全寬差異清單 + 右側彙總**

```
┌────────────────────────────────────────┬──────────────────┐
│ 盤點差異清單                            │ 差異彙總          │
│                                        │                  │
│ 庫位 A-01-1  IC-7805                   │ 差異庫位：3      │
│   系統庫存：50個  實際清點：48個        │ 差異料號：3      │
│   差異：-2個                           │ 差異金額：$432   │
│   [覆盤確認] [標記原因▼]               │                  │
│                                        │ [送主管審核]      │
│ 庫位 B-02-3  電容100uF                 │ Alt+S            │
│   系統庫存：200個  實際清點：200個      │                  │
│   差異：0  ✅ 正常                      │                  │
└────────────────────────────────────────┴──────────────────┘
```

**差異原因標記（必填）：**

| 代碼 | 說明 |
|------|------|
| LOST | 貨物遺失（找不到）|
| DMG | 貨物損壞（無法販售）|
| ERR-IN | 入庫錯誤（多入或少入）|
| ERR-OUT | 出庫錯誤（多出或少出）|
| THEFT | 疑似竊盜（需通報）|
| OTHER | 其他原因 |

### 6-4 異常處理（倉管部經理審核）

**版型：全寬審核清單**

```
待審核差異
─────────────────
盤點單 SL-202604-001
  IC-7805  差異 -2個  原因：ERR-OUT（出庫錯誤）
  金額影響：-$17

審核決定：
  [✓ 核准調整]  → 系統調整庫存，記錄損耗
  [✗ 退件重查]  → 退回組長重新覆盤
```

**核准後：**
- 系統自動調整 `stock_balance`
- 產生盤點差異報告
- 解除庫位凍結
- 若為 LOST/DMG → 通知採購考慮補貨
