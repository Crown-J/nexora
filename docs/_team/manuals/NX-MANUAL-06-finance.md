## §1. 這本手冊是什麼

這本講「公司的錢怎麼進、怎麼出、怎麼算稅」：

- 應收帳款（誰欠我多少、幾時到期、催收）。
- 應付帳款（我欠誰多少、幾時要付）。
- 收付款（票據、4 種付款方式、一對多沖銷）。
- 折讓（採購側保固退錢 + 銷貨側銷退退錢、兩路徑整合、本書 §6 詳寫）。
- 月關帳（每個月把帳鎖起來、避免事後改動）。
- 401 雙月一期申報（給國稅局上報營業稅）。
- 帳戶管理（往來對象帳戶 vs 公司自有銀行帳戶）。
- **⭐⭐ LITE 內含 vs 加購套件邊界**（Crown 特別交代揭露：電子發票、自動上傳、金流串接、本書 §9 詳寫）。

### 1.1 財務中心結構（3 區 6 卡）

| 區 | 卡 | 開放狀況 |
|---|---|---|
| **帳款管理** | 應收帳款、應付帳款 | LITE 全開 |
| **收付款 + 折讓** | 票據管理、折讓核可 | LITE 全開 |
| **關帳與帳戶** | 關帳作業 + 401、帳戶管理 | LITE 全開 |

⭐ 6 張卡 LITE 全開放、沒有任何套件鎖卡（功能完整、但範圍有界線、見 §9）。

### 1.2 ⭐⭐ LITE 財務的明確邊界（Crown 重點交代、§9 詳寫）

⭐ **總經理關心的「LITE 內含什麼、什麼算加購套件」、簡要先說、§9 詳細展開**：

#### LITE 內含

| 項目 | 開放程度 |
|---|---|
| 應收帳款追蹤 | ✅ 完整 |
| 應付帳款追蹤 | ✅ 完整 |
| 票據 4 種收付（現金 / 匯款 / 支票 / 信用卡）| ✅ 完整 |
| 折讓核可（P 進貨折讓 / S 銷貨折讓）| ✅ 完整 |
| 月關帳 | ✅ 完整 |
| 401 雙月一期預覽 | ✅ 完整 |
| 401 TXT 兩檔下載（媒體檔 + 主檔）| ✅ 完整、給人工上傳國稅局用 |
| 帳戶管理（往來 / 自有銀行）| ✅ 完整 |

#### LITE 不含、需加購對應套件（已對齊新版本模型 8 套件）

| 項目 | 屬哪個套件 | 指路 | 目前替代做法 |
|---|---|---|---|
| **電子發票自動印 / 寄客戶** | **電子發票套件** | NX-MANUAL-PACKAGE-02 | 用發票機 / 第三方（綠界 / 藍新 / ezPay）開、手動標 NEXORA 銷貨單為 INVOICED |

## §2. 財務中心入口

### 2.1 三種進財務中心的方法

| 方法 | 怎麼做 |
|---|---|
| 螢幕最上方那排 | 點「財務」分頁 |
| 星球按鈕 | 點左上星球（或 `Alt+X`）→ 左欄選「財務」|
| 直接打網址 | 網址列尾端 `/dashboard/finance` |

⚠️ 沒有財務權限的員工、財務分頁不會顯示。LITE 預設**只有負責人 + 自訂的會計角色員工**能進財務區。

### 2.2 財務中心首頁長什麼樣

- 頂部標題：「FINANCE CENTER / 財務中心」
- 副標：「月關帳 + 401 雙月一期申報、應收應付彙整、票據與帳戶管理」
- 下方 3 區 6 張卡直排展開。

### 2.3 工作流總覽

```
日常作業（每天 / 每週）：
   業務開銷貨單 → INVOICED → 自動掛應收 (§3)
   採購單 → CONFIRMED → 自動掛應付 (§4)
   客戶來付款 → 業務 / 會計開收款票據沖應收 (§5)
   付廠商貨款 → 會計開付款票據沖應付 (§5)
   有折讓 → 走折讓核可流程 (§6 Stop 2)
   ↓
月關帳節奏：
   每月底 → 月關帳 (§7 Stop 2)
   雙月末 → 401 預覽 + TXT 兩檔下載 (§7 Stop 2)
   會計拿 TXT → 手動上傳國稅局網站
   上報完成 → NEXORA 標「已上報」
```

## §3. 應收帳款（AR）

### 3.1 是什麼

「**客戶欠公司多少錢、什麼時候要還**」的清單。每筆 AR 來自一張上游單據、會自動掛進來、會計只需要追蹤狀態 + 沖銷收款。

### 3.2 應收的兩種來源

| 來源類型 | 從哪來 | 業務語意 |
|---|---|---|
| **SO 銷貨單** | 銷貨單 INVOICED 時自動建（NX-MANUAL-05 §6.10）| 客戶買貨欠的 |
| **PR 廠商退費衍生應收** | 採購側退供應商 → 廠商該退錢給公司（NX-MANUAL-03 §8）| **「我們的供應商欠我們」、罕見但會發生** |

⭐ NEXORA 應收**不只是「客戶欠的」**、也涵蓋「廠商該退我們的」、財務一張清單統一管。

### 3.3 5 狀態流轉

| 狀態 | 是什麼 | 顏色 |
|---|---|---|
| **OPEN 未付** | 應收已掛、客戶尚未付款 | 一般 |
| **PARTIAL 部分付** | 收了一部分、還有餘額 | 黃 |
| **PAID 已付清** | 完全收齊、沖銷完成 | 綠 |
| **OVERDUE 已逾期** | 過了到期日還沒付清（系統自動判定）| 紅 |
| **WRITTEN_OFF 已沖銷** | 收不回來、會計手動沖呆帳 | 灰 |

#### 自動狀態邏輯

```
原始狀態（OPEN / PARTIAL）+ 過了到期日
   ↓
系統列表顯示 displayStatus = OVERDUE（前端視覺紅色）
（資料庫 status 不一定改、是即時計算的「顯示狀態」）
```

### 3.4 列表畫面欄位

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產（例：`NX05AR0001234`）|
| **來源類型** | SO 銷貨 / PR 廠商退費 |
| **來源單號** | 來源 SO / PR 的 docNo（可點跳）|
| **客戶 / 廠商** | 從往來對象帶 |
| **應收日** | 帳掛上的日期 |
| **到期日** | 依付款條件算（例：月結 30 天 → 應收日 + 30 天）|
| **原始金額** | 應該收多少 |
| **已收金額** | 累計沖銷掉的（多筆收款累加）|
| **餘額** | 原始 − 已收 |
| **狀態** | 5 狀態（含 displayStatus）|
| **付款條件** | 預付 / NET30 / NET60 / NET90 等（從客戶帶）|
| **逾期天數** | 過了多少天（OVERDUE 才顯示）|
| **備註** | 自由文字 |

### 3.5 列表上方的篩選

- **狀態篩選**：全部 / 未付 / 部分付 / 已付清 / 逾期 / 已沖呆帳。
- **關鍵字搜尋**：可打單號、客戶名稱、來源單號。

### 3.6 應收詳情頁 + 收款沖銷歷史

點某筆 AR 進詳情頁：

- 上半顯示基本資訊。
- 下半顯示「**沖銷歷史**」（settlements）、每行：
  - 票據單號（哪張收款）
  - 收款日期
  - 收款方式（現金 / 匯款 / 支票 / 信用卡）
  - 沖銷金額（這張票據用了多少抵這筆 AR）
  - 累計沖銷金額
  - 餘額

⭐ 一筆 AR 可能被**多張票據**分次沖銷（例：客戶分 2 次付）。

### 3.7 催款

對逾期應收、會計可發起「**催款**」動作：

| 操作 | 系統做什麼 |
|---|---|
| 從某筆 AR 詳情頁按「催款通知」| 寫一筆催款紀錄（純內部紀錄、不自動發郵件 / 訊息）|
| 填催款備註 | 例：「已電話聯絡客戶、承諾下週付」|
| 系統 log 催款歷史 | 後續可從報表看「業務員 / 客戶 催款頻率」 |

⚠️ NEXORA 目前**只記內部催款動作、不自動寄催款訊息**。客戶要實際打電話 / 寄 Email / 寄律師信、會計自己做。

### 3.8 沖呆帳（WRITTEN_OFF）

客戶倒帳、收不回來：

```
1. 會計在該筆 AR 詳情頁、按「沖呆帳」
2. 填沖銷原因（必填、稽核用）
3. 確認 → 狀態切 WRITTEN_OFF、餘額視為「公司損失」
```

⚠️ 沖呆帳會在「**月關帳**」（§7 Stop 2）時影響應收帳款餘額、但**不會自動進損益表**、要會計手動處理對應的會計分錄。

### 3.9 資料來源 / 資料去向

- 來源：
  - 銷貨單 INVOICED 自動建（NX-MANUAL-05 §6.10）。
  - 採購側退供應商過帳產生「廠商該退錢」紀錄（NX-MANUAL-03 §8）。
- 去向：
  - 收款票據沖銷（§5）。
  - 銷退折讓沖帳（D 折讓、NX-MANUAL-05 §7.7）。
  - 月關帳的應收期末餘額（§7 Stop 2）。
  - 401 雙月銷項統計（§7 Stop 2）。
  - 報表「應收帳齡 / 業務員應收追蹤」（NX-MANUAL-07）。

## §4. 應付帳款（AP）

### 4.1 是什麼

「**公司欠誰多少錢、什麼時候要還**」的清單。對稱於應收、但角色相反。

### 4.2 應付的多種來源

| 來源類型 | 從哪來 | 業務語意 |
|---|---|---|
| **PO 採購單** | 採購單 CONFIRMED 時自動建（NX-MANUAL-03 §6.3）| **核心、最常見**：採購應付（先款後貨設計）|
| **RR 進貨單** | 部分場景（不經過 PO 直接收貨）| 緊急採購、現場掃貨 |
| **TI 同行調貨** | 跟同行調貨欠款 | 銷貨缺貨救急時 |

### 4.3 ⭐ 應付彙整視圖（Payable View）

財務中心首頁的「應付帳款」卡進去、預設顯示**彙整視圖**、把這 2 種混合呈現：

| 種類 | 是什麼 | 來源 |
|---|---|---|
| **AP 採購應付** | 正常採購欠款 | PO / RR / TI |
| **SR Allowance 銷退折讓** | 客戶退貨、公司要退錢 / 折讓 | NX-MANUAL-05 §7.7 R/D 自動建 |

⭐ **為什麼把 SR Allowance 也算「要付的款項」**：

- 銷退 R 退錢：公司要實際付錢給客戶 = 我欠客戶錢 = 廣義應付。
- 銷退 D 折讓：之後客戶下次採購會扣帳 = 我也算欠客戶錢、不過直接從應收扣。
- 會計看「應付彙整視圖」一次掌握「**所有我要付出去的款項**」、不漏帳。

⚠️ **可能會問**：「為什麼客戶的退費出現在『應付』？」

> 「應付」這個帳本的意義 = **公司要付出去的款項**、不限定付給「廠商」。銷退 = 公司要把錢退回給客戶、本質就是「公司要付出去」、所以歸應付彙整視圖。原始 AP 表只記廠商欠款、彙整視圖加上 SR 折讓、給會計看完整的「**錢要往外出**」清單、不漏。

### 4.4 5 狀態流轉

| 狀態 | 是什麼 | 顏色 |
|---|---|---|
| **OPEN 未付** | 應付已掛、尚未付款 | 一般 |
| **PARTIAL 部分付** | 付了一部分 | 黃 |
| **PAID 已付清** | 完全付清 | 綠 |
| **OVERDUE 已逾期** | 過了到期日（注意：對廠商來說「我們欠他們的」逾期、信用會掉）| 紅 |
| **VOID 已作廢** | 來源單據作廢、應付也跟著作廢（例：採購單取消、沖掉應付）| 灰 |

⚠️ NEXORA 應付沒有「WRITTEN_OFF 沖呆帳」狀態（廠商不會把錢「沖呆」、只有客戶會被沖呆）。

### 4.5 列表畫面欄位

跟應收（§3.4）結構幾乎一樣、差別：

- 「客戶 / 廠商」→ 改成「供應商」（從往來對象 S 帶）
- 「逾期天數」 → 同樣顯示、但意義是「**我們逾期沒付對廠商的天數**」、信用問題。

### 4.6 操作 + 沖銷邏輯

跟應收（§3.6）對稱：

- 點 AP 進詳情頁、看沖銷歷史（多筆付款票據可分次沖）。
- 從 AP 詳情頁觸發付款（建立付款票據、§5）。

### 4.7 採購單取消的沖帳行為

⚠️ **重要邊界**（呼應 NX-MANUAL-03 §6.5「取消已認列應付的採購單」）：

```
採購單 CONFIRMED → 已產 AP 應付
   ↓
採購單 → CANCELLED 取消
   ↓
系統自動沖原 AP：狀態切 VOID + 餘額為 0
（不需會計手動處理、系統自動做）
```

⚠️ 但如果該 AP 已有部分付款、會擋 cancellation、要先處理已付的部分。

### 4.8 資料來源 / 資料去向

- 來源：
  - PO 採購單 CONFIRMED（NX-MANUAL-03 §6.3）。
  - RR 進貨單緊急採購。
  - TI 同行調貨。
  - 銷退 R/D 自動建的 Allowance（從彙整視圖看到）。
- 去向：
  - 付款票據沖銷（§5）。
  - 採購折讓沖帳（P 折讓、NX-MANUAL-03 §9.9 保固 REF + A）。
  - 月關帳的應付期末餘額（§7 Stop 2）。
  - 401 雙月進項統計（§7 Stop 2）。
  - 報表「應付帳齡 / 廠商付款追蹤」（NX-MANUAL-07）。

## §5. 票據 / 收付款（一張票多筆沖銷）

### 5.1 是什麼

公司「**錢進來 / 錢出去**」的紀錄。NEXORA 把所有現金移動統一叫「票據」（不只實體支票、包含現金、匯款、刷卡）。

### 5.2 2 種票據類型 × 4 種付款方式

| 票據類型 | 是什麼 |
|---|---|
| **R 收款** | 客戶付錢給公司、沖應收 |
| **P 付款** | 公司付錢給廠商、沖應付 |

| 付款方式 | 代碼 | 適合場景 |
|---|---|---|
| **現金** | CASH | 小額、即時 |
| **匯款** | TRANSFER | 銀行轉帳、大額為主 |
| **支票** | CHECK | 票期、延後兌現 |
| **信用卡** | CREDIT | 客戶刷卡 / 公司付廠商刷企業卡 |

### 5.3 ⭐ 一張票一對多沖銷

⭐ **NEXORA 票據設計的核心**：**一張收款 / 付款票據、可以同時沖銷多筆應收 / 應付**。

例：

```
場景：客戶和興汽車匯款 50,000 來、用來付：
  - AR 單 NX05AR0001230：18,000（一張舊發票剩餘）
  - AR 單 NX05AR0001234：32,000（這個月新的發票）
        合計：50,000

會計操作：
1. 建一張收款票據（R / TRANSFER / 和興汽車 / 50,000 / 今天）
2. 在「沖銷明細」加 2 行：
   - 行 1：選 AR 單 0001230 / 沖 18,000
   - 行 2：選 AR 單 0001234 / 沖 32,000
3. 過帳 → 系統同時沖 2 筆 AR、各自更新已付金額 / 餘額 / 狀態
```

### 5.4 列表畫面

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產 |
| **類型** | R 收款 / P 付款 |
| **付款方式** | 4 種圖示 |
| **對象** | 客戶或廠商 |
| **金額** | 票據金額 |
| **狀態** | 草稿 / 已過帳 / 已作廢 |
| **票據日期** | 收款 / 付款日 |
| **備註** | 自由文字 |

### 5.5 開新票據（含沖銷）

按「**+ 新增票據**」彈出開單表單：

#### 基本資訊

| 欄位 | 說明 |
|---|---|
| **類型** | R 收款 / P 付款（必選）|
| **付款方式** | 4 選 1 |
| **對象** | 客戶（R 用、從 C 身分挑）/ 廠商（P 用、從 S 身分挑）|
| **金額** | 票據金額 |
| **日期** | 預設今天 |
| **備註** | 自由文字 |

#### 沖銷明細

| 欄位 | 說明 |
|---|---|
| **沖哪一筆** | 從該對象的「未付清」AR / AP 清單挑 |
| **沖多少** | 這筆票據要拿多少抵 |

⚠️ 規則：

- 「沖銷明細各行加總」必須 ≤ 票據金額。
- 沖銷明細加總 < 票據金額時、差額會留在票據上、之後可再用（**這部分多收 / 多付的處理 LITE 可能簡化、複雜場景需手動處理**）。

### 5.6 沖銷後系統做什麼

```
1. 票據單據建立、狀態「已過帳」
2. 依沖銷明細、逐筆 AR / AP 更新：
   - 累加已收 / 已付金額
   - 重算餘額
   - 餘額 = 0 → 狀態切 PAID
   - 餘額 > 0 但 < 原始 → 狀態切 PARTIAL
3. 寫稽核紀錄（誰收/付、什麼日、用哪張票、沖哪些）
4. 月關帳統計用
```

### 5.7 查 AR / AP 的沖銷歷史

從應收應付詳情頁按「**沖銷歷史**」、列出該筆 AR / AP 所有的相關票據：

| 欄位 | 說明 |
|---|---|
| **票據單號** | 哪張收款 / 付款 |
| **付款日期** | 票據日 |
| **付款方式** | 4 種 |
| **沖銷金額** | 這張票據用了多少抵這筆 AR/AP |
| **備註** | 票據備註 |

⭐ 方便會計回溯「**這張發票被哪幾張票分次收 / 付的**」。

### 5.8 資料來源 / 資料去向

- 來源：會計手動建（依銀行對帳單、收到的支票、收到的現金等）。
- 去向：
  - 更新 AR / AP 狀態 + 已收 / 已付金額（§3 / §4）。
  - 月關帳統計（§7 Stop 2）。
  - 報表「收款 / 付款日明細」、「業務員業績（已收）」用（NX-MANUAL-07）。

⚠️ **LITE 不含金流自動串接**：銀行匯款進來、不會自動偵測 + 自動建收款票據、會計要看銀行對帳單手動建。是否升級加購「金流串接套件」由客戶決定（見 §9 Stop 2）。

## §6. 折讓核可 ⭐ 兩路徑整合章節

### 6.1 是什麼

「**折讓**」= 已認列的款項要打折扣 / 退一部分回去。NEXORA 的折讓不限定哪個方向、兩種折讓統一在這個模組管：

| 折讓類型 | 代碼 | 是什麼 | 業務語意 |
|---|---|---|---|
| **進貨折讓** | **P** | 我們的供應商要退錢回來給我們 | 我們少付 / 供應商少收 |
| **銷貨折讓** | **S** | 我們要退錢給客戶 | 我們少收 / 客戶少付 |

### 6.2 ⭐⭐ 三條來源路徑（跨手冊整合）

折讓單可以從三條路徑進來：

#### 路徑 A：採購側保固 REF + A → 自動建 P 進貨折讓

來自 NX-MANUAL-03 §9.9 保固申請單：

```
保固單 → 結果 = REF 退錢 → 退款方式 = A 折讓單
   ↓
系統自動建一張 DRAFT 折讓單（type = P 進貨折讓）
   ↓
財務核可後 → 自動沖原採購單對應的應付（NX-MANUAL-06 §4）
```

#### 路徑 B：銷貨側銷退 R/D → 自動建 S 銷貨折讓

來自 NX-MANUAL-05 §7.7 銷退單：

```
銷退單 → 過帳（returnMethod = R 退錢 / D 折讓）
   ↓
系統自動建一張 Allowance（type = S 銷貨折讓）
   ↓
依 R/D 分流：
   - R 退錢 → 折讓單獨立、之後實際付錢給客戶（走收付款、§5）
   - D 折讓 → 自動沖應收（NX-MANUAL-06 §3）
```

#### 路徑 C：人工建立折讓（會計手動）

會計遇到「無上游單據、純會計協議的折讓」場景、可手動建：

```
會計從「折讓核可」工作頁按「+ 新增人工折讓」
   ↓
填欄位：
   - 類型 P / S（必選）
   - 對象（廠商或客戶）
   - 日期
   - 金額
   - 關聯應收 / 應付（可選、選了 approve 後自動沖）
   - 備註（原因稽核用）
   ↓
建立 → 狀態 DRAFT、等主管核可
```

⚠️ 人工折讓常見場景：
- 跟廠商談判完、廠商口頭同意退一筆但沒給保固單據。
- 跟客戶談判完、客戶反映某問題、公司同意給折扣但沒走銷退單。

### 6.3 ⭐ 三條路徑匯入同一張表

⭐ 不管哪條路徑建的折讓單、進來都長一樣的單據：

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產 |
| **類型** | P 進貨折讓 / S 銷貨折讓 |
| **對象** | 廠商（P）或 客戶（S）|
| **折讓日** | 折讓建立日 |
| **金額** | 折讓金額 |
| **關聯應收 / 應付** | refArId / refApId、核可後沖這筆 |
| **狀態** | DRAFT / APPROVED / REJECTED |
| **核可人 / 時間** | 主管核可的人 + 時間 |
| **退回原因** | 主管駁回時填的理由 |
| **備註** | 自由文字 |

### 6.4 4 狀態流轉

| 狀態 | 是什麼 |
|---|---|
| **DRAFT 草稿** | 已建好、等主管核可 |
| **APPROVED 已核可** | 主管核可、自動沖對應 AR / AP |
| **REJECTED 已退回** | 主管駁回、不沖帳、可改後重送或作廢 |

⭐ 流轉：

```
（任一路徑建立）→ DRAFT
                    ├─ 主管核可 → APPROVED → 自動沖 AR/AP
                    └─ 主管退回 → REJECTED → 可改後重送
```

### 6.5 ⭐ 為什麼要主管核可（防亂打折）

⭐ NEXORA 折讓核可的核心原因：

> 折讓 = 公司放棄部分原本應得的錢。會計 / 業務員任何人都能建、但**只有主管能核可**、避免「自己人對自己人打折少收」、是防舞弊機制。

### 6.6 操作流程

```
業務員 / 會計：
   1. 用其中一條路徑建立折讓單（自動 / 自動 / 手動）
   2. 狀態 DRAFT、進入「折讓核可」工作頁的「待核可」清單

主管：
   3. 從首頁待辦看到「折讓待核可」
   4. 進「折讓核可」工作頁、看詳情：
      - 為什麼折讓（原因 / 來源）
      - 金額多少
      - 沖哪筆 AR / AP
   5. 決定：
      - 核可 → 狀態 APPROVED + 自動沖 AR/AP
      - 退回 → 填退回理由 → 狀態 REJECTED
      
業務員 / 會計：
   6. 從通知收到結果
   7. 核可 → 完事
   8. 退回 → 看理由、改後重送、或作廢
```

### 6.7 ⚠️ 自動路徑（A / B）vs 人工路徑（C）的核可差別

⚠️ **重要邊界**：

| 來源 | 是否仍需主管核可 |
|---|---|
| 路徑 A 保固 REF + A 自動建 | ✅ **仍要核可**（雙重把關：保固單已通過、但金額還要主管最後簽）|
| 路徑 B 銷退 R/D 自動建 | ⚠️ **目前實作會自動建並自動沖**（銷退已經是業務動作、折讓單純記錄）、實際不走 DRAFT 核可流程、看實作有沒有跳過 |
| 路徑 C 人工建立 | ✅ **必要核可**（最容易被亂打折、防舞弊機制最有用的入口）|

⚠️ 路徑 B 的核可邏輯實作細節 LITE 客戶目前在跑、實際是否走 DRAFT 還是自動 APPROVED 之後 Alex 跟總經理確認後補。

### 6.8 列表畫面

| 欄位 | 說明 |
|---|---|
| **單號** | 自動產 |
| **類型** | P / S 徽章 |
| **對象** | 客戶 / 廠商 |
| **金額** | 折讓金額 |
| **狀態** | DRAFT / APPROVED / REJECTED |
| **建立人** | 誰建的 |
| **建立日** | 何時建的 |
| **核可人 / 時間** | 主管 + 時間 |

### 6.9 資料來源 / 資料去向

- 來源：3 條路徑（採購側保固 / 銷貨側銷退 / 會計人工）。
- 去向：
  - 核可後自動沖 AR / AP（§3 / §4）。
  - 月關帳的折讓總額（§7）。
  - 401 雙月銷項 / 進項減項（§7 詳細）。
  - 報表「折讓總額 / 折讓對象分析」（NX-MANUAL-07）。

## §7. 月關帳 + 401 雙月一期

### 7.1 是什麼

兩個獨立但相關的會計動作、合在同一個工作頁（「關帳作業 + 401」）：

| 動作 | 頻率 | 為什麼 |
|---|---|---|
| **月關帳** | 每月一次 | 把上個月的帳「鎖起來」、避免事後改動 |
| **401 雙月一期申報** | 雙月一次（一期 = 2 個月）| 申報營業稅給國稅局 |

⭐ 月關帳是**內部財務動作**、401 是**對外稅務申報**、兩個獨立但聯動：401 雙月一期 = 包含 2 個月關帳的彙整。

### 7.2 月關帳的 4 狀態流轉

| 狀態 | 是什麼 |
|---|---|
| **OPEN 待關帳** | 月底剛建立、等會計開始關 |
| **CLOSING 關帳中** | 會計開始檢核、帳還沒鎖死 |
| **CLOSED 已關帳** | 完成關帳、月份的帳鎖死、不能再改 |
| **REOPENED 已重開** | 已關後又被重新打開（特殊狀況、需填理由）|

#### 合法切換

```
OPEN → CLOSING → CLOSED
                   ↓
                   REOPENED → CLOSING → CLOSED（再關一次）
```

### 7.3 開新關帳

```
場景：6 月底要把 5 月的帳關掉

1. 會計按「+ 建立關帳」、傳入今日
2. 系統自動把日期 normalize 到「上月最後一天」（系統判定）
3. 建立 OPEN 狀態的關帳單、編號自動產
```

### 7.4 月關帳操作

#### 從 OPEN 切到 CLOSING

會計確認該月所有單據都已處理完（銷貨 / 進貨 / 收付款 / 折讓）→ 按「關帳中」→ 狀態切 CLOSING、系統開始檢核：

- 該月期間所有銷貨單是否都 INVOICED 或 CANCELLED（不能停在 PICKING）。
- 該月所有應收 / 應付是否狀態正常。
- 該月所有票據是否已過帳。
- ⚠️ 有未處理的單會在這跳出「警告清單」、會計要先處理完。

#### 從 CLOSING 切到 CLOSED

確認沒問題 → 按「完成關帳」→ 狀態切 CLOSED：

- 該月所有相關單據鎖死（不能改、不能新增日期落在該月的單）。
- 帳上資料定稿、可進報表。
- 也可選 isAuto 模式（系統定時自動關、不需人工按）。

### 7.5 REOPENED 重新打開

特殊狀況、已關的月份想改（補漏的單、修錯帳）：

```
1. 會計按「重新打開」
2. 必須填重開理由（必填、稽核用）
3. 確認 → 狀態切 REOPENED
4. 該月又能新增 / 改單
5. 處理完後重新關帳：CLOSING → CLOSED 再走一次
```

⚠️ **重新打開會被稽核紀錄保留**（誰開的、何時、什麼理由）、是嚴重操作、頻繁重開會引起會計師注意。

### 7.6 401 雙月一期預覽

⭐ NEXORA 401 期 = 「**reportPeriod**」、雙月一期：

```
2026 年 1-2 月 → reportPeriod = '202601-02' 或類似格式
2026 年 3-4 月 → '202603-04'
2026 年 5-6 月 → '202605-06'
... 一年 6 期
```

#### 預覽畫面內容（2026-06-04 BUG #6 修後算法）

⭐ **2026-06-04 重要修正**：preview 應納稅額算法改成跟 TXT export 一致的「**拆 5% 稅**」正確算法、不再是「（含稅淨額相減）× 5%」的近似值。

選定某期 → 點「401 預覽」：

| 區塊 | 顯示內容 |
|---|---|
| **期別資訊** | reportPeriod / months / startDate / endDate |
| **銷項彙整**（賣給客戶）| 含稅總額 / 銷退含稅 / **未稅淨額（subtotal）** / **銷項稅額（taxAmount）** / 銷貨單筆數 / 銷退單筆數 |
| **進項彙整**（向廠商買）| 含稅總額 / 進退含稅 / **未稅淨額（subtotal）** / **進項稅額（taxAmount）** / 進貨單筆數 / 退供應商單筆數 |
| **應納稅額** | **銷項稅額 − 進項稅額**（跟 TXT 一致、正確拆 5%）|
| **本期涵蓋的關帳期** | 列出本 401 期包含哪些月關帳（一期 2 月、所以 2 筆）|
| **filed 已上報** | true / false（會計手動標）|
| **readyToFile 可上報** | 系統判定 2 個月關帳都 CLOSED 才 true |

⭐ **數學等價說明（給會計）**：

> 對 5% 稅率的單一稅別、「銷項稅 − 進項稅」跟「(銷項未稅淨額 − 進項未稅淨額) × 5%」**結果相同**、只是先後乘的順序不同。系統實際從每張單的 `taxAmount` 欄位累加、跟 TXT 申報檔的算法用同一條路、保證 preview 跟 TXT 上的數字對得起來。

⚠️ **手冊 v1.0 描述的 bug**：之前手冊跟系統都把「(含稅淨額 − 含稅淨額)」當應納稅額（缺乘 5%）、preview 跟 TXT 差 20 倍、會嚇到客戶。BUG #6 已修、preview 跟 TXT 兩處數字現在完全對齊。

### 7.7 401 TXT 兩檔下載

⭐ NEXORA 為「**人工上傳國稅局**」設計：

| 檔案 | 是什麼 |
|---|---|
| **媒體檔（mediaFile）** | 國稅局指定的媒體申報格式 |
| **主檔（mainFile）** | 國稅局指定的主檔格式 |

操作：

```
1. 該期 401 預覽顯示 readyToFile = true（2 個月關帳都 CLOSED）
2. 會計按「下載 TXT 兩檔」
3. 系統產出 2 個 base64 編碼的 TXT 檔
4. 會計下載到電腦
5. 開啟財政部營業稅電子申報網站
6. 手動上傳兩個 TXT
7. 上傳完成、財政部回覆收件
8. 會計回到 NEXORA、按「標記已上報」+ 填上報日期 / 備註
9. NEXORA 狀態：reportFiledAt / reportFiledBy 寫入、filed = true
```

### 7.8 「自動上傳」⛔ 401 上傳套件

⚠️ **重要邊界**：上述 §7.7 第 5-8 步「**人工上傳國稅局**」是 LITE 預設流程。

⭐ 想跳過「會計人工去財政部網站上傳 TXT」→ 加購「**401 自動上傳套件**」、**詳見 NX-MANUAL-PACKAGE-03**：

- 系統自動把 TXT 兩檔送到財政部 API
- 自動回標已上報

⚠️ 401 自動上傳套件**目前尚未實作**、屬規劃中、屬套件範疇、後續再做。LITE 客戶（未加購）會計人工上傳 TXT 流程順暢、不影響日常作業。

### 7.9 資料來源 / 資料去向

- 來源：本期所有銷貨單 / 進貨單 / 銷退單 / 退供應商單統計（過 voidedAt 過濾、跳過取消）。
- 去向：
  - TXT 兩檔下載、會計手動上傳國稅局（LITE 流程）。
  - 自動上傳國稅局（加購套件、§9）。
  - 月關帳的 reportPeriod / reportFiledAt 欄位。
  - 報表「銷項 / 進項分析」「稅金預測」（NX-MANUAL-07）。

## §8. 帳戶管理

### 8.1 是什麼

兩種帳戶的管理工作頁：

| 種類 | 是什麼 | 用途 |
|---|---|---|
| **往來對象帳戶** | 客戶 / 廠商的銀行帳戶 | 匯款給廠商 / 客戶匯款給公司時對到帳號 |
| **公司自有銀行帳戶** | NEXORA 客戶自己的銀行帳戶 | 收款進公司哪個戶、付款從公司哪個戶 |

### 8.2 為什麼分開呈現

⭐ 設計原則：「**我家的帳戶」跟「對方的帳戶」業務語意不同、分開避免混淆。

- 對方帳戶：屬於客戶 / 廠商主檔的延伸資料、用於「指定收款 / 付款戶」。
- 自家帳戶：屬於公司主檔的延伸資料、用於「銀行對帳 / 現金流追蹤」。

### 8.3 往來對象帳戶（客戶 / 廠商）

#### 從哪管理

| **帳號** | 14 碼帳號 |

### 8.4 自有銀行帳戶

#### 欄位

| 欄位 | 說明 |
|---|---|

| **目前餘額** | 跟銀行對帳後手動更新（**LITE 不自動串銀行 API**）|

| **備註** | 自由文字 |

### 8.5 ⚠️ 自有帳戶餘額不自動串銀行

⚠️ **重要邊界**：「目前餘額」**不自動跟銀行帳戶同步**、要會計人工對帳銀行月結單後手動更新。

LITE 客戶實務：

```
1. 收到銀行月結單
2. 跟 NEXORA 票據對帳（哪些票據是月結單上的）
3. 對齊後、手動把 NEXORA 自有帳戶的「目前餘額」填上月結末日餘額
4. 之後 NEXORA 系統用「餘額 + 後續票據加減」算預估餘額
```

升級「金流自動串接」（見 §9）才能自動同步。

### 8.6 資料來源 / 資料去向

- 來源：負責人 / 會計手動建（接觸新對象 / 開新銀行戶時）。
- 去向：
  - 票據單據的「收款帳戶 / 付款帳戶」選擇。
  - 報表「現金流分析」「銀行帳戶餘額」（NX-MANUAL-07）。

## §9. ⭐⭐ LITE 內含 vs 加購套件邊界（Crown 重點章節）

⭐ **總經理拍板的明確定義**、LITE 哪些功能內含、哪些需要加購套件、本章寫清楚避免日後客戶誤會。

### 9.1 LITE 內含 = 基本版能用、不另收錢

✅ LITE 訂閱費包含的所有財務功能：

| 功能 | 對應章節 | 業務語意 |
|---|---|---|
| 應收帳款追蹤 | §3 | 知道客戶欠多少 |
| 應付帳款追蹤 | §4 | 知道我欠廠商多少 |
| 票據 4 種收付（現金 / 匯款 / 支票 / 信用卡）| §5 | 記錄錢進出 |
| 一張票多筆沖銷 | §5.3 | 一張匯款抵多筆應收 |
| 折讓核可（P 進貨 / S 銷貨 / 三條路徑）| §6 | 退錢 / 折扣管理 |
| 月關帳 4 狀態 | §7 | 鎖月份的帳 |
| **401 雙月一期預覽 + 應納稅額計算** | §7 | 知道這期要繳多少營業稅 |
| **401 TXT 兩檔下載** | §7.7 | 拿檔去財政部網站手動上傳 |
| 月關帳重新打開 | §7.5 | 補漏帳的特殊狀況 |
| 帳戶管理（往來 + 自有）| §8 | 看公司帳戶、看客戶 / 廠商的帳戶 |
| 催款（純內部紀錄）| §3.7 | 記錄催了誰、誰回應 |

⭐ **LITE 已經夠中小企業日常用、稅務也能自己處理**（會計願意自己上傳 TXT 的話）。

### 9.2 ⭐ 跟財務有關的 3 個加購套件（8 套件中的 3 個）

⭐ 新版本模型 8 套件中、跟「財務」直接相關的有 3 個：**電子發票 / 401 上傳 / 第三方串接**。三套件**互相獨立、不重疊、買哪個就只開哪個的自動化**。其他 5 套件（汽車資料庫 / 打卡 / KPI / EIP / 多據點）跟財務無直接關聯、見 NX-MANUAL-00 §3.3。

#### 套件 A：電子發票套件 ⛔ 詳見 NX-MANUAL-PACKAGE-02

| 項目 | 說明 |
|---|---|
| **是什麼** | 系統幫客戶跟「加值中心」串接、能印出或寄電子發票給客戶 |
| **典型加值中心** | ezPay / 綠界 / 藍新 等財政部認證加值中心 |
| **沒買 = LITE 預設** | 客戶用發票機 / 自己另外用第三方開、再手動標 NEXORA 銷貨單為 INVOICED |
| **買了 = 加購版** | NEXORA 銷貨單 INVOICED 時、系統自動透過加值中心開發票、印出或寄給客戶 |
| **業務邊界** | 發票專用、不做其他事 |
| **目前實作狀態** | ⚠️ 套件範疇、後續再做 |

⚠️ **重要邊界**：電子發票套件**只負責**「跟加值中心串接、發發票」、不做物流通知、不做 LINE 訊息、不做催收、不做金流串接。

#### 套件 B：401 自動上傳套件 ⛔ 詳見 NX-MANUAL-PACKAGE-03

| 項目 | 說明 |
|---|---|
| **是什麼** | 系統自動把 401 TXT 兩檔送到財政部 API、自動標已上報 |
| **沒買 = LITE 預設** | 系統產 401 報表 + TXT、客戶自行到財政部網站上傳（§7.7）|
| **買了 = 加購版** | TXT 直接傳檔、不用會計手動上傳 |
| **業務邊界** | 自動上傳國稅局、不做別的稅務功能 |
| **目前實作狀態** | ⚠️ 套件範疇、後續再做 |

⚠️ ⭐ **重要：401 預覽 + TXT 兩檔下載功能 LITE 內含**、就算不買套件、會計也能自己處理 401 申報。

#### 套件 C：第三方串接套件 ⛔ 詳見 NX-MANUAL-PACKAGE-07

| 項目 | 說明 |
|---|---|
| **是什麼** | 一籃子「跟外部 API 串接」的通用套件、含 LINE / Lalamove / 簡訊 / 催收訊息 / GPS 等 |
| **沒買 = LITE 預設** | 所有「給對方發訊息 / 同步對方系統」的動作都靠人工 |
| **買了 = 加購版** | 系統自動發 LINE / 派 Lalamove / 寄簡訊催收 / 即時 GPS 追蹤 |
| **業務邊界** | 通用第三方 API、不含發票（電發走套件 A）|
| **目前實作狀態** | ⚠️ 套件範疇、後續再做 |

⚠️ ⭐ **重要邊界**：

- 「催款訊息」（NX-MANUAL-06 §3.7）= **第三方串接套件範疇**（走 LINE / 簡訊）。
- 物流串接（Lalamove）= **第三方串接套件範疇**。
- 電子發票串接（加值中心）= **電發套件範疇、不在這**。

### 9.3 套件對應的業務語意

⭐ 客戶該如何選套件、看「**有沒有需要自動化**」：

| 客戶情境 | 推薦 |
|---|---|
| 純國內、量少、會計自己會用 | 純 LITE 就夠 |
| 開發票需求大、希望系統自動處理 | 加 **電發套件 A** |
| 會計怕上傳 401 麻煩 | 加 **401 套件 B** |
| 希望系統能自動發 LINE / 簡訊提醒客戶 | 加 **第三方串接套件 C** |
| 全自動營運 | 三個套件全買 |

### 9.4 ⚠️ 其他「規劃中、不在 8 套件範圍」的功能

LITE 沒有 + 跟 8 套件無歸屬的財務相關功能：

| 功能 | 規劃歸屬建議 | 狀態 |
|---|---|---|
| 自動跟銀行 API 同步餘額 | 規劃中、可能獨立成「金流串接」第 9 套件、跟第三方串接套件分開（實作複雜、有合規風險）| 待總經理拍 |
| 公司自有銀行 API 自動扣款廠商款 | 同上「金流串接」範疇 | 待總經理拍 |
| 自動寄催收 Email（非 LINE / 簡訊）| 規劃中、可能擴充第三方串接套件加 Email 通道 | 待規劃 |
| 預測現金流（明天 / 一週 / 一個月會缺多少錢）| 屬「**KPI 系統套件**」延伸（套件 5）| 規劃中 |

⚠️ 上述功能歸屬待總經理日後拍板、目前**未確認**。

### 9.5 LITE 帳邏輯邊界總結

⭐ NEXORA LITE 的稅務 / 帳務「自己能搞定」原則：

```
公司日常作業：
   業務開單 → 庫存 / 應收應付自動算 ✅
   會計收款付款 → 票據沖銷 ✅
   月底 → 月關帳 ✅
   雙月 → 401 預覽 + TXT 下載 ✅
   會計拿 TXT → 自己上傳國稅局 ✅
   國稅局回覆 → 會計回標已上報 ✅

升級套件帶來的差別：
   電發套件 = 開發票自動寄客戶（不用發票機）
   401 套件 = TXT 自動上傳（不用會計開瀏覽器）
   第三方套件 = 自動發 LINE / Lalamove / 催收訊息
```
