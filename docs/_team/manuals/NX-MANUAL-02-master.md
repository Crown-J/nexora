## §1. 這本手冊是什麼

「主檔」是 NEXORA 的字典：

- 員工、客戶、供應商、產品、倉庫、職務、幣別…等等「會被別的單據參照」的基礎資料。
- 開報價單時的「客戶」、開進貨單時的「供應商」、開銷貨單時的「產品」、都是從主檔裡挑。

這本手冊教您：

- 主檔中心怎麼進、長什麼樣（§2）。
- 所有主檔共通的操作方式：新增、查詢、編輯、停用、批次（§3、**最重要**、學會這個之後 26 個主檔都會用）。
- 26 個主檔各自管什麼、有哪些欄位、誰用得到（§4~§9）。

### 1.1 26 個主檔總圖

| 區（6 區）| 主檔數 | 包含 |
|---|---|---|
| **帳號與權限** | 5 | 使用者、職務、職務權限、使用者職務設定（規劃中）、使用者據點設定（多據點模組）|
| **產品與料號** | 7 | 零件、車廠品牌、零件廠牌、零件群組、品牌料號規則（汽車資料庫套件）、零件關聯（汽車資料庫套件）、料件車型適配（汽車資料庫套件）|
| **車型字典** | 5 | 引擎 / 車型 / 變速箱 / 傳動方式 / 車體類型（全屬汽車資料庫套件）|
| **組織架構** | 3 | 倉庫、據點、庫位 |
| **交易對象** | 2 | 往來對象（客戶 / 供應商 / 同行 / 銀行…六分類）、客戶分級（**全版本可用、含 LITE**）|
| **系統設定** | 4 | 公告、國家、幣別、注音字典（規劃中、屬汽車資料庫套件）|

⚠️ **套件 / 規劃中標記**：「汽車資料庫套件」「多據點模組」要加購對應套件、或升級 PLUS/PRO 拿免費贈送。LITE 版若不加購、看得到卡名但點下去會跳「需加購對應套件」提示視窗。

⚠️ **客戶分級全版本可用（含 LITE）**：手冊照 2026-06-04 新決策標、實際系統 code 暫仍鎖 PLUS、待工程軌放開（不影響 LITE 客戶綁定使用毛利保護機制、見 NX-MANUAL-05 §3.1）。

## §2. 主檔中心入口

### 2.1 三種進主檔中心的方法

| 方法 | 怎麼做 |
|---|---|
| 螢幕最上方那排 | 點「主檔中心」分頁 |
| 星球按鈕 | 點左上星球（或 `Alt+X`）→ 左欄選「主檔」 |
| 搜尋 | 點左上星球（或 `Alt+X`）→ 上方搜尋框、直接打主檔名稱（例：「職務」「幣別」「零件」）→ Enter |

### 2.2 主檔中心首頁長什麼樣

- 頂部標題：「主檔中心 / MASTER DATA」。
- 下方依「6 區」直排展開、每區有一條淡色橫線分隔。
- 每區標題右邊顯示「X 項 / Y 鎖」（X = 該區主檔總數、Y = 您的方案還鎖住幾個）。
- 每張卡顯示：圖示、版本/套件徽章、主檔名稱、一句話說明。
- 您未加購對應套件的卡會「灰階 + 加鎖頭」、點下去會跳「**需加購 XX 套件**」提示視窗。

### 2.3 手機版的差異

手機螢幕只會顯示一區、底部有 6 個分區按鈕、點哪個切到哪區。

### 2.4 進入單一主檔

點任何一張卡（沒鎖住的）→ 進入該主檔的「工作頁面」、所有主檔的工作頁面長一樣、操作也一樣（§3 詳細講）。

## §3. 主檔通用操作（最重要、學一次全會）

NEXORA 26 個主檔共用同一套工作頁面範式。學會這套、後面 §4~§9 講各別主檔時只會提「這個主檔特有」的部分。

### 3.1 工作頁面長什麼樣

進入單一主檔後（例如點「零件基本資料」）會看到：

```
┌─ 頂列（小星球 + 「主檔 · 零件基本資料」 + 公告 / 任務 / 使用者）─┐
├─────────────────────────────────────────────────────────────────┤
│ 工具列（一整排按鈕、按 Alt+數字可快捷）                          │
├─────────────────────────────────────────────────────────────────┤
│ Tab：[列表]  [詳細]                                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  列表 Tab：表格列、每列一筆資料、點某列可看詳情                 │
│  詳細 Tab：展開單筆資料的所有欄位（瀏覽或編輯）                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 工具列：8 個常用按鈕

由左到右、每個按鈕都有鍵盤快捷鍵（Alt + 字母）：

| 按鈕 | 快捷 | 作用 | 在什麼狀態下亮起 |
|---|---|---|---|
| **A 新增** | `Alt+A` | 加一筆新資料 | 隨時可按 |
| **E 更正** | `Alt+E` | 編輯目前選中的這筆 | 有選中一筆時 |
| **F 查詢** | `Alt+F` | 打開搜尋面板（按條件找資料）| 列表頁時 |
| **D 停用 / 啟用** | `Alt+D` | 選中啟用的 → 變「停用」（紅色）；選中停用的 → 變「啟用」（一般色）| 有選中一筆時 |
| **匯出** | `Alt+P` | 選 CSV / PDF / 列印 | 列表頁時 |
| **R 重新整理** | `Alt+R` | 抓最新資料 | 隨時可按 |
| **選取批次** | `Alt+S` | 進選取模式、勾多筆做批次啟用 / 停用 | 列表頁時 |
| **Q 結束** | `Alt+Q` | 離開這個主檔、回主檔中心 | 隨時可按 |

⭐ 編輯模式下、工具列會自動換成兩個按鈕：

| 按鈕 | 快捷 | 作用 |
|---|---|---|
| **S 存檔** | `Alt+S` | 把這次編輯存進系統 |
| **C 取消** | `Alt+C` | 不存檔、回瀏覽模式 |

### 3.3 NEXORA 不能刪除資料

⭐ **重要原則**：NEXORA **沒有「刪除」這個功能**。

理由：主檔被很多單據引用（例：客戶被銷貨單引用、產品被進貨單引用）、一刪掉、那些單據會找不到資料、整個系統亂掉。

所以系統用「**軟刪除**」：

- 想讓某筆主檔不再被選用 → 按「**停用**」（按鈕圖示是電源關閉的樣子、紅色）。
- 停用後、那筆資料還在系統裡（單據查得到）、但新單據選不到。
- 想恢復使用 → 列表頂部勾選「顯示停用」、選中該筆 → 按「**啟用**」。

### 3.4 列表頁的操作

#### 看資料

- 表格顯示所有資料（一頁顯示幾筆可調、預設 20）。
- 鍵盤 `↑↓` 切上下列、`Enter` 進詳細 Tab。
- 滑鼠點某列 = 選中該列。
- 滑鼠雙擊某列 = 直接進詳細 Tab。

#### 篩選

- 預設只顯示「啟用」的、想看停用的：列表頂部勾「顯示停用」。
- 想複雜條件篩：按 `F` / `Alt+F` 開查詢面板、可組合多條件（例：「廠牌 = 瑞利」+「狀態 = 啟用」）。
- 篩選條件數量會在「篩選」按鈕上顯示徽章。

#### 欄位設定

- 表格欄位太多想隱藏？按工具列「欄位」按鈕、勾選想顯示的欄位。
- 已隱藏的數量會在「欄位」按鈕上顯示徽章。

#### 翻頁

工具列左邊有 4 個小按鈕：第一頁 / 上一頁 / 下一頁 / 最末頁。

### 3.5 詳細頁的操作

#### 瀏覽模式

- 顯示這筆資料的所有欄位、唯讀。
- 看完按 `Esc` 或工具列「結束」（Q）回主檔中心。

#### 編輯模式

按工具列「更正」（E）→ 表單欄位變成可填、工具列換成 S / C：

- 填完按 **S 存檔**：系統存進去、回瀏覽模式、頂部跳綠色「存檔成功」提示。
- 不想存按 **C 取消**：
  - 沒改動 → 直接回瀏覽模式。
  - 有改動 → 跳「3 選 1 確認框」：
    - **存檔後離開**：存進系統 + 回瀏覽。
    - **丟棄變更**：不存 + 回瀏覽。
    - **繼續編輯**：留在編輯模式（取消這次取消）。

⚠️ 編輯有錯（例：必填沒填）→ 跳橘色提示框告訴您哪欄錯、不會存進系統。

### 3.6 分區編輯（zoned editing）

⭐ 比較複雜的主檔（使用者、零件、往來對象、倉庫）會把欄位分成幾個「區」、用小分頁切。

例：使用者主檔有 4 區：

- **基本資料**：員工編號、姓名、聯絡信箱、電話。
- **權限**：掛哪些職務、是不是負責人、帳號啟不啟用。
- **安全**：強制改密、登入失敗次數、鎖定狀態（負責人才看得到）。
- **人資**：員工主檔關聯、部門、團隊（**需打卡 + KPI 整合包、PRO 免費送、LITE 可單買**）。

切到哪一區、就看到 / 改那一區的欄位、不會擠在一起難找。

### 3.7 衛星表（一對多 / 子表）

有些欄位是「一筆主檔 + 多筆子資料」、例：

- 使用者掛多個職務 → 主檔是「王經理」、衛星表是「採購、銷貨、倉管」3 筆角色。
- 倉庫有多個庫位 → 主檔是「主倉」、衛星表是「A 區 / B 區 / C 區 / …」。
- 往來對象有多個送貨地址 → 主檔是「和興汽車」、衛星表是「台北分店 / 台中分店 / …」。

詳細 Tab 內、衛星表會以「副表」形式顯示在主檔欄位下方、可以加列 / 改列 / 刪列、按 S 存檔時連同主檔一起存。

### 3.8 鍵盤一覽

| 動作 | 鍵 |
|---|---|
| 上一列 / 下一列 | `↑` / `↓` |
| 列表 → 詳細 | `Enter` |
| 詳細 → 列表 | `Esc` |
| 新增 / 編輯 / 查詢 / 停用 / 匯出 / 重新整理 / 選取 / 結束 | `Alt+A/E/F/D/P/R/S/Q` |
| 編輯模式存檔 / 取消 | `Alt+S` / `Alt+C` |
| 列表 / 詳細 Tab 切換 | `Alt+1` / `Alt+2` |
| 開星球選單 | `Alt+X` |

⭐ 全鍵盤可操作、滑鼠完全不碰也能做事、適合老倉管或大量資料輸入時。

## §4. 帳號與權限區（5 個主檔）

這區管「誰能登入、能用什麼功能」。LITE 基本含 3 個、另 2 個：使用者職務設定（規劃中）、使用者據點設定（屬多據點模組）。

### 4.1 使用者基本資料（LITE）

#### 是什麼

公司所有員工的登入帳號清單。**員工不在這建、就不能登入系統**。

#### 4 分區

| 分區 | 內容 |
|---|---|
| **基本資料** | 員工編號（= 登入帳號）、姓名、聯絡信箱、電話 |
| **權限** | 掛哪些職務（可多個）、是否負責人、帳號啟不啟用 |
| **安全** | 強制改密旗標、登入失敗次數、鎖定狀態、最後登入時間（負責人才看）|
| **人資（打卡+KPI 包送、或 PRO 免費送）** | 員工主檔關聯、部門、團隊（**未加購 人資套件 此區看不到**）|

#### 重要欄位說明

- **員工編號**：員工登入時打的「員工編號」、租戶內唯一、可以改但內碼不變（改完員工就要用新編號登入）。
- **聯絡信箱**：用來收通知 / 重設密碼用、**不是登入帳號**。
- **強制改密**：勾起來 → 該員工下次登入會跳改密碼畫面（伊諾瓦剛建好的新帳號預設打勾）。
- **是否負責人**：勾起來 = 系統內建的「全權限」、能看所有東西、能設定所有東西（**不是客戶自訂的角色**、是系統旗標）。

#### 操作

- 負責人新增員工：按 A 新增 → 填欄位 → S 存檔 → 系統自動給預設密碼 `changeme` + 強制改密旗標打勾。
- 員工離職：選中該員工 → D 停用（系統不刪資料、保留所有歷史單據關聯）。
- 員工權限變更：選中該員工 → E 更正 → 切到「權限」分區 → 勾選 / 移除職務 → S 存檔。

⚠️ **席次制提醒**：依方案不同、公司能啟用幾個帳號是有上限的。買 LITE 10 席 = 最多同時啟用 10 個員工。想再加要先停掉某個舊員工、或聯絡伊諾瓦業務加買席次。

#### 資料來源 / 資料去向

- 來源：負責人手動建、或伊諾瓦開戶時代建。
- 去向：登入畫面驗證、其他單據的「業務員」「倉管」「核可人」欄位都是從這挑、稽核紀錄寫誰做了什麼也是用這的姓名。

### 4.2 職務基本資料（LITE）

#### 是什麼

「職務」= 一組權限的集合、例：「採購員」「業務員」「倉管」「會計」「送貨員」。

員工掛上某職務、就獲得該職務的所有權限。

⭐ **NEXORA 預設不給任何職務**：公司負責人從零開始建職務、想怎麼分都自己決定。系統不會塞「採購經理」「業務助理」這種預設職務給您。

#### 欄位

- **職務代碼**：自由命名（例：`PURCH`、`SALES`、`STORE`）。
- **職務名稱**：員工看到的中文名（例：「採購員」「業務員」）。
- **狀態**：啟用 / 停用。

#### 操作

- 建職務：A 新增 → 填代碼 + 名稱 → S 存檔。建好之後**還沒給權限**、要去「職務權限設定」（§4.3）勾選這職務能看哪些頁面。
- 改職務名：選中 → E → 改名 → S。
- 廢職務：選中 → D 停用（**已掛這職務的員工不會被踢、但新員工選不到**）。

#### 資料來源 / 資料去向

- 來源：負責人手動建（系統不預設）。
- 去向：使用者基本資料的「掛載職務」、職務權限設定的「行」。

---

### 4.3 職務權限設定（LITE）

#### 是什麼

把「職務」對應到「畫面權限」、決定該職務能不能看某個工作頁面。

#### 畫面長什麼樣

一張 **職務 × 畫面** 的矩陣：

```
                報價單  銷貨單  進貨單  庫存查詢  應收明細  ...
採購員（PURCH）   ☐      ☐      ☑      ☑         ☐
業務員（SALES）   ☑      ☑      ☐      ☑         ☐
倉管（STORE）     ☐      ☐      ☑      ☑         ☐
會計（ACCT）      ☐      ☑      ☐      ☐         ☑
```

打勾 = 該職務能看這個畫面、空白 = 看不到（沒入口、進不去）。

#### 操作

- 勾選或取消 → 自動存（不用按 S）。
- 想看「目前生效的規則總數」→ 右上角會顯示。

⚠️ **改完不會即時生效給員工**：員工要重新整理頁面（F5）或重新登入、新權限才會跑出來。

#### 資料來源 / 資料去向

- 來源：負責人在這裡手動勾選。
- 去向：員工登入後系統按這張表算「他能看到什麼選單、什麼工作頁能進」。

### 4.4 使用者職務設定（規劃中、暫不在 8 套件內）

⚠️ **此功能尚未實作 UI**：屬「批次工具」進階範疇、目前未在 8 加購套件清單內、暫無歸屬版本、列為規劃中、待總經理確認歸屬。

#### 是什麼（規劃中）

「**反向視角**」批次工具：

- 目前所有版本（LITE / PLUS / PRO）都從「使用者基本資料 → 權限分區」一個員工一個員工掛職務（**正向視角**）。
- 規劃中：另開「使用者職務設定」、可以「依職務批次操作」、例如建好新職務「夜班倉管」、一次勾 5 個夜班員工掛上。

---

### 4.5 使用者據點設定（多據點模組）

⚠️ **此功能屬「多據點模組」、需加購**（PLUS / PRO 免費送、LITE 也可單買）。

#### 是什麼（加購後才能用）

多倉公司、每個員工要設定「能操作哪幾個倉」（**據點授權**）：

- LITE 預設單倉所以不需要這個設定。
- 加購「多據點模組」後：可以從使用者頁逐個設、或從「使用者據點設定」依倉庫批次匯入 / 移除成員。

### 4.6 帳號與權限區的引用關係

| 主檔 | 被誰用 |
|---|---|
| 使用者基本資料 | 登入畫面、所有單據的「業務員」「倉管」「核可人」、稽核紀錄 |

## §5. 產品與料號區（7 個主檔）

這區管「公司賣什麼、進什麼」。是 NEXORA 的核心字典、報價、銷貨、進貨、庫存全部從這查料件。

LITE 基本內含 4 個、另 3 個（品牌料號規則 / 零件關聯 / 料件車型適配）屬「**汽車資料庫套件**」、加購才能用。

### 5.1 零件基本資料（LITE）⭐ 最核心

#### 是什麼

公司所有產品的字典：機油、剎車片、輪胎、雨刷……每個料件都在這建一筆。料件不在這建、就不能開報價單、不能進貨、不能查庫存。

#### 4 分區

⚠️ 重要：本主檔有「資訊保密設計」、不同分區只在對應工作頁顯示。

| 分區 | 內容 | 在哪些工作頁看得到 |
|---|---|---|
| **基本資料** | 料號、品名、品牌、規格、零件類型、產地、單位等 | 全部工作頁 |
| **銷貨** | A/B/C/D 四級售價、最後調價人 / 時間 | **只在銷貨類工作頁顯示**（業務員看、採購員看不到）|
| **採購** | 進貨成本 | **只在進貨類工作頁顯示**（採購員看、業務員看不到）|
| **庫存** | 退貨政策、保固月數、安全量 / 最高量 / 預設庫位 | 庫存類工作頁顯示 |

⭐ **為什麼這樣分**：避免業務員看到進貨成本（不利談判）、採購員看到客戶售價（不利議價）。「主檔中心」入口會顯示全部 4 分區、由負責人決定誰能進主檔中心。

#### 重要欄位說明

**基本資料區**：

- **料號**：公司給該料件的代碼（例：`BRK001`、`OIL-5W30-1L`），在公司內唯一。
- **副廠料號**：對應的副廠零件編號（用來找替代品）。
- **舊料號**：給「轉系統客戶」用、保留舊系統的編號方便對照。
- **料號段 1~5**：依「品牌料號規則」（§5.5）切的分段碼。

⚠️ **顯示主碼的小邊界**（2026-06-04 實測揭露）：

  系統有一個「**顯示主碼**」邏輯（service 內部叫 `displayCode`）：
  - **沒選編碼規則** → 顯示原樣手填的「料號」（最常見、LITE 客戶大多走這條）
  - **選了編碼規則 + 完整填齊（品牌 + 國家 + seg1~5）** → 顯示組合後的格式化主碼（例 `VAG-8K0 819 439 B`）
  - ⚠️ **選了編碼規則但品牌 / 國家沒填齊** → 顯示**空字串**

  如果您看到主碼欄位空白、又確定有設「編碼規則」、表示品牌或國家欄沒填齊、補上即可。LITE 客戶大多不會碰這個邊界（因為品牌料號規則屬汽車資料庫套件、不加購不會出現「選了規則」這個狀態）。
- **零件類型**：
  - `1` 專用（只能用在特定車型）
  - `2` 通用（多車型可用）
  - `3` 組合（賣的時候是一組、進貨拆成零件）
  - `4` 拆解（進貨是一整箱、賣的時候拆零）
- **單位**：LITE 固定 `pcs`、客製化單位需「**多據點模組**」（PLUS / PRO 免費送）。

**基本資料區還有 4 張衛星表**（一對多子表）：

| 衛星表 | 是什麼 |
|---|---|
| 正廠料號對應 | 找替代品用、列出哪些正廠零件等同這料件 |
| 改號關聯 | 新舊型號互通（例：剎車片 V1 改成 V2、系統知道是同一件、庫存合算）|
| 車型適配 | 通用零件可用於哪些車型（汽車資料庫套件：自動接 §6 車型字典）|
| 版本 | 規格變更歷史 |

**銷貨區**：

- **A / B / C / D 售價**：給不同等級客戶用、A 級客戶最低、D 級最高（依客戶分級主檔配對、見 §8.2）。
- **售價更新時間 / 人**：每次改 A/B/C/D 都自動記、稽核用。

**採購區**：

- **進貨成本**：業務員手動填、會被「重算售價」功能拿來當基準。

**庫存區**：

- **退貨政策**：
  - `F` 全額退（出廠瑕疵）
  - `S` 部分退（含保固）
  - `R` 限換不退錢
  - `N` 不退
  - `W` 過保固期退處理
- **保固月數**：`0` = 不保固。
- **安全量 / 最高量 / 預設庫位**（衛星表）：**每倉一筆**、多倉時每倉自己設（**多據點模組**範圍）。

#### 操作

- 建料件：A 新增 → 填基本資料 + 必填項（料號 / 品名 / 退貨政策 / 保固月數 / 單位）→ S 存檔。
- 改售價：選中料件 → E → 切「銷貨」分區 → 改 A/B/C/D → S。
- 改成本：選中料件 → E → 切「採購」分區 → 改成本 → S。
- 設安全量：選中料件 → E → 切「庫存」分區 → 在衛星表加列（選倉庫 + 安全量 + 最高量 + 預設庫位）→ S。
- 停用料件：選中 → D 停用（**已存在的單據還能查、新單據選不到**）。

#### 資料來源 / 資料去向

- 來源：負責人或採購員手動建、或伊諾瓦開戶時代建。
- 去向：所有業務單據的「料件」欄位都從這挑（報價單、銷貨單、進貨單、盤點單、庫存查詢…）。

### 5.5 品牌料號規則基本資料（汽車資料庫套件）

⚠️ **此功能屬「汽車資料庫套件」、需加購**：LITE 看得到卡、未加購點下去會跳「需加購汽車資料庫套件」提示。

某些大廠牌的料號有規範格式（例：「3 碼類別 + 3 碼系列 + 3 碼變體」）。把規則登進系統、之後建料件時系統會自動切分段碼、方便檢索與篩選。

#### 欄位

|---|---|
| **規則名稱** | 自由命名（例：「Toyota 副廠標準碼」）|
| **零件品牌** | 這規則套用到哪個零件廠牌（從 §5.3 挑）|
| **說明** | 補充說明 |
| **SEG1 ~ SEG5 最大字數** | 5 段各自的最大字數（0 = 不使用）|
| **分段預覽** | 系統自動產出範例、確認規則對不對 |

#### 操作

### 5.6 零件關聯基本資料（汽車資料庫套件）

⚠️ **此功能屬「汽車資料庫套件」、需加購**。

#### 是什麼（加購後才能用）

明確登記「兩個料件之間的關係」、讓系統幫您處理「改號」「同款」「組合 / 拆解」這類情境。

#### 欄位

| 欄位 | 說明 |
|---|---|
| **來源零件** | 從零件主檔挑 A 件 |
| **目標零件** | 從零件主檔挑 B 件 |
| **關聯類型** | 1 改號 / 2 同款 / 3 改版 / 4 組合 / 5 拆解 |
| **排序** | 顯示順序 |

#### 用途

- **改號**：A 是舊型號、B 是新型號、系統查庫存時把兩者合算。
- **同款**：A 和 B 在外觀 / 規格上幾乎相同、賣不到 A 時可以推 B。
- **改版**：A 是舊版、B 是新版（規格略改、用途相同）。
- **組合 / 拆解**：用於零件包（A 包裡有 B 零件、進貨入 A、賣的時候賣 B）。

| **適配等級** | 1 原廠 / 2 副廠等效 / 3 通用 |

### 5.8 ⭐ 零件編碼設計：四層碼 + 內碼錨點（2026-06-04 系統實測揭露）

⭐ **這段是 2026-06-04 系統 schema + service code 實測查證得出的「零件編碼真相」**、避免把「規劃中」當成「已實作」誤導客戶。

#### 已實作（不分版本、LITE 也享）

| 層 | 名稱 | 已實作？ | 證據 |
|---|---|---|---|
| ① **內碼**（綁定錨點）| `part_id` 系統自動產的 `NX01PART0000001` 格式 | ✅ 完全實作 | DB sequence `gen_nx01_part_id()`、不是 UUID 也不是 auto-increment、所有 17+ 業務單據明細的 `partId` 外鍵都綁這欄 |
| ④ **副碼**（廠牌對照）| `secCode` 副廠料號 + `Nx01PartOemCode` 一對多對照表 | ✅ 完全實作 | 一個料件可掛多筆正廠 / TecDoc 對照碼 |
| **歷史單據料號凍結** | `partNo` + `partName` 快照 | ✅ 完全實作 | 所有單據明細表（採購 / 進貨 / 銷貨 / 銷退 / 庫存帳…）都有 `partNo` snapshot 欄、註解標「避免主檔變更影響歷史」 |

⭐ **內碼錨點價值**：

> 之後您改料件的「對外料號」（公司給的代碼）、所有舊單據顯示的還是當時的料號（不會被改動影響）、但用內碼綁定的庫存帳 / 應收應付追蹤都對得起來。

#### 規劃中 / 屬汽車資料庫套件範疇

| 層 | 名稱 | 狀態 | 預計歸屬 |
|---|---|---|---|
| ② **編號**（系統自動產的統一主碼）| 半成品 | preview-code endpoint 算法已有、最終仍人工確認 dto.code | 汽車資料庫套件 |
| ③ **舊碼**（自由填、是 ② 空時的 fallback）| 欄位 `oldCode` 已存在、但 fallback 邏輯未做 | 目前只用於搜尋輔助、不參與主碼顯示 | 汽車資料庫套件 + 系統升級 |
| **主碼動態判定**（2 號有值用 2、空退 3）| 系統有「動態判定」但判定軸是「有無 codeRule」、不是「2 空退 3」 | 與設計意圖部分對齊 | 汽車資料庫套件 |

⭐ **總經理設計 vs 系統現況的落差圖**：

```
總經理設計四層         系統現況
─────────────────       ─────────────────
① 內碼（綁定錨點）  →  ✅ part_id 已實作
② 編號（自動產主碼）→  ⚠️ preview-code 算法已有、最終手動
③ 舊碼（fallback）  →  ⚠️ oldCode 存在、但不參與主碼顯示
④ 副碼（廠牌對照）  →  ✅ secCode + OemCode 已實作

主碼判定：「2 空退 3」  →  ⚠️ 改判定軸 + 拆 code 欄位是後續工作
歷史凍結               →  ✅ 17+ 單據明細 partNo snapshot 全套已實作
```

⭐ **客戶端表現的差異**（負責人 / 業務員看主碼欄）：

- 沒加購汽車資料庫套件：主碼 = 手填的「料號」欄、沒問題。
- 加購了套件 + 設了規則 + 填完整品牌/國家/seg1~5：主碼 = 系統算出的格式化碼（例 `VAG-8K0 819 439 B`）。
- 加購了套件 + 設了規則 + 但品牌/國家沒填：主碼顯示**空字串**（前文 §5.1 已揭露此邊界）。

## §6. 車型字典區（5 個主檔、全屬汽車資料庫套件）

⚠️ **此整個分區屬「汽車資料庫套件」、需加購**：5 張卡片都標套件徽章、未加購點下去會跳「需加購汽車資料庫套件」提示視窗。

### 6.1 是什麼分區

汽車零件 ERP 領域特化的字典、讓料件能精準綁定到「Toyota Corolla 2018 1.8L CVT 前驅 房車」這種具體車型。

5 張卡都需加購、給有需要做「精準車型對應」的客戶用。LITE 版（未加購）客戶通常用「料件主檔的料號 + 零件群組」就能應付日常業務、不需要這 5 張卡。

### 6.2 車型基本資料（汽車資料庫套件）

#### 是什麼

整套「車廠品牌 + 車型代號 + 年式 + 引擎 + 變速箱 + 傳動 + 車體類型」的組合字典。

#### 欄位

| 欄位 | 說明 |
|---|---|
| **車型代碼** | 自由命名（例：`COROLLA-18`、`CIVIC-22`）|
| **車型名稱** | 中文名（例：「Corolla 11 代 1.8L」）|
| **車廠品牌** | 必填、從 §5.2 挑 |

## §7. 組織架構區（3 個主檔）

這區管「公司的物理位置」：在哪裡、有幾個倉、倉裡怎麼分區放貨。

LITE 全 3 個都能用、但 LITE 預設「單據點 + 單倉」、組織單純的公司基本上動到的不多；多據點 / 多倉 / 跨倉調撥屬「**多據點模組**」（PLUS / PRO 免費送、LITE 也可單買）。

### 7.1 據點基本資料（LITE）

#### 是什麼

「據點」是公司的物理分點（總公司、台北分店、台中分店、高雄倉…）、概念上**比倉庫大一層**：

```
公司
├─ 據點 A（台北總公司）
│   ├─ 倉庫 A1（主倉）
│   │   └─ 庫位 A1-01、A1-02、…
│   └─ 倉庫 A2（成品倉）
│       └─ 庫位 A2-01、…
└─ 據點 B（台中分店）
    └─ 倉庫 B1
        └─ 庫位 B1-01、…
```

LITE 公司大多就一個據點、伊諾瓦開戶時建好「總公司」一筆、之後您可以改名 / 改地址、但通常不會再加。

#### 欄位

| 欄位 | 說明 |
|---|---|
| **據點代碼** | 自由命名、大寫（例：`HQ`、`TPE`、`TCH`）、租戶內唯一 |
| **據點名稱** | 中文名（例：「總公司」「台北分店」）|
| **設為主據點** | 全公司只能有一個主據點（伊諾瓦開戶時自動勾上）|
| **地址** | 自由文字（之後升級會接到結構化地址簿、目前先用自由文字）|
| **聯絡電話** | 該據點主電話 |
| **排序** | 下拉選單裡的排列順序 |

#### 資料來源 / 資料去向

- 來源：伊諾瓦開戶時建「總公司」一筆、之後負責人視需要加。
- 去向：倉庫主檔的「所屬據點」欄、報表「依據點統計」用。

---

### 7.2 倉庫基本資料（LITE）

#### 是什麼

存放實體商品的物理倉。LITE 版伊諾瓦開戶時自動建一個「主倉」、單倉公司日常不太動到。

#### 3 分區

| 分區 | 內容 |
|---|---|
| **基本資料** | 倉庫代碼、名稱、所屬據點、倉別、主管、結構化地址 |
| **庫存** | 庫位（樹狀分區、區 → 架 → 層 → 格）|
| **配送（地址視角）** | 跟基本資料同一份地址、但用「司機送貨怎麼到」的視角呈現 |

#### 重要欄位說明

- **倉庫代碼**：自由命名（例：`MAIN`、`WH-TPE`）、租戶內唯一、大寫。
- **所屬據點**：必填、從 §7.1 挑、決定這倉在物理上哪個地方。
- **是否主倉**：全公司只能一個主倉、預設取貨 / 進貨 / 銷貨都先看主倉。
- **倉別**（多據點模組用）：分 `H` 總倉 / `M` 中間倉 / `W` 自助倉 / `S` 寄賣倉、影響自動調撥規則。
- **倉管主管**：選使用者主檔的某員工、之後該員工離職停用、自動清空（資料不會壞掉）。
- **結構化地址**：縣市、鄉鎮、路街、巷、弄、號、樓、室分開填、報表跟列印用。

#### 衛星表：庫位（在「庫存」分區）

樹狀子表、每個倉庫可以再切「區 → 架 → 層 → 格」、見 §7.3。

#### 操作

- LITE 公司：開戶時伊諾瓦給您一個主倉、平常不用動。
- 想改主倉名（例如「主倉」改成「台北倉」）：選中 → E → 改名 → S。
- 加副倉（**多據點模組才有意義**）：A 新增 → 設另一倉、跨倉調撥才有用武之地（PLUS / PRO 免費送多據點模組、LITE 也可單買）。

#### 資料來源 / 資料去向

- 來源：伊諾瓦開戶時建主倉、之後負責人視需要加。
- 去向：進貨單、銷貨單、撿貨單、包貨單、盤點單、庫存查詢、調撥單、所有業務單據的「倉庫」欄。

---

### 7.3 庫位基本資料（LITE）

#### 是什麼

倉庫內部的物理小格、決定每件貨「**放在哪一格**」。倉小不用做也行（NEXORA 允許一個倉只有一個預設庫位）；倉大、要做撿貨優化就建議分。

階層結構：**區 → 架 → 層 → 格**

```
倉庫「主倉」
├─ 區 A
│   ├─ 架 01
│   │   ├─ 層 1：格 A、格 B、格 C…
│   │   └─ 層 2：…
│   └─ 架 02：…
├─ 區 B：…
```

#### 欄位

| 欄位 | 說明 |
|---|---|
| **所屬據點** | 從 §7.1 挑 |
| **所屬倉庫** | 必填、從 §7.2 挑 |
| **庫位代碼** | 自由命名（例：`A-01-1-A`、`B-03-2-C`）、倉內唯一 |
| **名稱** | 易記名稱（選填、例：「靠走道」「靠窗」「冷氣口」）|
| **區 / 架號 / 層 / 格** | 階層欄位、跟代碼配對、撿貨員照這個找貨 |

#### 操作

- 建庫位：A → 選據點 + 倉庫 + 填代碼 + 填區/架/層/格 → S。
- 大量建（例：規劃全倉 50 個位置）：建議伊諾瓦業務協助代建（庫位產生器規劃中、暫不在 8 套件清單）。

#### 資料來源 / 資料去向

- 來源：倉管主管手動建。
- 去向：零件主檔的「預設庫位」（每倉一筆）、撿貨單的撿貨路徑、盤點單的盤點順序。

---

### 7.4 組織架構區的引用關係

```
據點 ──→ 倉庫 ──→ 庫位
                 ↓
                被零件「預設庫位」引用
                被進貨 / 銷貨 / 撿貨 / 盤點等所有業務單據引用
```

## §8. 交易對象區（2 個主檔）

這區管「公司跟誰做生意」：客戶、供應商、同行、銀行、外包物流…通通在這。

### 8.1 往來對象基本資料（LITE）⭐ 高使用率

#### 是什麼

公司所有「會打交道的對象」字典。**重要：六種對象身分共用一張主檔**（不是分開六張）、用「對象類型」欄位區分。

#### 六分類

| 代碼 | 類型 | 是什麼 | 典型例子 |
|---|---|---|---|
| **C** | 保養廠 | 您的客戶（多半是修車廠 / 保養廠）| 和興汽車保養廠、德立車業 |
| **O** | 同行 | 同業（互相調貨用、不是客戶也不是供應商）| 友美零件、信達汽材 |
| **S** | 供應商 | 您向誰進貨 | 瑞利汽材廠、台聯零件 |
| **T** | 外包物流 | 配送公司 | 黑貓 / 嘉里大榮、自雇司機 |
| **V** | 一般廠商 | 雜項開銷對象（房東、水電、清潔）| 房東、台電、自來水 |
| **B** | 銀行 | 票據往來、收款 / 付款帳戶 | 國泰世華、台新銀行 |

#### 4 分區（依身分動態顯示）

⭐ **重要設計**：在「主檔中心」看會顯示全部 4 分區；但在**其他業務頁面**（例：銷貨頁面選客戶）只顯示跟那個身分相關的分區、減少誤填。

| 分區 | 內容 | 哪些身分看得到 |
|---|---|---|
| **基本資料** | 對象代碼、名稱、身分類別、聯絡資訊 | 全部身分 |
| **銷貨** | 客戶等級、信用額度、信用狀態、預設取貨倉、業務歸屬 | C 保養廠、O 同行 |
| **配送** | 送貨地址（多筆）| C、O、S、T |
| **財務** | 統一編號、付款條件、貿易條件、預設幣別、供應商等級 | C、O、S、V、B |

| 身分 | 看得到 |
|---|---|
| C 保養廠 | 基本 / 銷貨 / 配送 / 財務（4 區全顯）|
| O 同行 | 基本 / 銷貨 / 配送 / 財務（4 區全顯）|
| S 供應商 | 基本 / 配送 / 財務（3 區）|
| T 外包物流 | 基本 / 配送（2 區）|
| V 一般廠商 | 基本 / 財務（2 區）|
| B 銀行 | 基本 / 財務（2 區）|

#### 重要欄位說明

**基本資料區**：

- **對象代碼**：自由命名（建議用首字代號、例：`C0001` 保養廠、`S0001` 供應商）。
- **對象類型**：必填、6 選 1（建好後不能改、想換要新建一筆）。

**銷貨區**（C / O 用）：

- **客戶等級**：從「客戶分級」（§8.2）挑、影響定價。
- **信用額度**：客戶最多賒帳多少（`0` = 不限制）。
- **信用狀態**：
  - `N` 正常（一切照常）
  - `W` 警示（額度將滿、出單會跳提示）
  - `F` 凍結（不能再賒帳、只收現金）
- **預設取貨倉**：開銷貨單時、系統預設出這倉的貨。
- **可同行調貨**：勾起來代表這對象可以幫您調貨（O 同行預設勾、C 保養廠可手動開）。
- **業務歸屬**：指派負責這客戶的業務員、銷貨單自動帶他名字。

**配送區**：

- **送貨地址**（衛星表、可多筆）：一個客戶可有「公司」「分店」「老闆家」多個地址、預設一筆、開單時可換。

**財務區**：

- **統一編號**：發票用。
- **國內付款條件**：`PREPAY` 預付 / `NET30` 月結 30 / `NET60` 月結 60 / `NET90` 月結 90。
- **進口付款條件**（S 供應商國外用）：`TT` 電匯 / `LC` 信用狀 / `DP` 付款交單 / `DA` 承兌交單。
- **貿易條件**：FOB / CIF / EXW / DDP（國外交易用）。
- **預設幣別**：跟這對象交易預設用什麼幣。
- **供應商等級**：S 純供應商才用、A/B/C/D 影響詢價優先順序。

#### 操作

- 建客戶 / 供應商：A 新增 → 選類型 → 填基本資料 → 切到相關分區補完 → S 存檔。
- 停用：選中 → D 停用（歷史單據還查得到、新單據選不到）。

⭐ **特殊操作：客戶等級變更**：業務員提變更 → **要負責人核可**才生效（見 NX-MANUAL-05 銷貨手冊）。

#### ⭐ NDA 簽署紀錄（2026-06-04 補政策）

⭐ 伊諾瓦每次跟客戶簽約**會同時簽 NDA**（保密協議）、系統記錄：

| 欄位 | 內容 |
|---|---|
| **NDA 已簽署** | 是 / 否（旗標）|
| **簽署日期** | YYYY-MM-DD |
| **附件**（可選）| 簽署版 PDF 留底 |

⚠️ **系統只記「已簽 + 簽署日 + 附件留底」**、NDA **條款內容由律師 / 法務處理**、不在系統範圍。客戶端負責人 / 業務員看主檔詳情頁時看得到簽署狀態、但條款內容請參考紙本或附件。

#### 資料來源 / 資料去向

- 來源：負責人 / 業務員 / 採購員手動建（接觸新客戶時加）；伊諾瓦開戶時可代建一批舊客戶清單。
- 去向：報價單 / 銷貨單 / 銷退單（C、O 身分）、詢價單 / 採購單 / 進貨單 / 退供應商單（S 身分）、票據 / 收付款（B 身分）、配送單（T 身分）、應付帳款（V 身分）。

### 8.2 客戶分級基本資料（全版本可用、含 LITE）

⭐ **2026-06-04 新決策**：客戶分級**全版本開放、包含 LITE**（不再 PLUS 鎖）。  
⚠️ **預設 4 級不可新增、只能改**：分級代碼 A / B / C / D 系統建好、不能再加 E、F、…；可以改名稱跟加成率。  
⚠️ **手冊已對齊新決策、實際 system code 暫仍鎖 PLUS**（master-cards.ts `minPlan: 'PLUS'`、待工程軌放開、不影響 LITE 客戶從往來對象主檔綁定使用毛利保護、見 NX-MANUAL-05 §3.1）。

#### 是什麼

把客戶分 A / B / C / D 四級、影響「**售價自動帶哪一級**」。

例：
- **A 級**：大批發客戶、量大但毛利低、加成率 5%。
- **B 級**：固定保養廠、加成率 15%。
- **C 級**：散戶 / 偶爾來、加成率 25%。
- **D 級**：一次性顧客、加成率 35%。

#### 欄位

| 欄位 | 說明 |
|---|---|
| **分級代碼** | A / B / C / D（系統內建、不能新增刪除）|
| **分級名稱** | 中文名（可改、例：「大批發」「保養廠」「散戶」「一次性」）|
| **加成率（%）** | 進貨成本加幾趴 = 該級售價 |
| **排序** | 顯示順序 |

#### 怎麼影響定價

開報價單時、系統依「客戶等級 → 取對應的加成率 → 用成本 × (1 + 加成率)」自動算售價。業務員可手動覆寫、但低於「最低售價保護」會跳紅字警告。

#### 資料來源 / 資料去向

- 來源：系統建好 A/B/C/D 4 筆、負責人改名稱跟加成率。
- 去向：往來對象主檔的「客戶等級」欄、報價單 / 銷貨單的自動定價邏輯。

```
  ├─ O 同行   ──→ 報價 / 銷貨 / 同行調貨

  ├─ T 外包物流 ──→ 配送單、運費結算
  ├─ V 一般廠商 ──→ 雜項應付

客戶分級（全版本可用）── 影響 ──→ 往來對象（C/O）的售價自動帶
```

## §9. 系統設定區（4 個主檔）

這區管「全公司共用的基礎字典」：公告、國家、幣別、注音字典。

### 9.1 公告基本資料（LITE）

#### 是什麼

公司公告字典、發到首頁螢幕最上方那排的喇叭圖案那邊（NX-MANUAL-01 §5.3 講過）。

#### 欄位

| 欄位 | 說明 |
|---|---|
| **標題** | 必填、員工看到的公告標題 |
| **內容** | 詳細內容（可長文）|
| **重要性** | 一般 / 重要 / 緊急 |
| **置頂** | 勾起來 = 永遠排在最上面 |
| **到期日** | 過了這天自動下架（選填、不填永久顯示）|

#### 操作

- 發公告：負責人或有權限的員工 A 新增 → 填標題 + 內容 + 重要性 → S。
- 下架公告：選中 → D 停用、或者設「到期日」讓系統自動處理。

#### 資料來源 / 資料去向

- 來源：負責人 / 管理員手動發。
- 去向：首頁螢幕最上方那排「喇叭圖案」的徽章數量、點開的列表、首頁行事曆 / 事件簿可能也會顯示（看公告設定）。

### 9.2 國家基本資料（LITE）

#### 是什麼

國家代碼字典、標「產地」「廠牌國家」用。

#### 欄位

| 欄位 | 說明 |
|---|---|
| **國家代碼** | 必填、大寫（例：`TW` 台灣、`JP` 日本、`DE` 德國、`US` 美國）、ISO 兩碼為主 |
| **國家名稱** | 中文名 |
| **排序** | 下拉排列順序 |

#### 怎麼初始

伊諾瓦開戶時會代建常見國家（TW / JP / DE / US / CN / KR / IT…）、之後接觸到新國家再 A 新增。

#### 資料來源 / 資料去向

- 來源：伊諾瓦開戶代建 + 後續手動加。
- 去向：車廠品牌的「國別」欄、零件廠牌的「國別」欄、料件主檔的「產地」欄。

### 9.3 幣別基本資料（LITE）

#### 是什麼

幣別字典、給多幣別交易用。

#### 欄位

| 欄位 | 說明 |
|---|---|
| **幣別代碼** | 必填（例：`TWD`、`USD`、`JPY`、`EUR`、`CNY`）、ISO 三碼 |
| **幣別名稱** | 中文名（例：「新台幣」「美元」「日圓」）|
| **幣別符號** | 顯示符號（例：`NT$`、`$`、`¥`、`€`）|
| **小數位數** | 該幣別的小數位（TWD = 0、USD = 2、JPY = 0）|
| **排序** | 下拉排列順序 |

#### LITE 版的提醒

LITE 預設只用 `TWD` 新台幣、單據都用台幣計算。
真正的多幣別（外幣單據、匯率自動轉換、外幣應收應付）屬「**多據點模組**」範疇（PLUS / PRO 免費送、LITE 也可單買）。未加購此模組時、建多筆幣別也只能拿來給「國家 / 產地」做參考、單據實際只走 TWD。

#### 資料來源 / 資料去向

- 來源：伊諾瓦代建 TWD / USD / JPY / EUR / CNY 等常見幣別。
- 去向：往來對象的「預設幣別」欄、加購多據點模組後的外幣單據。

### 9.4 注音字典基本資料（規劃中、屬汽車資料庫套件範疇）

⚠️ **此功能規劃中、屬「汽車資料庫套件」範疇**：櫃台高速搜尋的注音輔助、跟「自動產統一料號」「車型字典」屬同一個套件邏輯（汽配業特化）。

#### 是什麼（加購汽車資料庫套件後可用）

櫃台快搜的中文注音對照表、加速「F4 快速搜尋」（例：打注音「ㄔㄜ」就找到所有「車」開頭的料件、不用全打中文）。

#### 欄位

| 欄位 | 說明 |
|---|---|
| **字** | 中文字（一筆一字）|
| **主注音** | 該字的標準注音 |
| **主聲母** | 該字的聲母（用來建索引）|
| **使用頻率** | 數字、影響搜尋排序 |

#### 為什麼歸這個套件

櫃台高速搜尋只對「員工流動率高、新人多、用注音輸入比較順」的中大型客戶有意義、小公司熟手通常直接打料號或打中文更快。歸「汽車資料庫套件」是因為跟車型/料號搜尋整合最緊。
