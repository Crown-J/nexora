## §1. 這本手冊是什麼

這本講「公司的貨怎麼管」（LITE 全版本基本內含）：

- 庫存怎麼查（每個料件有多少、放在哪倉、哪個庫位、總值多少）。
- 安全量 / 最高量怎麼設、低於安全量會發生什麼。
- 倉位 / 庫位怎麼管。
- 盤點怎麼做、實際 vs 帳面有差異怎麼處理。
- 撿貨 / 包貨 / 配送的手機版工作站。
- **⭐ 異常處置怎麼做**（瑕疵品退貨 / 走保固 / 重組分解 / 報廢、Crown 特別關注的核心章節）。
- **⭐ 重組分解怎麼運作**（拆零件成多筆、組多筆成一筆、自動計算成本）。
- **⭐ 同行調貨入庫**（LITE 基本內含、跟下方「跨倉調撥」屬不同套件、別搞混）。
- 改號（同一料件新舊型號互通）。

套件範疇（指路、加購後可用）：
- **跨倉調撥** + 倉別自動補貨 + 撿貨路徑最佳化 → 需加購「多據點模組」、詳見 NX-MANUAL-PACKAGE-08。
- 配送工作站的 **GPS 即時追蹤** + **Lalamove API 整合** → 需加購「第三方串接套件」、詳見 NX-MANUAL-PACKAGE-07。
- 庫存 KPI / 坪效分析 → 需加購「KPI 系統套件」、詳見 NX-MANUAL-PACKAGE-05。

### 1.1 庫存中心結構（5 區）

| 區 | 卡 | 開放狀況 |

| **主檔管理** | 倉位/庫位管理、產品設定（安全量等）| LITE 全開 |

## §3. 庫存查詢

### 3.1 是什麼

公司「每個料件、在每個倉、每個庫位、目前有多少數量、總成本是多少」的全公司即時帳。

⭐ NEXORA 庫存帳走「**加權平均成本**」、不是「先進先出 FIFO」、也不是「後進先出 LIFO」。每次進貨後、成本依數量加權重新計算。

### 3.2 三種查詢維度（依實際資料表能力分檔）

進入庫存查詢、可選 3 種視角、**但 3 種視角的「能力強度」不一樣**（2026-06-04 實測揭露）：

| 維度 | 看到的 | 用在什麼場景 | 能力強度 |
|---|---|---|---|
| **依料號** | 一料件 → 在所有倉的分佈（A 倉 5 個、B 倉 12 個、總計 17）| 找「我這個料件全公司還有多少」| ✅ 從即時帳直接撈 |
| **依倉庫** | 一倉庫 → 所有料件的當前庫存（總筆數、總值）| 倉管月底盤點前先看「我這倉現在有幾種料件」| ✅ 從即時帳直接撈 |
| **依庫位** | 一庫位 → 該庫位裡的所有料件 + 數量 | 撿貨員去某庫位前先看「這格目前有什麼」| ⚠️ **從異動帳追溯算**（見下說明）|

#### ⚠️ 「依庫位查」的實作真相

⚠️ NEXORA 即時庫存帳（`stock_balance`）的最細顆粒度是 **(料件 × 倉庫)**、**不是 (料件 × 倉庫 × 庫位)**。也就是說、系統不會直接記錄「**A-01-1-A 庫位現在有 5 顆煞車片**」。

那「依庫位查」怎麼跑出資料？

> 系統從「庫存異動帳」（`stock_ledger`、每次進貨 / 出貨 / 重組 / 報廢時各寫一筆帳）追溯算出來：
> - 找該庫位歷史上所有「入帳 + 出帳」紀錄。
> - 推算當下該庫位剩餘數量。

#### 實務影響（重要）

| 場景 | 影響 |
|---|---|
| 該庫位異動次數少（例 < 100 筆）| 查詢秒回、跟「依料號 / 依倉庫」一樣順 |
| 該庫位異動次數多（例 > 1 萬筆）| 查詢會略慢、因為要掃 ledger |
| 同一料件**在同倉的不同庫位**怎麼分配 | 進貨入帳時的「入庫庫位」決定、之後撿包出貨會扣 |
| 庫位間搬動（沒走系統、員工偷搬）| ⚠️ 系統不知道、會跟實際對不上、要靠盤點調平 |

⭐ **撿貨員實務做法**：依庫位查是「**參考用**」、最權威還是實地清點。庫位間搬動務必走系統、不要員工口頭協調。

#### LITE 客戶通常用得到的維度

| LITE 用度 | 為什麼 |
|---|---|
| **依料號** | 高（業務員 / 採購員每天用）|
| **依倉庫** | 低（LITE 只有主倉、單倉一覽就好）|
| **依庫位** | 中（撿貨員撿貨前快查一下）|

### 3.3 每筆顯示什麼

不管哪個視角、每筆查詢結果會顯示：

| 欄位 | 說明 |
|---|---|
| **料號 / 品名** | 從料件主檔帶 |
| **倉庫** | 在哪倉 |
| **庫位** | 在哪格 |
| **數量** | 當前帳上有多少 |
| **單位成本** | 加權平均成本（不是進貨時的單價、是滾動加權的）|
| **總成本** | 數量 × 單位成本 |
| **最後異動時間** | 庫存最近一次變動的時間（不是建帳時間）|

### 3.4 篩選

- 料件關鍵字（料號 / 品名）。
- 倉庫篩選（LITE 通常只有主倉、**多倉需「多據點模組」**）。
- 庫位篩選。
- 「只顯示低於安全量的」勾選框（撿出補貨優先名單）。
- 「只顯示有庫存的」勾選框（過濾數量 0 的舊料件、減少雜訊）。

### 3.5 加權平均成本怎麼算

舉例：

```
進貨 1：10 個、單價 100、總成本 1,000
進貨 2：20 個、單價 130、總成本 2,600
此時帳上：30 個、總成本 3,600
加權平均單位成本 = 3,600 / 30 = 120
```

之後賣出 5 個：

```
帳上：25 個、扣 5 × 120 = 600
剩餘總成本 = 3,000、單位成本仍 120
```

再進貨 10 個、單價 150：

```
帳上：35 個、(25 × 120 + 10 × 150) = 3,000 + 1,500 = 4,500
新加權平均單位成本 = 4,500 / 35 = 128.57
```

### 3.6 「庫存帳」會被誰動

| 動作 | 庫存怎麼變 | 哪本手冊 |
|---|---|---|
| 進貨單過帳 | + 數量 / 加權算成本 | NX-MANUAL-03 §7 |
| 銷貨單包貨完成 | − 數量 / 沖成本 | NX-MANUAL-05 §X |
| 盤點過帳 | 帳實調平（多了補、少了扣）| 本手冊 §6 |
| 異常回報處置 | 報廢時扣 / 重組分解時走 Conversion | 本手冊 §7、§8 |
| 重組 / 分解過帳 | inputs 出庫、outputs 入庫 + 成本攤分 | 本手冊 §8 |
| 同行調貨入庫 | + 數量 | NX-MANUAL-05 §X 同行調貨 |

### 3.7 資料來源 / 資料去向

- 來源：系統自動算（受 §3.6 任一單據過帳影響）。
- 去向：報表「庫存報表 / 庫存週轉率 / 庫存總值」用。

## §4. 產品庫存設定

### 4.1 是什麼

每個料件的「**該倉應有多少、最多放多少、放哪一格**」的設定表。

進入後會看到一張表、每列 = 一個料件在某個倉的設定。

### 4.2 重要欄位

| 欄位 | 說明 |
|---|---|
| **料件** | 從料件主檔挑 |
| **倉庫** | 在哪倉的設定（**每倉一筆**、LITE 單倉所以基本上每料件一筆）|
| **安全量** | 低於這數量會自動產採購需求單 |
| **最高量** | 超過這數量會在進貨時跳提示「庫存將過高」|
| **預設庫位** | 進貨上架時、系統建議放這格 |
| **狀態** | 啟用 / 停用 |

### 4.3 安全量會發生什麼

⭐ NEXORA 安全量機制：

```
每日結帳時系統檢查：
  該倉某料件當前庫存 ≤ 安全量
     ↓
  自動產一筆「採購需求單」（demandType = S 補貨自動、見 NX-MANUAL-03 §4）
     ↓
  採購員第二天上班看到清單、可詢價、可採購、可忽略
```

### 4.4 操作

- 設新料件的安全量：A 新增 → 選料件 + 倉庫 + 填安全量 / 最高量 / 預設庫位 → S 存檔。
- 改數值：選中 → E → 改 → S。
- 暫時不用（不要讓系統再產補貨需求）：選中 → D 停用。

⚠️ 同一個料件 × 同一個倉 只能有一筆設定（重複會擋）。

### 4.5 資料來源 / 資料去向

- 來源：負責人 / 採購主管手動設、或從料件主檔的「庫存」分區衛星表設（同一份資料）。
- 去向：
  - 每日結帳自動掃 → 採購需求單（NX-MANUAL-03 §4）。
  - 進貨單上架建議庫位 → 預設庫位欄。
  - 庫存查詢的「只顯示低於安全量的」篩選用。

## §5. 倉位 / 庫位管理（從庫存角度看）

### 5.1 跟主檔中心的差別

倉位 / 庫位的「**主檔**」在主檔中心（NX-MANUAL-02 §7.2 倉庫 / §7.3 庫位）、內容相同。

庫存中心的「**倉位/庫位管理**」入口提供同一份資料的「**從庫存角度**」視角：

| 看的角度 | 主檔中心 | 庫存中心（本入口）|
|---|---|---|
| 倉庫基本資料 | ✅ 完整 4 區 | ✅ 完整 |
| 結構化地址 / 配送資訊 | ✅ | （不重要、隱藏）|
| 庫位樹狀結構 | ✅ | ✅ **主要操作**（撿貨員主要在這調整）|
| 庫位坪效記錄 | （不在主檔）| ✅ 只在這看 |

### 5.2 庫位坪效

⚠️ **坪效紀錄欄位規劃中、暫不在 8 套件範圍**：規格寫了、實際 UI 還沒接、待總經理拍歸屬。

LITE 客戶看得到入口、但點進去就是跟主檔中心同款的庫位樹狀編輯介面、沒有坪效資料。

### 5.3 在這要做的主要動作

- **加新庫位**：倉庫擴充、新加一個區 / 架 / 層 / 格、跟主檔中心一樣按 A 新增。
- **整理庫位**：重新分區、舊庫位停用、新庫位啟用。
- **看哪些庫位有貨**：搭配「庫存查詢 → 依倉庫」交叉用。

⭐ NEXORA 規格寫過「庫位產生器」可以一次大量建（例：建一個倉 50 個位置）— ⚠️ **目前尚未開放**、實務上要一個一個建、或請伊諾瓦協助代建。

### 5.4 資料來源 / 資料去向

- 來源 / 去向：跟主檔中心倉位 / 庫位同（見 NX-MANUAL-02 §7.4）。

## §6. 盤點工作台

### 6.1 是什麼

定期清點「**實際倉庫的貨**」與「**系統帳上的數字**」、把差異調平、讓帳實一致。

NEXORA 設計成「**邊盤邊調**」、不需要全部清點完才開單、適合中小公司倉管彈性作業。

### 6.2 5 狀態流轉

| 狀態 | 是什麼 |
|---|---|
| **DRAFT 草稿** | 開了盤點單但還沒開始清點 |
| **COUNTING 清點中** | 倉管在數實際庫存、把實數填進系統 |
| **ADJUSTING 調帳中** | 清點完、差異有了、選原因 / 等核可 |
| **POSTED 已過帳** | 調帳結果寫入庫存帳、實際庫存 = 系統帳 |
| **CANCELLED 已作廢** | 中途取消、不影響庫存 |

### 6.3 核可流程

盤點過帳前要看「差異夠不夠大」決定要不要主管核可：

| 核可狀態 | 是什麼 |
|---|---|
| **N 不需核可（自動 pass）** | 最大單筆差異成本 ≤ 設定的「小容差」、系統自動 pass、可直接過帳 |
| **P 待核可** | 差異超過小容差、需主管按「核可」才能過帳 |
| **A 已核可** | 主管按核可、可過帳 |
| **R 已駁回** | 主管覺得有問題、要倉管重新清點 |

⭐ **小容差 (smallToleranceQty)**：盤點單上有一個欄位、預設值由系統參數設、單筆差異金額在這以下就走自動 pass、簡化日常小盤點作業。

### 6.4 開新盤點單

按「**+ 新增盤點單**」：

| 欄位 | 說明 |
|---|---|
| **倉庫** | 必填、要盤哪個倉 |
| **盤點日期** | 預設今天 |
| **盤點範圍** | 全倉 / 特定區 / 特定料件（**LITE 預設全倉**、細範圍規劃中）|
| **小容差** | 差異金額在這以下自動 pass、預設帶系統參數 |
| **備註** | 可選 |

### 6.5 清點步驟（COUNTING 狀態）

倉管走到倉庫、實際清點：

```
1. 看每個庫位 → 數實際數量
2. 對應系統那行 → 填「實盤數」
3. 系統自動算「差異」= 實盤數 − 系統數
4. 差異不為 0 時、選「差異原因」（見 §6.6）+ 填備註
5. 全部清點完 → 按「進入調帳」→ 狀態切 ADJUSTING
```

### 6.6 4 種差異原因

| 代碼 | 原因 | 說明 |
|---|---|---|
| **S** | 被偷 | 確定有人偷走 |
| **M** | 算錯 | 倉管之前數錯、或單據之前打錯數 |
| **B** | 破損 | 庫存實品已破損、實際少 |
| **U** | 不明 | 不知道為什麼少（或多）|

⚠️ 同一張盤點單裡、不同行可以選不同原因（不會強制全張單同一個原因）。

### 6.7 調帳過帳

調帳狀態送核可：

```
1. 倉管按「送主管核可」→ 系統算「最大單筆差異成本」
2. ≤ 小容差 → 自動 pass、可直接過帳
3. > 小容差 → 顯示「待主管核可」、主管在「等我核可」清單看到
4. 主管按「核可」或「駁回」
   - 核可：倉管可按「過帳」、狀態切 POSTED、系統做帳：
       * 差異 > 0：庫存帳 + 差異 / 走 I 帳調增
       * 差異 < 0：庫存帳 − 差異 / 走 O 帳調減
       * 差異 = 0：走 N 無差異（不動帳）
   - 駁回：狀態回 COUNTING、倉管重新清點
```

### 6.8 帳調怎麼處理成本

- **帳調增（I）**：帳上多出來的部分、用「原料件當前加權平均成本」入帳、不影響成本均值（因為單價沒變）。
- **帳調減（O）**：扣帳上的數量、按加權平均成本扣總成本、單位成本不變。

⭐ NEXORA 盤點調帳「**不會自動寫進財務報表的損益**」、只動庫存帳本身。差異成本是內部稽核紀錄、要不要列入損益由負責人 / 會計手動處理。

### 6.9 資料來源 / 資料去向

- 來源：倉管定期手動開、或負責人指示。
- 去向：庫存帳的「最後異動 / 數量」會被改動、報表「盤點差異 / 盤點頻率」用。

## §7. 異常回報 → 處置機制 ⭐

### 7.1 是什麼

倉管 / 業務 / 任何員工發現「庫存有問題」（瑕疵、過期、放錯、數不對）就在這開單、選一個處置動作、走到對應流程結尾。

⭐ **這是 NEXORA 庫存的「異常統一入口」**、不管什麼問題、先進這、再分流到對應處理單。

### 7.2 5 種異常類型（issueType）

| 代碼 | 異常類型 | 怎麼發現 |
|---|---|---|
| **D** | 損毀 | 倉管搬貨時看到外觀破損、或客戶退來的瑕疵品 |

## §8. 重組 / 分解（Conversion）⭐

### 8.1 是什麼

把「**一批料件**」和「**另一批料件**」之間互換的單據、兩種操作方向：

- **重組 M（Merge）**：把多個零件組成一個成品（N 個 inputs → 1 個 output）。
- **分解 D（Disassemble）**：把一個成品 / 整包拆成多個零件（1 個 input → N 個 outputs）。

### 8.2 真實場景

**重組情境**：

- 「機油 + 機油濾 + 工資工時」打包成「定期保養組合」賣（不常用、汽配業少見）。
- 「煞車片 × 4 + 煞車碟 × 2」組成「煞車整套」當一個料件。

**分解情境**：

- 進貨進來一整箱、廠商沒拆、要拆成單顆零件入帳（常見）。
- 「煞車組合包」拆成「煞車片」+「煞車碟」+「煞車油」分開賣（常見）。
- 滯銷組合品拆零售賣。
- 從異常處置 C 分流過來（壞掉的成品拆好的零件保留）。

### 8.3 3 狀態流轉

| 狀態 | 是什麼 |
|---|---|
| **DRAFT 草稿** | 開了單還沒過帳 |
| **POSTED 已過帳** | 庫存帳已動：inputs 扣 / outputs 加、成本算好 |
| **VOIDED 已作廢** | 整張單作廢、不能改回 |

⚠️ **重要規則**：「**DRAFT 過帳之後、inputs / outputs 內容不能改**」、要改只能作廢重建。

### 8.4 開新重組 / 分解單

按「**新增轉換單（N 快捷鍵）**」展開表單：

| 欄位 | 說明 |
|---|---|
| **類型** | M 重組 / D 分解（必選、決定 inputs / outputs 數量限制）|
| **倉庫** | 必填、在哪個倉做這個動作（inputs 從這出、outputs 進這個倉）|
| **日期** | 預設今天 |
| **inputs**（取出料件清單）| M 可多筆、D 鎖定恰好 1 筆 |
| **outputs**（產出料件清單）| M 鎖定恰好 1 筆、D 可多筆 |
| **備註** | 可選 |

每筆 input / output 一行：

| 欄位 | 說明 |
|---|---|
| **partId** | 料件 ID |
| **locationId** | 庫位 ID |
| **qty** | 數量 |
| **costRatio** | 僅 D 分解的 outputs 用、可空、見 §8.6 |
| **remark** | 可選 |

### 8.5 ⚠️⚠️ partId 是「手動輸入」、不是下拉選 ⭐ Crown 重點

⭐⭐ **誠實揭露：實際 UI 沒有零件下拉、partId 是輸入框、必須打入「已存在主檔的料件 ID」**。

意味著：

- **重組的 output「成品」料件**：必須**先到主檔中心建好**、才能在這選。
- **分解的 outputs「拆出來的零件」**：必須**先到主檔中心建好**、才能在這選。

⭐ **NEXORA 目前不支援「分解 / 重組時即時建新料件主檔」**。

實際工作流程：

```
場景：把「煞車組合包」拆成「煞車片」「煞車碟」「煞車油」3 種零件分開賣

操作：
1. 先到「主檔中心 → 零件基本資料」（NX-MANUAL-02 §5.1）
   按 A 新增建好 3 筆新料件：煞車片 / 煞車碟 / 煞車油
   填好料號、品名、退貨政策、保固月數、單位等必填
2. 回到「庫存中心 → 重組/分解」按 N 新增
3. 選類型 D 分解
4. input 填「煞車組合包」的料件 ID、選庫位、填 qty
5. outputs 加 3 行、各別填 §1 建好的 3 個新料件 ID、選庫位、填 qty
6. 過帳 → 系統扣 input 庫存、加 outputs 庫存 + 算成本
```

⚠️ 如果 Crown 規劃「第 6 處置 = 特價售出」涉及「拆零件後再特價賣」、會走同樣的「先建主檔 → 再分解 → 再特價售出」路徑。

### 8.6 成本怎麼算 ⭐

NEXORA 重組 / 分解的成本邏輯：

#### 重組 M 的成本

```
output 的單位成本 = Σ inputs 總成本 / output 的數量
（標準加權平均、Σ inputs 總成本 = Σ (input_i.qty × input_i.加權平均成本)）
```

舉例：

```
inputs：
  煞車片 4 個、單位成本 100、總成本 400
  煞車碟 2 個、單位成本 300、總成本 600
inputs 總成本 = 1,000

output：
  煞車組合 1 套
  output 單位成本 = 1,000 / 1 = 1,000
```

#### 分解 D 的成本（兩種模式）

**Mode A：manual（人工分攤）**

每個 output 填 `costRatio`（成本分攤比例）、所有 outputs 的 `costRatio` 加起來必須 = 1.0（容差 0.000001）。

```
input：煞車組合 1 套、成本 1,000

outputs：
  煞車片 4 個、costRatio = 0.4 → 分配成本 = 1,000 × 0.4 = 400 / 單位成本 = 400/4 = 100
  煞車碟 2 個、costRatio = 0.6 → 分配成本 = 1,000 × 0.6 = 600 / 單位成本 = 600/2 = 300
```

**Mode B：auto（系統按 A 級售價自動分攤）**

每個 output 都 **不填** `costRatio`、系統用「該料件的 A 級售價（priceA）× 數量」當權重自動分配：

```
input：煞車組合 1 套、成本 1,000

outputs：
  煞車片 4 個、A 級售價 200
  煞車碟 2 個、A 級售價 600
weight_煞車片 = 200 × 4 = 800
weight_煞車碟 = 600 × 2 = 1,200
Σ weight = 2,000

煞車片分配成本 = 1,000 × 800/2000 = 400 / 單位成本 = 100
煞車碟分配成本 = 1,000 × 1200/2000 = 600 / 單位成本 = 300
```

⚠️ **規則**：所有 outputs 必須**全 manual** 或**全 auto**、不能混用。
⚠️ **auto 模式**需要所有 outputs 對應的料件 A 級售價（priceA）非 0、否則過帳會擋。

### 8.7 過帳會做什麼（POSTED）

```
1. inputs 走出庫（applyQtyOutWithLedger、source=D 分解 或 M 重組）
   - 扣對應倉位的庫存
   - 寫一筆庫存異動帳（ledger）
2. outputs 走入庫（applyQtyInWithLedger、source=D）
   - 加對應倉位的庫存
   - 寫一筆庫存異動帳
   - 各 output 用算好的 unitCost 入帳（會影響該料件的加權平均成本）
3. 寫稽核紀錄
4. 完成
```

### 8.8 ⚠️ 跟銷貨 / 財務的串接邊界 ⭐ Crown 重點

⭐⭐ **重組 / 分解只動庫存帳 + 成本帳、不直接動銷貨、不直接動財務**。

| 項目 | 是否串 |
|---|---|
| 庫存帳 | ✅ inputs 出 / outputs 入 |
| 成本帳 | ✅ outputs 用算好的成本入帳 |
| 銷貨單 | ❌ 不會自動產銷貨單 |
| 應收 / 應付 | ❌ 不會動 |
| 折讓單 | ❌ 不會產折讓 |
| 損益表 | ❌ 不會列損益 |

意思：

- 重組組好的成品、之後**正常走銷貨流程**才會有銷貨記錄與應收。
- 分解拆出來的零件、之後**正常走銷貨流程**賣才有銷貨記錄與應收。
- 重組 / 分解本身是純內部庫存搬動 + 成本搬動。

### 8.9 資料來源 / 資料去向

- 來源：負責人 / 倉管主動開、或從異常回報 §7 處置 = C 重組分解分流過來。
- 去向：
  - 庫存帳：inputs 對應的庫位減 / outputs 對應的庫位加。
  - 料件加權平均成本：outputs 各自的 unitCost 寫入。
  - 報表「重組分解頻率 / 成本攤分軌跡」用。


⚠️ **GPS 即時追蹤** ⛔ 第三方串接套件 → 需加購、詳見 NX-MANUAL-PACKAGE-07。⭐ LITE 客戶（未加購）跳過、用配送員回報「已派車 / 已送達」+ 客戶電子簽收即可。

⚠️ **Lalamove API 整合** ⛔ 第三方串接套件 → 需加購、詳見 NX-MANUAL-PACKAGE-07。⭐ LITE 客戶（未加購）跳過、配送方式選「寄送」手動填 Lalamove 訂單編號即可。

### 9.6 資料來源 / 資料去向

- 來源：銷貨單包貨確認後的撿貨單（NX-MANUAL-05 §X）。
- 去向：銷貨單狀態自動推進（撿貨中 → 包貨中 → 已出貨）、庫存實際扣除。

## §10. 同行調貨入庫（LITE 基本內含）+ 跨倉調撥（⛔ 多據點模組）

⚠️ **重要區分**（跟採購 §3.2 一致）：

| 流程 | 對象 | 版本 |
|---|---|---|
| **同行調貨入庫**（§10.1） | 跨公司：向**同行**（O 身分往來對象）調貨 | ✅ **LITE 基本內含、不分版本** |
| **跨倉調撥**（§10.2） | 公司內：自家 A 倉搬 B 倉 | ⛔ 需加購「多據點模組」、詳見 NX-MANUAL-PACKAGE-08 |

### 10.1 同行調貨入庫（LITE 基本內含）

#### 是什麼

向同行（NX-MANUAL-02 §8.1 O 身分往來對象）調貨的入庫流程。

⭐ NEXORA 同行調貨是 **LITE 基本內含、不分版本**（批發 / 零售客戶日常用很多）、跟「跨倉調撥」（屬多據點模組）是兩回事。

#### 流程跟銷貨的關聯

詳細的「為什麼開同行調貨單」見 NX-MANUAL-05 §X 銷貨章節（業務員發現庫存不夠賣、開同行調貨單調過來）。

從庫存角度看：

```
1. 銷貨員開同行調貨單 → 同行送貨來
2. 倉管在「庫存中心 → 同行調貨入庫」收貨
3. 確認料件 + 數量、選入庫的倉庫 + 庫位
4. 過帳：庫存 + 數量、入主倉
5. 同步通知原銷貨單「料件已到、可出貨」
```

#### 入口

桌機 hub 沒有獨立卡（屬於同行調貨流程的一環）、手機版工作站可能會收到「同行調貨待入庫」任務。實務上 LITE 客戶大多從銷貨單詳情頁追蹤狀態、不會專門進這。

### 10.2 跨倉調撥單 ⛔ 多據點模組

⚠️ **此功能需加購「多據點模組」、詳見 NX-MANUAL-PACKAGE-08**（自家 A 倉搬 B 倉 / 含倉別 H/M/W/S 自動補貨規則）。

⭐ **LITE 客戶（單倉、未加購）跳過**：單倉沒有「跨倉」意義、桌機 hub 進不去也合理。要做跨倉時、加購多據點模組（PLUS / PRO 免費送、LITE 也可單買）。

> 跨倉調撥流程 / 倉別自動補貨規則 / 手機版「調撥」分頁操作 → 加購後見 PACKAGE-08 對應章節。

## §11. 進貨工作站（驗貨 / 上架、手機）

### 11.1 是什麼

採購流程 STEP 4 進貨單到貨後、倉管在手機上做「實際驗貨 + 上架」的兩個工作站。

跟桌機版的「進貨單」（NX-MANUAL-03 §7）是**同一張單**、但角度不同：

| 入口 | 角度 |
|---|---|
| 桌機 採購中心 → 進貨單 | 採購員看「驗收完成的數量 / 金額 / 應付狀態」|
| 手機 庫存中心工作站 → 驗貨 / 上架 | 倉管現場操作「實際數出來的數 / 放到哪格」|

### 11.2 驗貨工作站

#### 流程

```
1. 看「待驗貨清單」（系統從採購單 / 進貨單帶來）
2. 點某筆 → 進驗貨單詳情
3. 對照採購明細 + 實際拆箱數
4. 一個一個料件勾「無誤」/「短缺數量 N」/「有瑕疵」
5. 確認 → 進入「上架」工作站
```

⚠️ 驗到瑕疵時可直接在這開「異常回報」（§7）、選 R 退貨 / W 保固 處置。

### 11.3 上架工作站

#### 流程

```
1. 看「待上架清單」（驗貨完成的）
2. 點某筆 → 顯示每件料件的「建議庫位」（從料件主檔的「預設庫位」帶）
3. 倉管走到對應庫位、放上去
4. 按「上架完成」、系統把該筆庫存入到指定庫位
5. 對應進貨單狀態自動推進「部分已收 / 全部已收」
```

### 11.4 桌機 hub 卡占位

⚠️ **庫存中心首頁桌機版的「進貨」區（驗貨 / 上架 2 張卡）目前是占位、桌機點下去無頁面**、要走：

- 手機版分頁「工作站 → 驗貨 / 上架」。
- 或直接打網址 `/dashboard/inventory/receiving`（桌機可進、但介面是手機尺寸的）。

之後升級會補桌機完整版 UI。
