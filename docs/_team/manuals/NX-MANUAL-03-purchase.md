## §1. 這本手冊是什麼

這本講「公司怎麼向供應商買東西、把貨拿到、再進倉」。

包含（LITE 全版本基本內含）：
- 採購怎麼啟動（缺貨自動冒出 / 客訂帶起來 / 手動加）。
- 完整 5 步驟採購工作流：**需求 → 詢價 → 採購單 → 進貨 → 退貨**。
- 進貨退貨怎麼變成「保固申請單」找廠商換 / 退錢。
- 從進貨角度看的供應商管理、產品管理。

套件範疇（指路、加購後可用）：
- 國外進貨 6 階段流程（進口費用攤分 / 提貨單 / 多幣別） → 需加購「多據點模組」、詳見 NX-MANUAL-PACKAGE-08（PLUS / PRO 免費送、LITE 也可單買）。
- 品牌料號規則自動編碼 → 需加購「汽車資料庫套件」、詳見 NX-MANUAL-PACKAGE-01。LITE 未加購不影響採購主流程、料件主檔的「料號」欄手填即可。

### 1.1 ⭐ 應付帳款認列規則（總經理拍板 + 2026-06-04 實測補完條件）

⚠️ **重要財務規則**：NEXORA 應付帳款（AP）認列**分兩條路徑**、依「進貨有沒有對應的採購單」決定：

#### 路徑 A：標準流程（有 PO）= **CONFIRMED 認列、進貨不再產**

業務語意 = 「**先款後貨**」：採購單流到「廠商確認」時認列、後續進貨只動庫存：

```
DRAFT 草稿 → APPROVED 已核可 → SUBMITTED 已送廠商
                                    ↓
                              CONFIRMED 廠商確認  ⚡ 此時系統自動產一筆應付帳款進財務
                                    ↓
                              PARTIAL_RECEIVED 部分已收 / RECEIVED 全部已收 → CLOSED 結案
```

- 廠商一回覆「OK 我接單、會出貨」、系統就認列應付（您欠他了）。
- 不用等實際貨到、財務就能掌握「這個月會有多少貨款要付」。
- ⭐ **有對應 PO 時**、之後實際進貨（RR）**不會再產應付**、只做庫存入帳（見 §7.7）。

#### 路徑 B：LITE 直接路徑（無 PO）= **RR 過帳時獨立認列**

業務語意 = 「**現場掃貨 / 緊急採購、廠商直接送貨、沒走 PO 簽核**」：進貨單 POSTED 時認列：

```
（沒走 PO）→ RR 進貨單建立 → POSTED 過帳
                              ⚡ 此時系統自動產一筆應付帳款進財務
                              （sourceType = 'RR'、跟標準路徑的 sourceType='PO' 分開區辨）
```

- 適用情境：緊急採購、現場補貨、廠商直接送貨來、沒時間走詢價+採購單流程。
- ⭐ **無對應 PO 時、RR POSTED 是認列點**、跟路徑 A 對稱、避免「貨進來但帳上沒記欠款」。

#### dedup（避免雙重認列）

系統有 dedup 邏輯：

> **同一張 RR 進貨單**最多認列一筆應付：
> - 如果 RR 有 `poId`（接到 PO）→ 跳過 RR 認列（路徑 A 已在 CONFIRMED 認列過）
> - 如果 RR 沒 `poId`（獨立 RR）→ RR 自己認列（路徑 B）

⚠️ ⚠️ **重要避免會計誤會**：手冊舊版（v1.0）寫「進貨單不會再產應付」是針對**路徑 A**、不是絕對。實際 LITE 客戶若同時用兩種模式（部分採購走 PO、部分直接收貨）、會看到 2 種來源的應付（sourceType='PO' 跟 sourceType='RR'）、是合理的。

#### CANCELLED 沖帳

⚠️ 如果採購單最後變成 CANCELLED 取消、對應的應付會由系統做沖帳處理（詳見 NX-MANUAL-06 財務手冊）。

## §2. 採購中心入口

### 2.1 三種進採購中心的方法

| 方法 | 怎麼做 |
|---|---|
| 螢幕最上方那排 | 點「進貨」分頁 |
| 星球按鈕 | 點左上星球（或 `Alt+X`）→ 左欄選「採購」|
| 直接打網址 | 網址列尾端 `/dashboard/purchase` |

⚠️ 沒有採購類權限的員工、「進貨」分頁不會顯示（NX-MANUAL-02 §4.3 講過權限怎麼設）。

### 2.2 採購中心首頁長什麼樣

採購中心分 **3 區**：

| 區 | 卡 | 用途 |
|---|---|---|
| **主檔管理** | 產品管理、供應商管理 | 採購相關的主檔捷徑（同一份資料、從採購角度看）|
| **國內採購** | SOP 精品示範、需求、詢價、採購單、進貨單、退貨單 | 6 張卡、5 個步驟工作流 + 1 個示範入口 |
| **特殊採購** | 採購單、進貨單、退貨單 | 不經詢價的「掃貨採購」流程（**3 張卡目前都尚未開放**、見 §11）|

⭐ 國內採購區的步驟卡上有 STEP1~STEP5 徽章、引導新人照順序走。

### 2.3 SOP 精品示範

「SOP 精品示範」卡（國內採購區第一張、火焰 🔥 圖示）是針對「手機版採購流程」的引導範例、9 步走完一張採購單、內建防呆。新人用一次熟悉流程之後、不用每次都從這進。

### 2.4 手機版差異

手機螢幕底部會出現 3 個分區按鈕：「主檔管理 / 國內採購 / 特殊採購」、預設停在「國內採購」（讓新人一進來就看到 SOP 引導）。

## §3. 採購工作流總覽

### 3.1 5 步驟主流程（國內採購）

```
STEP 1：需求      → 知道「該買什麼、買多少」
   ↓
STEP 2：詢價      → 向廠商問價、等回覆
   ↓
STEP 3：採購單    → 確認價格 → 主管核可 → 送廠商 → 廠商確認 ⚡應付認列
   ↓
STEP 4：進貨單    → 貨到、驗收、入庫
   ↓
STEP 5：退貨單    → 驗收有問題、退回廠商（可選步驟）
       ↓ 若選保固
       保固申請單  → 找廠商換新 / 退錢 / 報修
```

### 3.2 哪些步驟可以跳

| 場景 | 跳哪些步驟 |
|---|---|
| **正常採購** | 1→2→3→4（5 看狀況）|
| **熟悉廠商、不需要再問價** | 1→3→4（跳過 2 詢價）|
| **緊急現場掃貨** | 直接走「特殊採購」3→4（**尚未開放**）|
| **客戶等不到、跟同行調貨** | 走「同行調貨」、不在採購流程裡（見 NX-MANUAL-05 §5.3）|

### 3.3 採購中心 vs 主檔中心

「進貨」分頁的「**產品管理 / 供應商管理**」跟「主檔中心」的「零件 / 往來對象」是**同一份資料**、但欄位視角不同：

| 入口 | 看得到的欄位 |
|---|---|
| 主檔中心 → 零件 | 4 分區全部（基本 / 銷貨 / 採購 / 庫存）|
| 進貨 → 產品管理 | **只顯示基本資料 + 採購分區**（看不到客戶售價）|
| 主檔中心 → 往來對象 | 4 分區全部 |
| 進貨 → 供應商管理 | **只顯示 S 身分的供應商**（不顯示 C 保養廠 / O 同行 / B 銀行）|

⭐ 這就是 NX-MANUAL-02 §5.1 講的「資訊保密設計」、採購員從採購入口進、看不到客戶售價。

## §4. 採購需求單（STEP 1）

### 4.1 是什麼

把「該買、但還沒買」的需求集中在一張清單。

### 4.2 兩種需求類型

實際系統有 **2 種類型**：

| 類型 | 來源 | 怎麼出現的 |
|---|---|---|
| **S 補貨自動** | 系統自動產 | 庫存低於安全量、系統每天結算後自動寫進需求清單 |
| **O 客訂** | 業務 / 採購手動加 | 業務員拿到客戶訂單發現缺料、按「+ 手動新增」直接加進來；或開銷貨單時系統提示加 |

⚠️ 藍圖規格曾經提過第 3 種「盤點低量」、目前系統把它跟「補貨自動」合併成同一種類型 S。

### 4.3 列表畫面

進入「採購需求單」會看到一張表、每列一筆需求：

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產（例：`NX02DR0001234`）|
| **來源類型** | 補貨自動（藍色徽章）/ 客訂（琥珀徽章）|
| **產品** | 從零件主檔挑 |
| **倉庫** | 該補哪個倉的貨 |
| **數量** | 需求量 |
| **客戶** | 客訂類型才有 |
| **預期日期** | 客訂類型才有、客戶希望何時拿到 |
| **狀態** | 待處理（琥珀）/ 處理中（藍）/ 已完成（綠）/ 已忽略（灰）|
| **備註** | 自由文字 |

### 4.4 列表上方的篩選

- **類型篩選**：全部 / 補貨自動 / 客訂。
- **狀態篩選**：全部 / 待處理 / 處理中 / 已完成 / 已忽略。
- **關鍵字搜尋**：可打單號、備註關鍵字。

### 4.5 操作

#### 手動新增（針對客訂等臨時需求）

按「**+ 手動新增**」彈出對話框：

- **類型**：預設「客訂」（也可改補貨自動）。
- **料號**：從零件主檔挑（必填）。
- **倉庫**：要補到哪個倉（必填）。
- **數量**：需求量、必填、要 >0。
- **客戶**：可選、誰訂的。
- **預期日期**：可選、什麼時候要。
- **備註**：可選。

填完按「建立」、就會出現在列表、狀態「待處理」。

#### 忽略某筆需求

選中某筆 → 按「忽略」→ 跳對話框填「**忽略原因**」（必填、稽核用）→ 確認。
- 該筆狀態變「已忽略」、不會被詢價單拉走。
- 可以從「狀態篩選」切回「已忽略」查歷史。

#### 把需求轉成詢價

採購員在「詢價單」頁面開新單時、可以勾選「採購需求單」未處理的行、自動帶進詢價單明細（見 §5.4）。

### 4.6 狀態流轉

```
O 待處理 → P 處理中（被詢價單拉走）→ C 已完成（採購完成）
   ↓
   I 已忽略（手動忽略）
```

### 4.7 資料來源 / 資料去向

- 來源：庫存低量系統自動產 / 業務 / 採購手動加。
- 去向：詢價單拉項目時帶過去；報表「依需求類型 / 來源統計」用。

## §5. 詢價單（STEP 2）

### 5.1 是什麼

向 1~多家供應商問「這幾項您賣多少錢」的單據、等廠商回價、選最便宜或最快交期的、再進採購單。

### 5.2 列表畫面

進入「詢價單」會看到所有詢價：

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產（例：`NX02RFQ0001234`）|
| **供應商** | 問哪家 |
| **開單日** | 開詢價的日期 |
| **預期到貨日** | 詢問廠商最快能何時送到 |
| **總金額** | 該詢價單估算金額 |
| **狀態** | 草稿 / 已送出 / 已回覆 / 已結案 / 已取消 |

### 5.3 狀態流轉

| 狀態 | 是什麼 |
|---|---|
| **草稿（DRAFT）** | 採購員開了單、還沒送出 |
| **已送出（SENT）** | 已把詢價內容傳給供應商（LINE / Email / 電話）|
| **已回覆（REPLIED）** | 採購員把廠商回的價填回系統 |
| **已結案（CLOSED）** | 已轉成採購單、本詢價完成任務 |
| **已取消（CANCELLED）** | 中途作廢 |

⭐ 採購員開新詢價可以直接跳到「已回覆」（廠商當場報價、不必走「已送出」中間狀態）。

### 5.4 開新詢價

按「**+ 新增詢價單**」進入開單畫面：

#### 基本資訊

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產、不能改 |
| **供應商** | 從供應商主檔（S 身分）挑、必填 |
| **預期到貨日** | 問廠商最快何時能送 |
| **備註** | 可帶系統設定的「客套話模板」自動產出（在「設定 → 系統參數」設）|

#### 詢價明細（衛星表）

每一行：

| 欄位 | 說明 |
|---|---|
| **產品** | 從零件主檔挑 |
| **數量** | 詢問量 |
| **預估價** | 系統自動帶「該產品 × 該廠商」的歷史進貨平均價、可手動覆寫 |
| **總額** | 數量 × 預估價（自動算）|

兩種加明細的方法：

1. **從採購需求單拉項目**：按「+ 從採購需求單拉項目」彈出待處理需求清單（§4）→ 勾選 → 自動帶進詢價明細、對應需求單轉「處理中」。
2. **手動加一行**：「+ 手動加一行」自己挑料件。

### 5.5 詢價單詳情頁

開好的詢價單點進去詳情頁有 4 個按鈕：

| 按鈕 | 作用 |
|---|---|
| **編輯** | 改內容（草稿狀態才能完整改、其他狀態只能改備註）|
| **作廢** | 把狀態切到「已取消」|
| **產生詢價文字** | 跳一個可複製的文字框、自動套廠商名 + 詢問項目 + 客套話、直接貼進 LINE 給廠商 |
| **採用、建立採購單** | 進入「採購單」開單畫面、本詢價明細自動帶過去 |

### 5.6 產生詢價文字（精品功能）

按「產生詢價文字」會出現可複製文字、長這樣：

```
瑞利汽材老闆您好、

想跟您詢以下幾項：
1. 剎車片 BRK001 × 10
2. 機油濾 OIL-FT-22 × 5

請報價、麻煩您。
```

採購員複製貼到 LINE 給廠商即可、不用自己打字。

### 5.7 狀態說明：什麼時候手動切

- 開好詢價 → 自動「草稿」。
- 按「產生詢價文字」+ 實際傳給廠商 → 手動切「已送出」。
- 廠商回價、採購員填進系統 → 切「已回覆」。
- 轉成採購單後 → 系統自動切「已結案」。

### 5.8 資料來源 / 資料去向

- 來源：採購員手動建、或從採購需求單轉。
- 去向：採購單（採用後自動帶明細）；報表「詢價 → 採購 轉換率」、「廠商回價速度」用。

## §6. 採購單（STEP 3、AP 認列點 ⚡）

### 6.1 是什麼

決定「跟這家廠商、買這些東西、用這個價」的正式單據。**這是整套採購流程裡最關鍵的一張單**、因為應付帳款在這裡認列。

### 6.2 列表畫面

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產（例：`NX02PO0001234`）|
| **供應商** | 跟哪家買 |
| **開單日** | 開採購單的日期 |
| **預期到貨日** | 廠商承諾的到貨日 |
| **狀態** | 8 狀態（見 §6.3）|
| **總金額** | 採購單總額（含稅）|

### 6.3 8 狀態流轉

⚠️ 這是 NEXORA 採購單最完整的狀態流、跟應付認列直接相關：

| 狀態 | 是什麼 | 應付認列？ |
|---|---|---|
| **DRAFT 草稿** | 採購員建好、還沒送主管核可 | ❌ |
| **APPROVED 已核可** | 主管按「核可」（小公司：負責人核可）、寫入核可人/時間 | ❌ |
| **SUBMITTED 已送廠商** | 把 PO 內容傳給廠商（LINE / Email / 傳真）、等廠商確認 | ❌ |
| **CONFIRMED 廠商確認** | 廠商回覆「接單、會出貨」、採購員切到這狀態 | **✅ 系統自動產應付帳款（sourceType='PO'）** |
| **PARTIAL_RECEIVED 部分已收** | 第一次驗收完成、但還沒全到 | （**有 PO 的 RR** 不再產應付、應付已在 CONFIRMED 認列）|
| **RECEIVED 全部已收** | 所有項目全部到貨且驗收完成 | （同上）|
| **CLOSED 結案** | 採購單關閉、不會再有任何動作 | （同上）|
| **CANCELLED 取消** | 任何狀態都可作廢；已認列的應付會由系統做沖帳 | （沖帳處理）|

⭐ **路徑分流提醒**（見 §1.1）：本表是「**走 PO 路徑**」的認列規則。若客戶採取「無 PO 直接收貨」、看 §7.7 RR 路徑 B。

#### 合法狀態切換

```
DRAFT ──→ APPROVED ──→ SUBMITTED ──→ CONFIRMED ──→ PARTIAL_RECEIVED ──→ RECEIVED ──→ CLOSED
  │          │            │              │                  │                  │
  └──────────┴────────────┴──────────────┴──────────────────┴──────────────────┴──→ CANCELLED
```

⚠️ 系統會擋「跳格」（例：不能 DRAFT 直接到 CONFIRMED、必須先過 APPROVED + SUBMITTED）、防止漏簽核。

### 6.4 開新採購單

兩種開法：

#### 方法 1：從詢價單轉

在詢價單詳情頁按「採用、建立採購單」、明細自動帶過來（最常用、減少重複輸入）。

#### 方法 2：直接開

按「**+ 新增採購單**」自己挑廠商、加明細（適合熟悉廠商、不用問價的場景）。

#### 開單欄位

| 欄位 | 說明 |
|---|---|
| **單號** | 自動產 |
| **供應商** | 必填、從供應商主檔挑 |
| **開單日** | 預設今天、可改 |
| **預期到貨日** | 廠商承諾到貨日 |
| **稅率** | 預設 5%、可改 |
| **幣別** | 預設 TWD、多幣別需「多據點模組」 |
| **採購明細** | 一行多筆、每筆 = 料件 + 數量 + 單價 + 行小計 |
| **備註** | 自由文字 |

#### 明細特殊欄位

每行採購明細裡的「**料號 / 品名**」是**進單時的快照**（snapshot）：

- 之後零件主檔改名 / 改料號、舊採購單的明細不會跟著變、保留當時樣貌。
- 報表查歷史採購、看的是當時的料號、不是現在的。

### 6.5 操作流程實例

#### 標準走法

```
1. 採購員開草稿（DRAFT）→ 輸入廠商 + 明細
2. 採購員按「送主管核可」→ 系統切 APPROVED、記下核可人 + 時間
3. 採購員按「送廠商」（傳 LINE / Email）→ 系統切 SUBMITTED
4. 廠商回覆「接單」→ 採購員按「廠商確認」
   ⚡ 系統執行：
      - 切狀態到 CONFIRMED
      - 自動產一筆應付帳款進財務（金額 = 採購總額）
      - 寫稽核紀錄
5. 之後貨到、開進貨單驗收（見 §7）
6. 全部驗收完 → 採購員按「結案」→ 切 CLOSED
```

#### 取消已認列應付的採購單

選中已 CONFIRMED 的採購單 → 按「取消」→ 跳確認框警告「**本採購已認列應付帳款 N 元、取消後系統會做沖帳處理**」→ 確認 → 切 CANCELLED + 沖帳。

### 6.6 採購單詳情頁

打開單筆採購單看到的東西：

- 頂部：單號、廠商、目前狀態（徽章）、開單人、核可人、應付認列時間。
- 中段：採購明細表。
- 底部：操作按鈕（按狀態顯示不同的、例：DRAFT 顯示「送核可」、APPROVED 顯示「送廠商」、SUBMITTED 顯示「廠商確認」、CONFIRMED 顯示「開進貨單」）。
- 右側欄：狀態時間軸（Timeline）、顯示這張 PO 走過的所有狀態 + 經手人 + 時間、稽核非常清楚。

### 6.7 資料來源 / 資料去向

- 來源：詢價單轉、或採購員直接開。
- 去向：
  - **狀態到 CONFIRMED 時**：自動產應付帳款進財務模組（見 NX-MANUAL-06 §X 應付帳款）。
  - 進貨單會引用本採購單作為來源。
  - 報表「採購總額 / 廠商占比 / 採購頻率」用。

## §7. 進貨單（STEP 4、貨到驗收入庫）

### 7.1 是什麼

廠商把貨送來、倉管驗收、入帳到主倉的單據。

### 7.2 列表畫面

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產（例：`NX02RR0001234`）|
| **供應商** | 跟哪家進的貨 |
| **倉庫** | 入哪個倉 |
| **進貨日** | 貨實際到的日子 |
| **狀態** | 草稿（D）/ 已過帳（P）/ 已取消（C）|
| **總金額** | 該進貨單總額 |
| **幣別** | 預設 TWD |

### 7.3 狀態流轉

NEXORA 進貨單目前用 **3 狀態**：

| 狀態 | 是什麼 |
|---|---|
| **草稿（D）** | 倉管開單在驗收中、明細還在改 |
| **已過帳（P）** | 驗收完成、明細 / 數量 / 金額確認、貨已入庫 |
| **已取消（C）** | 整張單作廢 |

⚠️ 後端有預留更細的「驗收中 / 拒收」狀態（之後升級會接、目前 LITE 走簡化版的 3 狀態）。

### 7.4 開新進貨單

兩種開法：

#### 方法 1：從採購單轉

採購單詳情頁狀態到 CONFIRMED（廠商確認、應付已認列）之後、頁面會出現「開進貨單」按鈕、按下去明細自動帶過來。

#### 方法 2：直接開

按「**+ 新增進貨單**」自己挑廠商、選倉庫、加明細（適合「沒有採購單、廠商直接送來」的緊急場景）。

#### 開單欄位

| 欄位 | 說明 |
|---|---|
| **單號** | 自動產 |
| **供應商** | 必填、從供應商主檔挑 |
| **倉庫** | 必填、入哪個倉（LITE 預設主倉）|
| **進貨日** | 預設今天、可改 |
| **稅率** | 預設 5%、可改 |
| **幣別** | 預設 TWD |

### 7.5 進貨明細（衛星表）

每行明細：

| 欄位 | 說明 |
|---|---|
| **項次** | 自動編號 |
| **料號** | 從料件主檔挑、自動帶料號 / 品名 / 廠牌作快照 |
| **品名** | 自動帶 |
| **廠牌** | 自動帶 |
| **入庫庫位** | 從該倉的庫位挑、決定貨放哪一格 |
| **進貨數量** | 倉管實際驗收的數量（**可能跟採購單不同**、之後可能要開退供應商或保固）|
| **採購單價** | 從採購單帶、可改（如果廠商出貨價跟採購單不同）|
| **明細金額** | 自動算：數量 × 單價 |
| **備註** | 可選 |

### 7.6 操作流程

```
1. 倉管收到貨、開進貨單草稿
2. 填供應商 + 倉庫 + 進貨日
3. 一行行加明細：料件 + 入庫庫位 + 實收數量 + 實際單價
4. 系統自動算每行金額 + 整單總額
5. 確認無誤 → 按「過帳」→ 狀態切「已過帳」
   此時系統：
      - 庫存 + 該料件數量、入指定庫位
      - 寫稽核紀錄
      - 通知原採購單「部分已收 / 全部已收」（如果有對應 PO）
6. 驗收發現問題 → 別過帳、改開退供應商單（§8）或保固申請單（§9）處理
```

### 7.7 ⭐ 進貨單的應付認列規則（補完條件、非絕對）

⚠️ **重要提醒**（2026-06-04 實測補完）：進貨單對應付的影響**分兩種情況**、不是絕對「不產應付」：

#### 情況 A：有對應 PO → 進貨不再產應付

- RR 明細的 `poId` 有值 → 應付已在 §1.1 §6.3 的 CONFIRMED 路徑認列過、RR POSTED 時系統 dedup 跳過、不重複產。
- RR 做的事 = **庫存增加 + 通知原 PO「部分已收 / 全部已收」**、財務面看採購單那張應付。

#### 情況 B：無對應 PO（LITE 直接收貨）→ RR POSTED 獨立產應付

- RR 沒有 `poId`（採購員直接開、沒走 PO 流程）→ RR POSTED 時系統認列一筆**獨立應付**（sourceType='RR'、跟 PO 路徑分開）。
- 適用情境：緊急採購、現場補貨、廠商直接送貨、沒時間走 PO 簽核。
- 帳上會看到 sourceType='RR' 的應付、不會跟 PO 那條重複（因為根本沒對應 PO）。

⚠️ **避免會計誤會的提醒**：手冊 v1.0 寫「進貨不會再產應付」是針對情況 A、實際 LITE 客戶若**部分採購走 PO、部分直接收貨**、會看到兩種來源的應付（PO + RR）、是合理的、不是 bug。建議統計時依 `sourceType` 分流看。

### 7.8 資料來源 / 資料去向

- 來源：採購單轉、或倉管直接開。
- 去向：
  - 庫存帳：對應料件、對應倉、對應庫位 + 數量。
  - 採購單狀態：自動更新部分已收 / 全部已收。
  - 進貨成本：寫進料件主檔的「進貨成本」（影響之後重算售價）。
  - 報表「進貨報表 / 廠商占比 / 進貨成本走勢」用。

## §8. 退供應商單（STEP 5）

### 8.1 是什麼

進貨驗收發現問題（瑕疵、規格不對、數量短缺要退）、把貨退回廠商的單據。

⚠️ **此功能尚未對 LITE 客戶開放**：採購中心首頁「退貨單」STEP 5 卡目前是占位、點下去無頁面。

### 8.2 後端狀態（已實作、等前端做完才會開）

後端狀態機已就緒：

| 狀態 | 是什麼 |
|---|---|
| **草稿（DRAFT）** | 開單但還沒過帳 |
| **已過帳（POSTED）** | 確認退貨、庫存扣回 |
| **已取消（CANCELLED）** | 作廢 |

### 8.3 預計運作方式（規格、實際 UI 未完成）

- 從進貨單或庫存查詢觸發、選要退的料件 + 數量。
- 倉管裝箱 → 廠商來收、或公司送回。
- 過帳時：庫存扣回、應付帳款做沖帳處理（沖原採購單的應付）。

### 8.4 目前替代做法

LITE 客戶遇到「驗收後想退」的場景、目前實務上可以：

- **小問題**：跟廠商協商換貨、之後重新驗收。
- **大問題**：直接走「保固申請單」（見 §9）、走完整退錢 / 換新 / 維修流程。
- **整批退**：聯絡伊諾瓦客服協助手動沖採購單。

⚠️ 後端基礎已備好、之後升級會直接補上前端 UI、客戶不用搬資料。

## §9. 保固申請單

### 9.1 是什麼

向供應商提報「貨有問題、要求廠商處理」的單據。常見場景：

- 客戶買回去發現有瑕疵、退到您這、您再轉跟供應商求償。
- 您自己驗貨發現重大問題、要求廠商換新 / 修 / 退錢。

### 9.2 兩種申請類型

| 類型 | 是什麼 | 用在 |
|---|---|---|
| **自家內訴（SELF）** | 公司自己發現問題（驗貨 / 倉庫巡檢發現）| 廠商直接對公司 |
| **客訴（CUST）** | 客戶反映、有對應的銷貨單 | 必須填「來源銷貨單」追溯 |

### 9.3 列表畫面

進入「保固申請單」會看到：

| 欄位 | 說明 |
|---|---|
| **單號** | 系統自動產（例：`NX02WAR0000056`）|
| **類型** | 自家內訴 / 客訴 |
| **供應商** | 求償對象 |
| **零件** | 哪個料件出問題 |
| **數量** | 求償數量 |
| **申請日** | 開申請的日期 |
| **狀態** | 5 狀態（見 §9.4）|
| **結果** | 廠商處理結果（見 §9.5）|

### 9.4 5 狀態流轉

| 狀態 | 是什麼 | 顏色 |
|---|---|---|
| **草稿（D）** | 開了單還沒送供應商 | 白底 |
| **已送出（S）** | 已通報供應商、等對方回覆 | 藍 |
| **審核中（R）** | 供應商收件、檢查中 | 琥珀 |
| **已結案（C）** | 結果登記、處理完成 | 綠 |
| **已作廢（V）** | 中途取消 | 紅 |

#### 流轉操作

- 草稿 D：按「**送出**」→ 狀態切 S。
- 已送出 S：按「**進入審核**」→ 狀態切 R。
- 審核中 R：填結果 + 回覆 → 按「**登記結果**」→ 狀態切 C。
- D / S / R 任一狀態：按「**作廢**」→ 狀態切 V。

### 9.5 4 種處理結果（在「審核中」狀態填）

| 結果 | 代碼 | 是什麼 |
|---|---|---|
| **換新** | NEW | 廠商寄新品來替換 |
| **退錢** | REF | 廠商退錢、有 3 種退法（見 §9.6）|
| **維修** | RPR | 廠商收件維修後送回 |
| **拒絕** | REJ | 廠商不接受求償 |

### 9.6 「退錢」的 3 種退款方式

選結果 = REF 時、必須再選退款方式 + 填退款金額：

| 退款方式 | 代碼 | 系統做的事 |
|---|---|---|
| **下次扣抵** | O | 純記錄、業務下次採購這家廠商時手動扣 |
| **折讓單** | A | ⚡ **系統自動建一張草稿折讓單**、財務核可後沖應付 |
| **直接退現** | R | 純記錄、之後用「收付款」開付款選沖應付 |

⭐ **建議退款金額**：選 REF 時、系統會自動算「該料件的進貨成本 × 求償數量」並帶入金額欄、業務員可手動改。

### 9.7 開新保固申請

按「**+ 新建保固申請**」展開表單、依「分層填欄位」設計、分 3 層：

#### 必填欄位（required）

| 欄位 | 說明 |
|---|---|
| **申請類型** | 自家內訴 / 客訴 |
| **申請日期** | 預設今天 |
| **來源銷貨單 ID**（客訴才有）| 必填、追溯哪張銷貨單 |
| **供應商** | 求償對象 |
| **零件** | 哪個料件 |
| **數量** | 求償數量 |
| **問題描述** | 寫給供應商看、例：「第一次使用 3 個月後漏油、無撞擊痕跡」|

#### 建議欄位（recommended）

| 欄位 | 說明 |
|---|---|
| **來源銷貨單號**（客訴）| 顯示用（snapshot）|

#### 進階欄位（advanced）

| 欄位 | 說明 |
|---|---|
| **備註** | 內部紀錄（不給供應商看）、例：「本批已通報業務 G、由 A 後續追蹤」|

填完按「**建立（草稿）**」、狀態 D 草稿、進入列表。

### 9.8 附件上傳（每筆保固單都可上傳）

每筆保固申請（除了已作廢狀態）右側都有「📎 附件」區、可上傳 3 種：

| 類型 | 代碼 | 接受格式 |
|---|---|---|
| **行照** | LIC | 圖片 / PDF |
| **照片** | PHO | 圖片 |
| **影片** | VID | 影片 |

點檔案類型 → 跳檔案選取 → 自動上傳 → 顯示「✅ 已上傳 XXX.jpg（N KB）」。

### 9.9 折讓單自動沖應付的流程

⚠️ 重要：選結果 = REF + 方式 = A 折讓單時、系統自動產一張**草稿折讓單**到財務模組、財務人員核可那張折讓單時、系統自動沖原採購單的應付帳款。

```
保固單結果 = REF / 方式 = A
   ↓
系統自動建 DRAFT 折讓單（金額 = 退款金額）
   ↓
財務人員到「折讓單」工作頁核可
   ↓
系統自動沖應付帳款（應付 ↓ 折讓金額）
```

詳見 NX-MANUAL-06 §X 折讓單。

### 9.10 資料來源 / 資料去向

- 來源：進貨驗收問題（自家內訴）、銷貨退款追溯（客訴）。
- 去向：
  - 結果 = REF + 方式 = A → 自動建草稿折讓單進財務。
  - 結果 = NEW → 等廠商送新品來、實務上再開新進貨單入帳。
  - 報表「廠商保固通過率 / 保固處理速度」用。

## §10. 國外進貨 ⛔ 多據點模組

⚠️ **此整個功能需加購「多據點模組」、詳見 NX-MANUAL-PACKAGE-08**（國外採購 6 階段追蹤：備貨中 → 要求付款 → 待出貨 → 出貨上船 → 已到港 → 驗收完成、含進口費用攤分 / 提貨單 / 多幣別 / 結匯）。

⭐ **LITE 客戶（國內為主、未加購）跳過整章不用看**：
- 國外進貨整個流程（含船號 / 貨櫃號 / ETA / 貿易條件 / 進口付款條件 / 進口費用攤分到料件成本 / 提貨單）都歸多據點模組。
- LITE 採購主流程（§4 ~ §9）足夠應付國內採購 + 在地廠商代理進口的場景（廠商已含稅關報關、用一般採購單 §6 入帳即可）。
- 真正自己進口、需要追蹤船期 / 攤分進口費用 / 開外幣單時、再加購多據點模組（PLUS / PRO 免費送、LITE 也可單買）。

> 6 階段追蹤頁面 / 推進操作 / 跟國內採購的差別表 → 加購後見 PACKAGE-08 對應章節。

## §11. 從採購角度看的產品 / 供應商管理

採購中心首頁「主檔管理」區的兩張卡、跟主檔中心是**同一份資料**、欄位視角不同。

### 11.1 採購 → 產品管理

#### 跟主檔中心的差別

| 入口 | 顯示分區 |
|---|---|
| 主檔中心 → 零件基本資料 | 4 區全顯（基本 / 銷貨 / 採購 / 庫存）|
| 採購 → 產品管理 | **3 區（基本 / 採購 / 庫存）**、**銷貨區不顯示** |

⭐ **保密設計**：採購員從採購入口進、看不到客戶售價（A/B/C/D 四級）。這是 NX-MANUAL-02 §5.1 講過的「資訊保密設計」實作。

#### 採購區看得到的欄位

唯一一個重要欄位：**進貨成本**（業務員填、之後重算售價的基準）。

#### 操作

跟主檔中心一樣的範式（A 新增 / E 更正 / D 停用、見 NX-MANUAL-02 §3 通用操作）。
- 建料件時、設「進貨成本」是採購員的主要動作。
- 業務員之後在銷貨頁面看到的售價建議、會用這個成本算。

### 11.2 採購 → 供應商管理

#### 跟主檔中心的差別

| 入口 | 顯示對象 / 分區 |
|---|---|
| 主檔中心 → 往來對象 | 全部 6 身分（C / O / S / T / V / B）+ 4 分區 |
| 採購 → 供應商管理 | **只顯示 S 供應商**、可編 **2 分區（基本 / 財務）** |

#### 編得到什麼

| 分區 | 看得到 | 可編 |
|---|---|---|
| **基本資料** | 對象代碼、名稱、聯絡資訊、身分標 S | ✅ |
| **財務** | 統編、付款條件、貿易條件、預設幣別、供應商等級 A/B/C/D | ✅ |
| ~~銷貨~~ | （不顯示、S 身分不需要）| — |
| ~~配送~~ | （不顯示）| — |

#### 操作

- 建新供應商：A 新增 → 系統預設 `partnerType = 'S'`、只要填基本 + 財務 → S 存檔。
- 改付款條件：選中 → E → 切到「財務」分區 → 改 → S。
- 停用供應商：選中 → D 停用（之後不能選、歷史單據還在）。

#### 資料來源 / 資料去向

- 來源：採購員手動建（接觸新廠商時）、或伊諾瓦開戶代建一批。
- 去向：詢價單 / 採購單 / 進貨單 / 退供應商單 / 保固申請單 的「供應商」欄、應付帳款的「對象」欄。
