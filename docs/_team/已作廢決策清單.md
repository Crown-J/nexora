# 已作廢決策清單

## 這份檔案要解決什麼

Hank 開工前一律 grep 確認現狀、不憑記憶——這是對的。
但**程式碼不會告訴你，它裡面的東西是現行決策還是已被推翻的舊決策**。

作廢的四級價躺在 schema 裡，跟現行的公司定價長得一樣真實。
於是每次分析都會把已經作廢的東西當成「系統真相」帶進判斷，執行長要重講一次。

**這份清單就是那個分辨依據。**

## 維護規則

- 執行長推翻一個舊設定 → 當場記一條，⛔ 不等到有空再補
- 每條四件事：**被推翻的是什麼 / 被什麼取代 / 哪一天 / 程式碼裡還有什麼殘留**
- ⛔ **不刪除**已作廢的紀錄（G.4 歷史 fact 保留）——作廢本身就是歷史
- 殘留清乾淨後、把「殘留」欄改成 `✅ 已清`，條目留著
- Hank 開工必讀順序：`CLAUDE.md` → `git log` → **本檔** → 對應規格書

## 一、定價與價格紀律

### 1. 零件四級價（priceA / B / C / D）

| | |
|---|---|
| **舊決策** | 傳統汽配 ERP 四級價：客戶分 A/B/C/D 四級，每級各賣一個價，零件主檔存四個價格欄位 |
| **取代它的** | **2026-08-01**：priceA 重新定義為**市場行情價**（產品組向正廠經銷商索取的原廠報價）、priceB 重新定義為**公司定價**（實際賣給保養廠的價）。**查價查貨只顯示這兩個價，都從零件主檔直出、⛔ 不現場算** |
| **日期** | 2026-08-01 重新定義　·　**2026-08-02 明確作廢 priceC / priceD** |
| **⚠️ 殘留** | `Nx01Part.priceC`、`Nx01Part.priceD` 欄位與資料都還在 schema 裡，沒有任何現行邏輯讀它們 |

### 2. 成本式底價

| | |
|---|---|
| **舊決策** | 底價 ＝ 平均成本 ×（1 ＋ 客戶等級最低毛利率）。售價低於底價就擋下來、要求填原因 |
| **取代它的** | **2026-08-02**：底價 ＝ **公司定價 ×（1 −客戶等級折讓上限）**。理由：公司定價是產品組看著進價訂的、**毛利決策已經包在裡面**，⛔ 不需要在報價當下用成本再算一次 |
| **日期** | 2026-08-02 |
| **⚠️ 殘留** | `quote.service.ts` 的 `computeMinPrice()` 仍是成本式（`minPrice = avgCost × (1 + marginPct/100)`）。⭐ **「低於底價要填原因」那整套強制機制不變、繼續用**，只換算式 |
| **⭐ 為什麼重要** | 舊算法業務**算不出底價在哪**（他看不到成本），只會看到系統擋他。新算法業務算得出來 |

### 3. 個別客戶折數覆寫

| | |
|---|---|
| **舊決策** | `Nx01Partner.customMarginPct`——個別客戶毛利率覆寫，蓋過客戶等級的 marginPct。業務口語「個別折數」 |
| **取代它的** | **2026-08-02** 作廢。折讓空間一律由客戶等級決定，⛔ 不做個別客戶覆寫 |
| **日期** | 2026-08-02 |
| **⚠️ 殘留** | 欄位還在 schema |

### 4. ⚠️ 客戶等級 `marginPct` 的命名衝突（⛔ 未解、待拍板）

**不是作廢，是同一個欄位在系統裡有兩個名字兩種意思**——列在這裡是因為它同樣會誤導判斷：

| 出現位置 | 叫什麼 | 意思 |
|---|---|---|
| schema 註解 / service | 最低毛利率 | 底價 ＝ 成本 ×（1＋它） |
| 前端主檔設定畫面 | **加成率(%)** | — |

⚠️ 底價改成定價式之後，這個欄位的語意要重訂（折讓上限？KPI 加成？兩個都要？）。**待執行長拍板。**

## 二、定價鏈條（現行、⛔ 不是作廢——放這裡當判斷依據）

```
產品組分析市場  →  市場行情價（priceA）
        ↓ 給採購當詢價依據
採購詢價        →  進價（cost）⛔ 業務不可見
        ↓ 產品組據進價訂
公司定價（priceB）  ⭐ 唯一的紀律基準
```

**2026-08-02 執行長口述。** 判斷任何定價相關問題以這條鏈為準。
