報價轉銷貨（路 A 全線打通）

查價 → 出正式報價 → 等客戶回 → 轉銷貨 → 帶入品項 → 開單。

  • 單價用報價當初談定的價，⛔ 不重新帶價（那會推翻業務跟客戶講好的數字）
  • ⛔ 不自動把整張報價塞進去，讓業務勾——客戶常只買其中幾項
  • 帶進來的行夾帶報價行 id → 送出後報價自動標成已成交、同客戶同料號的舊報價自動作廢

實測：報價頁按轉銷貨 → 客戶自動選好 → 跳明細段 → 挑選器自動打開 → 勾選帶入 → 明細金額與報價單一致（未稅 200／含稅 210）。⛔ 未按送出，沒有產生真實銷貨單。

現場殼（今天的主體）

一支殼・一個路由・三套佈局：走動（手機）／定點（固定螢幕）／看板（電腦）。

流程狀態備註

幾個關鍵決定：

  • 看板一律沿用既有元件，⛔ 不重寫——舊的三欄看板已有「待撿／已撿／已取消」與管理動作，那正是看板該做的事
  • 工作站綁在螢幕上，⛔ 不綁在人身上：那台螢幕第一次開機問一次「你是哪個站」，之後記住。存瀏覽器本機、⛔ 不動資料庫
  • ⛔ 不做「小規模／大規模」設定：沒註冊工作站→全走手機→自動是單人作業；註冊了→定點→自動是多工作線。沒有人會選錯
  • 掃描槍＝打很快的鍵盤＋Enter：間隔超過 300ms 就當人在按。實測慢打不會誤觸發
  • 盤點⛔ 不顯示系統帳上的數量——先看到答案再去數，數出來的一定是答案

清單殼第一刀＋字級守門

  • 兩支共用元件（27／29 頁共用）字級收斂；全站代碼欄 12px → 14px：171 處／84 個檔 ——料號是 ERP 裡最常被眼睛掃的一欄，卻全站用最小字級
  • 三種資料量級驗過：幣別 4 筆／廠牌 463 筆／適配車型 142,690 筆，表格內字級只剩 14 與 15px
  • ⭐ 加 lint 規則守住下限：v3 新範式區＝error（⛔ 不准回歸）、其餘＝warn（2,679 則慢慢清）。 規則上線當場就抓到兩個我肉眼沒看到的違規

三、發現（這些比程式碼重要）

⚠️ 業務看得到成本（已修一半）

即時銷售站在低於底價時，警告訊息把成本數字直接印出來。業務只要改價格試到警告跳出來， 就能反推任何一顆零件的進價。而那個工作站掛在每一頁上、是活的。

已修：訊息改成只講事實不帶數字，擋的邏輯完全不變。
⚠️ 未修：後端仍把成本回傳到瀏覽器（開發者工具看得到）。 建議跟定價改制一起改——新底價＝公司定價×(1−折讓上限) 本來就不需要成本，⛔ 不要同樣的工做兩次。

⚠️ 「已上線 80」裡有 19 個是空殼

整個物流作業（5 格）、整個經營作業（7 格）、行政人員資料（4 格）、倉庫分析（2）、出納報表（1）—— 點進去只有一個標題和一段說明文字。

所以真實的改版進度是 2 / 60，⛔ 不是 2 / 80。全站這種佔位頁共 54 個（＝後端做完、UI 沒做）。

⚠️ 封箱之後回不去了

為了驗證出貨走了完整一條鏈，發現封箱是單向的——退回建箱中與作廢都被狀態機擋下。

⭐ 這個設計是對的（膠帶封了就是封了）。但它直接回答了「銷貨建單怎麼測」： 這條鏈上有一個不可逆的點，而且它在「送出」之後。

更麻煩的是封箱是跨模組的——它同時把銷貨單從「已確認」推到「已出貨」。 所以清除測試痕跡永遠不是「刪一筆」，是「還原一串」（實際跨了 5 張表）。
