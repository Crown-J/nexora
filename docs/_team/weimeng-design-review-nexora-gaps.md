# 偉盟設計檢視 → NEXORA 加強與避免清單

> 方法：偉盟 `AT52SS` 274 表＋155 程式物件已全庫分析（`C:\wellan\分析\*`、資料字典 v6 xlsx）。
> 本檔把結論收斂成三類：✅ 我方已做對（30 年實務印證）、🛠 該加強（偉盟有我方缺）、⛔ 該避免（負面教材→守則）。
> 我方 schema 佐證已逐項 grep 核實（發票抬頭/條碼/HS Code 全庫 0 處、SoItem 無實際出貨料號欄）。

## 1. ✅ 已被 30 年實務印證我方做對的（保持、不動）

| # | 偉盟的做法/坑 | 我方對應 | 印證 |
|---|---|---|---|
| 1 | 8 種單據塞單一 69 欄大表（RSIO），`ROCOT` 成本欄隨單型變義、`RONUM` 一欄雙義 | 依單型拆表（Rr/Pr/So/Sr/St/Conversion/Disposal/StockTake） | 拆表是對的；一欄多義是移轉最大痛點 |
| 2 | 全庫 **0 外鍵** → 孤兒資料（我們匯入時親歷：30 孤兒客戶＋1,063 孤兒料號） | 全 FK 約束 | 保持 |
| 3 | 折讓「軟作廢」（旗標+作廢金額/日/備註，不刪） | `isActive`/`voidedAt`/`cancelledAt` 軟刪除鐵則 | 同思路、我方更一致 |
| 4 | 調撥＝成對兩列互指＋實體「驗收暫存庫位」(Z01W) 表達在途 | `Nx03St` 單列 from/to＋status/receivedAt 工作流 | 我方模型較乾淨；移轉時偉盟兩列要收斂成一列 |
| 5 | 料件主檔 `BSQTY` 單倉彙總（多倉真相散在流水卡） | `Nx03StockBalance` 料×倉一筆 | 我方正確；移轉庫存不可搬 BSQTY |
| 6 | 移動加權平均成本：僅進貨改均價、`ROUND((舊量×舊均+進量×進價)/(舊量+進量),2)` | `applyQtyInWithLedger` 同款公式 | 公式一致，放心 |
| 7 | 過帳時把品名/廠牌/車型快照進明細（denormalize） | SoItem/RrItem 的 partNo/partName/brandName snapshot | 同款、正確（歷史不隨主檔變） |
| 8 | 客戶多地址/多聯絡真實需求：BCUX 8,197 筆（每戶≈2 個據點、各自發票資訊） | `Nx01PartnerAddress`(BILLING/SHIPPING 多筆)＋`Nx01PartnerContact` | 需求被印證；結構化地址方向對 |
| 9 | 名稱首碼注音（BCCJ5）＋品名注音字典（BWPS） | phonetic-dictionary＋F4 注音搜尋 | 同款，30 年前就在用 |
| 10 | 單號流水計數表 `BREN` | `Nx01SeqCounter`＋`gen_*` | 同款成熟做法 |
| 11 | AR 用總帳式（RACDA01 全科目流水），per 客戶餘額被 28 年期初/年結/轉帳污染成考古題 | `Nx05ArLedger` **open-item 逐單制**（每單 original/paid/balance） | 我方天生免疫「全期加總」考古題 ⭐ |
| 12 | 客戶/供應商分兩表（BCUP 幾乎是 BCUS 子集、欄位重複） | 單一 `Nx01Partner`＋partnerType 六分類 | 我方乾淨；移轉時兩表合一 |

## 2. 🛠 該加強（偉盟有、我方缺）— 需執行長拍板

### P1（高價值、直接影響日常開單/開票）

**2.1 ⭐ 客戶側「前次成交價記憶」**
- 偉盟：`BSTS` 快取表（對象×料號×交易類別→最近一次價+來源單），413 萬筆；開單自動帶「上次賣他多少」。**這是偉盟訂價的真核心**——ABCD 價只是參考底價、客戶等級欄 30 年空置沒人用。
- 我方：採購側有（`Nx02PartnerPart.defaultUnitCost`）、**銷售側缺**；靜態 `customerGrade→priceA-D` 正是偉盟證明「沒人用」的那條路。
- 建議：對齊我們已定案的報價/定價架構（自動帶價一個月規則）**實作銷售側帶價**。註：偉盟建快取表是老技術補償；我方壓測 306 萬明細查「同客戶該料最近成交」只要 4~16ms，**先用 live 查詢實作、不必建快取表**，慢了再快取。
- 影響：SO/報價開單體驗核心。

**2.2 ⭐ 發票抬頭欄（invoiceTitle）**
- 偉盟：`BCINT` 92% 有值、**常異於客戶名**（人獅汽車 vs 發票開「京寶」）；且 BCUX 每個據點可各自抬頭。
- 我方：Partner 與 PartnerAddress **皆無此欄**（grep 0 處）。
- 建議：`Nx01Partner` 補 `invoiceTitle`＋`Nx01PartnerAddress`(BILLING) 補 `invoiceTitle`（據點各自開票）。不補的話開發票要手打抬頭。

**2.3 ⭐「免開發票」狀態 — 📕 訂正（2026-07-10）：我方早已實作、免補**
- 偉盟：稅則 `BCTXP` 0=免開發票占 **2,229/4,109 過半**（現實：一半客戶不開票）。
- 我方：初版報告稱「只有 2/3」**有誤**——實查 DTO `INVOICE_COPIES=[0,2,3]`（partner＋SO 兩端）、
  UI 下拉含「不開發票」選項，**0=免開早已全鏈實作**；錯誤源於只讀 schema 舊註解未查 DTO。
- 已處置：schema/so.dto/so.service 五處過時註解訂正為 0/2/3；本項自決策表移除。

**2.4 結帳/請款循環（月結文化三件套）**
- 偉盟：每客戶記「每月結帳日 `BCEDT`／請款日 `BCPDT`」（31/25/C/X）＋「發票開立批次 `BCINO`」（月結全額/挑選/一般）＋「請款作業方式 `BCPAY`」25 種 SOP（貼明細抬頭撕摺、A4 明細銷 5 成…）。
- 我方：只有帳期 `paymentTermDomestic`（NET30/60/90），**無結帳日/請款方式**。
- 建議：Partner 補「每月結帳日」欄；「開票批次＋請款注意事項」歸 NX05 AR 對帳設計（抽共性做欄位，25 碼不照搬）。這是台灣月結請款文化核心，對帳單/請款單功能遲早要。

**2.5 銷貨明細「實際出貨料號」（替代出貨）**
- 偉盟：明細雙料號 `ROPTN` 基準/`ROPNO` 使用，**二者可不同＝下單 A 料實際出替代 B 料**，都留在單上。
- 我方：`Nx04SoItem` 只有一個 partId＋快照（grep 無 actual/substitute 欄）。替代料三機制在主檔層，**交易層沒記實際出了哪顆**。
- 建議：SoItem 補「實際出貨料號」（可空、預設同 partId）。對保固追溯、退貨核對、庫存正確性都重要。

### P2（真需求、可排後）

**2.6 條碼對照** — 偉盟 `BANO` 29 萬筆（料號↔條碼/使用料號＋預設旗標）＋標籤列印函數；我方零件主檔**無 barcode**（grep 0），但手機版已做掃碼（BarcodeScanner）——掃了要對到料號就需要這張對照。建議：`Nx01PartBarcode` 子表（一料多條碼）。

**2.7 代購/直送鏈** — 偉盟進貨可綁銷貨單（`RORER`＝為某張銷貨現金代購）＋「帳款對象≠交易對象」＋「指送對象/地址≠客戶」。我方：SO 有 deliveryAddress、Rr 無 sourceSoId、AP 無帳款對象分離。建議：評估 `Nx02Rr.sourceSoId`（我們同行調貨 G 流程已蓋一部分，先確認缺口再補）。

**2.8 批次調價工具** — 偉盟「訂價碼」機制（料件掛折扣碼→改 CODE 表一碼＝全品類調價，含生效日）。我方是靜態四價（已定案方向），但**漲價潮一鍵批次調價**的維運工具值得做（不必回到動態訂價碼）。

### P3（維運/進階、列入待辦池）

**2.9 料號合併工具** — 偉盟有 `poMergeProduct*` 三支（資料/庫存/進貨歷史合併）。30 年營運必然重複建檔；**我們現在就有 1.3 萬占位料號日後要收斂**，這工具很現實。
**2.10 進口屬性** — HS Code／淨毛重材積／多單位包裝／外幣訂價（德系進口需求，偉盟填充率低）。我方料件層皆無（grep 0）。列待評估、不急。

## 3. ⛔ 該避免（偉盟負面教材 → 我方守則）

| # | 偉盟的坑 | 我方守則 |
|---|---|---|
| 1 | **一欄多義**：ROCOT 隨單型變義、RA* 逐表不同義、RONUM 對象/內部倉雙義 | 欄位語意唯一；語意會分岔就拆欄/拆表，禁止「同欄看情況解讀」 |
| 2 | **欄位挪用**：英文名存狀態、Email 存對帳備註、網址存雜記 | 需求來了開正式欄，不借舊欄；UI 不給模糊自由欄 |
| 3 | **名稱欄塞狀態**：客戶名尾註「-結束/◎」當停用標記（我們匯入時被迫用名稱猜停用） | 狀態只走 `isActive`/狀態欄；名稱欄驗證/清洗，絕不承載狀態 |
| 4 | **死欄堆積**：BCUS 13 死欄、BSTO 約半數空欄/死旗標 | 「先有業務再有欄」；每欄帶用途註解（現制度）；廢欄走正式移除流程 |
| 5 | **備份表塞正式庫**：72 張 `*BAKD/_日期` 混在營運庫 | 備份走 DB 備份機制；禁 SELECT INTO 備份表進正式庫 |
| 6 | **報表快取表增殖**：SACM 同資料七胞胎（SACD/SACI/SACP/SACX/SACW/SACZ） | 先索引＋live 查詢（壓測 306 萬列 1~4ms 已證可行）；快取要量測證明才建、且單一來源 |
| 7 | **業務規則散兩層**（DB proc＋Delphi 客戶端）→ 餘額公式失傳、要考古 | 規則集中 service 層＋規格書同步（現制度，引以為戒） |
| 8 | **期初/年結/客戶間轉帳混進交易流水** → per 客戶餘額 28 年後成考古題 | AR 維持 open-item 逐單制；未來做「客戶間轉帳/債權轉讓」必須是**明確單據型＋雙邊配對**，不可一筆借貸摘要帶過 ⭐ |
| 9 | **稅額不存明細**（發票時才算）→ 歷史對不準、移轉重算 | 明細金額/稅率快照照存（現況已對） |
| 10 | **影響資料語意的開關藏參數表**（SETSYS#31 決定「庫位前 3 碼=倉」） | 這類開關進 schema 註解＋規格書，不藏參數 |
