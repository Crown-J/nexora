## 3. 目標架構：F2 即時工作檯

```
F2 ──開──> ┌─ 即時工作檯（單一浮層、蓋在任何頁面上）─────────────┐
           │ [1 庫存查詢] [2 即時報價] [3 調貨詢價] [4 補貨籃]      │ ← 分頁列：權限決定長哪幾個
           │ ─────────────────────────────────────────────── │
           │  站 1 錨=料號    直接輸入料號查                        │
           │  站 2 錨=客戶    先定客戶 → 料一顆顆掛上去（現 F2 原樣）│
           │  站 3 錨=調貨對象 先定對象 → 詢價清單（現 F5 原樣）      │
           │  站 4 錨=收集籃  料一顆顆丟進來 → 批次產單               │
           └───────────────────────────────────────────────┘
```

核心原則：

1. **一顆鍵教全公司**：「F2 = 查料號做事」。倉管按開只長站 1（+4）、業務按開長站 1~3、
   老闆全開。新人訓練一句話。
2. **站 = 註冊表一筆**（§6），加站不動殼——「陸續新增」的架構保證。
3. **session 常駐**：每站各自記自己的錨與清單，切站、關檯（同日）不清空。
   站 2 現有 QuoteWorkspace 的工作狀態守門（誤觸不能丟）原樣保留。
4. **未上線 / 無權限的站不渲染**：分頁列上根本沒有那顆，不出現灰色「開發中」。

### 4.3 焦點守衛規則（全系統統一、寫進監聽一次）

- **會撞打字／游標的鍵**（`Home`、`` ` ``、裸數字、裸字母）：焦點在
  `input / textarea / select / [contenteditable]` 時一律讓原生。
- **打不進欄位的鍵**（`F1`~`F4`、`Alt+*`）：永遠有效——業務打報價單打到一半按 F2 照樣開檯。

## 5. 權限模型：三道防線

> 背景：偉盟「料號即時查詢」單一視窗攤平 A~D 價＋最近進價＋庫存＋異動，任何人開了全看光。
> 執行長已把它按職務拆開（倉管看庫存＋異動不看價；業務看價不看異動），本架構落實為三道防線。

| 防線 | 內容 |
|---|---|
| ① 鍵位／分頁 | keymap 每鍵、station registry 每站帶 `permissionCode`；無權限 → 鍵無效、分頁不渲染、提示列不顯示 |
| ② 視窗純化 | 每站畫面**設計上就沒有**越權欄位（站 1 無價格欄、站 2 無異動紀錄），不是「有欄位藏起來」 |
| ③ API 分流 | 各站走各的 endpoint、各查各的權限；庫存 API 回應**從頭到尾不含價格**——F12 看封包也看不到 |

跨職務共用欄位邊界（B 期站 1 落地時逐欄對照表給執行長勾）：
**庫存數量**兩邊都看（業務報價要知道有沒有貨、站 2 現在本來就顯示公司總存貨）；
敏感的是「**價**」（對倉管）與「**異動紀錄**」（對業務），不是料號與數量本身。

## 6. keymap 真相檔（SSOT）設計

範式對齊 `master-registry.ts`（主檔導覽 SSOT、2026-06-27 已驗證有效消 drift）。

### 6.1 兩份 registry

```
apps/nx-ui/src/design/keyboard/
├─ keymap-registry.ts          # 全域保留鍵 SSOT
└─ instant-station-registry.ts # 即時工作檯站註冊表 SSOT
```

```ts
// keymap-registry.ts（欄位示意）
type GlobalKeyDef = {
  id: string;              // 'open-instant-workbench'
  keys: string[];          // ['F2']
  label: string;           // '即時工作檯'
  focusGuard: 'immune' | 'yield-in-input';  // §4.3 兩類
  permissionCode?: string; // 缺省 = 全員
  status: 'live' | 'planned';   // planned = 佔位保留、不觸發
};

// instant-station-registry.ts（欄位示意）
type InstantStationDef = {
  no: 1 | 2 | 3 | 4;       // 檯內數字鍵
  id: string;              // 'stock-query'
  label: string;           // '即時庫存查詢'
  anchor: 'part' | 'customer' | 'transfer-target' | 'basket';
  permissionCode: string;
  status: 'live' | 'planned';   // planned → 分頁不渲染
  component: LazyComponent;
};
```

### 6.2 消費者（都只讀 registry、不各自硬編）

1. **全域鍵盤監聽**（單一 listener 掛 dashboard layout、取代現在三個元件各掛各的）
2. **工作檯分頁列**（渲染 = registry filter(status==='live' && hasPermission)）
3. **引導精靈（AutoPageGuide）快捷鍵段落**（執行長拍板：提示統一收引導精靈、不做常駐底部列）

### 6.3 使用者自定義（架構預留、v1 不做）

- registry 讀取時預留一層 `userOverrides`（多租戶 user preference 表、schema 位子先想好不建）
- v1 全員用預設值：手冊／教學／客服對話不裂開；等預設鍵位被真實客戶驗證過再開放
- 將來開放 = 加一頁設定 UI + 一張偏好表，殼與監聽不用改

## 7. 跨站送料（B 期、治「抄在紙上」）

偉盟痛點：查完庫存**抄料號在紙上**再去打調撥單。解法是送料通道、不是再做一個頁面：

```
站 1 查到料、選中列 ──按 2──> 掛進站 2 當前客戶的報價清單
                    ──按 3──> 掛進站 3 當前對象的詢價清單
                    ──按 4──> 丟進站 4 補貨籃
```

- 通道機制沿用既有 `nx-transfer-add` CustomEvent 解耦範式（§2.2、已驗證）
- 送料也走權限：無站 3 權限 → 選中料按 `3` 無反應
- 站 4 本質 = **那張紙的數位版**：巡站 1 → 丟籃 → 站 4 批次產單（產什麼單見 §9 未決點 2）
