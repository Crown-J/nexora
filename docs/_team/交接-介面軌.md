## 0. ⭐ 單據改造順序（執行長既定、⛔ 不得自行更動）

> **報價 → 賣貨 → 撿貨 → 包貨 → 送貨 → 詢價 → 採購 → 進貨 → 驗收**

**這是執行長早先就定下的順序，2026-08-03 重申。⛔ 開工前不得自己另想一個順序，
也⛔ 不得用「哪一張風險最低」「哪一張最快看到成果」當理由跳號。**

### 為什麼是這個順序（⛔ 不只是整齊）

它是**一條貨的完整生命週期**：客戶要買 → 出得去 → 補得回來。

⭐ **先做下游、再做上游。** 上游做完會回頭改下游的接口——
例：採購單的常態入口是「從詢價單帶過來」，詢價還沒定型就先做採購，
採購的第一段等於白做一次（2026-08-03 實際發生）。
