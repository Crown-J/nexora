## 1. 命名規範

### 1.1 三層命名範式（schema.prisma 全表一致）

| 層 | 格式 | 範例 |
|---|---|---|
| DB 表名 | `nx{NN}_{snake_case}` | `nx04_so`、`nx04_promotion`、`nx05_ar_ledger` |
| Prisma model | `Nx{NN}{PascalCase}` | `Nx04So`、`Nx04Promotion`、`Nx05ArLedger` |
| DB 欄位名 | `snake_case` | `created_at`、`customer_id`、`total_amount` |
| Prisma 欄位 | `camelCase` via `@map("snake_case")` | `createdAt @map("created_at")`、`customerId @map("customer_id")` |

代表樣本：
- `Nx01Part` / `nx01_part` — schema.prisma:770-870
- `Nx02Po` / `nx02_po` — schema.prisma:1965-2035
- `Nx04Promotion` / `nx04_promotion` — schema.prisma:4451-4489

### 1.2 業務代碼欄

- 主檔有 **`code` 欄**（VARCHAR、人讀代碼、tenant 內唯一），跟系統 `id`（15 字 ID）分開：
  - `Nx01Partner.code` / `Nx01Part.code` / `Nx01Brand.code` / 等
  - 多租戶唯一性：`@@unique([tenantId, code])`

### 1.3 平台層特例

- 平台層表 **無 `nx{NN}_` prefix**：`platform_admin`（schema.prisma:9026）
- 平台層 ID generator 仍循同範式：`gen_platform_admin_id()`

### ⚠️ 舊文件差異

- `nx-table.csv` 標的「舊表格名稱 nx00_*」是歷史遷移痕跡、現行 schema 一律 `nx{NN}_*`。

## 2. 模組 NX 碼 + ID 規則

### 2.1 ID 格式總則

- **全表 `id` = `VARCHAR(15)`** 由 DB function 自動產生
- 格式：`NX{NN}{XXXX}{0000001}` — `NX` + 2 碼模組 + 4 碼表代碼 + 7 碼流水
- 例：`NX01USER0000001`、`NX04PRMO0000001`、`NX99TANT0000001`

### 2.2 ID generator 機制

每個表配一個 sequence + function：
```sql
CREATE SEQUENCE IF NOT EXISTS seq_nx04_promotion_id START 1;
CREATE OR REPLACE FUNCTION gen_nx04_promotion_id() RETURNS VARCHAR AS $$
  SELECT 'NX04PRMO' || LPAD(nextval('seq_nx04_promotion_id')::text, 7, '0');
$$ LANGUAGE sql;
```

Prisma 端：
```prisma
id String @id @default(dbgenerated("gen_nx04_promotion_id()")) @db.VarChar(15)
```

## 4. 通用資料慣例

### 4.1 必填欄位四件套 + 多租戶

每張業務表（NX01~NX10）必有：

```
tenantId    String   @map("tenant_id") @db.VarChar(15)
createdAt   DateTime @default(now())  @map("created_at")
createdBy   String   @map("created_by") @db.VarChar(15)
updatedAt   DateTime @updatedAt        @map("updated_at")
updatedBy   String   @map("updated_by") @db.VarChar(15)
```

### 4.2 多租戶 tenantId 強制

- 每個 service query 必 `where: { tenantId, ... }`
- 共用 helper：`requireTenantId(user: RequestUser): string`（`apps/nx-api/src/shared/nx01/require-tenant.ts:6`）
- 缺 `tenantId` → 400 BadRequest

### 4.3 軟刪除範式（主檔 vs 單據）

| 類型 | 範式 | 例 |
|---|---|---|
| 主檔 | `isActive: Boolean @default(true)` + `setActive(false)`、UI 標「停用」（不是「刪除」）| Nx01Part、Nx01Partner、Nx04Promotion |
| 業務單據（QT/SO/PO/...）| `voidedAt: DateTime?` + `voidedBy` + `voidReason`（作廢、保留歷史）| Nx04Quote |
| 出貨/銷貨單 | `cancelledAt: DateTime?` + `cancelledBy` + `cancelReason` | Nx04So |
| Closing 已關帳的 SO 改 | `assertFinancePeriodMutable` 守期間鎖（27 處使用）| 全 NX05 |

⚠️ **絕無硬刪除**（DELETE）— 所有「刪除」UI 動作後端都是 setActive=false 或 cancelledAt 寫入。

### 4.4 建立後鎖定欄位

- `code`（業務代碼）— 主檔建立後不可改
- `docNo`（單據編號）— 系統自動產生、永不可改
- ID 永不可改
- `tenantId` 永不可改

### ⚠️ 舊文件差異

- PROJECT_RULES.md 提及「軟刪除是 D 刪除」字眼、實際 UI 使用「停用」(PowerOff icon)、不是 D 刪除（見 Memory `project_no_hard_delete`）。

## 5. 過帳邏輯

### 5.1 @FUNCTION_CODE 規範

- 業務邏輯關鍵函式標 `@FUNCTION_CODE NX{NN}-{ENT}-{LAYER}-{NNN}-F{NN}`
- 範例：`NX02-PO-UI-001-F01`、`NX00-UI-NX00-PART-API-001-F01`
- 用途：業務規格追溯（340 處左右）
- 跟錯誤碼 `XX-NNN`（user-facing）跟 `@CODE`（function marker）三層共存

### 5.2 自動過帳觸發點清單（code-truth）

| 事件 | 觸發來源 | helper / service | 寫入 |
|---|---|---|---|
| SO `SHIPPED` 推進 | `SoService.update` `applySoShipping` | `createArFromShippedSo` + `applyQtyOutWithLedger` | AR + Nx03StockLedger 出庫 |
| PO `CONFIRMED` 廠商確認 | `PoService.update` `isVendorConfirming` | `createApFromConfirmedPo` | AP（dueDate = poDate + paymentTerm）|
| RR 驗收 `POSTED` | `RrService.post` | `createApFromPostedRr` + `applyQtyInWithLedger` | AP + 庫存增加 |
| PR 退供應商 `POSTED` | `PurchaseReturnService` | `createArFromPostedPr` | 廠商 AR（廠商欠我們退錢）|
| SR `POSTED` 銷退 | `SalesReturnService.update` | `createAllowanceFromSalesReturn`(DRAFT) + `createReturnPickupFromPostedSr` | Allowance 草稿 + NX06 DN 草稿 |
| Allowance `APPROVED` 折讓核可 | `AllowanceService.approve` | `applySettlementsForPaylog`（建 paylog + settlement）| 扣 AR/AP balance |
| Paylog `POSTED` 收付款 | `PaylogService.createWithSettlements` | `applySettlementsForPaylog` | 扣 AR/AP balance + 狀態 PAID/PARTIAL |
| DN 簽收 `signedAt` 寫入 | `DnLogisticsService.applySignatureToStops` | 更新 `Nx04SoItem.fulfillStatus='F'` → `maybeCompleteAfterDelivery` | SO header → `COMPLETED` |
| Issue Report `dispose='X'` 特價售出 | `IssueReportService.dispose` | `SoService.create` with `specialPriceFlag=true` | 特價 SO（流入正常 AR）|
| SO CONFIRMED→PICKING | `SoService.update` | `autoCreateTransferFromSo` | NX03 ST 跨倉調撥草稿 |

### 5.3 冪等鎖統一範式

每個自動建單 helper 都先查 dup：
```ts
const dup = await tx.nx05ArLedger.findFirst({
  where: { tenantId, soId },
  select: { id: true },
});
if (dup) return dup.id;
```

冪等鍵：
- AR by `(tenantId, soId)` / AP by `(tenantId, poId)` / Allowance by remark prefix `SR:{docNo}` / DN by `sourceSoId`

### 5.4 期間鎖

- 月關帳 `Nx05Closing.status='CLOSED'` → 該月所有 NX02~NX06 寫入由 `assertFinancePeriodMutable` 守
- 401 期 `markFiled` → 該期兩月全鎖（不可解鎖）

- PROJECT_RULES 過去寫「廠商確認應付建置中」— 已 closure（v1.2 階段 F P3、見 `createApFromConfirmedPo`）。

## 9. 設計紅線（產品鐵則）

### 9.1 三版「只」差人數上限（席次制）

| 版本 | 人數上限 |
|---|---|
| LITE | 15 |
| PLUS | 50 |
| PRO | 100 |

- **席次制是唯一版本機制**（席次數=啟用員工帳號數）
- 超出席次 → `SE-001` 擋啟用、不擋停用
- 實作：v2.3.0-seats-enforcement closure（commit `9544aea`）

### 9.2 功能全模組化、不綁版本

- **絕不做「版本功能閘門」**（舊 Plan Guard 模型已廢、不可復活）
- 所有模組（NX02~NX10）+ 所有套件（PACKAGE-01~08）任何版本都可加購
- 「免費送哪些套件」是包銷售包配、不是技術閘門

### 9.3 客戶端介面不露技術代碼

- URL 不出現 `nx{NN}`、僅後端 API 路徑可用
- 主檔/單據名稱用業務中文（核心主檔、進貨、銷貨...）、不寫 NX02/NX03

### 9.4 平台層 vs 租戶層嚴格隔離

- 平台 user 走 `platform_admin` + `PlatformAdminGuard` + 獨立 JWT scope
- 租戶 user 走 `Nx01User` + `JwtAuthGuard` + tenant-scoped JWT
- 兩者**絕不混用**（伊諾瓦營運 user 不在客戶 tenant 裡）

### 9.5 多租戶嚴格隔離

- 每個業務表必有 `tenantId`、每個 query 必 filter
- 跨租戶查詢只允許 `SYSADMIN` 或 `platform_admin`
- 缺 tenantId → 後端 400

### 9.6 軟刪除絕對主義

- 任何「刪除」UI 動作都是 setActive=false 或 voidedAt/cancelledAt
- 沒有業務表允許硬 DELETE
- 已過帳資料更嚴：期間鎖 + status='POSTED' 雙重防護

### 9.7 工程紀律

- **改 schema / 跨表讀寫 / 過帳邏輯前**：必先 grep 確認現狀、不憑記憶
- **migration 一律 additive**：不刪欄、不改型別、不重命名（要重命名走兩步：加新欄→搬資料→停用舊欄）
- **migration 前必備份**：`dev-backups/pre-{task}_{timestamp}.sql`
- **Railway production 0 動**（dev 本地操作、prod 等明確指示）
