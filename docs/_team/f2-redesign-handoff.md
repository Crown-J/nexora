# F2 即時零件查詢改版 — 設計交接

> 你這條線的任務：把 F2 從「現況彈窗」重構成下述設計。**純前端 + 既有 API 為主；
> ⛔ 不動 schema**（本線鐵律：schema 需求列清單交公司機主線做）。

---

## 1. 核心定調（執行長拍板）

**一個模板、三種入口、銷售為錨。**

- 偉盟「一個模板吃多情境」省工但臃腫；我們保留單一模板的經濟性，用「入口情境 + 角色」決定預設長相。
- 高頻使用者是**銷售**（電話進來就查、主動獨立入口）；採購低頻（嵌採購需求單旁）；倉管低頻（嵌撿貨/盤點/庫存管理）。

## 2. 搜尋入口

- 預設搜尋方式＝**使用料號（公司料號，最常用）**。
- **2 主力**：基準料號 / 品名+車型；**其餘收進「進階」**（不做 7 個平權按鈕）。
- 「車型+品名」與「品名+車型」重複 → 砍/併。
- 保留鍵盤流：Enter 預覽 / Alt+F 跳搜 / F12。
- 已有「顯示停用資料」開關概念（對齊恆迎 Z 開關）。

## 3. 預設首頁（簡化後）＝ 基本資訊 + 公司總存貨

- 一進來**不分倉**，只答「公司到底有沒有貨」：大狀態（有貨可出／低於安全／缺貨）+ 總可出/總庫存/在途 + 公司庫存水位條。
- ⚠️ 執行長明確拿掉「各倉分布攤在預設頁」——那是過度設計。

## 4. 倉別＝情境決定（棄用全域開關）

執行長想通的關鍵一顆——**不做**「登入選倉 / 頂部倉別切換器」：

- 銷售 → 按即時報價選客戶後 → 帶出**客戶預設出貨倉**（依客戶主檔）
- 倉管 → 走庫存管理/出入庫 → 看**自己隸屬倉** + 出入庫歷史

## 5. 4 快捷鍵深入（取代偉盟 11 彈窗的常用集）

| 鍵 | 功能 | 備註 |
|---|---|---|
| F3 | 可替代零件 | 只露 料號/廠牌/庫存數量 |
| F4 | 即時報價 | 比價 → 報價 |
| F5 | 周轉率分析 | — |
| F6 | 出入庫紀錄 | — |

## 6. 庫存圖像化

- 水位條一條看懂：安全量 ─ 現量 ─ 最高量。
- 各倉橫向長條（資料驅動可長可短）；空倉折疊（沿用現有機制）、本倉 pin 頂；一屏軟上限 6~8 倉、不硬砍資料。
- 基本資訊卡加大面積。

## 7. 參考基準：恆迎舊系統（偉盟）11 下鑽

我們已有：主檔、通用件(族群)、各倉分布、產品圖像。
**缺口**（改版時依優先度撿）：銷貨比價 / 進貨比價 / 適用車型 / 對應料(B=基準料、O=替料) / 進銷統計 / 相關單據 / 延伸欄位 / 組件資料(kit)。
⭐ 族群＝**客戶自行設定**（非系統固定）。詳細對照表在公司機 Hank 記憶 `reference_old_part_query`，需要時請執行長轉。

## 8. 程式現況（2026-07-10、都已在 main）

- 現行 F2 檔案：`apps/nx-ui/src/design/components/quick-search/`（`PartQuickSearchModal.tsx`、`PartMainWindow.tsx` 等 4 檔）。
- **配色已重皮主題金/琥珀**（commit `34173c05`）：182 處 token、外殼金光/實心 popover；**車型篩選**已做（品名/廠牌/族群三查法加車型縮小、後端 dto `modelQuery`）。
- 版型重構（本檔 §1~§6 整套）**尚無程式**，只有 4 張視覺提案圖 + 本文件。

## 9. 開工前必驗的資料依賴（grep 再說話）

1. 客戶主檔是否已有「**預設出貨倉**」欄位（§4 銷售帶倉用）——沒有＝schema 需求、**交公司機**。
2. 使用者「**隸屬倉**」——2026-05-26 audit 標過 user-warehouse 模組缺，倉管情境可能卡，先驗證再設計。

## 10. 本線環境限制

- 家用機快照**不含歷史銷貨/進貨單** → 銷貨比價/前次售價這類下鑽在本機是空的；先用假資料開發、最終驗證回公司機。
- 權限題（庫存共享、價格敏感分權）執行長指示**先擱置**，走現有權限目錄即可。
- 開工前 `git pull` main、開 `feature/f2-redesign` 分支；分支 push 隨做隨推、main 合併回公司機拍板。

## 11. 建議實作順序（漸進式、每步 commit）

1. Step 0：§9 兩項依賴 grep 驗證 + 回報。
2. Step 1：預設首頁簡化（基本資訊 + 公司總存貨大狀態 + 水位條）。
3. Step 2：搜尋入口收斂（2 主力 + 進階摺疊）。
4. Step 3：庫存圖像化（各倉橫向長條 + 折疊/pin）。
5. Step 4：4 快捷鍵框架（先 F3/F6 用既有資料，F4 接報價、F5 周轉率視 API 而定）。
6. Step 5：三入口情境接線（銷售錨定；採購/倉管嵌入點）。
