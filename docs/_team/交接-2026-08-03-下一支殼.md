# 交接：v3.0.0 介面軌 → 下一支殼

## 0. ⭐ 單據改造順序（執行長既定、⛔ 不得自行更動）

> **報價 → 賣貨 → 撿貨 → 包貨 → 送貨 → 詢價 → 採購 → 進貨 → 驗收**

**這是執行長早先就定下的順序，2026-08-03 重申。⛔ 開工前不得自己另想一個順序，
也⛔ 不得用「哪一張風險最低」「哪一張最快看到成果」當理由跳號。**

### 為什麼是這個順序（⛔ 不只是整齊）

它是**一條貨的完整生命週期**：客戶要買 → 出得去 → 補得回來。

⭐ **先做下游、再做上游。** 上游做完會回頭改下游的接口——
例：採購單的常態入口是「從詢價單帶過來」，詢價還沒定型就先做採購，
採購的第一段等於白做一次（2026-08-03 實際發生）。

### 各環現況（2026-08-03 grep 實測）

| 環 | 狀態 |
|---|---|
| 報價 | ✅ 建單殼五段＝對象 → 搜尋 → 檢查庫存 → 報價 → 發送訊息 |
| 賣貨 | ✅ 建單殼五段＝客戶 → 明細 → 交易 → 確認 → 訊息 |
| 撿貨 | ✅ 現場殼 |
| 包貨 | ✅ 現場殼 |
| 送貨 | ⚠️ `/dashboard/inventory/delivery` 是 2026-06-09 的舊軌，**跟本檔 v1.0 寫的「現場殼五個流程完成」對不上**，待確認 |
| 詢價 | ⛔ 舊畫面。⭐ 執行長 2026-08-03 已口述五段：供應商 → 明細 → 核對 → 訊息 → 確認 |
| 採購 | ⚠️ **跳號做了**（commit `02195224`／`b635e3b8`）。五段＝供應商 → 明細 → 審核 → 訊息 → 確認。<br>第 1 段「手動選供應商」待詢價定型後改成「從詢價帶入」 |
| 進貨 | ⛔ 舊畫面 |
| 驗收 | ✅ 現場殼 |

### ⛔ 系統裡沒有「請購單」

執行長口述流程時提到「詢價 → 請購 → 採購」，但**全庫 grep「請購」0 處**
（`Nx02Pr` ＝ 進貨退回 Purchase Return，⛔ 不是請購）。
新增這張單要動 schema 與後端，⛔ 介面軌做不了，需另開一軌。
