## §0. 這份規格書是什麼

這份文件描述「客戶用 NEXORA LITE 完整版時、會看到什麼畫面、有哪些按鈕、按下去會發生什麼事」。

不寫程式怎麼寫、不寫資料表怎麼設計。工程師看完這份應該知道「要做出什麼樣的產品」、但細節（怎麼存資料、怎麼接 API）由工程師自己決定。

驗收標準：總經理用「先鋒企業」這個測試客戶手動建一個帳號、按本文件每一個章節的「驗收清單」逐項確認、有差就改、全對就過。

## §1. NEXORA 客戶從接觸到使用的 5 個階段

### 1.1 五階段流程

```
階段 1：諮詢
   客戶來諮詢 → 伊諾瓦給問卷 → 建議用哪個版本（LITE / PLUS / PRO）

階段 2：簽約
   伊諾瓦業務 ↔ 客戶
   確認版本、付費方式、訂閱時間 → 簽約 → 收款

階段 3：開戶（伊諾瓦操作）
   伊諾瓦在後台幫客戶建好帳號
   設好公司基本資料 + 負責人帳號 + 主倉
   寄登入資訊給客戶

階段 4：客戶首次登入
   登入 → 跳「匯入精靈」（教客戶把舊資料匯進來、可全部略過）
   每進一個新頁面 → 跳「設定精靈」（教這頁面怎麼用）

階段 5：客戶日常使用
   就像一般 ERP 系統那樣用
   有問題隨時按頁面右上「?」按鈕看引導
```

### 1.2 兩種客戶類型

```
類型 A：新公司
   剛成立、沒有歷史資料
   匯入精靈大部分用不到、只匯員工就好
   範例：先鋒企業（亞羅草創時期）

類型 B：舊公司轉系統
   已經跑了多年、有大量歷史資料
   匯入精靈會大量使用、把舊系統資料搬進 NEXORA
   範例：跑了 30 年的汽材行轉新系統
```

### 1.3 先鋒企業情境（驗收測試用）

```
公司：先鋒企業（對應亞羅草創時期）
產業：汽車零件批發
人數：7 人（負責人 + 6 員工）
業務：國內進貨 + 國內銷貨、不做外銷
資料：草創、全空

員工分工（總經理參考、由總經理手動建角色掛上、
        不是系統預設）：
─ 負責人：自動全權限
─ A、B：資深、做採購 + 銷貨、跑保養廠
─ C、D：中堅、銷售 + 倉管
─ E、F：新手、送貨為主、聽 ABCD 指派
```

## §2. 階段 3：開戶（伊諾瓦做）

### 2.1 伊諾瓦開戶後台

伊諾瓦業務簽完約、進「開戶後台」（NEXORA 內部系統、客戶看不到），建立新客戶的租戶。

開戶後台填的欄位：

```
公司基本資料
─ 公司名稱（必填、簽約時已知）
─ 統一編號（必填）
─ 公司地址（必填、用來寄帳單）
─ 公司電話
─ 公司 LOGO 上傳（必填、本機端安裝時會顯示）

負責人帳號
─ 負責人姓名
─ 負責人 Email（用來登入）
─ 初始密碼（系統可自動產、首次登入時提示客戶改）

主倉設定
─ 主倉名稱（預設「主倉」、可改）
─ 主倉地址（預設帶公司地址、可改）

訂閱方案
─ 版本（LITE / PLUS / PRO）
─ 訂閱期間
─ 開通日期
```

### 2.2 開戶完成後

伊諾瓦按「開通」→ 系統做完以下：

```
1. 建好客戶租戶
2. 設好公司資料（包括 LOGO 和地址）
3. 建好負責人帳號
4. 建好主倉
5. 寄通知 Email 給負責人
   ─ 含登入網址
   ─ 含 Email 帳號
   ─ 含初始密碼（提示首次登入改）
```

### 2.3 驗收

```
[ ] 伊諾瓦業務能進開戶後台
[ ] 必填欄位卡關（公司名稱 / 統編 / 地址 / LOGO 沒填不能開通）
[ ] 開通成功後系統自動建租戶 + 負責人帳號 + 主倉
[ ] 通知 Email 寄送成功、客戶收得到
[ ] 客戶用 Email + 初始密碼能登入
```

## §3. 階段 4：客戶首次登入

### 3.1 登入流程

```
1. 客戶打開瀏覽器、進 NEXORA 登入頁
2. 輸入 Email + 初始密碼
3. 系統提示「首次登入、請改密碼」
4. 客戶設新密碼
5. 進系統主畫面
6. 自動跳「匯入精靈」（見 §3.2）
```

### 3.2 匯入精靈（第一次登入跳）

進入主畫面後自動彈出全螢幕浮層、引導客戶把舊系統的資料匯入 NEXORA。

#### 精靈第一頁：歡迎畫面

```
歡迎使用 NEXORA！

接下來會引導您把現有資料匯入系統。
所有步驟都可以略過、之後到主畫面右上「精靈引導」按鈕重開。

如果您是新公司、沒有舊資料、可以全部跳過。

[開始引導]    [全部略過、之後再說]
```

#### 精靈第二頁：建議匯入順序

```
建議匯入順序（不強制）：
1. 員工
2. 客戶 / 廠商
3. 倉庫 / 庫位（如果有多倉）
4. 產品
5. 進貨歷史
6. 銷貨歷史
7. 票據

跳著做也可以、但有些資料會互相依賴：
─ 沒先匯產品、進貨匯入時找不到產品
─ 沒先匯客戶、銷貨匯入時找不到客戶
系統會在每一步開頭提示您依賴狀況。

[繼續]
```

#### 精靈第 3~9 頁：各類資料匯入

每一類資料的匯入畫面長一樣、流程：

```
畫面標題：匯入【員工 / 客戶廠商 / 倉庫 / 產品 / 進貨 / 銷貨 / 票據】

說明：
這一步可以匯入您現有的 XXX 資料。
（依依賴狀況提示、例如：建議先匯產品才能匯進貨）

步驟：
1. 按「下載範本」拿到 Excel 範本檔
2. 把資料填進範本
3. 把填好的檔案拖進虛線框、或按「選擇檔案」

範本說明：
─ 必填欄位用紅字標示
─ 範本第一列是欄位說明、第二列開始填資料

[下載 Excel 範本]   [上傳檔案]

如果這類資料沒有：
[沒有這類資料、略過]   [上一步]   [下一步]
```

上傳檔案後跳預覽畫面：

```
畫面標題：匯入預覽

系統檢查您的檔案、結果如下：

✅ 100 筆資料格式正確
⚠️ 5 筆資料有問題（點看詳情）：
   - 第 12 列：Email 格式錯誤
   - 第 23 列：必填欄位空白
   - ...

[修正後重新上傳]   [略過有問題的、只匯成功的]   [取消]

確定要匯入 95 筆嗎？
[確定匯入]
```

#### 票據匯入特別說明

票據這一步畫面多一個提示：

```
⚠️ 重要提醒

匯入票據時請選擇「上報狀態」：

○ 已上報國稅局（已報過 401 的票據）
  ─ 這些票據只會進系統當「查詢用」
  ─ 不會進 NEXORA 的 401 報表計算
  ─ 避免跟國稅局已有資料衝突

○ 未上報（還沒報過 401 的票據）
  ─ 這些票據會正常進 NEXORA 的 401 報表

如果不確定、請洽會計師。
```

⚠️ Alex 註：票據上報狀態相關的法定細節、總經理 LITE 完整版上線前
   建議找會計師確認本機制是否符合法規。

#### 精靈最後一頁：完成

```
匯入完成！

匯入結果：
✅ 員工：6 筆
✅ 客戶：120 筆
⚠️ 廠商：略過
✅ 產品：380 筆
⚠️ 倉庫：略過（您已有主倉）
✅ 進貨：250 筆
✅ 銷貨：800 筆
✅ 票據：60 筆（未上報）

接下來建議：
1. 到「設定 → 角色與權限」建立員工的職務權限
2. 到「主檔中心 → 員工」幫員工掛上職務
3. 您可以按主畫面右上「精靈引導」隨時重開這個精靈

[開始使用 NEXORA]
```

### 3.3 設定精靈（每頁第一次進跳）

匯入精靈跑完後、客戶開始用 NEXORA。每進一個沒進過的頁面、會自動跳「設定精靈」、教這頁怎麼用。

#### 設定精靈長什麼樣子

進新頁面時、頁面上半透明遮罩、彈出小視窗：

```
📚 報價單頁面引導

這個頁面用來給客戶開報價。

主要功能：
1. 列表頁可以看所有報價單、依日期 / 客戶 / 狀態篩選
2. 點「新增報價單」開新單
3. 加料件行時系統會顯示「這客戶上次買這料件的價格」
4. 如果單價低於最低售價、會紅字警告需補理由
5. 報價單可以被銷貨單「拉走」、自動帶價

操作流程：
DRAFT 草稿 → SENT 已寄出 → ACCEPTED 被銷貨拉走 / REJECTED 客戶拒絕

[我知道了、開始使用]
```

⭐ 按右下「?」按鈕可以隨時重看。

#### 設定精靈的記憶邏輯

```
每位員工 × 每個頁面 = 一個記憶旗標

員工 A 第一次進「報價單」 → 自動跳精靈 → 看完按「我知道了」→ 旗標記住
員工 A 第二次進「報價單」 → 不跳精靈

員工 B 第一次進「報價單」 → 還是會跳精靈（每人各自記憶）

員工 A 想再看「報價單」精靈 → 按頁面右上「?」按鈕 → 重開精靈

各頁面各自記憶：
─ 員工 A 看過「報價單」精靈、但「銷貨單」還沒看過
─ 員工 A 第一次進「銷貨單」 → 還是會跳「銷貨單」精靈
```

### 3.4 驗收

```
[ ] 客戶第一次登入時、強制改密碼
[ ] 改完密碼後自動跳匯入精靈
[ ] 匯入精靈每一步都能略過
[ ] Excel 範本下載功能正常
[ ] 上傳 Excel 後預覽畫面正確顯示驗證結果
[ ] 票據匯入有「已上報 / 未上報」選項
[ ] 全部略過也能跳過匯入精靈、進主畫面
[ ] 主畫面右上「精靈引導」按鈕能重開匯入精靈
[ ] 進每個新頁面自動跳設定精靈
[ ] 看完後再進該頁面不跳
[ ] 頁面右上「?」按鈕能重看設定精靈
[ ] 不同員工的「進過哪些頁面」獨立記憶
```

## §4. 電腦版主畫面

### 4.1 整體結構

客戶登入後看到的主畫面分三層：

```
最上面：頂部主導覽（5 大分類 + 主檔中心 + 設定 + 用戶選單）
中間：主內容區（看點什麼分類顯示對應內容）
最下面：頁尾資訊（公司版權 / 版本號 / 客服連結）
```

### 4.2 頂部主導覽

```
┌────────────────────────────────────────────────────────────┐
│ NEXORA  進貨  銷貨  庫存  財務  報表 │ 主檔中心  設定 │ 王經理▼│
└────────────────────────────────────────────────────────────┘
```

點 NEXORA logo：回主畫面 dashboard
點 5 大分類：展開該分類的子頁面選單
點主檔中心：到主檔中心首頁
點設定：到設定首頁
點右上用戶名：展開個人選單（個人設定 / 登出）

⚠️ 主導覽分類「依使用者權限顯示」：
- 負責人：全部 5 大分類都看得到
- 員工只看到「該員工掛載的職務有權限的分類」
- 例：員工 E 只掛「送貨」職務、職務只有庫存權限 → E 只看到「庫存」分類
- 主檔中心 / 設定：所有人看得到、但點進去能改的內容由權限決定

#### 採購單 / 進貨單 / 退貨單

跟詢價單畫面類似、依工作流推進。重點操作：

- 採購單可以針對同一份詢價單分多次採購（如先採急的、剩下等廠商有貨）
- 進貨單對應某採購單、清點數量、寫進倉庫
- 進貨後發現品項有問題 → 開退貨單、選「處置方式」：退回換新 / 退錢 / 保固

選「保固」會自動產一張保固申請單（見 §5.5）。

### 5.3 國外進貨作業

跟國內類似、多了「提貨單」階段：

```
詢價單 → 採購單 → 提貨單 → 進貨單 → （需要時）退貨單
```

提貨單 = 物流到港、海關進口、運費 / 關稅按比例攤分到各品項成本。

⭐ 國外進貨亞羅初期不會用、LITE 完整版要做但可能很少測試。

### 8.5 關帳作業

> ⚠️ v1.2 對齊軌 階段 F（2026-05-31）修正：原寫「月末關帳產出 401」是法規事實錯誤。
> 營業稅依法「每兩個月為一期」申報、報期為單數月（1/3/5/7/9/11）15 號前。
> NEXORA 設計：**月關帳**（內部控管、每月鎖一次）+ **401 雙月一期產出**（系統把單+雙月合併成一期）。

**月關帳（內部控管用）**：每月關帳一次、鎖定當月單據，供業務人員作每月結算依據。

**401 雙月一期產出**（法定營業稅申報用）：

```
401 申報期（一年 6 期、雙月一期）：
├─ 01 期：1-2 月（3 月 15 日前申報）
├─ 02 期：3-4 月（5 月 15 日前申報）
├─ 03 期：5-6 月（7 月 15 日前申報）
├─ 04 期：7-8 月（9 月 15 日前申報）
├─ 05 期：9-10 月（11 月 15 日前申報）
└─ 06 期：11-12 月（隔年 1 月 15 日前申報）

期碼以 YYYY-EE 表示（例：2026-03 = 2026 年 5-6 月那期）
```

```
┌─ 關帳作業 ──────────────────────────┐
│                                      │
│ 當前未關帳月份：2026 年 5 月         │
│ 所屬 401 期：2026-03（5-6 月）        │
│                                      │
│ 5 月概況：                           │
│ 銷售總額：1,250,000                  │
│ 銷售退回：-32,000                    │
│ 進貨總額：980,000                    │
│ 進貨退回：-15,000                    │
│                                      │
│ 401 報表預覽（雙月期到齊時可預覽）：  │
│ ─ 2026-02 期（3-4 月）：[已上報]      │
│ ─ 2026-03 期（5-6 月）：[等 6 月關帳] │
│                                      │
│ ⚠️ 關帳後 5 月資料鎖定               │
│   → 若期未上報、負責人可解鎖回頭改   │
│   → 若期已上報、整期（5+6 月）鎖死   │
│                                      │
│ [執行 5 月關帳]                      │
│ [預覽 401 報表]                      │
│ [標記 401 已上報]                    │
└──────────────────────────────────────┘
```

**鎖定 / 解鎖規則（C 案）**：
- 月關帳後：當月單據鎖定、不能新增 / 修改 / 刪除
- 期未上報 401：負責人可「解鎖」該期關帳（含該期兩個月）回頭改單據
- 期已上報 401：該期所有月鎖死、解鎖按鈕消失、只能開折讓單 / 紅字單沖正

**401 媒體申報檔輸出**：產出可上報格式 TXT 檔（檔名 = 公司統編.TXT、含進項+銷項明細）、客戶自己拿去報、不做自動串接財政部。

## §14. 開發路線建議

完整版按以下大致順序補完、每個階段都按本規格書驗收：

```
階段 A：介面骨架重整
   把現有兩套並存 UI 整成一套、主導覽用業務語意（不再用 nx02 / nx03 編號）

階段 B：權限系統重做 ⭐ 核心
   建系統權限項目清單、角色管理頁面、員工綁角色、各頁面按權限顯示

階段 C：開戶後台 + 匯入精靈
   伊諾瓦運營後台、客戶端匯入引擎、7 類 Excel 匯入器、票據雙標、資料起算點

階段 D：設定精靈框架
   每頁第一次跳引導、「?」按鈕重看、22 工作台引導內容

階段 E：主檔分區編輯
   各模組頁面只顯示該區欄位、主檔中心顯示完整

階段 F：NX05 財務作業
   應收應付、票據、關帳、帳戶管理

階段 G：手機版補齊
   5 個 dock 工作站接真實資料、包裹編號、配送路線

階段 H：NX08 報表
   個人月報、6 大報表、權限過濾

階段 I：補連線 + 收尾
   退貨→保固連線、採購需求 3 來源、國外進貨 UI、整體 closure
```

⚠️ B 階段（權限系統）必須做完才能繼續 C 以後、否則所有後續模組都會撞「沒對齊新權限模式」的問題。
