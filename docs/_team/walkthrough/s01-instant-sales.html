關卡一｜客戶來電：三十秒內答「有沒有貨」

角色：業務（電話上）
📞 「喂，我要 GOLF 的前輪軸承，有貨嗎？多少錢？」——客戶在線上等、手不能離鍵盤。
  1. 任何頁面直接按 F2 開料件即時查詢窗
    預期：查詢窗彈出、游標已在搜尋框（不用點）
  2. 打料號或關鍵字 → ↑↓ 選料 → Enter 進主視窗、中欄看庫存
    預期：總量水位條（安全量─現量─最高量）看得懂；可用量（＝在手－已承諾）跟在手量分得清、不會答應客戶其實被別單訂走的貨
  3. 沒貨 → 按 F3 可替代零件（通用件群組）——有替代的話跟客戶說明、問要不要
    預期：替代料的庫存/廠牌一眼可比、電話上講得出差在哪
  4. 順手按 F10 相關零件（改號/同款/組合包＋適用車型兩頁籤）——有時是料號改版、翻一下避免漏答
    預期：兩頁籤切換順、改號鏈看得懂
🧭 分歧點①：查完庫存、客戶怎麼說？
  • A有貨（或替代品客戶接受）→ 跳關卡三・即時報價
  • B沒貨、客戶很急等不了 → 老實說沒貨、請他先問別間——系統不用動作；長期信用比一單重要
  • C沒貨、客戶可以等一下下 → 關卡二・同行調貨詢價
  • D沒貨、客戶願意等下次到貨 → 跳關卡三報價（備註交期）、關卡四銷貨行標「客戶訂單」（支線 D）
💡 攻略提示
F2 窗內八快捷：F3 可替代 F4 即時報價 F5 周轉 F6 出入庫 F7 即時詢價（調貨） F8 銷貨比價 F9 進貨比價 F10 相關零件

關卡二｜同行調貨詢價：打三家、記三筆、比一比

角色：業務（掛掉客戶電話後）
☎️ 客戶願意等你半小時。翻同行名單、一家一家問。恆迎日常。
  1. 打之前先看行情：F2 同一顆料 → F9 進貨比價（歷史進價、實際成本橘色強調）、F7 面板先掃過去詢價紀錄
    預期：先知道行情價、決定先打哪家、心裡有底價再拿起電話
  2. 每問到一家 → F2 → F7 即時詢價：選同行、填數量、填「同行報我的價」→ 存一筆。打三家就記三筆
    預期：對話框欄位少、電話夾在肩膀上單手也能操作
  3. Alt+W 銷售選單 → 詢價紀錄：看剛記的三筆、點「單價」欄排序、最低價那家一眼挑出來
    預期：排序找最低價夠快；決定跟哪家調、回頭打給那家口頭下訂
⚠️ 現況差異（實走後給判斷）
詢價目前一次記一家一筆、比價靠紀錄清單自己排序——沒有「同一顆料 × 多家同行並排、一鍵採用最低價」的比價畫面。且之後開調貨單、系統帶的是你選的那家同行「最近一筆」詢價價、不是自動挑「最低那家」——挑哪家是人腦決定。判斷題：清單排序夠用？還是要並排比價視圖？
✅ 執行長 07/11 已定：實務上業務直接在 Line 問同行、比價/決定跟誰調（看價或看到貨速度）都在通訊軟體完成、不在系統比。系統只要記得住這些詢價紀錄供調貨單帶成本即可、不做並排比價視圖。
💡 攻略提示
這三筆不白記：關卡五開同行調貨單時、調貨成本會自動帶入該同行最近一筆詢價價。

關卡三｜即時報價：「上次跟你拿多少」馬上答

角色：業務（回到電話上）
📞 「有貨（調得到／等到貨約幾天）。價格是——」報價根據：過去報價、過去成交、建議售價。
  1. 路線一（電話上最快）：F2 選著料直接按 F4 即時報價——選客戶、單行快報、Alt+S 存報價紀錄
    預期：從接電話到報出口、整條路徑十秒內
  2. 報價時看歷史價參考面板：建議售價（成本＋客戶等級毛利）、這個客戶最近報價／最近成交、同級客戶最近報價／成交
    預期：五格都在、超過一個月的舊價不會自動帶入；客戶問「上次跟你們拿多少」馬上答得出
  3. 路線二（多顆料、要留正式單）：回首頁按 1 開報價單 → 加行：Alt+A 新增、Alt+F 從報價紀錄拉入、填量價 Enter 一路跳格到底
    預期：即時報價（單行、留紀錄）vs 報價單（多行、正式文件）分工清楚
  4. 報價單 Alt+S 存檔 → 寄出（狀態 草稿→已寄出）
    預期：⚠️ 草稿直接轉銷貨會被擋（業務閘）、訊息看得懂
  5. 支線 D（等到貨）：報價行備註寫交期說明（例「等下批到貨、約 7 天」）
    預期：行備註欄在、字數夠寫一句話
🆕 07/11 新增：給客戶的訊息（一鍵複製貼 Line）
執行長要求「報價要快、生成文字複製直接貼通訊軟體」。即時報價（F4）填完量價、下方出現「給客戶的訊息」框、按「複製」貼進 Line/訊息即可（銷貨與成交作業的報價頁本來就有、這次補進最快的即時報價路徑）。測：文字格式（料號 品名 數量 報價 NT$）對客戶讀得順嗎？要不要加招呼語／交期／有效期？
💥 遭遇戰：報價低於底價
給熟客殺到最低售價以下 → 系統要求必填理由才放行。測：理由欄好不好找？填完流程順嗎？
🧭 分歧點②：客戶說「好、要了」
  • →不管從哪條路線來的、都進關卡四・銷貨單（你稿子裡「先調貨單再銷貨單」的順序題、關卡五有專門判斷格）

關卡四｜銷貨單：成交落成單、缺貨行標來源

角色：業務
✅ 客戶確定要。開單——對象、倉庫、交易條件、出貨方式、明細從報價拉。
  1. 建單路線 A：報價單詳情按「轉銷貨」——整張帶入（只帶客戶選定的行）
    預期：不用重 key 任何一行、單價跟報價一字不差、銷貨單看得到來源報價單號
  2. 建單路線 B：Alt+W → 銷貨單 → 新增 → 明細「從報價帶入」勾行拉入
    預期：列出該客戶所有未轉完的報價行（可跨多張報價、可只拉部分行）、拉過的量不會重複轉
  3. 表頭核對：客戶、出貨倉自動帶（客戶預設倉→你的隸屬倉→主倉）、付款條件自動帶客戶設定、出貨方式（配送／自取／寄貨）
    預期：倉位欄已有值不用手選；交易條件不用重新想
  4. 缺貨那行：補貨來源標「同行調貨」→ 行狀態變「待補貨」
    預期：一張單裡現貨行跟調貨行一眼分得出來
  5. 支線 D：等到貨的行、補貨來源標「客戶訂單」→ 產生客訂追蹤
    預期：到貨後補得回來、客戶不會被忘掉
  6. 行備註寫情境註記（例「同行調、約明天到」）→ 核對金額稅額 → 存檔
    預期：Enter 跳格鏈不斷、全程不用滑鼠
⚠️ 現況差異（你情境稿點名的兩題、實走後給判斷）
1) 報價階段不帶貨源。報價單明細目前「沒有」出貨倉／貨源欄——貨源（本倉／自倉調撥／同行調貨／客戶訂單）是到銷貨行才標、而且是專屬欄位不是塞備註——比你稿子想的「備註欄註記」更結構化、但發生在銷貨階段不是報價階段。判斷題：報價階段要不要也能註記「這顆是調貨／別倉」？
2) 加行沒有即時缺貨提示。加明細行當下、系統「不會」跳「這顆在出貨倉沒貨」——要嘛你 F2 先查過、要嘛到單據確認時系統才自動處理自倉調撥。判斷題：加行當下要不要即時缺貨警示？
✅ 執行長 07/11：貨源在銷貨行標（不在報價階段）這設計可接受。加行即時缺貨警示可追加（銷貨行已存各倉可用量、加行時查一下就能在該行亮黃字提示「本倉不足 N」、軟提示不擋單）——待執行長確認要不要做。

關卡五｜同行調貨單：一鍵補單據

角色：業務
🤝 電話上你已經跟同行講好了（關卡二比完價那家）。回系統把單據補齊。
  1. 銷貨單上的「待補貨」行 → 「同行調貨」→ 選同行、勾行、一鍵建調貨單草稿
    預期：只列出等調貨的行、不會把現貨行混進來
  2. 核對草稿：調貨成本自動帶你在關卡二記的那家同行最近詢價價；銷貨行轉「補貨中」、回連調貨單號
    預期：成本不用重 key、兩張單互相連得起來
  3. Alt+W → 同行調貨單：確認單在（銷售選單、不在採購）、明細回連銷貨行
    預期：後續狀態 發出→回覆→待驗收→完成、每一步看得懂
⚠️ 順序題（本本最大的設計判斷、請執行長拍板）
你的情境稿寫「(4) 調貨單 → (5) 銷貨單」；系統目前反過來：一定要先有銷貨單、才能從缺貨行開調貨單（調貨明細硬綁銷貨行、開不了獨立調貨單）。電話節奏不受影響——跟同行口頭講好、回系統先開銷貨單（十秒）再一鍵補調貨單。實走後拍板：
🅐 這順序可接受（單據事後補記、自動回連）　🅑 要支援「先開調貨單、之後才掛銷貨單」→ 設計變更、Hank 整理轉給 Alex（跟同行直送案一起看）
✅ 執行長 07/11 傾向 🅐（Hank 同意）：真正的風險是「同行說貨被賣掉了」、但那個確認發生在 Line 上、業務是先在 Line 跟客戶＋同行都敲定了才回系統開單。所以進系統時兩邊都已成定局、單據純記錄——先銷貨單再補調貨單完全夠用。「先調貨單」的獨立建單需求不成立、除非之後遇到「同行直送客戶（貨不進倉）」才另議。
💡 攻略提示
收貨不在這關：貨到是倉管在 庫存管理→入庫作業→到貨驗收 收。單據歸業務、收貨歸倉管。
