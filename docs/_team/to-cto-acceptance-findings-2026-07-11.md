# 轉 CTO：2026-07-11 全系統驗收發現彙整

> 背景：執行長拍板家用機全面驗收。六組流程（主檔/銷售/採購/庫存/財務/鍵盤）
> API 端對端 + 實體帳核對共 80 項全綠；過程揪出 3 個 production 級問題（已修）、
> 6 個口徑/一致性題（待定案）。所有測試資料已清除還原、驗證細節在 dailylog 0711-M~T。

## 一、已修三件（知悉＋請檢視規格側是否有同源缺口）

### 修 1：銷貨建單 warehouseId 驗證死鎖（0711-M）
- 根因＝雙層 drift：service 早有「dto→客戶預設倉」fallback、但 DTO 仍標必填→
  fallback 永遠跑不到；且 UI 文案承諾三層鏈（客戶預設倉→使用者隸屬倉→主倉）只實作一層
- 修法：DTO 鬆綁 + service 補齊三層（隸屬倉取 isPrimary 優先、單倉隸屬次之、最後租戶主倉）
- 驗證：三層優先序全數實測（客戶倉 > 隸屬倉 > 主倉）
- ⚠️ 請 CTO 檢視：其他單據（報價已有同款三層、採購/調撥？）倉別 fallback 口徑是否要統一進規格

### 修 2：調撥版本功能閘門殘留（0711-S）⭐
- nx03 調撥 8 個進入點被 `requires PLUS or PRO plan` 擋——**違反產品鐵則**
  （三版只差人數、絕不做功能閘門、舊 Plan Guard 已廢）、LITE 客戶完全不能調撥
- 修法：閘門 + 孤兒 helper（plan-plus-support.ts）整組拆除；grep 全庫確認是最後一處
- ⚠️ 請 CTO 檢視：規格書若還有引用「PLUS 級功能」字樣的段落、需同步清理

### 修 3：退貨走保固「自動建保固單」從未生效（0711-S）🐛
- 階段 I P2 功能：PR dispositionFlag='W' 過帳→自動建保固申請單。實際上線以來一次都沒跑過
- 根因：helper 內「status 須已 POSTED」防呆、但 caller（applyPrPosting）在 header
  status 寫入**之前**執行→交易內讀到 DRAFT→靜默 return。無錯誤無日誌、純死路
- 修法：移除該防呆（呼叫語境唯一、dispositionFlag 防呆保留）；修後實測自動建成功
  （SELF 草稿、sourcePrId/sourcePrItemId 雙回連）
- ⚠️ 教訓供規格範式：交易內 helper 不可依賴「同交易稍後才寫入」的狀態欄防呆；
  建議 CTO 在工程慣例補一條（過帳鏈 helper 的前置條件由 caller 保證、不重讀 header 狀態）

## 二、待定案六題（口徑/一致性、零急迫、請逐題給方向）

### Q1 直接付款過帳不寫沖銷明細列
- 現狀：付款/收款「過帳」直接更新 AR/AP 的 paid/balance；`paylog_settlement` 明細列
  只有「票據/一票多單沖銷」流在寫
- 影響：沖銷歷史頁對直接付款顯示「總額有數、明細列空白」——對帳時看不到單筆軌跡
- Hank 建議：直接付款過帳也補寫一筆 settlement（來源標 direct）、歷史才完整；小改

### Q2 配送型銷貨無配送地址不擋
- 現狀：schema 註解「deliveryType=D 時必填」、但建單/出貨都放行（service fallback
  客戶預設地址、沒有→null 照走）；出貨時配送單（DN）因無地址**靜默不建**
- 影響：配送型銷貨出貨了卻沒有配送單、無任何警示、物流串接斷鏈
- Hank 建議：至少出貨（SHIPPED）時擋或警示；建單時擋更早但要配 UI（地址帶入/手填）

### Q3 已付清 AR 可建收款草稿
- 現狀：AR balance=0/PAID 仍可 POST 收款草稿（過帳時才擋超收、錢不會多收）
- 影響：僅 UX——會計可能建了一堆過不了帳的草稿
- Hank 建議：建立時軟警示即可、不必硬擋（低優先）

### Q4 銷退折讓金額口徑（未稅 vs 含稅）
- 現狀：退 1 顆單價 100（含稅單、稅率 5%）→ 自動折讓單金額 100＝未稅小計；
  當初 AR 收的是含稅 105
- 影響：退款給客戶到底退 100 還是 105？折讓與 AR 沖轉的稅額歸屬
- Hank 建議：請 CTO 定退款口徑（含稅退、稅額同折）並在 NX05 對帳設計一併寫死

### Q5 AP 歸戶後的付款條件來源
- 現狀（0711-L AP 歸戶案的保守決策）：AP 掛歸戶對象（母公司）時、到期日仍依
  「交易供應商」的付款條件算、不依歸戶對象的條件
- Hank 建議：維持現狀直到月結/請款設計定案、屆時一起定（與 Q1/Q4 同題域）

### Q6 currency_id 預設值違反 FK（重提、尚未處理）
- nx04_so / nx02_rr 的 currency_id DB default 'TWD'＝幣別代碼、但 FK 指向
  nx01_currency.id（NX01CURR…）——預設值本身違反 FK、靠應用層每次明填才沒炸
- Hank 建議：default 改 NX01CURR0000001 或移除 default 改必填；db execute 一條可解

## 三、業務閘行為記錄（驗收實測、可直接當手冊素材）

1. 報價單須「寄出（SENT）/已接受」才可轉銷貨、草稿不能轉（可讀訊息）
2. 銷貨單須「已出貨/已開發票」才可開銷退、草稿不能退
3. 銷退過帳前每行需倉管標好品/壞品（G/B）、未標全被擋且訊息指明缺哪行
4. 進退（PR）狀態機 DRAFT→POSTED 直達（無驗貨中間態）；過帳每行需庫位
5. 月關帳期間鎖訊息品質佳：「會計月份 YYYY-MM 已關帳、不可修改（負責人可解鎖回頭改）」
6. 授信凍結戶建銷貨被擋、訊息含凍結原因
7. PO 轉進貨（to-rr）每行需指定收貨庫位
