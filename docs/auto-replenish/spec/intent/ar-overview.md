## §1 AR 業務本質

### 1.1 AR 是什麼

**AR 自動補貨建議單 = NEXORA 核心戰略特色**、業界中小企業 ERP 第一個能做「智能品牌替代補貨」的功能。

業務本質回答 3 個核心問題：

1. **哪些料件該補貨？**（自動偵測缺貨 / 低於安全量 / 暢銷預測）
2. **該補多少？**（系統依平均出貨量算建議量、考慮配比規則）
3. **該補什麼品牌？**（兩層分類 OE / 副廠、副廠按銷貨比例分配）

### 1.2 AR 在 NEXORA 全棧的角色

```
NX03 庫存 → 偵測缺貨 → AR 算建議量 → NX02 採購建議單（Demand）→ 詢價 RFQ → 採購流程
```

- **上游**：NX03 庫存（stock_balance / stock_ledger / part_stock_setting）
- **下游**：NX02 採購（Demand → RFQ → Qt → Po → Rr）
- **核心定位**：系統建議 + 人最終決定的決策支援工具

### 1.3 NEXORA 戰略意義

⭐⭐⭐ AR 是 NEXORA 「**業務員 muscle memory → 系統 query**」範式最強落地點：

- 業界傳統：靠老師傅腦記、Excel 月底校正、補貨憑經驗
- NEXORA：系統自動算 + 智能品牌替代 + 倉管/產品最終決定

⭐ **業界第一個**能做以下 3 件事：
1. **智能品牌替代補貨**（OE 缺貨自動推副廠、副廠彙整算銷貨）
2. **倉層級彈性頻率**（每倉自訂計算頻率）
3. **系統建議 + 人介入並重**（倉庫實體限制 / 採購策略雙重把關）

## §2 主使用者與權限

### 2.1 三層使用者

| 角色 | 業務動作 | 介入時機 |
|---|---|---|
| **系統**（cron job）| 自動計算建議單 | 按倉設定的頻率自動跑 |
| **WAREHOUSE 倉管** | 手動介入：調整建議量 | 倉庫實體限制（放不下、堆積等）|
| **PURCHASING 產品** | 最終決定：審核 / 轉詢價 | 採購策略（市場、季節、廠商關係）|

對齊 Crown Q-AR1 拍板：系統自動算 + 倉管 / 產品手動介入並重。

### 2.2 權限分工

- **計算引擎**：系統自動、不涉人權限
- **建議單查看**：倉管 + 產品雙看（對齊 NX03 Q-C 拍板）
- **建議單調整**：倉管（量）+ 產品（最終決策）
- **轉詢價**：產品專屬

## §3 業務功能架構

### 3.1 AR 4 大業務功能

```
AR 自動補貨建議單
   │
   ├─ 1. 自動計算引擎
   │   ├─ 倉層級彈性頻率（每倉自訂）
   │   ├─ 平均出貨量計算（排除調撥）
   │   ├─ 兩層分類（OE / 副廠）
   │   └─ 配比規則套用
   │
   ├─ 2. 建議單管理
   │   ├─ 一張建議單列多料件（產品看單）
   │   ├─ 倉管調整量（實體限制）
   │   └─ 產品挑選 / 忽略
   │
   ├─ 3. 詢價接點
   │   ├─ 走 NX02 Demand demandType='S'
   │   └─ Demand → RFQ → Qt → Po → Rr
   │
   └─ 4. 手動介入機制
       ├─ 倉管：調整量 / 拒絕建議
       └─ 產品：審核 / 改配比 / 替代品牌
```

### 3.2 計算引擎核心邏輯

對齊 Crown Q-AR3 拍板：**平均出貨量、排除調撥**（X 不算）

```
階段 1：偵測需求
  系統掃描 stock_balance
  → 低於 PartStockSetting.safetyQty 的料件 → 入候選池
  
階段 2：計算需求量（part_model 維度）
  對該料件的 part_model 群組：
  - 撈近 N 天 stock_ledger 異動
  - 篩 source = S（純市場銷貨、不算 X 調撥）
  - 算平均每日出貨量
  - × 採購 lead time = 預估需求量

階段 3：兩層分類分配
  總需求量 → 按 OE / 副廠配比規則拆分
  - OE 量 = 總量 × OE 比例
  - 副廠量 = 總量 × 副廠比例

階段 4：副廠池內銷貨比例分配
  副廠量 → 按各品牌近 N 天銷貨比例拆分
  - 鳥牌量 = 副廠量 × 鳥牌銷貨佔比
  - febi 量 = 副廠量 × febi 銷貨佔比
  - ...

階段 5：產出建議單
  建議單 = 多料件 row（每料件 × 每品牌一行）
  寫入 Nx02Demand demandType='S'
```

### 3.3 廠牌維度業界範式（Crown Q-AR-廠牌 4 題拍板）

⭐ **NEXORA 智能品牌替代補貨**業界第一個範式：

**兩層分類**（Crown Q-AR-廠牌-1=c）：
- 第 1 層：OE 正廠 vs 副廠（`Nx01Part.isOem` 既有 ✓）
- 第 2 層：副廠內品牌（`Nx01PartBrand` 既有 ✓）

**混合計算解法**（Crown Q-AR-廠牌-2=d）：
- 解法 B：part_model 維度算總量 + 配比規則
- 解法 C：副廠池內按銷貨比例分配
- 解法 D：替代品牌邏輯（缺正廠推副廠）

**配比規則來源**（Crown Q-AR-廠牌-3=d）：
- 系統建議為主（自動依銷貨比例算）
- 手動為輔（特殊料件可手動覆寫）

**替代品牌業務場景**（Crown Q-AR-廠牌-4=b）：
- 缺正廠可推副廠
- 銷貨數據跨品牌彙整（part_model 維度）

### 3.4 業務範例（Crown 揭露的 Golf 7 三角架）

```
料件：Golf 7 三角架（part_model 維度同一個）
配比規則：OE 2 : 副廠 2
近 90 天銷貨：正廠 60% / 鳥牌 25% / febi 15%

倉庫目標：4 組
實際庫存：正廠 × 1 + 鳥牌 × 1 + febi × 1 = 3 組（缺 1）

系統計算：
- 總需求 = 4 組
- OE 池 = 2（正廠 1 顆 → 缺 1）
- 副廠池 = 2（鳥牌 1 + febi 1 → 滿、缺 0）
- 副廠池銷貨比例：鳥牌 25/40 = 62.5% / febi 15/40 = 37.5%

建議單產出：
- 正廠 補 1 顆（OE 池缺）
- 鳥牌 補 0（副廠池滿）
- febi 補 0（副廠池滿）

倉管介入場景：
- 倉庫實體限制、改 1 組總量 → 不補

產品介入場景：
- 採購策略：正廠廠商有促銷、改補 2 顆正廠
```

## §4 倉層級彈性頻率（Crown Q-AR2 拍板）

### 4.1 頻率設定範式

| 設定層級 | 業界場景 |
|---|---|
| 倉層級 | 每倉自訂計算頻率 |
| LITE 預設 | 每天一次 |
| PLUS 預設 | 各倉自訂 |
| PRO 預設 | 各倉自訂（含跨區營運不同節奏）|

### 4.2 頻率業界範式

- **快銷倉**：每天算（如熱銷品集中倉）
- **慢銷倉**：每週算（如季節性料件倉）
- **特殊倉**：每月算（如冷門料件倉）
- **手動觸發**：任何時機產品 / 倉管可主動觸發重算

## §5 配比規則設計

### 5.1 配比規則 schema 範式（Crown Q-AR-設計-1=a）

**新建 `Nx03BrandAllocationRule` 主檔**：
- 配比規則業務語意獨立（不只是「安全量」一個維度）
- 對齊 NEXORA 主檔範式（獨立 schema = 獨立業務模型）
- 未來擴展空間大（可加配比歷史、按倉/按客戶分等）

### 5.2 配比規則來源（Q-AR-廠牌-3=d）

**系統建議為主**：
- 依近 N 天銷貨數據自動算 OE:副廠比例
- 依各副廠品牌銷貨佔比自動算

**手動為輔**：
- 特殊料件允許手動覆寫
- 業務 / 採購策略需求（如新品牌試銷）

## §6 替代品牌邏輯（Crown Q-AR-廠牌-4=b）

### 6.1 替代邏輯範式（Crown Q-AR-設計-2=b）

**application 層解、不動 schema**：
- 既有 `Nx01PartModel.fitLevel`（1 原廠 / 2 副廠等效 / 3 通用替代）已含業界語意
- 不新增 PartRelation type、避免 schema 耦合
- 計算引擎內部即時算替代池

### 6.2 替代業務場景

```
場景 A：缺正廠
  → 系統檢查 fitLevel=2 副廠等效列表
  → 推副廠補貨（銷貨數據彙整）

場景 B：缺副廠特定品牌
  → 系統檢查同副廠池其他品牌（fitLevel=2）
  → 推同等級替代

場景 C：完全缺貨
  → 升級為 fitLevel=3 通用替代
  → 推通用品牌
```

## §7 詢價接點（Crown Q-AR5 拍板）

### 7.1 走既有 NX02 進貨鏈

對齊 Hank AR-AUDIT-01 v2 揭露 + Crown「不直接轉採購、先詢價」：

```
AR 建議單（Demand demandType='S'）
   ↓ 產品挑選 + 確認
   ↓
NX02 Demand 確認
   ↓
NX02 RFQ（依 demandId 串）
   ↓
NX02 Qt（廠商報價）
   ↓
NX02 Po（採購單）
   ↓
NX02 Rr（進貨入庫）
   ↓
NX03 stock_balance + ledger（source=P）
```

### 7.2 不需新表

**Nx02Demand demandType='S'** 已是業界「採購建議單」載體、AR 直接寫入即可。
