# P-W08｜向供應商申請保固

> 版本需求：LITE
> 最後更新：2026-04-11

---

## 流程概述

客戶反映已安裝的零件有問題時，由營業處倉管組長初步判斷是否符合保固條件，再通知業務向客戶索取證明文件，最後由採購接洽廠商提出保固申請。涉及三個部門：倉管→銷售→採購→廠商。

---

## 觸發條件

| 來源 | 代碼 | 說明 |
|------|------|------|
| 客戶反映 | S01W | 客戶聯繫業務，反映已安裝零件有問題 |
| 銷退驗收 | S-W03 | 銷退驗收時發現零件確有瑕疵 |

---

## 保固適用條件

| 條件 | 說明 |
|------|------|
| 保固期內 | 零件本體貼紙上的保固 QR Code 有效（Phase 2 系統驗證，目前人工確認）|
| 非人為損壞 | 非安裝不當/碰撞/改裝造成的損壞 |
| 原廠零件 | 僅適用有廠商保固的原廠/副廠零件 |
| 有購買記錄 | 可查到對應的 SO 銷貨單 |

---

## 責任判斷邏輯

```
零件有問題
  ├── 零件本身瑕疵 → 向廠商申請保固（本流程）
  ├── 安裝問題 → 通知業務向客戶說明，非保固範圍
  └── 正常耗損 → 通知業務向客戶說明，非保固範圍
```

---

## 流程階段

### 階段一：初步判斷（營業處倉管組長）

**觸發：** 業務接到客戶反映後，通知所屬營業處倉管組長
**執行者：** 倉管組長

| 行為 | 說明 |
|------|------|
| W01 查詢銷售記錄 | 確認客戶是否有購買此料號的 SO 記錄 |
| W02 確認保固期 | 確認銷售日期，判斷是否在保固期內 |
| W03 判斷損壞原因 | 依客戶描述初步判斷是零件瑕疵或其他原因 |

| 結果 | 條件 | 下一步 |
|------|------|--------|
| ✅ 符合保固條件 | 有購買記錄、在保固期內、疑似零件瑕疵 | 通知業務進入階段二 |
| ⊗ W⊗00 | 無購買記錄 | 通知業務告知客戶不符合保固，流程結束 |
| ⊗ W⊗01 | 超過保固期 | 通知業務告知客戶超過保固期，流程結束 |
| ⊗ W⊗02 | 非零件瑕疵（安裝問題/正常耗損）| 通知業務向客戶說明，流程結束 |

---

### 階段二：向客戶索取證明文件（業務）

**觸發：** 倉管組長通知符合保固條件
**執行者：** 業務專員

| 行為 | 說明 |
|------|------|
| W04 聯繫客戶 | 告知符合保固條件，請客戶提供證明文件 |
| W05 索取證明文件 | 請客戶提供以下文件 |

**必要文件清單：**

| 文件 | 說明 |
|------|------|
| 照片/影片 | 清楚顯示零件損壞狀況 |
| 行照 | 確認車輛資訊（車型/年份）|
| 維修記錄（若有）| 安裝日期/里程數 |
| 保固貼紙照片 | 確認貼紙完整（Phase 2 改為掃 QR Code）|

| 行為 | 說明 |
|------|------|
| W06 填寫保固申請單 | 業務在系統填寫保固申請單 |
| W07 上傳證明文件 | 上傳客戶提供的照片/影片/行照 |
| W08 傳送給採購 | 系統通知採購組長有新的保固申請 |

**產出：** 保固申請單（狀態：待採購處理）

| 結果 | 條件 | 下一步 |
|------|------|--------|
| ✅ 文件齊全 | 所有必要文件已上傳 | 進入階段三 |
| ⚠️ 文件不完整 | 客戶無法提供部分文件 | 採購組長決定是否仍可申請 |
| ⊗ W⊗03 | 客戶拒絕提供文件 | 無法申請保固，流程結束，通知倉管組長 |

---

### 階段三：採購接洽廠商申請保固

**觸發：** 收到業務傳來的保固申請單
**執行者：** 採購專員（執行）、採購組長（審核）

| 行為 | 執行者 | 說明 |
|------|--------|------|
| W09 確認廠商保固政策 | 採購專員 | 查詢該廠商/料號的保固條款 |
| W10* 採購組長審核 | 採購組長 | 確認申請資料完整、符合廠商保固條件 |
| W11 向廠商提出申請 | 採購專員 | 傳送保固申請單與證明文件給廠商 |
| W11^ 廠商審核回覆 | 廠商（外部）| 廠商確認是否接受保固申請 |

| 結果 | 條件 | 下一步 |
|------|------|--------|
| ✅ 廠商核准 | 廠商接受保固申請 | 進入階段四 |
| ❌ 廠商退件 | 廠商認為不符合保固條件 | 進入異常處置 |
| ⊗ W⊗04 | 廠商無回應/超時 | 採購組長決定處置方式，通知業務 |

**廠商退件的異常處置：**

| 處置方式 | 說明 |
|---------|------|
| 重新協商 | 採購組長親自與廠商交涉 |
| 公司自行吸收 | 公司決定自行補貨給客戶（客戶關係考量）|
| 告知客戶 | 業務通知客戶廠商不接受，非公司責任 |

---

### 階段四：保固處理結果

**觸發：** 廠商核准保固申請
**執行者：** 採購專員

**廠商處理方式：**

| 方式 | 說明 | 後續作業 |
|------|------|---------|
| 補發良品 | 廠商寄送良品給我方 | 走一般進貨驗收（P-W01 階段四）後配送給客戶 |
| 退款 | 廠商退回零件款項 | 引用 [F01 應付帳款作業] AP 沖銷或退款 |
| 以折讓代替 | 廠商給予折讓，下次採購扣抵 | 引用 [F02 折讓作業] |

| 行為 | 執行者 | 說明 |
|------|--------|------|
| W12 記錄保固結果 | 採購專員 | 在保固申請單記錄廠商處理方式 |
| W13 通知業務 | 系統自動 | 通知業務保固結果，請業務聯繫客戶 |
| W14 業務通知客戶 | 業務專員 | 告知客戶補貨/退款進度 |

| 結果 | 條件 | 下一步 |
|------|------|--------|
| ✅ W⊗05 保固完成 | 客戶收到補貨或退款 | 流程結束 |

---

## 結束點總覽

| 代碼 | 結束原因 | 後續處理 |
|------|---------|---------|
| W⊗00 | 無購買記錄 | 業務告知客戶不符合保固 |
| W⊗01 | 超過保固期 | 業務告知客戶超過保固期 |
| W⊗02 | 非零件瑕疵 | 業務向客戶說明原因 |
| W⊗03 | 客戶拒絕提供文件 | 無法申請保固，案件關閉 |
| W⊗04 | 廠商無回應 | 採購組長決定處置，通知業務 |
| W⊗05 | 保固完成 | 客戶收到補貨或退款 |

---

## 跨部門分工總覽

```
倉管組長（第一關）
  └── 初步判斷是否符合保固條件
        ↓
業務專員（第二關）
  └── 向客戶索取證明文件、填寫保固申請單
        ↓
採購組長/採購專員（第三關）
  └── 審核申請、接洽廠商
        ↓
廠商（外部）
  └── 審核後補貨/退款/折讓
        ↓
採購通知業務 → 業務通知客戶
```

---

## Phase 2 規劃

```
目前：人工確認保固貼紙/保固期
Phase 2：
  零件出貨時系統自動產生保固 QR Code
  客戶/倉管掃描 QR Code 即可確認保固有效性
  系統自動比對保固期，不需人工查詢
```
