# NX10-W02｜遊戲化轉職系統

> 版本需求：PRO
> 最後更新：2026-04-11

---

## 流程概述

將升遷流程遊戲化，當員工達成系統定義的轉職條件後，系統解鎖轉職申請資格，員工提出申請後由主管與負責人審核，最終引用 H-W04 員工異動作業執行升遷。

---

## 設計理念

```
傳統升遷：主觀/不透明/靠關係
NEXORA 轉職系統：
  → 條件明確，員工清楚知道距升遷還差什麼
  → 系統自動驗證客觀條件
  → 主管僅負責人格/適任性的主觀評估
  → 兩者結合，升遷更公平透明
```


## 轉職流程階段

### 階段一：系統監控轉職條件

**執行者：** 系統自動
**時機：** 每日計算

| 行為 | 說明 |
|------|------|
| T01 監控所有員工的轉職條件 | 持續追蹤各客觀條件是否達標 |
| T02 條件全達標時通知員工 | 「您已達成 物流組長 轉職條件，可申請轉職！」|
| T03 同時通知直屬主管 | 讓主管提前準備評估 |

---

### 階段二：員工申請轉職

**執行者：** 員工本人

| 行為 | 說明 |
|------|------|
| T04 查看轉職條件進度 | NX10 → 轉職系統 → 我的轉職進度 |
| T05 申請轉職 | 條件全達標後，點擊「申請轉職審核」|
| T06 填寫自我陳述 | 說明為何認為自己適合晉升 |

**轉職進度顯示範例：**
```
外務 → 物流組長

✅ 勳章等級：鑽石 IV（已達標）
✅ 在職年資：1年3個月（已達標）
✅ KPI 達成率：87%（已達標）
✅ 帶新人：1人（已達標）
✅ 無重大懲罰（已達標）
⬜ 主管推薦（待申請後填寫）
⬜ 負責人核准（待審核）

狀態：可申請轉職 ✨
```

---

### 階段三：主管評估

**執行者：** 直屬主管

| 行為 | 說明 |
|------|------|
| T07 收到轉職申請通知 | 系統通知主管有員工申請轉職 |
| T08 查看員工完整表現 | 系統顯示員工所有 Exp/KPI/懲罰記錄 |
| T09 填寫主管推薦意見 | 從人格/溝通/領導力/適任性等主觀面評估 |

| 結果 | 條件 | 下一步 |
|------|------|--------|
| ✅ 推薦 | 主管認為適合晉升 | 送負責人審核 |
| ❌ 不推薦 | 主管認為時機未到 | 通知員工原因，可 3 個月後再申請 |

---

### 階段四：負責人最終核准

**執行者：** 總經理/負責人

| 行為 | 說明 |
|------|------|
| T10* 審核轉職申請 | 查看系統數據 + 主管推薦意見 |

| 結果 | 條件 | 下一步 |
|------|------|--------|
| ✅ 核准轉職 | 同意升遷 | 引用 [H-W04 員工異動作業] 執行 |
| ❌ 不核准 | 時機或條件不符 | 說明原因，員工可繼續累積 |

---

### 階段五：執行升遷

**執行者：** 行政專員

| 行為 | 說明 |
|------|------|
| T11 引用 H-W04 員工異動作業 | 更新職務/薪資/系統權限 |
| T12 系統記錄轉職成就 | 員工個人頁面新增「轉職紀錄」|
| T13 系統全員通知 | 「恭喜 XXX 晉升為 物流組長！」|
| T14 轉職 Exp 獎勵 | 系統自動補充特定轉職里程碑 Exp |

## 帶新人機制

```
帶新人是轉職條件之一，也是知識傳承的核心

定義：
  正式帶新人關係需主管確認建立
  新人通過試用期 = 在職 3 個月 + KPI 達標

帶新人 Exp：
  新人通過試用期 → 帶新人 +500 Exp
  新人首次晉升銀牌 → 帶新人額外 +200 Exp（培養成果）

帶新人記錄：
  員工個人頁面顯示「帶過幾位新人」
  作為企業知識傳承的指標
```
